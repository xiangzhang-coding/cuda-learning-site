术语表（Glossary）记录 CUDA 学习站（Learning Site）采用的规范词汇。中文正文第一次使用受控术语时会同时给出英文，方便你继续阅读代码、工具和上游资料。

## 如何使用

“避免使用”不是在禁止日常表达，而是在指出会改变本站教学合同或资源类型的称呼。每个词条都给出相关学习单元（Learning Unit）和版本边界。

## 已发布词条

<span id="term-001" class="resource-target" aria-hidden="true"></span>

### Learning Site · 学习站

- **定义：** 包含稳定课程（Stable Curriculum）、可运行示例（Runnable Example）、实验（Lab）和练习（Exercise）的完整公开学习资源。
- **避免使用：** 博客、文档站。
- **相关单元：** O01。
- **版本说明：** 不受特定 Toolkit 版本约束。

<span id="term-002" class="resource-target" aria-hidden="true"></span>

### Stable Curriculum · 稳定课程

- **定义：** 建立在非预览接口和耐久概念上的先修课程；“稳定”描述教学依赖合同，不表示每个动手活动都已有硬件观察。
- **避免使用：** 主课程、最新特性目录。
- **相关单元：** O01。
- **版本说明：** 课程持续维护，不按 Toolkit 复制多套版本。

<span id="term-003" class="resource-target" aria-hidden="true"></span>

### Learning Unit · 学习单元

- **定义：** 按顺序讲授一个主题的课程部分，先说明动机，再发展心智模型和相关历史背景，最后通过实践检查理解。
- **避免使用：** 文章、帖子。
- **相关单元：** O01。
- **版本说明：** 资源类型本身不受版本约束。

<span id="term-004" class="resource-target" aria-hidden="true"></span>

### Publication Pair · 双语发布对

- **定义：** 同一公开页面的中英文对应版本，共享事实、结构、代码、可视化、元数据和来源日期。
- **避免使用：** 翻译回退、可选翻译。
- **相关单元：** O01。
- **版本说明：** 适用于每次发布。

<span id="term-005" class="resource-target" aria-hidden="true"></span>

### Runnable Example · 可运行示例

- **定义：** 展示一个聚焦概念的独立源代码项目，是学习单元引用的规范可执行来源。
- **避免使用：** 代码片段、伪代码、实验。
- **相关单元：** O01、F01。
- **版本说明：** 具体项目必须另行声明适用版本。

<span id="term-006" class="resource-target" aria-hidden="true"></span>

### Lab · 实验

- **定义：** 学习者在外部 CUDA 环境中执行的引导式活动，包含预期观察和验收条件。
- **避免使用：** 演示、浏览器游乐场。
- **相关单元：** O01、LAB02。
- **版本说明：** 具体实验必须另行声明环境要求。

<span id="term-007" class="resource-target" aria-hidden="true"></span>

### Exercise · 练习

- **定义：** 由学习者完成的任务，说明目标、约束和验收条件，而不是只给出答案。
- **避免使用：** 示例、实验。
- **相关单元：** O01。
- **版本说明：** 资源类型本身不受版本约束。

<span id="term-008" class="resource-target" aria-hidden="true"></span>

### Practice Bank · 练习题库

- **定义：** 跨课程整理的原创问题集合，每个条目都会链接到教授其先修知识的学习单元。
- **避免使用：** 常见问题、复制的题目堆。
- **相关单元：** O01。
- **版本说明：** 具体条目在需要时声明版本边界。

<span id="term-009" class="resource-target" aria-hidden="true"></span>

### Visual Explainer · 可视化讲解

- **定义：** 用交互或动画显露空间、时间或架构行为的表示；可以在浏览器中建模 CUDA 概念，但不会执行 CUDA。
- **避免使用：** 装饰、CUDA 演示。
- **相关资源：** O01、[VIS01](/visuals/kernel-journey/)、[VIS02](/visuals/indexing/)、[VIS04](/visuals/memory-transactions/)、[VIS05](/visuals/shared-memory-banks/)、[VIS06](/visuals/memory-hierarchy-lifetime/)、[VIS11](/visuals/tiled-transpose/)、[VIS19](/foundations/asynchronous-errors/#vis19)、[VIS20](/foundations/compute-capability/#vis20)、[VIS21](/foundations/runtime-driver-api/#vis21)、[VIS22](/foundations/launch-geometry/#vis22)。
- **版本说明：** 概念模型和特定硬件行为必须分开说明。

<span id="term-010" class="resource-target" aria-hidden="true"></span>

### Glossary · 术语表

- **定义：** 面向学习者的双语规范术语索引。
- **避免使用：** 字典、关键词清单。
- **相关单元：** O01。
- **版本说明：** 词条会随课程复核，但不会暗示接口兼容性。

<span id="term-011" class="resource-target" aria-hidden="true"></span>

### Evidence Status · 证据状态

- **定义：** 描述实验或可运行示例当前具有什么可复核证据的受控标签；编译轴和运行轴彼此独立。
- **避免使用：** 不加限定的“已验证”“已支持”。
- **相关单元：** O02。
- **版本说明：** 状态必须绑定对象、环境、标准和日期；网页发布本身不授予状态。

<span id="term-012" class="resource-target" aria-hidden="true"></span>

### Compile-Checked · 编译已检查

- **定义：** 要求的源代码在声明的 Toolkit Lane 中实际构建成功，并记录方言、目标、命令和构建环境；不要求也不暗示 GPU 执行。
- **避免使用：** 运行已验证、已在 GPU 测试。
- **相关单元：** O02、O03。
- **版本说明：** 每次声明都绑定精确 Toolkit Lane。

<span id="term-013" class="resource-target" aria-hidden="true"></span>

### Community-Observed · 社区已观察

- **定义：** 社区成员提交了完整 Environment Manifest、日志或产物、标准和日期的运行观察；它不等同于维护者复现。
- **避免使用：** Runtime-Verified、轶闻支持。
- **相关单元：** O02、O03。
- **版本说明：** 可与 Pending Hardware Verification 并存。

<span id="term-014" class="resource-target" aria-hidden="true"></span>

### Runtime-Verified · 运行已验证

- **定义：** 对象在已声明、由维护者控制的 Reference Environment 中执行，并满足预先声明的正确性和观察标准。
- **避免使用：** Compile-Checked、预期可运行。
- **相关单元：** O02、O03。
- **版本说明：** 结论只覆盖记录的 GPU、驱动、Toolkit、组件、工作负载和方法。

<span id="term-015" class="resource-target" aria-hidden="true"></span>

### Pending Hardware Verification · 待硬件验证

- **定义：** 验收需要 GPU 行为，但所需合格运行证据尚不存在。
- **避免使用：** Runtime-Verified、应该能运行。
- **相关单元：** O02。
- **版本说明：** 编译成功或社区观察不会自动移除此状态。

<span id="term-016" class="resource-target" aria-hidden="true"></span>

### Runtime-Not-Applicable · 无需运行验证

- **定义：** 验收只要求编译或检查产物，不要求任何 GPU 行为时使用的运行轴状态。
- **避免使用：** 编译专用、跳过运行。
- **相关单元：** O02。
- **版本说明：** 不能用来隐藏运行正确性或性能要求。

<span id="term-017" class="resource-target" aria-hidden="true"></span>

### Environment Manifest · 环境清单

- **定义：** 为解释构建、运行或测量而分别记录的 GPU、计算能力、数量、驱动、Toolkit、组件、编译器、操作系统、工作负载和方法坐标。
- **避免使用：** 版本字符串、机器描述。
- **相关单元：** O03。
- **版本说明：** 证据发生变化时必须记录新的观察日期和坐标。

<span id="term-018" class="resource-target" aria-hidden="true"></span>

### Supported Environment · 受支持环境

- **定义：** 本站承担安装说明、故障边界和验证声明责任的环境家族；只有原生 Linux 属于此范围。
- **避免使用：** 任何可能碰巧运行的平台。
- **相关单元：** O03。
- **版本说明：** 上游产品支持不会自动扩大本站责任。

<span id="term-019" class="resource-target" aria-hidden="true"></span>

### Reference Environment · 基准环境

- **定义：** 受支持环境中一套已声明、由维护者控制、拥有完整 manifest 和成功受控基线运行的具体配置。
- **避免使用：** 推荐环境、社区配置。
- **相关单元：** O03。
- **版本说明：** 当前尚未声明任何 Reference Environment。

<span id="term-020" class="resource-target" aria-hidden="true"></span>

### Toolkit Lane · 工具包通道

- **定义：** 固定 Toolkit 和主机环境、并声明所测 C++ 方言的编译证据目标。
- **避免使用：** 站点版本、文档版本。
- **相关单元：** O03。
- **版本说明：** Lane 不是课程副本或 Reference Environment；构建成功后才能获得 Compile-Checked。

<span id="term-021" class="resource-target" aria-hidden="true"></span>

### GPU Capability Tier · GPU 能力层级

- **定义：** 由计算能力、显存、GPU 数量、特性和权限共同定义的课程支持层级。
- **避免使用：** GPU class、显存档位。
- **相关单元：** O03。
- **版本说明：** 产品名和更大显存不能单独决定层级。

<span id="term-022" class="resource-target" aria-hidden="true"></span>

### Baseline GPU Capability Tier · 基础 GPU 能力层级

- **定义：** 稳定课程基础内容的层级，要求 compute capability 7.5 或更新，并采用能放入 8 GB 的问题规模。
- **避免使用：** 8 GB GPU tier、Turing tier。
- **相关单元：** O03。
- **版本说明：** 8 GB 描述工作负载边界，不是单独的硬件档位。

<span id="term-023" class="resource-target" aria-hidden="true"></span>

### Modern Single-GPU Capability Tier · 现代单 GPU 能力层级

- **定义：** 完整单 GPU 路线的层级，要求 compute capability 8.0 或更新并且至少 8 GB；额外活动另行声明门槛。
- **避免使用：** complete tier、Ampere tier。
- **相关单元：** O03。
- **版本说明：** 多 GPU 和架构专用活动不由此层级自动覆盖。

<span id="term-024" class="resource-target" aria-hidden="true"></span>

### CUDA Toolkit · CUDA 工具包

- **定义：** NVIDIA 提供的编译器、库、工具和运行时开发组件集合；它和已安装驱动、单个组件版本分别记录。
- **避免使用：** CUDA 驱动版本、整台 CUDA 环境。
- **相关单元：** O03。
- **版本说明：** 本站 Toolkit Lane 使用精确 `X.Y.Z` 坐标。

<span id="term-025" class="resource-target" aria-hidden="true"></span>

### compute capability · 计算能力

- **定义：** 描述一组 GPU 架构功能和技术限制的 major.minor 能力坐标。
- **避免使用：** GPU 代际、Toolkit 版本。
- **相关资源：** [O03](/start/environment-manifest/)与 [F06](/foundations/compute-capability/)。
- **版本说明：** 型号映射、功能、限制与编译目标必须按当前 NVIDIA 文档复核。

<span id="term-026" class="resource-target" aria-hidden="true"></span>

### kernel · 核函数

- **定义：** 由 host 发起、在 CUDA device 上由许多 thread 执行的函数；CUDA C++ 中 `__global__` kernel 使用 execution configuration launch。
- **避免使用：** 普通 CPU 函数、浏览器动画。
- **相关资源：** [F01](/foundations/first-cuda-kernel/)、[F02](/foundations/execution-hierarchy/)、[F03](/foundations/multidimensional-indexing/)、[F04](/foundations/host-device-lifecycle/)、[EX03](/examples/multidimensional-indexing/)、[LAB02](/labs/vector-addition/)。
- **版本说明：** F01 使用 CUDA Programming Guide v13.3 的基础执行模型。

<span id="term-027" class="resource-target" aria-hidden="true"></span>

### execution configuration · 执行配置

- **定义：** Kernel launch 中声明 grid 与 thread block 形状的配置；一维场景常写成 block 数和每 block thread 数。
- **避免使用：** 数据范围、GPU 配置。
- **相关资源：** [F01](/foundations/first-cuda-kernel/)、[F02](/foundations/execution-hierarchy/)、[F03](/foundations/multidimensional-indexing/)、[VIS02](/visuals/indexing/)、[EX03](/examples/multidimensional-indexing/)。
- **版本说明：** 配置创建执行 thread，不自动定义逻辑数据 extent。

<span id="term-028" class="resource-target" aria-hidden="true"></span>

### grid · 网格

- **定义：** 一次 kernel launch 创建的全部 thread block 集合，可具有一维、二维或三维形状。
- **避免使用：** 数据数组、固定调度顺序。
- **相关资源：** [F01](/foundations/first-cuda-kernel/)、[F02](/foundations/execution-hierarchy/)、[F03](/foundations/multidimensional-indexing/)、[VIS01](/visuals/kernel-journey/)、[VIS02](/visuals/indexing/)、[EX03](/examples/multidimensional-indexing/)。
- **版本说明：** Block 的分派和完成顺序不由 grid 坐标保证。

<span id="term-029" class="resource-target" aria-hidden="true"></span>

### thread block · 线程块

- **定义：** Grid 中一组共同调度到一个 SM 的 thread；`blockIdx` 标识 block，`blockDim` 描述其形状。
- **避免使用：** CPU thread pool、warp。
- **相关资源：** [F01](/foundations/first-cuda-kernel/)、[F02](/foundations/execution-hierarchy/)、[F03](/foundations/multidimensional-indexing/)、[VIS01](/visuals/kernel-journey/)、[VIS02](/visuals/indexing/)、[EX03](/examples/multidimensional-indexing/)。
- **版本说明：** F01 只使用一维 block；多维关系由 VIS02 说明。

<span id="term-030" class="resource-target" aria-hidden="true"></span>

### thread · 线程

- **定义：** Kernel 的一个逻辑执行实例；它通过 `threadIdx` 与 block/grid 坐标推导自己负责的数据位置。
- **避免使用：** 元素、warp、操作系统线程。
- **相关资源：** [F01](/foundations/first-cuda-kernel/)、[F02](/foundations/execution-hierarchy/)、[F03](/foundations/multidimensional-indexing/)、[VIS02](/visuals/indexing/)、[EX03](/examples/multidimensional-indexing/)。
- **版本说明：** Launch thread 可以落在逻辑数据范围外，因此仍需 bounds check。

<span id="term-031" class="resource-target" aria-hidden="true"></span>

### host and device · 主机与设备

- **定义：** Host 代码在 CPU 侧管理分配、复制、launch 和同步；device 代码由 CUDA GPU 执行，二者的内存和完成边界必须显式处理。
- **避免使用：** 把 host test 当作 GPU run、把 device memory 当作 host memory。
- **相关资源：** [F01](/foundations/first-cuda-kernel/)、[F04](/foundations/host-device-lifecycle/)、[EX03](/examples/multidimensional-indexing/)、[LAB02](/labs/vector-addition/)。
- **版本说明：** LAB02 使用 CUDA Runtime API 11.8.0、12.9.2 或 13.3.1 的声明 Lane。

<span id="term-032" class="resource-target" aria-hidden="true"></span>

### bounds check · 边界判断

- **定义：** Thread 在访问数组前比较推导索引与逻辑 extent，使最后一个 partial block 的越界 thread 跳过访问。
- **避免使用：** 阻止 thread launch、缩小 grid。
- **相关资源：** [F01](/foundations/first-cuda-kernel/)、[F03](/foundations/multidimensional-indexing/)、[VIS02](/visuals/indexing/)、[EX03](/examples/multidimensional-indexing/)、[LAB02](/labs/vector-addition/)。
- **版本说明：** EX02 的一维条件是 `index < element_count`。

<span id="term-033" class="resource-target" aria-hidden="true"></span>

### CPU reference · CPU 参考实现

- **定义：** 与 CUDA kernel 独立、在 CPU 上计算预期结果的实现，用于逐元素正确性比较。
- **避免使用：** GPU runtime evidence、性能基线（除非另有测量合同）。
- **相关单元：** F01、LAB02。
- **版本说明：** EX02 的 host-only test 不运行 GPU，也不授予 Runtime-Verified。

<span id="term-034" class="resource-target" aria-hidden="true"></span>

### tolerance · 容差

- **定义：** 浮点比较的预先声明接受规则；EX02 在绝对 `1e-5` 或相对 `1e-5` 任一标准满足时接受元素。
- **避免使用：** 要求两个标准同时满足、看到小数就视为正确。
- **相关单元：** F01、LAB02。
- **版本说明：** 容差值属于 EX02 correctness contract，改变时需要新证据范围。

<span id="term-035" class="resource-target" aria-hidden="true"></span>

### RAII · 资源获取即初始化

- **定义：** 把资源所有权绑定到 C++ 对象生命周期的管理方法，在初始化时获取资源，并由 owner 的析构函数负责释放。O04 把裸指针用作非拥有型视图，这是一项指导，不是 C++ 语言规则。
- **避免使用：** 垃圾回收、把每个裸指针都当作所有者。
- **相关单元：** O04。
- **版本说明：** O04 采用 C++17 基线；接口仍可明确记录所有权转移。

<span id="term-036" class="resource-target" aria-hidden="true"></span>

### undefined behavior · 未定义行为

- **定义：** C++ 规范不要求产生任何特定行为的操作。
- **避免使用：** 必然崩溃、未指定行为、实现定义行为。
- **相关单元：** O04。
- **版本说明：** O04 采用 C++17 语言基线；compiler diagnostic 和 sanitizer 结果不会重新定义未定义行为，也不能证明它不存在。

<span id="term-037" class="resource-target" aria-hidden="true"></span>

### translation unit · 翻译单元

- **定义：** 一个源文件经过预处理并展开 include 与 macro 后形成、由编译器作为一个单元翻译的源码材料。
- **避免使用：** 未预处理的源文件、整个程序、已链接的可执行文件。
- **相关单元：** O04。
- **版本说明：** O04 以 C++17 和 NVCC 13.3 说明边界；Toolkit 内部步骤可以变化，但 translation unit 位于预处理之后。

<span id="term-038" class="resource-target" aria-hidden="true"></span>

### reproducible command record · 可复现命令记录

- **定义：** 对一个命令阶段的可复核记录，包含字面命令与参数边界、工作目录与允许列表环境等执行上下文、独立 stdout 和 stderr、退出状态、采集日期与 UTC 起止时间，以及保留输入和产物的哈希。
- **避免使用：** 改写后的命令、只有截图的日志、没有退出状态的合并输出。
- **相关单元：** O05。
- **版本说明：** 工具与操作系统版本属于执行上下文；命令、上下文或被哈希字节改变后，就是另一份记录。

<span id="term-039" class="resource-target" aria-hidden="true"></span>

### latency · 延迟

- **定义：** 一个指定事件从已声明起点到已声明终点经过的时间，必须同时报告单位。它衡量单个事件，不是单位时间内完成的工作量。
- **避免使用：** 吞吐量、速率、没有事件和边界的计时值。
- **相关单元：** O06。
- **版本说明：** 比较 latency 时必须对齐事件、同步边界、timer 及其版本、workload 和单位。

<span id="term-040" class="resource-target" aria-hidden="true"></span>

### throughput · 吞吐量

- **定义：** 在已声明时间窗口内完成的指定工作量，以 items/s、operations/s 等单位表示。它是速率，不是一个事件的经过时间。
- **避免使用：** 单次操作的 latency、没有工作量和时间窗口的速率、未说明条件的 peak 值。
- **相关资源：** O06、O07、[Q09](/correctness/occupancy-stalls-throughput/)、[Q10](/correctness/roofline-arithmetic-intensity/)和 [LAB09](/labs/build-original-roofline/)。
- **版本说明：** CUDA 13.3 与 Nsight Compute 2026.2.1；并发或批处理可以在单项 latency 不变时提高 throughput，比较时必须对齐 work/traffic、时间窗口、单位、scope 与 exact ceiling。

<span id="term-041" class="resource-target" aria-hidden="true"></span>

### bandwidth · 带宽

- **定义：** 沿一条已命名路径和方向的数据传输速率，必须声明 byte 计数口径、时间区间以及 GB/s 或 GiB/s 等单位。
- **避免使用：** 没有路径的 throughput 声明、省略单位、混用 GB/s 与 GiB/s。
- **相关单元：** O06。
- **版本说明：** 只有路径、方向、时间和单位口径一致时，theoretical、effective 与 actual bandwidth 才能比较。

<span id="term-042" class="resource-target" aria-hidden="true"></span>

### concurrency · 并发

- **定义：** 两个或更多指定操作在已声明作用域内的时间区间发生重叠；它本身不表示这些操作在同一时刻由不同硬件单元执行。
- **避免使用：** 把 stream 数量、异步提交、residency 或 occupancy 当作已观察 overlap 的证明。
- **相关单元：** O06。
- **版本说明：** 源码与 API 最多说明 overlap 可能发生；声称实际并发需要精确执行下的 timeline 或等价观察，并注明 kernel、copy/compute 或 CPU/GPU 等作用域。

<span id="term-043" class="resource-target" aria-hidden="true"></span>

### arithmetic intensity · 算术强度

- **定义：** 对一个指定 workload，把已声明的算术工作计数除以穿过已声明内存边界的数据流量，单位为 operations/byte。
- **避免使用：** 只有 operation count、FLOP/s、没有流量边界的比值。
- **相关资源：** O06、[A14](/algorithms/algorithm-choice-arithmetic-intensity/)、[Q10](/correctness/roofline-arithmetic-intensity/)、[LAB09](/labs/build-original-roofline/)和 [VIS13](/visuals/roofline/)。
- **版本说明：** CUDA 13.3、Nsight Compute 2026.2.1 与 original Roofline model；operation 计数规则、read/write 流量、memory path、workload scope 或 provenance 改变时，intensity 也会改变。

<span id="term-044" class="resource-target" aria-hidden="true"></span>

### occupancy · 占用率

- **定义：** 通常指每个 SM 的 active warp 数与硬件允许的最大 active warp 数之比，不是 GPU utilization，也不保证性能。
- **避免使用：** GPU utilization、并发执行证明、性能分数或性能保证。
- **相关资源：** O06、[Q09](/correctness/occupancy-stalls-throughput/)和 [LAB09](/labs/build-original-roofline/)。
- **版本说明：** CUDA 13.3 与 Nsight Compute 2026.2.1；active-warps numerator 与 exact-device maximum-warps denominator 必须同 scope。架构、block size、register 和 shared memory 共同限制 occupancy；更高 occupancy 不保证更高 throughput 或更短 runtime。

<span id="term-045" class="resource-target" aria-hidden="true"></span>

### programmable shader stage · 可编程着色器阶段

- **定义：** 图形流水线中允许应用提供指令的指定阶段，其调用、输入、输出、资源限制和周围阶段仍遵循图形语义。
- **避免使用：** 通用 kernel、不受限制的处理器接口、CUDA kernel。
- **相关单元：** O07。
- **版本说明：** 可用阶段、profile 和能力随图形 API 与时期变化；这个术语始终受图形流水线边界约束。

<span id="term-046" class="resource-target" aria-hidden="true"></span>

### GPGPU · 通用 GPU 计算

- **定义：** 使用 GPU 完成非图形计算的广义实践，历史上常把数据与工作映射到 texture、shader stage 和 render target，后来也使用通用计算接口。它是一个历史类别，不是 CUDA 的同义词。
- **避免使用：** CUDA 的同义词、可编程着色器阶段、所有 GPU 工作的统称。
- **相关单元：** O07。
- **版本说明：** GPGPU 跨越多个时期、API 和硬件；CUDA 是其中一种通用计算平台与模型，两者并不等价。

<span id="term-047" class="resource-target" aria-hidden="true"></span>

### compatibility assessment · 兼容性评估

- **定义：** 把精确环境坐标与选定的当前 owner documentation 进行带来源日期的比较，只能得到 `documented-path`、`not-documented` 或 `indeterminate` 三种初筛结果之一，任何结果都不授予编译或运行证据。
- **避免使用：** “受支持”结论、Evidence Status、runtime validation 或 Reference Environment 声明。
- **相关单元：** O08。
- **版本说明：** 结果只适用于已记录坐标、来源和日期，三种结果都不授予编译或运行证据；`documented-path` 只允许继续验证。

<span id="term-048" class="resource-target" aria-hidden="true"></span>

### Reference Environment candidate · 基准环境候选配置

- **定义：** 正在按 manifest、tier、compatibility、maintainer control 和独立 baseline 门槛接受审查的一套精确原生 Linux GPU 与软件配置。候选身份不构成 Reference Environment 声明。
- **避免使用：** 已声明的 Reference Environment、推荐配置、已验证机器。
- **相关单元：** O08、LAB01。
- **版本说明：** 候选身份不是声明；只有全部门槛满足后的独立维护者声明，才能建立 Reference Environment。

<span id="term-049" class="resource-target" aria-hidden="true"></span>

### streaming multiprocessor (SM) · 流式多处理器

- **定义：** CUDA GPU 中接收 thread block 并调度其 warp 的硬件执行资源；一个 SM 可驻留的 block 和 warp 数受寄存器、shared memory 等架构资源限制。
- **避免使用：** 整张 GPU、CUDA core、thread block。
- **相关资源：** [F02](/foundations/execution-hierarchy/)、[VIS01](/visuals/kernel-journey/)。
- **版本说明：** 执行层次与调度表述按 CUDA Programming Guide v13.3；SM 数量和每 SM 限制属于架构特定信息，不能从 launch geometry 推断。

<span id="term-050" class="resource-target" aria-hidden="true"></span>

### warp · 线程束

- **定义：** 同一 thread block 中按局部线性编号连续分组、由 SM 在 SIMT 模型下调度的 32 个 thread；每个 thread 占据一个 lane。
- **避免使用：** thread block、CPU SIMD vector、完成顺序保证。
- **相关资源：** [F02](/foundations/execution-hierarchy/)、[VIS01](/visuals/kernel-journey/)、[VIS02](/visuals/indexing/)。
- **版本说明：** 32-thread 分组与执行模型按 CUDA Programming Guide v13.3；具体调度时序仍不能由 warp 编号推断。

<span id="term-051" class="resource-target" aria-hidden="true"></span>

### lane · 通道

- **定义：** 一个 block thread 在所属 warp 中的 `0..31` 位置；对 block 内局部线性编号 `t`，lane 为 `t % 32`，它不表示数据索引或执行先后。
- **避免使用：** CUDA core、global data index、`threadIdx.x` 的同义词。
- **相关资源：** [F02](/foundations/execution-hierarchy/)、[VIS02](/visuals/indexing/)。
- **版本说明：** 位置与取模规则按 CUDA Programming Guide v13.3 的 32-thread warp 模型。

<span id="term-052" class="resource-target" aria-hidden="true"></span>

### dim3 · 三分量 launch 配置类型

- **定义：** 用 `x`、`y`、`z` 三个分量表示 grid 或 thread block 尺寸的 CUDA C++ 类型；构造时未显式给出的分量默认为 `1`。
- **避免使用：** 逻辑范围、数据布局、完整 kernel launch。
- **相关资源：** [F03](/foundations/multidimensional-indexing/)、[EX03](/examples/multidimensional-indexing/)。
- **版本说明：** 类型与默认分量按 CUDA Programming Guide v13.3 和 CUDA Runtime API 13.3.1；EX03 选择 CUDA 11.8.0、12.9.2 和 13.3.1 Toolkit Lane，选择本身不是 Compile-Checked。

<span id="term-053" class="resource-target" aria-hidden="true"></span>

### logical extent · 逻辑范围

- **定义：** 应用为问题或数据在每个有效轴上声明的合法坐标范围；thread 必须在访问前逐轴检查它，而 launch thread 数可以更大。
- **避免使用：** `gridDim`、allocation byte count、launch geometry。
- **相关资源：** [F03](/foundations/multidimensional-indexing/)、[VIS02](/visuals/indexing/)、[EX03](/examples/multidimensional-indexing/)。
- **版本说明：** 坐标与 launch 模型按 CUDA Programming Guide v13.3；EX03 在所选 CUDA 11.8.0、12.9.2 和 13.3.1 Toolkit Lane 中共享同一 extent 合同。

<span id="term-054" class="resource-target" aria-hidden="true"></span>

### row-major layout · 行主序布局

- **定义：** 由应用声明、把一行中的连续列映射到连续线性位置的数据布局；F03 和 EX03 使用 x-fastest 公式 `((z * height) + y) * width + x`。CUDA launch geometry 只产生坐标，不声明该布局。
- **避免使用：** CUDA 默认布局、grid/block shape、column-major layout 的同义词。
- **相关资源：** [F03](/foundations/multidimensional-indexing/)、[VIS02](/visuals/indexing/)、[EX03](/examples/multidimensional-indexing/)。
- **版本说明：** CUDA 坐标模型按 CUDA Programming Guide v13.3；布局公式是跨 EX03 所选 CUDA 11.8.0、12.9.2 和 13.3.1 Toolkit Lane 保持不变的应用合同。

<span id="term-055" class="resource-target" aria-hidden="true"></span>

### resource lifecycle · 资源生命周期

- **定义：** 按所有权和最后使用边界组织资源的取得、初始化、使用、同步或传输以及释放；显式 CUDA 程序必须分别跟踪 host storage 与 device allocation。
- **避免使用：** 仅指 kernel 执行、RAII 的同义词、没有所有权与释放责任的 API 清单。
- **相关资源：** [F04](/foundations/host-device-lifecycle/)、[O04](/start/cpp17-for-cuda/)、[EX03](/examples/multidimensional-indexing/)。
- **版本说明：** F04 的 CUDA 调用边界按 CUDA Runtime API 13.3.1；EX03 在所选 CUDA 11.8.0、12.9.2 和 13.3.1 Toolkit Lane 中声明同一显式生命周期，Lane 选择不授予编译或运行证据。

<span id="term-056" class="resource-target" aria-hidden="true"></span>

### asynchronous error · 异步错误

- **定义：** 由此前提交的 device work 产生、因为 submission 可在执行完成前返回，所以可能直到后续 API observation 或 completion boundary 才对 host 可见的失败。
- **避免使用：** 声称所有 CUDA error 都是 asynchronous，或报告失败的 API call 必然就是原因。
- **相关资源：** [F05](/foundations/asynchronous-errors/)、[F07](/foundations/runtime-driver-api/)、[EX04](/examples/error-handling-lifecycle/)、[LAB03](/labs/break-and-repair-indexing/)。
- **版本说明：** Error 与 synchronization boundary 按 Runtime API 11.8.0、页面标为 12.9.1 的 12.9.2 archive 和 13.3.1 复核；精确 reporting status 可能不同。

<span id="term-057" class="resource-target" aria-hidden="true"></span>

### last-error state · 末次错误状态

- **定义：** 与 host thread 关联、记录最后一项 Runtime error 的 Runtime-library state；`cudaPeekAtLastError` 读取但不 reset，`cudaGetLastError` 读取后 reset 为 `cudaSuccess`。
- **避免使用：** 每个 kernel 一条 error queue、direct return value、completion check。
- **相关资源：** [F05](/foundations/asynchronous-errors/)、[EX04](/examples/error-handling-lifecycle/)、[LAB03](/labs/break-and-repair-indexing/)。
- **版本说明：** Getter-reset、peek-non-reset 与 previous-asynchronous-launch caveat 在 selected 11.8.0、12.9.2 archive/页面标签 12.9.1 和 13.3.1 Runtime 文档中一致。

<span id="term-058" class="resource-target" aria-hidden="true"></span>

### CUDA Runtime API · CUDA 运行时 API

- **定义：** NVIDIA 较高层的 `cuda*` host API 与 CUDA C++ launch surface；通常隐式管理 primary-context initialization 和 module，但 allocation、argument、status check、completion、correctness 与 release 责任仍属于 application。
- **避免使用：** 无需所有权的 CUDA、独立 GPU execution system、Driver API 的一对一别名。
- **相关资源：** [F04](/foundations/host-device-lifecycle/)、[F05](/foundations/asynchronous-errors/)、[F07](/foundations/runtime-driver-api/)、[EX04](/examples/error-handling-lifecycle/)、[LAB03](/labs/break-and-repair-indexing/)。
- **版本说明：** Implicit state 与 interoperability 细节必须按 selected 11.8.0、12.9.2 archive/页面标签 12.9.1 或 13.3.1 坐标读取；不能把新版 execution-context interface 向旧 Lane 倒推。

<span id="term-059" class="resource-target" aria-hidden="true"></span>

### CUDA Driver API · CUDA 驱动 API

- **定义：** NVIDIA 较低层的 `cu*` host API，把显式 initialization 与 device、context、module、function、memory、launch、synchronization handle 或 operation 暴露给 application control。
- **避免使用：** 不同的 device stack、自动更快的 Runtime replacement、能消除 asynchronous error 的 API。
- **相关单元：** [F07](/foundations/runtime-driver-api/)。
- **版本说明：** Handle ownership、current-context rule、interoperability 与 teardown 按 Driver API 11.8.0、页面标为 12.9.1 的 12.9.2 archive 和 13.3.1 分版本复核。

<span id="term-060" class="resource-target" aria-hidden="true"></span>

### virtual architecture target · 虚拟架构目标

- **定义：** NVCC 的 `compute_XY`、`compute_XYa` 或 `compute_XYf` target，用来选择 device source 在 preprocessing 和编译成 PTX 时采用的 GPU feature assumptions。
- **避免使用：** Installed GPU、real architecture target、Toolkit version、runtime compatibility verdict。
- **相关单元：** [F06](/foundations/compute-capability/)。
- **版本说明：** Accepted name 与 suffix 取决于精确 compiler；F06 复核 NVCC 11.8.0、12.9.2 archive 与 Toolkit 13.3.1 下 current NVCC page 的 selected rows。

<span id="term-061" class="resource-target" aria-hidden="true"></span>

### real architecture target · 实际架构目标

- **定义：** NVCC 的 `sm_XY`、`sm_XYa` 或 `sm_XYf` code target，指定 assembled binary code 面向的 GPU architecture；它必须实现 paired virtual target 的全部 feature assumptions。
- **避免使用：** Installed GPU 的证明、product model、virtual target、performance prediction。
- **相关单元：** [F06](/foundations/compute-capability/)。
- **版本说明：** Compiler acceptance 按版本变化；accepted pair 仍只是一项 compile-plan fact，直到合格 build 记录实际 artifact。

<span id="term-062" class="resource-target" aria-hidden="true"></span>

### architecture-specific feature set · 架构特定功能集

- **定义：** 针对一个 exact compute capability、且不保证在后续 architecture 上可用的完整 specialized feature set；`a` target 启用该集合，并把 code 限定到该 exact capability。
- **避免使用：** Baseline feature set、family-wide compatibility、“更新 GPU 自动支持”。
- **相关单元：** [F06](/foundations/compute-capability/)。
- **版本说明：** 当前 CUDA Programming Guide v13.3 从 compute capability 9.0 开始定义 architecture-specific feature set；精确 target 仍须 selected NVCC 支持。

<span id="term-063" class="resource-target" aria-hidden="true"></span>

### family-specific feature set · 系列特定功能集

- **定义：** 一个 compute-architecture family 中明列成员共享的 architecture-specific feature 子集；`f` target 启用该子集，并把 code 限定到这些 family members。
- **避免使用：** Baseline set、exact-architecture `a` set、与所有数值更大 capability 兼容。
- **相关单元：** [F06](/foundations/compute-capability/)。
- **版本说明：** 当前 CUDA Programming Guide v13.3 从 compute capability 10.0 开始定义 family-specific set；family membership 与 accepted compiler target 需要当前 owner table。

<span id="term-064" class="resource-target" aria-hidden="true"></span>

### launch geometry · 启动几何

- **定义：** 一次 kernel launch 提供的 grid 与 thread-block dimensions，决定创建的 block、每 block thread、coordinate coverage 与 fringe thread，同时与 application logical extent 和 data layout 分开。
- **避免使用：** Logical extent、仅指 block shape、launch legality 的证明、performance configuration。
- **相关资源：** [F02](/foundations/execution-hierarchy/)、[F03](/foundations/multidimensional-indexing/)、[F08](/foundations/launch-geometry/)、[LAB03](/labs/break-and-repair-indexing/)。
- **版本说明：** F08 按 CUDA Programming Guide v13.3 与 Runtime API 13.3.1 device/function limits 复核；实际 launch 必须使用 selected environment 与 kernel 的 properties。

<span id="term-065" class="resource-target" aria-hidden="true"></span>

### block shape · 线程块形状

- **定义：** 为 launch 选择的一维、二维或三维 `blockDim` tuple；每个 axis 及其 checked product 必须通过 device limits，product 与 resource use 还必须通过 specific kernel limits。
- **避免使用：** 仅指 threads-per-block scalar、logical data tile、occupancy target、fastest configuration。
- **相关资源：** [F08](/foundations/launch-geometry/)、[LAB03](/labs/break-and-repair-indexing/)。
- **版本说明：** 相同 thread count 可以有不同 coverage/fringe，device/function limits 也会随 environment、target 与 kernel 改变；只有 controlled measurement 才能比较速度。

<span id="term-066" class="resource-target" aria-hidden="true"></span>

### address space · 地址空间

- **定义：** 程序可见的 storage 与 naming domain，用来约束哪些 execution agent 可以寻址某个对象、它们是否共享同一 instance，以及该 instance 在多长时间内有效；它本身不等于 cache、physical chip 或 access time。
- **避免使用：** Cache level、physical-memory tier、speed class。
- **相关资源：** [M01](/memory/address-spaces/)、[VIS06](/visuals/memory-hierarchy-lifetime/)。
- **版本说明：** M01 以 current Programming Guide v13.3，以及 selected Toolkit Lane 的 11.8.0 与 12.9.1 owner documentation 复核。

<span id="term-067" class="resource-target" aria-hidden="true"></span>

### global memory · 全局内存

- **定义：** 一种 device address space；持有合法 device pointer 的 kernel thread 可以寻址其中对象，而对象可以跨越单个 block 或 kernel launch。显式 Runtime allocation 在全部 device user 完成后，由 host 控制流取得和释放。
- **避免使用：** Device DRAM 的精确同义词、全部 device memory、一定不经过 cache 的 memory。
- **相关资源：** [M01](/memory/address-spaces/)、[M02](/memory/coalescing-transactions/)、[VIS04](/visuals/memory-transactions/)、[EX05](/examples/coalesced-strided-access/)。
- **版本说明：** Ownership、accessibility 与 access-shaping semantic 按 selected 11.8.0、12.9.1 和 current v13.3/v13.3.1 坐标复核；cache path 仍取决于 architecture 与 instruction。

<span id="term-068" class="resource-target" aria-hidden="true"></span>

### constant memory · 常量内存

- **定义：** 通过 `__constant__` 声明、随 module/context 存续的 device storage；对 kernel 只读，在一个 device 的 grid 中可见，并由 host symbol operation 初始化或更新。这个 symbol 不是用 `cudaFree` 释放的 allocation。
- **避免使用：** Constant cache、整个 application 都不可修改、普通 global allocation。
- **相关资源：** [M01](/memory/address-spaces/)、[VIS06](/visuals/memory-hierarchy-lifetime/)。
- **版本说明：** Declaration、symbol copy、accessibility 与 lifetime 由 current Programming Guide v13.3、Runtime API v13.3.1 及 selected 11.8.0/12.9.1 owner docs 共同复核。

<span id="term-069" class="resource-target" aria-hidden="true"></span>

### shared memory · 共享内存

- **定义：** 每个 thread block 各自实例化的 programmer-managed on-device storage，由该 block 的 thread 共享，并在 block execution 结束时自动退役。Static declaration 与 dynamic launch allocation 决定 capacity；两者都不会建立由 host free 的 global allocation。
- **避免使用：** L1 cache alias、跨 block shared object、自动 coherent global cache。
- **相关资源：** [M01](/memory/address-spaces/)、[M03](/memory/shared-memory-tiling/)、[M04](/memory/bank-conflicts-layouts/)、[VIS05](/visuals/shared-memory-banks/)、[EX06](/examples/shared-memory-tile-bank-padding/)。
- **版本说明：** M01/M03/M04 使用 selected 11.8.0、12.9.1 与 current v13.3 owner documentation；capacity 和 shared/L1 configuration 必须按 selected architecture 查询。

<span id="term-070" class="resource-target" aria-hidden="true"></span>

### local memory · 本地内存

- **定义：** 用于 compiler-managed automatic object 与 spill 的 thread-private CUDA address space。它在逻辑上只属于一个 thread，但 backing storage 物理位于 device memory，也可能使用 cache。
- **避免使用：** On-chip local storage、host stack memory、block-private shared memory。
- **相关资源：** [M01](/memory/address-spaces/)、[VIS06](/visuals/memory-hierarchy-lifetime/)。
- **版本说明：** Local placement 与 cache behavior 取决于 selected compiler、target、architecture 和 access pattern；M01 在 11.8.0、12.9.1 与 current v13.3 交叉核对 semantic boundary。

<span id="term-071" class="resource-target" aria-hidden="true"></span>

### register · 寄存器

- **定义：** Compiler 为一次 thread invocation 的 value 分配的有限 per-thread hardware resource。Source spelling 不保证 register placement；resource pressure 可以把 value 移到 thread-private local memory，而不改变 owner。
- **避免使用：** 一定留在 register 的 source variable、cache entry、跨 thread storage。
- **相关资源：** [M01](/memory/address-spaces/)、[VIS06](/visuals/memory-hierarchy-lifetime/)。
- **版本说明：** Register limit、allocation 与 spill 随 compute capability、compiler、target 和 kernel 变化，需要 selected environment 与 compilation artifact 才能判断。

<span id="term-072" class="resource-target" aria-hidden="true"></span>

### memory transaction · 内存事务

- **定义：** Hardware memory system 在特定 architecture 与 instruction boundary 上为 requested byte 提供服务的一次 transfer。M02 预测一个 active warp 的 global request 需要覆盖哪些 aligned 32-byte segment；静态 set 不是 observed transaction log。
- **避免使用：** Source-level load、requested word、改称 measured traffic 的 segment count。
- **相关资源：** [M02](/memory/coalescing-transactions/)、[VIS04](/visuals/memory-transactions/)、[EX05](/examples/coalesced-strided-access/)。
- **版本说明：** M02 模型适用于 CC 6.0+ 与本站 CC 7.5+ tier；access size、cache state 和 architecture 仍限制 actual issued transaction。

<span id="term-073" class="resource-target" aria-hidden="true"></span>

### coalescing · 合并访问

- **定义：** Memory system 根据 requested address、access size 与 selected compute-capability rule，把 active warp lane 的 global-memory request 组合成 transaction。Contiguous indexing 可以支持 coalescing，但本身不证明 transaction count 或速度。
- **避免使用：** 只有 contiguous source order、cache hit、automatic speedup。
- **相关资源：** [M02](/memory/coalescing-transactions/)、[VIS04](/visuals/memory-transactions/)、[EX05](/examples/coalesced-strided-access/)。
- **版本说明：** Coalescing rule 会随 architecture generation 改变；M02 明确采用 CC 6.0+ 的 naturally aligned 32-byte segment fixture，并用 current 与 selected archive owner guide 复核。

<span id="term-074" class="resource-target" aria-hidden="true"></span>

### shared-memory bank · 共享内存存储体

- **定义：** Shared memory 中可独立服务的一项 partition，由 architecture-specific mapping 从 word address 选择。M04 fixture 中，连续 32-bit word 依次映射到 32 个 bank。
- **避免使用：** Warp lane、cache line、每 thread 独占一个 bank。
- **相关资源：** [M04](/memory/bank-conflicts-layouts/)、[VIS05](/visuals/shared-memory-banks/)、[EX06](/examples/shared-memory-tile-bank-padding/)。
- **版本说明：** M04 使用 selected CC 7.5+ 的 32-bank、32-bit word fixture；扩展到另一 architecture 或 access size 前必须重新核对 bank width 与 mapping。

<span id="term-075" class="resource-target" aria-hidden="true"></span>

### bank conflict · 存储体冲突

- **定义：** 在 selected shared-memory model 中，一条 warp instruction 请求同一 bank 内多个 distinct word，因而这些 distinct-word access 需要分开服务。同地址读取广播单独分类，不属于 conflict。
- **避免使用：** 任何重复 bank number、data race、global-memory coalescing failure。
- **相关资源：** [M04](/memory/bank-conflicts-layouts/)、[VIS05](/visuals/shared-memory-banks/)、[EX06](/examples/shared-memory-tile-bank-padding/)。
- **版本说明：** Conflict degree 只有在声明 bank mapping、word size、active-lane set 与 read/write pattern 后才有意义，且不是 speedup ratio。

<span id="term-076" class="resource-target" aria-hidden="true"></span>

### tiling · 分块

- **定义：** 把问题划分成 bounded working subset，让 thread cooperative 地 stage、在前后 synchronization 并 reuse。M03 的 shared-memory 形式分开 load、first barrier、use/reuse，以及 shared storage 被覆盖前的 second barrier。
- **避免使用：** Automatic caching、没有 bounds 的 copy、guaranteed optimization。
- **相关资源：** [M03](/memory/shared-memory-tiling/)、[M04](/memory/bank-conflicts-layouts/)、[EX06](/examples/shared-memory-tile-bank-padding/)。
- **版本说明：** M03 为 selected Lane 教授 portable C++17 synchronous baseline；未来 asynchronous tiling interface 按版本隔离，不向旧 Lane 倒推。

<span id="term-077" class="resource-target" aria-hidden="true"></span>

### synchronization scope · 同步作用域

- **定义：** 一项 synchronization 或 atomic operation 的 documented guarantee 所覆盖的 execution-agent 范围；scope 必须包含所有 producer 与 consumer，但本身不等于 rendezvous、ordering、visibility 或 atomicity 的完整协议。
- **避免使用：** 同步强度等级、万能 barrier、越宽越正确。
- **相关资源：** [M05：同步作用域与内存可见性](/memory/synchronization-scopes/)。
- **版本说明：** M05 按 CUDA Programming Guide v13.3 以及 11.8.0/12.9.1 archive 复核 durable scope boundary；具体 primitive、memory order 与支持的 scope 仍须按 selected Toolkit 和 architecture 核对。

<span id="term-078" class="resource-target" aria-hidden="true"></span>

### memory visibility · 内存可见性

- **定义：** Intended consumer 在遵守有效 ordering 与 synchronization protocol 后，可以观察 producer 对指定 memory location 所做写入的性质；它不由 source proximity 或单独 fence 自动建立。
- **避免使用：** Flush every cache、rendezvous、ordinary-load eventual consistency。
- **相关资源：** [M05：同步作用域与内存可见性](/memory/synchronization-scopes/)。
- **版本说明：** Visibility 必须绑定 CUDA Programming Guide v13.3 memory-model relation、覆盖双方的 scope 和双方可访问的 storage；cache implementation 与 architecture 不能替代 protocol proof。

<span id="term-079" class="resource-target" aria-hidden="true"></span>

### active mask · 活动掩码

- **定义：** 在某个执行点当前 active 的 warp lane 集合；它描述该时刻的 control-flow participation，不自动等于算法期望的 collective participant set。
- **避免使用：** 永久 warp membership、intended participation mask、hardware schedule trace。
- **相关资源：** [F02](/foundations/execution-hierarchy/)、[M06：分支发散、重汇合与线程束安全推理](/memory/warp-divergence-reconvergence/)和 [VIS03](/visuals/warp-divergence/)。
- **版本说明：** CUDA Programming Guide v13.3 在 CC 7.0+ 使用 Independent Thread Scheduling；不能把 branch-local `__activemask()` 倒推成跨 divergence 的稳定 group，旧 architecture 的执行模型也必须按 archive 单独复核。

<span id="term-080" class="resource-target" aria-hidden="true"></span>

### divergence · 分支发散

- **定义：** 同一 warp 的 participating lanes 因 predicate 不同而沿不同 control-flow path 前进；它说明 active-lane partition，不规定 path issue order、instruction interleaving 或 elapsed time。
- **避免使用：** 固定 serial order、data race、warp 已永久拆分。
- **相关资源：** [M06](/memory/warp-divergence-reconvergence/)和 [VIS03](/visuals/warp-divergence/)。
- **版本说明：** M06/VIS03 以 Programming Guide v13.3 及 11.8.0/12.9.1 SIMT archive 为边界；CC 7.0+ 的 per-thread state 改变可依赖的 lockstep assumption，但不提供 exact schedule。

<span id="term-081" class="resource-target" aria-hidden="true"></span>

### reconvergence · 重汇合

- **定义：** Divergent lanes 再次到达可共同继续的 control-flow region；本站区分 source-level logical join 与 hardware 实际采用的 reconvergence mechanism。
- **避免使用：** Warp barrier、memory fence、shared-memory visibility guarantee。
- **相关资源：** [M06](/memory/warp-divergence-reconvergence/)和 [VIS03](/visuals/warp-divergence/)。
- **版本说明：** VIS03 只显示 deterministic logical join；Programming Guide v13.3 与 archive 不授权从 closing brace 推断同步、固定 path order 或 architecture-specific reconvergence stack。

<span id="term-082" class="resource-target" aria-hidden="true"></span>

### warp-safe reasoning · 线程束安全推理

- **定义：** 对 warp-level communication 显式证明 intended participants、一致 mask、collective reachability、source-lane validity，以及需要的 ordering/visibility，而不依赖 implicit lockstep。
- **避免使用：** Same-warp therefore safe、closing-brace synchronization、mask-free collective reasoning。
- **相关资源：** [M05](/memory/synchronization-scopes/)、[M06](/memory/warp-divergence-reconvergence/)和 [VIS03](/visuals/warp-divergence/)。
- **版本说明：** Proof 必须按 selected intrinsic contract 与 architecture 复核；CC 7.0+ Independent Thread Scheduling 尤其禁止把历史 implicit-lockstep assumption 当作 portable guarantee。

<span id="term-083" class="resource-target" aria-hidden="true"></span>

### stream · 流

- **定义：** CUDA Runtime 中按 enqueue order 排列 operations 的 sequence；同一 stream 提供 documented order，不同 stream 若无 dependency edge 则不能从 host source order 推出全局 device order。
- **避免使用：** GPU thread、必然并发的 queue、整个 device 的 global timeline。
- **相关资源：** [F05](/foundations/asynchronous-errors/)、[M07：用流取代全局顺序心智模型](/memory/stream-ordering/)和 [VIS07](/visuals/stream-event-dependencies/)。
- **版本说明：** M07 使用 Programming Guide v13.3 与 Runtime API v13.3.1；default-stream relationship 会随 legacy/per-thread mode 与 stream flags 改变，11.8.0/12.9.1 行为必须按对应 owner docs 复核。

<span id="term-084" class="resource-target" aria-hidden="true"></span>

### event · 事件

- **定义：** CUDA Runtime object；一次 record 会捕获该调用时相应 stream 的 work state，后续 query、synchronize、stream wait 或 timing operation 按最近捕获状态和 creation flags 工作。
- **避免使用：** Host callback、自动全局 barrier、永不变化的 timestamp。
- **相关资源：** [M08：用事件表达依赖并测量设备时间](/memory/event-dependencies-timing/)和 [VIS07](/visuals/stream-event-dependencies/)。
- **版本说明：** Runtime API v13.3.1 以及 11.8.0/12.9.1 archive 规定 record、re-record、completion 与 flags；同一 handle 的 earlier wait 不会因 later re-record 被 retroactively retarget。

<span id="term-085" class="resource-target" aria-hidden="true"></span>

### event dependency · 事件依赖

- **定义：** Producer stream 的 event record 与 consumer stream 的 wait 组成的 explicit ordering edge，使 wait 后提交的 consumer work 等待调用时捕获的 event generation。
- **避免使用：** Host-blocking wait、observed concurrency、自动包含 producer 后续全部 work。
- **相关资源：** [M07](/memory/stream-ordering/)、[M08](/memory/event-dependencies-timing/)和 [VIS07](/visuals/stream-event-dependencies/)。
- **版本说明：** Record/wait contract 按 Runtime API v13.3.1 与 11.8.0/12.9.1 archive 复核；dependency 只建立 declared partial order，不证明 hardware overlap 或 timing。

<span id="term-086" class="resource-target" aria-hidden="true"></span>

### device-time measurement · 设备时间测量

- **定义：** 使用 timing-enabled recorded event endpoints 对 declared device-work interval 取得 elapsed time，并在 endpoint 完成和 API result 检查后报告的方法。
- **避免使用：** Browser animation interval、host wall-clock 的无条件同义词、symbolic subtraction 本身。
- **相关资源：** [O06](/start/architecture-refresher/)、[M08](/memory/event-dependencies-timing/)和 [VIS07](/visuals/stream-event-dependencies/)。
- **版本说明：** Runtime API v13.3.1 的 `cudaEventElapsedTime` 不接受 timing-disabled endpoint；可解释记录还需要 Environment Manifest、included-work boundary 与 measurement method，archive 版本必须单独核对。

<span id="term-087" class="resource-target" aria-hidden="true"></span>

### absolute tolerance · 绝对容差

- **定义：** 比较 finite floating-point values 前声明的固定幅度误差界；在接近零、relative term 单独使用过严时尤其重要。
- **避免使用：** Universal epsilon、看到 mismatch 后才选择的 threshold、exact discrete check 的替代品。
- **相关资源：** [Q01：CPU reference、容差与不变量](/correctness/cpu-references-tolerances-invariants/)。
- **版本说明：** Q01 把它与单独论证的 relative tolerance 组合；NVIDIA current/archive guidance 不提供适用于所有算法的单一 absolute threshold。

<span id="term-088" class="resource-target" aria-hidden="true"></span>

### relative tolerance · 相对容差

- **定义：** 按 declared reference magnitude 缩放、并在比较前声明的 floating-point error term；它与 absolute term 组合，使 acceptance 随 value scale 变化且不会在零附近失去定义。
- **避免使用：** 只按 candidate 计算的 percentage、post-hoc threshold、non-finite-value policy 的替代品。
- **相关资源：** [Q01](/correctness/cpu-references-tolerances-invariants/)。
- **版本说明：** Scale、precision、operation structure、error budget 与 domain rationale 都属于 comparison contract；不存在通用 relative threshold。

<span id="term-089" class="resource-target" aria-hidden="true"></span>

### invariant · 不变量

- **定义：** 由问题规范要求、与实现路径无关的 property，例如 conservation、bounds、normalization、sortedness 或 permutation preservation；它可以发现 CPU 与 GPU 实现共享的缺陷。
- **避免使用：** 从 candidate output 反推的 target、reference comparison 的替代品、任意 pass flag。
- **相关资源：** [Q01](/correctness/cpu-references-tolerances-invariants/)。
- **版本说明：** Invariant 只覆盖它实际检查的 property；必须与 reference comparison、exact checks 和所用 precision policy 分开记录。

<span id="term-090" class="resource-target" aria-hidden="true"></span>

### memcheck · 内存检查工具

- **定义：** Compute Sanitizer 的 runtime detector，用于报告其 documented coverage 内已执行路径上的 supported out-of-bounds/misaligned access、leak 与部分 CUDA API error；full leak checking 有独立 enablement 和 teardown boundary。
- **避免使用：** Static proof、all-path correctness proof、其他 sanitizer 的总称。
- **相关资源：** [Q03](/correctness/memcheck-invalid-memory-access/)、[EX16](/examples/sanitizer-defect-suite/)和 [LAB07](/labs/diagnose-four-sanitizer-failures/)。
- **版本说明：** Command、report 与 limitation 必须按 selected Lane 的 Compute Sanitizer version 复核；clean executed-path report 不是程序正确性证明。

<span id="term-091" class="resource-target" aria-hidden="true"></span>

### racecheck · 数据访问危害检查工具

- **定义：** Compute Sanitizer 中检测 shared memory data access hazard 的 tool，按 documented analysis 报告 WAW、WAR 或 RAW hazard，并要求 reviewer 结合 source protocol 判断严重性与修复。
- **避免使用：** 任意 global-memory race proof、memcheck replacement、全程序 synchronization proof。
- **相关资源：** [Q04](/correctness/racecheck-initcheck-synccheck/)、[EX16](/examples/sanitizer-defect-suite/)和 [LAB07](/labs/diagnose-four-sanitizer-failures/)。
- **版本说明：** Stable baseline 绑定 shared-memory hazard；report levels、analysis details 与 architecture/tool support 按 selected Compute Sanitizer version 复核。

<span id="term-092" class="resource-target" aria-hidden="true"></span>

### initcheck · 未初始化读取检查工具

- **定义：** Compute Sanitizer 中检测未初始化 device global memory read 的 stable-baseline tool；它与 memcheck 的 invalid access、racecheck 的 shared hazard 和 synccheck 的 primitive misuse 分工不同。
- **避免使用：** 通用 memory sanitizer、race detector、默认覆盖所有 address space。
- **相关资源：** [Q04](/correctness/racecheck-initcheck-synccheck/)、[EX16](/examples/sanitizer-defect-suite/)和 [LAB07](/labs/diagnose-four-sanitizer-failures/)。
- **版本说明：** Shared-memory initcheck extension 必须按 current supporting version 显式 gate，不能倒推到 CUDA 11.8；cross-Lane claim 保持 device-global baseline。

<span id="term-093" class="resource-target" aria-hidden="true"></span>

### synccheck · 同步原语检查工具

- **定义：** Compute Sanitizer 中报告 synchronization primitive misuse 的 runtime tool，包括其 documented coverage 内的 divergent block/warp barrier 与 invalid primitive argument 等类别。
- **避免使用：** Memory-order proof、所有 deadlock 的 detector、source-level join checker。
- **相关资源：** [Q04](/correctness/racecheck-initcheck-synccheck/)、[EX16](/examples/sanitizer-defect-suite/)和 [LAB07](/labs/diagnose-four-sanitizer-failures/)。
- **版本说明：** Report class 与 limitation 按 selected Compute Sanitizer version 复核；clean run 只描述对应 binary/input 的 executed path。

<span id="term-094" class="resource-target" aria-hidden="true"></span>

### warm-up · 预热

- **定义：** 在 measured repetitions 之前执行并完成、用于触发 first-use effects 或建立预声明 steady condition、但明确不进入 retained timing samples 的工作。
- **避免使用：** 被隐藏的首个 sample、固定的 universal iteration count、无需 completion 的 launch。
- **相关资源：** [Q05](/correctness/timing-asynchronous-gpu-work/)、[LAB04](/labs/observe-coalescing/)和 [LAB05](/labs/remove-shared-memory-bank-conflicts/)。
- **版本说明：** Lazy loading 与 tool/runtime first-use behavior 随版本和 environment 变化；warm-up work、count、completion boundary 与 exclusion 必须写入每份 measurement plan。

<span id="term-095" class="resource-target" aria-hidden="true"></span>

### measurement statistic · 测量统计量

- **定义：** 在采集前指定、把一组 retained raw samples 映射为 summary 的规则，例如 median，并与同样预声明的 spread 一起报告；它不替代 samples、method 或 Environment Manifest。
- **避免使用：** 只有一个值的 average、采集后挑选的最好结果、跨方法混合 summary。
- **相关资源：** [Q05](/correctness/timing-asynchronous-gpu-work/)、[LAB04](/labs/observe-coalescing/)和 [LAB05](/labs/remove-shared-memory-bank-conflicts/)。
- **版本说明：** Statistic 不由 CUDA API 自动选择；必须绑定 frozen workload、measurement method、sample-retention rule、raw samples 和 observation coordinates。

<span id="term-096" class="resource-target" aria-hidden="true"></span>

### page-locked host memory · 页锁定主机内存

- **定义：** 由 CUDA host-allocation API 创建或由 registration API 锁定的 host range；操作系统在 CUDA 使用期间不能把其 physical storage 换出或重定位。Allocation path 以 `cudaFreeHost` 释放；registration path 在 last asynchronous use 后先 `cudaHostUnregister`，再由 original allocator 释放。
- **避免使用：** 自动 device-resident memory、transfer 已经开始、transfer overlap proof、无限 host resource。
- **相关资源：** [M09：Pinned memory 与传输重叠](/memory/pinned-memory-transfer-overlap/)和 [EX07](/examples/streams-events-overlap/)。
- **版本说明：** Programming Guide v13.3、Runtime API v13.3.1 与 12.9.1/11.8.0 archive 都保留 allocation/registration 与 matching release 的区别；pinning 只建立 storage eligibility，不观察 overlap。

<span id="term-097" class="resource-target" aria-hidden="true"></span>

### transfer overlap · 传输重叠

- **定义：** 在一个具名 run 中，data-transfer execution interval 与另一项 transfer 或 compute interval 实际相交的 runtime observation。
- **避免使用：** Unordered operations、overlap eligibility、copy-engine capability、两条 stream、source graph 或 browser animation。
- **相关资源：** [M09](/memory/pinned-memory-transfer-overlap/)、[Q05](/correctness/timing-asynchronous-gpu-work/)和 [EX07](/examples/streams-events-overlap/)。
- **版本说明：** Page-locked ranges、asynchronous API、dependency graph 与 device capability 只能打开 eligibility gate；exact-run device timeline 与 Environment Manifest 才能支撑 observation，且不会自动证明 speedup。

<span id="term-098" class="resource-target" aria-hidden="true"></span>

### copy engine · 复制引擎

- **定义：** CUDA-capable device 上可能独立于 SM compute 执行 data movement 的 hardware resource；其可用数量与方向属于所选 device/path 的 capability。
- **避免使用：** 每次 `cudaMemcpy*` 都使用的固定 DMA lane、transfer overlap observation、stream 的同义词。
- **相关资源：** [M09](/memory/pinned-memory-transfer-overlap/)和 [EX07](/examples/streams-events-overlap/)。
- **版本说明：** Runtime device properties 可以报告 asynchronous-engine capability，但 API spelling 与 nonzero value 都不能证明某次 copy 使用了 engine 或与 kernel overlap；需要 exact-run observation。

<span id="term-099" class="resource-target" aria-hidden="true"></span>

### managed memory · 托管内存

- **定义：** 由 CUDA Unified Memory system 管理、在适用 system contract 下可由 CPU 与 GPU code address 的 allocation；它仍有 owner、finite lifetime、data dependencies、synchronization 和 matching release。
- **避免使用：** 单一 physical memory、零 data movement、CPU/GPU 可无同步并发读写、自动最快 memory。
- **相关资源：** [M10：Unified Memory 与 page migration](/memory/unified-memory-page-migration/)、[VIS08](/visuals/page-migration/)和 [EX08](/examples/unified-memory-migration/)。
- **版本说明：** Programming Guide v13.3、Runtime API v13.3.1 与 12.9.1/11.8.0 archive 定义多个 support/coherence paradigms；`cudaMallocManaged` 的 stable pointer 不承诺 stable physical locality。

<span id="term-100" class="resource-target" aria-hidden="true"></span>

### page migration · 页面迁移

- **定义：** 在支持该 behavior 的 system model 中，runtime 为改变一段 managed backing 的 processor locality 而执行的 conditional action；它可能包含 fault service、mapping/ownership update、coherence action 和 data movement。
- **避免使用：** 每次 managed access 的必经阶段、prefetch call、browser page transition、M02 memory transaction。
- **相关资源：** [M10](/memory/unified-memory-page-migration/)、[VIS08](/visuals/page-migration/)和 [EX08](/examples/unified-memory-migration/)。
- **版本说明：** Software-coherent fault-and-migrate、hardware-coherent/direct access 与 limited coarse movement 必须按 exact environment 分支；source order、advice 或 model 不构成 migration count、bytes 或 timing evidence。

<span id="term-101" class="resource-target" aria-hidden="true"></span>

### residency · 驻留位置

- **定义：** 某个 physical backing range 在一个声明时间点对哪个 processor/local memory 属于 local 的状态；它可与 stable virtual address 和多 processor accessibility 并存。
- **避免使用：** Accessibility、ownership、virtual address、永久 placement、由 page color 推断的 runtime fact。
- **相关资源：** [M10](/memory/unified-memory-page-migration/)、[VIS08](/visuals/page-migration/)和 [EX08](/examples/unified-memory-migration/)。
- **版本说明：** Residency claim 绑定 range、time、OS/kernel、driver、device/interconnect、capability model 与 observation method；prefetch/advice 只影响 request/hint，不保证永久 residency。

<span id="term-102" class="resource-target" aria-hidden="true"></span>

### stream-ordered allocation · 流顺序分配

- **定义：** 把 allocation 与 deallocation 表示为 CUDA stream operations 的 allocator contract；pointer 只能在 allocation operation 完成后、free operation 执行前按 documented order 访问。
- **避免使用：** Host call return 即 allocation complete、lexical pointer lifetime、implicit cross-stream ownership、device-wide free barrier。
- **相关资源：** [M11：Stream-ordered allocation 与 memory pool](/memory/stream-ordered-allocation-memory-pools/)。
- **版本说明：** Programming Guide v13.3、Runtime API v13.3.1 与 12.9.1/11.8.0 archive 都要求 cross-stream first-use 和 last-use edges；实际 path 还需 checked `cudaDevAttrMemoryPoolsSupported`。

<span id="term-103" class="resource-target" aria-hidden="true"></span>

### memory pool · 内存池

- **定义：** 为 stream-ordered allocations 提供 backing resources 与 policy attributes 的 allocator object；allocation 可使用 device current/default pool 或显式选择的 pool。
- **避免使用：** Logical allocation 本身、stale pointer cache、相同 address guarantee、固定 physical footprint。
- **相关资源：** [M11](/memory/stream-ordered-allocation-memory-pools/)。
- **版本说明：** Pool 可能在 logical free 后保留 backing resources，但不会延长 pointer lifetime；default/current/explicit selection、access、ownership、release threshold 与 trim contract 按 selected Runtime version 复核。

<span id="term-104" class="resource-target" aria-hidden="true"></span>

### reuse policy · 复用策略

- **定义：** Memory-pool attributes 对 allocator 可考虑哪些 ordered relationships 的权限设置，包括 follow-event dependencies、opportunistic reuse 与 internal dependencies。
- **避免使用：** Reuse observation、same-pointer promise、无额外 ordering、speedup guarantee。
- **相关资源：** [M11](/memory/stream-ordered-allocation-memory-pools/)。
- **版本说明：** Policy enablement 是 permission 而不是 outcome；opportunistic result 可随 progress 变化，internal dependencies 可添加 serialization，任何 address/footprint/performance claim 都需独立 observation。

<span id="term-105" class="resource-target" aria-hidden="true"></span>

### Cooperative Groups · 协作组

- **定义：** 以 explicit group handles 表示 collaborating CUDA threads，并让 synchronization、partition 与 collective operations 相对于具名 membership、scope 和 participants 解释的 programming model/API。
- **避免使用：** 自动 whole-grid cooperation、implicit warp lockstep、任意 group 可互换的 barrier library。
- **相关资源：** [M12：Cooperative Groups 与可组合同步](/memory/cooperative-groups/)。
- **版本说明：** CUDA 13.3 current baseline 包含 single-device cooperative grid path；12.9.1/11.8.0 archive 的 deprecated multi-device material 仅作历史边界，不投射为 current support。

<span id="term-106" class="resource-target" aria-hidden="true"></span>

### thread group · 协作线程组

- **定义：** 由一个具体 Cooperative Groups handle 命名、拥有明确 membership、synchronization scope 与 required participants 的协作线程集合；它可以由 launch geometry、partition 或 active set 构成。
- **避免使用：** 永久 warp synonym、source branch 中“看起来一起”的 threads、未具名 participant set。
- **相关资源：** [M12](/memory/cooperative-groups/)。
- **版本说明：** `thread_block`、tile、`coalesced_group` 与 gated `grid_group` 的 membership/lifetime 不同；dynamic active set 只绑定捕获它的 control-flow point。

<span id="term-107" class="resource-target" aria-hidden="true"></span>

### collective operation · 集合操作

- **定义：** 相对于一个 named thread group 执行、要求该 group 的 documented participants 到达同一 operation instance，并满足 group-wide argument agreement 的 operation；部分 API 明确允许 per-thread input 不同。
- **避免使用：** 单 thread call、same call-site text、implicit synchronization、所有参数必须逐 bit 相同的笼统规则。
- **相关资源：** [M12](/memory/cooperative-groups/)。
- **版本说明：** `sync`、reduce、scan、partition 等逐 API 复核 participants 与 argument exceptions；missing participant 或不合法 group-wide disagreement 可产生 deadlock、corruption 或 undefined behavior。

<span id="term-108" class="resource-target" aria-hidden="true"></span>

### asynchronous copy · 异步复制

- **定义：** 把 copy submission 与 completion 分离的 data-movement operation；在 M13 中特指有 documented completion mechanism 的 global-to-shared `cuda::memcpy_async` path。
- **避免使用：** Completion-free copy、automatic overlap、必定发出某个 hardware instruction、所有 `cudaMemcpyAsync` 的总称。
- **相关资源：** [M13：Asynchronous copy 与 staged pipeline](/memory/asynchronous-copy-pipelines/)。
- **版本说明：** Applicable API 需要 CC 7.0+；hardware-accelerated global-to-shared path 需要 CC 8.0+ 及 size/alignment/type constraints。Source 不能证明 emitted instruction 或 runtime overlap。

<span id="term-109" class="resource-target" aria-hidden="true"></span>

### pipeline · 流水线

- **定义：** 由有限 reusable stages 组成、通过 producer acquire/commit 与 consumer wait/release sequence 协调 logical batches 的 FIFO contract。
- **避免使用：** 自动 performance optimization、infinite queue、只包含 copy 的 timeline、overlap evidence。
- **相关资源：** [M13](/memory/asynchronous-copy-pipelines/)。
- **版本说明：** Unified/partitioned pipeline 的 stage count、producer/consumer sets、collective sequence、early exit 与 warp convergence 按 selected CUDA contract 声明；多 stage 只创建 overlap opportunity。

<span id="term-110" class="resource-target" aria-hidden="true"></span>

### pipeline stage · 流水线阶段

- **定义：** Pipeline 中映射一个 logical batch 的 reusable storage/sequence slot，依次经历 available、acquired/filled、committed/pending、ready、used 与 released states。
- **避免使用：** 一块永不失效的 shared buffer、copy 已提交就 ready、consumer 未完成即可 overwrite。
- **相关资源：** [M13](/memory/asynchronous-copy-pipelines/)。
- **版本说明：** Completion-before-use 与 all-declared-reads-before-release/reuse 是两条独立 edge；prologue、steady-state rotation 与 drain 都必须保持 batch-to-stage mapping。

<span id="term-111" class="resource-target" aria-hidden="true"></span>

### CUDA Graph · CUDA 图

- **定义：** 把 CUDA operations 表示为 nodes、把 documented dependencies 表示为 directed edges 的有向无环图（DAG），独立于后续 instantiation 与 execution。
- **避免使用：** Source-order list、scheduler trace、executable graph handle、automatic concurrency 或 performance result。
- **相关资源：** [M14：CUDA Graphs 与 repeated launch structure](/memory/cuda-graphs/)和 [EX09](/examples/graph-capture/)。
- **版本说明：** Programming Guide v13.3、Runtime API v13.3.1 与 12.9.1/11.8.0 archive 允许 explicit API 或 stream capture 构造；static DAG 只证明 intended dependency structure。

<span id="term-112" class="resource-target" aria-hidden="true"></span>

### graph node · 图节点

- **定义：** CUDA Graph 中表示一项 typed operation 的 object，例如 kernel、copy、memset、host function、event operation 或 child graph，并带 parameters、external resources 与 incoming/outgoing dependencies。
- **避免使用：** 任意 source statement、node number 所隐含的 order、自动拥有 pointee lifetime 的 operation。
- **相关资源：** [M14](/memory/cuda-graphs/)和 [EX09](/examples/graph-capture/)。
- **版本说明：** Node type 与 parameter/update restrictions 按 selected Runtime API 复核；只有 directed path 创建 dependency，编号、UI 位置和 source layout 都不会。

<span id="term-113" class="resource-target" aria-hidden="true"></span>

### stream capture · 流捕获

- **定义：** 用 origin stream 的 begin/end capture boundary 把 supported stream submissions 与 captured event dependencies 转成 CUDA Graph template 的 construction mechanism；capture 期间这些 operations 不按普通方式执行。
- **避免使用：** Graph execution mode、任意 API recorder、无需 origin/rejoin 的 multi-stream capture、error 自动恢复。
- **相关资源：** [M14](/memory/cuda-graphs/)和 [EX09](/examples/graph-capture/)。
- **版本说明：** Auxiliary streams 必须在 origin end 前 rejoin；prohibited query/synchronization/legacy interactions 可 invalidate capture，随后仍需在 origin end capture、检查 error/null graph 并放弃 instantiation。

<span id="term-114" class="resource-target" aria-hidden="true"></span>

### executable graph · 可执行图

- **定义：** 由 successful graph instantiation 产生、可通过 `cudaGraphLaunch` 重复异步提交的 `cudaGraphExec_t` snapshot。
- **避免使用：** Mutable graph template、一次 launch 的 completion、external-resource owner、replay speedup proof。
- **相关资源：** [M14](/memory/cuda-graphs/)和 [EX09](/examples/graph-capture/)。
- **版本说明：** External storage/handles 必须活到相关 launch 完成；updates 受 topology、node type、context 与 parameter restrictions 限制，不兼容 change 需要新 graph 与 re-instantiation。

<span id="term-115" class="resource-target" aria-hidden="true"></span>

### NVCC · NVIDIA CUDA 编译器驱动

- **定义：** NVCC（NVIDIA CUDA Compiler Driver）是协调 CUDA source 的 documented compilation phases、host/device translation paths、device artifacts 与 link boundaries 的 compiler driver；它把适用的非 CUDA preprocessing、compilation 和 linking work 交给 selected host compiler。
- **避免使用：** 只有 device compiler、host compiler 的同义词、`--dryrun` 内部命令清单、CUDA runtime 或 GPU execution engine。
- **相关资源：** [M15](/toolchain/nvcc-compilation-flow/)、[EX10](/examples/ptx-fatbinary-inspection/)和 [VIS09](/visuals/artifact-pipeline/)。
- **版本说明：** Current owner coordinate 是 Toolkit 13.3.1 下页面标签 v13.3 的 NVCC 文档；Toolkit 12.9.2 archive 页面标为 v12.9，Toolkit 11.8.0 archive 单独保留。Documented phase/output 可以形成版本化合同，内部 steps 不能。

<span id="term-116" class="resource-target" aria-hidden="true"></span>

### host compiler · 主机编译器

- **定义：** 主机编译器（host compiler）是 NVCC 为 selected platform 调用、用于处理 host preprocessing、synthesized host C++、host object 和适用 host-link work 的 C++ compiler；其 family、major version 与 dialect support 属于完整 toolchain coordinate。
- **避免使用：** NVCC 的别名、`PATH` 上任意 compiler、用 `--allow-unsupported-compiler` 伪造的 supported configuration、GPU code generator。
- **相关资源：** [O04](/start/cpp17-for-cuda/)、[M15](/toolchain/nvcc-compilation-flow/)、[M19](/toolchain/cpp-dialect-boundaries/)和 [EX10](/examples/ptx-fatbinary-inspection/)。
- **版本说明：** Supported family/range 与 dialect minimum 必须按 exact Toolkit Lane 和 OS 核对；current CUDA 13.3 C++23 path 对 GCC 的 minimum 是 14.0，而 GCC 13.3 historical probe 只保留其 exact `unsupported` 结论。

<span id="term-117" class="resource-target" aria-hidden="true"></span>

### compilation phase · 编译阶段

- **定义：** 编译阶段（compilation phase）是 caller 可通过 documented option 选择的 logical translation boundary，声明 NVCC 如何解释 input、请求何种 primary output，以及 pipeline 在何处停止。
- **避免使用：** Internal implementation step、temporary filename、private subcommand、successful build 或 execution 的同义词。
- **相关资源：** [M15](/toolchain/nvcc-compilation-flow/)、[EX10](/examples/ptx-fatbinary-inspection/)和 [VIS09](/visuals/artifact-pipeline/)。
- **版本说明：** Input suffix 与 phase option 共同决定 boundary；current v13.3、12.9.2 archive 和 11.8.0 archive 分别核对。Phase 名称相对稳定不表示内部 tool order 跨版本稳定。

<span id="term-118" class="resource-target" aria-hidden="true"></span>

### PTX · PTX 中间代码

- **定义：** PTX 中间代码（PTX）是带 `.version` 与 `.target` module declarations 的 versioned virtual ISA text，可作为后续 real-architecture translation 或适用 driver JIT path 的 input candidate。
- **避免使用：** SASS、cubin、CUDA C++ source、任意 GPU 的 native binary、JIT 或 execution 已发生的证明。
- **相关资源：** [M16](/toolchain/ptx-cubin-fatbinary/)、[M17](/toolchain/compiler-architecture-targets/)、[EX10](/examples/ptx-fatbinary-inspection/)和 [VIS09](/visuals/artifact-pipeline/)。
- **版本说明：** Selected Toolkit 11.8.0、12.9.2 与 13.3.1 owner coordinates 分别记录 archived PTX ISA 7.8、archived 8.8 与 current 9.3；数字顺序不是 universal driver/PTX compatibility theorem。

<span id="term-119" class="resource-target" aria-hidden="true"></span>

### cubin · cubin 二进制

- **定义：** cubin 二进制（cubin）是面向具名 real GPU architecture、包含 architecture-specific executable device code 的 CUDA ELF binary；其中 machine-instruction encoding 可被 Binary Utilities 检查为 SASS。
- **避免使用：** PTX text、fatbinary container、host executable、runtime 已选择或执行该 image 的证明。
- **相关资源：** [M16](/toolchain/ptx-cubin-fatbinary/)、[M17](/toolchain/compiler-architecture-targets/)、[EX10](/examples/ptx-fatbinary-inspection/)和 [VIS09](/visuals/artifact-pipeline/)。
- **版本说明：** Standalone 与 embedded cubin 必须绑定 exact producing Toolkit/NVCC、real target、artifact hash 和 matching Binary Utilities record；current/12.9.2/11.8.0 tools 分别核对，不跨 Lane 外推。

<span id="term-120" class="resource-target" aria-hidden="true"></span>

### fatbinary · 胖二进制

- **定义：** 胖二进制（fatbinary）是可承载同一 device source 的一个或多个 PTX 和/或 cubin translations 的 container，可作为 standalone `.fatbin`，也可嵌入 host object、library 或 executable。
- **避免使用：** 单一 cubin、PTX 的别名、runtime image selection、JIT success、execution 或 portability guarantee。
- **相关资源：** [M15](/toolchain/nvcc-compilation-flow/)、[M16](/toolchain/ptx-cubin-fatbinary/)、[EX10](/examples/ptx-fatbinary-inspection/)和 [VIS09](/visuals/artifact-pipeline/)。
- **版本说明：** Current NVCC v13.3、12.9.2 archive/v12.9 与 11.8.0 archive 都保留 multi-image 和 conditional fallback model；inventory 只说明 container 中有什么，不说明 driver 用了什么。

<span id="term-121" class="resource-target" aria-hidden="true"></span>

### SASS · SASS 机器代码

- **定义：** SASS 机器代码（SASS）是在一个 architecture-specific cubin 中编码、由 `cuobjdump --dump-sass` 或 `nvdisasm` 等 Binary Utilities 显示的 GPU machine instructions 视图。
- **避免使用：** PTX、与 cubin 并列的 portable standalone format、source code、runtime instruction trace 或 performance evidence。
- **相关资源：** [M16](/toolchain/ptx-cubin-fatbinary/)、[M17](/toolchain/compiler-architecture-targets/)和 [EX10](/examples/ptx-fatbinary-inspection/)。
- **版本说明：** Disassembly 绑定 exact cubin hash、tool/version、command 与 output；current 13.3、12.9.2 archive 和 11.8.0 archive Binary Utilities 的 static output 都不证明 displayed instructions 被加载或执行。

<span id="term-122" class="resource-target" aria-hidden="true"></span>

### relocatable device code · 可重定位设备代码

- **定义：** 可重定位设备代码（relocatable device code）是保存在 host object 中、可保留 external device references 并供后续 device linker 合并的中间 device code；NVCC `-dc` 等价于 `--relocatable-device-code=true --compile`。
- **避免使用：** 普通 whole-program device code、任意 host object、device-link output、final executable 或 runtime module。
- **相关资源：** [M15](/toolchain/nvcc-compilation-flow/)、[M18](/toolchain/separate-compilation-device-linking/)和 [EX10](/examples/ptx-fatbinary-inspection/)。
- **版本说明：** 每个参与 cross-translation-unit device graph 的 CUDA source 都必须在 selected current v13.3、12.9.2 archive 或 11.8.0 archive contract 下产生 compatible RDC object；一侧的 RDC 不能追溯修复另一侧 whole-program object。

<span id="term-123" class="resource-target" aria-hidden="true"></span>

### device link · 设备链接

- **定义：** 设备链接（device link）是读取 relocatable device-code objects 与 eligible static archives、解析 external device symbols，并产生嵌有 linked executable device code 的 host object 的 compilation phase。
- **避免使用：** Final host link、shared-library device-symbol lookup、runtime loader、kernel launch 或最终 executable。
- **相关资源：** [M18](/toolchain/separate-compilation-device-linking/)和 [EX10](/examples/ptx-fatbinary-inspection/)。
- **版本说明：** Current v13.3、12.9.2 archive 与 11.8.0 archive 都要求 compatible device ABI、pointer size、target 与 linker version；device-link output 仍须进入 host link，且 link success 不授予 runtime evidence。

<span id="term-124" class="resource-target" aria-hidden="true"></span>

### host link · 主机链接

- **定义：** 主机链接（host link）是把 original CUDA host objects、需要时的 device-link object、其他 host objects 和 libraries 组合成 final host artifact，并解析 host symbols、registration stubs 与 Runtime references 的阶段。
- **避免使用：** Device link 的同义词、device-symbol resolution 的替代品、executable 已运行、GPU code 已执行或结果正确的证明。
- **相关资源：** [M15](/toolchain/nvcc-compilation-flow/)、[M18](/toolchain/separate-compilation-device-linking/)和 [EX10](/examples/ptx-fatbinary-inspection/)。
- **版本说明：** Final link input contract 按 selected Toolkit/NVCC 与 host compiler 核对；成功产生 executable 或 library 只证明该 link boundary，不证明 load、launch、completion、correctness 或 performance。

<span id="term-125" class="resource-target" aria-hidden="true"></span>

### C++ dialect · C++ 方言

- **定义：** C++ 方言（C++ dialect）是由 C++17、C++20 或 C++23 等标准坐标命名、并在 exact Toolkit、NVCC、host compiler、explicit option、source identity 和 checked phase 中请求的 language mode。
- **避免使用：** Host compiler default、仅凭 WG21 document 得出的 CUDA support、documentation eligibility 的同义词、从一个 probe 推广的 universal language claim。
- **相关资源：** [O04](/start/cpp17-for-cuda/)、[M19](/toolchain/cpp-dialect-boundaries/)和 [EX10](/examples/ptx-fatbinary-inspection/)。
- **版本说明：** Ordinary matrix 是 11.8.0/C++17、12.9.2/C++17+C++20、13.3.1/C++17+C++20。Run 33275734951 在 EX10 + Toolkit 13.3.1 + NVCC 13.3.73 + GCC 14.2.0 坐标上保留 narrow C++23 probe pass；它不是 ordinary C++23 support，WG21 N4659/N4861/N4950/N4951 仍只提供标准 provenance。

<span id="term-126" class="resource-target" aria-hidden="true"></span>

### elementwise map · 逐元素映射

- **定义：** 逐元素映射（elementwise map）把同一个 transform 独立应用到 logical domain 的每个 element，并为该位置声明 read set、write set 与唯一 output owner。
- **避免使用：** Vector addition 的同义词、默认 alias-safe 的 in-place update、自动需要 barrier/atomic、已观测到高 bandwidth 的 kernel。
- **相关资源：** [A01](/algorithms/elementwise-map/)、[F03](/foundations/multidimensional-indexing/)、[F04](/foundations/host-device-lifecycle/)和 [EX02](/examples/vector-addition/)。
- **版本说明：** 数学 map contract 不绑定 Toolkit；CUDA indexing/memory path 分别按 current v13.3/Runtime 13.3.1、12.9.1 owner guide 与 11.8.0 archive 复核，静态 ownership proof 不授予 runtime 或 performance evidence。

<span id="term-127" class="resource-target" aria-hidden="true"></span>

### reduction · 归约

- **定义：** 归约（reduction）按声明的 binary operation、identity 与 operation order，把一个 input set 组合成逐步减少的 partial values，直到得到最终 result。
- **避免使用：** 只指求和、scan 的同义词、无 order contract 的 atomic accumulator、天然逐 bit 等于 serial fold。
- **相关资源：** [A02](/algorithms/multi-stage-reduction/)、[A03](/algorithms/inclusive-exclusive-scan/)、[Q02](/correctness/floating-point-order-reproducibility/)和 [EX11](/examples/multi-stage-reduction/)。
- **版本说明：** Block/barrier 与 floating-point boundaries 分别在 current v13.3、12.9.1/11.8.0 archives 中核对；CCCL v3.4.2 `DeviceReduce` 是具名 production baseline，不是任意 custom reduction 的保证。

<span id="term-128" class="resource-target" aria-hidden="true"></span>

### reduction tree · 归约树

- **定义：** 归约树（reduction tree）是以 inputs 为 leaves、以 combine operations 为 internal nodes、以 result 为 root 的 dependency graph；tree edges 固定 pairing 与 floating-point operation order。
- **避免使用：** Scheduler timeline、serial left fold 的别名、自动满足 determinism 的 shape、硬件执行时间图。
- **相关资源：** [A02](/algorithms/multi-stage-reduction/)、[Q02](/correctness/floating-point-order-reproducibility/)、[VIS10](/visuals/reduction-stages/)和 [EX11](/examples/multi-stage-reduction/)。
- **版本说明：** Tree 是算法结构；current v13.3 与 12.9.1/11.8.0 owner coordinates 负责 barrier/order facts，实际 compiler、launch 与 library policy 仍可能选择不同 tree，VIS10 不执行 CUDA。

<span id="term-129" class="resource-target" aria-hidden="true"></span>

### inactive lane · 非活动通道

- **定义：** 非活动通道（inactive lane）是在某个 algorithm stage 不执行 combine 或 update、但若后续 collective/barrier 要求它参与就仍须沿合法 control flow 到达该点的 lane。
- **避免使用：** 已退出 thread、永久禁用的 hardware lane、无需 synchronization 的 thread、所有 divergence 中的统一角色。
- **相关资源：** [A02](/algorithms/multi-stage-reduction/)、[M05](/memory/synchronization-scopes/)和 [VIS10](/visuals/reduction-stages/)。
- **版本说明：** 角色绑定具体 stage 与 participant group；current v13.3 及 12.9.1/11.8.0 block-barrier contracts 都不允许用 data inactivity 推导提前退出安全。

<span id="term-130" class="resource-target" aria-hidden="true"></span>

### scan · 扫描

- **定义：** 扫描（scan）对 ordered inputs 的每个位置产生一个 prefix result，使用声明的 associative operation 与 identity，而不是只返回一个最终 aggregate。
- **避免使用：** Reduction、sort、只限 addition 的 cumulative sum、任意可交换 input order 的 operation。
- **相关资源：** [A03](/algorithms/inclusive-exclusive-scan/)、[A02](/algorithms/multi-stage-reduction/)和 [EX12](/examples/inclusive-exclusive-scan/)。
- **版本说明：** Blelloch CMU-CS-90-190 只提供 all-prefix-sums history；current CUDA v13.3、12.9.1/11.8.0 archives 与 CCCL v3.4.2 `DeviceScan` 分别负责 current/archive/production coordinates。

<span id="term-131" class="resource-target" aria-hidden="true"></span>

### inclusive scan · 包含式扫描

- **定义：** 包含式扫描（inclusive scan）在 output position `i` 的 prefix 中包含 current input `x[i]`，因此结果覆盖 ordered range `x[0]` through `x[i]`。
- **避免使用：** Exclusive scan、只输出 total 的 reduction、忽略 identity/operator type 的 running total、允许交换 operands 的 prefix。
- **相关资源：** [A03](/algorithms/inclusive-exclusive-scan/)和 [EX12](/examples/inclusive-exclusive-scan/)。
- **版本说明：** Semantic definition 跨 Toolkit 稳定；CUDA cooperation/barrier context 按 current v13.3、12.9.1/11.8.0 archives 核对，CCCL v3.4.2 `DeviceScan` contract 只绑定该 product/version。

<span id="term-132" class="resource-target" aria-hidden="true"></span>

### exclusive scan · 排除式扫描

- **定义：** 排除式扫描（exclusive scan）在 output position `i` 排除 current input `x[i]`，只组合更早的 ordered inputs，因此 position 0 是 identity。
- **避免使用：** Inclusive scan、无 identity 的 shift、把 inclusive output 右移却不证明 edge/type contract、block sum。
- **相关资源：** [A03](/algorithms/inclusive-exclusive-scan/)和 [EX12](/examples/inclusive-exclusive-scan/)。
- **版本说明：** Semantic definition 跨 Toolkit 稳定；current v13.3、12.9.1/11.8.0 owner coordinates 与 CCCL v3.4.2 分开记录，library source 不构成 EX12 execution evidence。

<span id="term-133" class="resource-target" aria-hidden="true"></span>

### histogram · 直方图

- **定义：** 直方图（histogram）用声明的 `bin_of` 与 range policy 把每个 valid sample 映射到一个 bin，并要求每个 bin 的 counter 等于 exact assigned-sample count。
- **避免使用：** 可视化柱状图本身、只计算一个 aggregate 的 reduction、未声明 bounds 的 bucketization、默认可容忍整数计数误差。
- **相关资源：** [A04](/algorithms/privatized-histogram/)和 [EX13](/examples/privatized-histogram/)。
- **版本说明：** Exact-count contract 不绑定 Toolkit；atomic/shared implementation 分别按 current v13.3 与 12.9.1/11.8.0 archives 核对，CCCL v3.4.2 `DeviceHistogram` 是具名 production baseline。

<span id="term-134" class="resource-target" aria-hidden="true"></span>

### atomic contention · 原子争用

- **定义：** 原子争用（atomic contention）是多个 concurrent atomic read-modify-write operations 竞争同一或相冲突 destination，导致 progress/serialization cost 与 address distribution 相关的情况；它与 atomic correctness 分开。
- **避免使用：** Data race、lost update、所有 atomics 必然完全串行、没有实际记录就声明的 slowdown。
- **相关资源：** [A04](/algorithms/privatized-histogram/)、[M05](/memory/synchronization-scopes/)和 [EX13](/examples/privatized-histogram/)。
- **版本说明：** Atomic operation/scope support 绑定 selected current v13.3 或 archive contract；contention cost 还绑定 architecture、type、address pattern 与 input distribution，必须测量而不能从 source 推断。

<span id="term-135" class="resource-target" aria-hidden="true"></span>

### privatization · 私有化

- **定义：** 私有化（privatization）为较小 participant group 建立 intermediate state 的独立实例，让 updates 先在较窄 sharing scope 内累积，再通过明确 merge 合并到 wider destination。
- **避免使用：** 必然 per-thread private、自动 race-free、消除所有 atomics、无需 merge、speedup guarantee。
- **相关资源：** [A04](/algorithms/privatized-histogram/)、[M03](/memory/shared-memory-tiling/)和 [EX13](/examples/privatized-histogram/)。
- **版本说明：** A04 的 baseline 是 per-block shared histogram，并按 current v13.3 与 12.9.1/11.8.0 barrier/atomic contracts 复核；CCCL v3.4.2 comparison 不证明 custom variant 更快。

<span id="term-136" class="resource-target" aria-hidden="true"></span>

### floating-point nonassociativity · 浮点非结合性

- **定义：** 浮点非结合性（floating-point nonassociativity）是有限精度 rounding 使 `(a + b) + c` 与 `a + (b + c)` 可能产生不同 representation，即使每个 operation 都符合声明的 rounding mode。
- **避免使用：** Data race、数学实数加法不满足结合律、任意 nondeterminism、自动可忽略的 correctness mismatch。
- **相关资源：** [A02](/algorithms/multi-stage-reduction/)、[Q02](/correctness/floating-point-order-reproducibility/)和 [EX11](/examples/multi-stage-reduction/)。
- **版本说明：** Numerical principle 跨 Toolkit 存在；具体 compiler flags、precision 与 operation graph 按 current CUDA v13.3、12.9.1 与 11.8.0 owner documents 和 exact environment ledger 解释。

<span id="term-137" class="resource-target" aria-hidden="true"></span>

### fused multiply-add (FMA) · 融合乘加（FMA）

- **定义：** 融合乘加（fused multiply-add, FMA）计算 `rn(a * b + c)`，不先把 exact product 舍入到 target precision，因此整个 multiply-add 只有一次 rounding。
- **避免使用：** `rn(rn(a*b)+c)`、两条独立 operations 的缩写、保证相同 bits、自动等于 compiler contraction。
- **相关资源：** [Q02](/correctness/floating-point-order-reproducibility/)和 [EX11](/examples/multi-stage-reduction/)。
- **版本说明：** FMA/accuracy facts 在 current v13.3 与 12.9.1/11.8.0 archives 分开核对；implicit contraction 还绑定 exact `--fmad`/`--use_fast_math` defaults、target 与 explicit intrinsics。

<span id="term-138" class="resource-target" aria-hidden="true"></span>

### determinism · 确定性

- **定义：** 确定性（determinism）是在明确固定的 inputs、build、device、algorithm/launch policy 与 run scope 内，repeated executions 按声明的 equality predicate 得到相同 output。
- **避免使用：** Correctness、所有环境的 reproducibility、固定 random seed、固定 tree 即自动跨 GPU 相同 bits。
- **相关资源：** [Q02](/correctness/floating-point-order-reproducibility/)、[A02](/algorithms/multi-stage-reduction/)和 [EX11](/examples/multi-stage-reduction/)。
- **版本说明：** Current CUDA v13.3 的 deterministic-result guidance 与 CCCL v3.4.2 CUB determinism levels 分开记录；后者是 product/version/scope-specific guarantee，不能外推到 custom kernel。

<span id="term-139" class="resource-target" aria-hidden="true"></span>

### bitwise reproducibility · 逐位可复现性

- **定义：** 逐位可复现性（bitwise reproducibility）要求在具名 comparison scope 内，比较对象的 floating-point representations 完全相同，并保存足以重建 build、environment、input 与 equality predicate 的记录。
- **避免使用：** Tolerance pass、只固定 reduction order、数学正确性的证明、未声明环境范围的“reproducible”。
- **相关资源：** [Q02](/correctness/floating-point-order-reproducibility/)、[Q01](/correctness/cpu-references-tolerances-invariants/)和 [EX11](/examples/multi-stage-reduction/)。
- **版本说明：** Claim 必须绑定 exact Toolkit/compiler/library/device scope；current CUDA v13.3、12.9.1/11.8.0 archives 与 CCCL v3.4.2 policy 只提供各自边界，任何 tolerance result 都不能升级该状态。

<span id="term-140" class="resource-target" aria-hidden="true"></span>

### matrix transpose · 矩阵转置

- **定义：** 矩阵转置（matrix transpose）把 input coordinate `(row,col)` 映射到 output `(col,row)`；对 row-major rectangular matrix，`output[col*rows+row] = input[row*columns+col]`。
- **避免使用：** In-place reshape、只交换显示标签、默认方阵、自动性能优化。
- **相关资源：** [A05](/algorithms/matrix-transpose-layout/)、[EX14](/examples/tiled-transpose/)和 [VIS11](/visuals/tiled-transpose/)。
- **版本说明：** Mapping 不绑定 Toolkit；CUDA v13.3 与 12.9.1/11.8.0 owner guides 负责 current/archive memory-layout context，实际 performance 需要独立证据。

<span id="term-141" class="resource-target" aria-hidden="true"></span>

### physical row stride · 物理行跨度

- **定义：** 物理行跨度（physical row stride）是相邻 logical rows 起点在实际 storage 中相隔的 element 或 byte 数，可能大于 logical column count。
- **避免使用：** Logical width、output leading dimension 的固定同义词、padding count 本身、row-major 语义保证。
- **相关资源：** [M04](/memory/bank-conflicts-layouts/)、[A05](/algorithms/matrix-transpose-layout/)、[EX14](/examples/tiled-transpose/)和 [VIS11](/visuals/tiled-transpose/)。
- **版本说明：** Shared-memory mapping 还绑定 element width、bank model 与 architecture；VIS11 只计算 declared physical slot，不观察 bank hardware。

<span id="term-142" class="resource-target" aria-hidden="true"></span>

### bank padding · 存储体填充

- **定义：** 存储体填充（bank padding）在 physical shared layout 中加入不承载 logical value 的 slot，以改变 row stride 与特定 access pattern 的 bank mapping。
- **避免使用：** 新的 logical matrix column、automatic conflict removal、universal `+1` rule、speedup guarantee。
- **相关资源：** [M04](/memory/bank-conflicts-layouts/)、[A05](/algorithms/matrix-transpose-layout/)、[EX14](/examples/tiled-transpose/)和 [VIS11](/visuals/tiled-transpose/)。
- **版本说明：** A05 使用 selected 32-bank/32-bit-word reasoning model；扩展到另一 type、instruction 或 architecture 前必须重核，实际 conflict/timing 需要 observation。

<span id="term-143" class="resource-target" aria-hidden="true"></span>

### stencil · 模板计算

- **定义：** 模板计算（stencil）为每个 output coordinate 读取一个声明形状的相对 input-offset set，并按固定 operation 组合该 neighborhood。
- **避免使用：** 任意 sliding window、只限 image filter、未声明 boundary policy 的邻域访问、convolution 的无条件同义词。
- **相关资源：** [A06](/algorithms/stencil-neighborhood-reuse/)。
- **版本说明：** Algorithm contract 不绑定 Toolkit；shared-memory 与 block synchronization 按 current CUDA v13.3 和 12.9.1/11.8.0 archives 解释。

<span id="term-144" class="resource-target" aria-hidden="true"></span>

### halo · 光环区

- **定义：** 光环区（halo）是一个 output tile 的 center region 之外、为满足其 neighborhood read set 而额外 staged 的 input region；二维 square footprint 还包含 corners。
- **避免使用：** Global boundary、padding 的必然同义词、只含四条 side strips、unused cache data。
- **相关资源：** [A06](/algorithms/stencil-neighborhood-reuse/)和 [A07](/algorithms/convolution-reuse-layout/)。
- **版本说明：** Extent 由 output tile、offset shape、stride、dilation 与 boundary policy 决定；CUDA v13.3 stencil context 不替代 application-level definition。

<span id="term-145" class="resource-target" aria-hidden="true"></span>

### convolution · 卷积

- **定义：** 卷积（convolution）按 kernel/filter 的声明 orientation 对 shifted input neighborhoods 做加权组合；mathematical discrete convolution 会翻转 spatial filter。
- **避免使用：** 默认不翻转的任意 deep-learning operation、所有 stencil、固定 NCHW layout、production-library performance guarantee。
- **相关资源：** [A07](/algorithms/convolution-reuse-layout/)。
- **版本说明：** A07 明确把 teaching path 定义为 cross-correlation；current cuDNN docs 只为 future pinned production comparison 提供 owner coordinate。

<span id="term-146" class="resource-target" aria-hidden="true"></span>

### cross-correlation · 互相关

- **定义：** 互相关（cross-correlation）按 filter storage order 使用 spatial taps，不沿 axes 翻转；A07 的 direct teaching equation采用该 convention。
- **避免使用：** Mathematical convolution 的完全同义词、自动相同输出、只由 API 名称隐含的 operation contract。
- **相关资源：** [A07](/algorithms/convolution-reuse-layout/)。
- **版本说明：** Tensor layout、stride、dilation、padding、data/compute type 与 component version 仍需单独声明；cuDNN Frontend v1.27.0 只是 future coordinate。

<span id="term-147" class="resource-target" aria-hidden="true"></span>

### general matrix multiplication (GEMM) · 通用矩阵乘法

- **定义：** 通用矩阵乘法（general matrix multiplication，GEMM）按声明的 layout、shape、transpose、scalar 与 precision contract 计算矩阵乘积及可选的既有 output contribution。
- **避免使用：** 只指 square `C=AB`、固定 row-major、任意 tiled kernel、production performance guarantee。
- **相关资源：** [A08](/algorithms/tiled-gemm-correctness/)、[EX15](/examples/tiled-gemm/)和 [VIS12](/visuals/gemm-tiling-hierarchy/)。
- **版本说明：** A08/EX15 冻结 row-major non-transposed FP32 subset；后续 cuBLAS/CUTLASS units 必须重新声明 exact component/architecture contract。

<span id="term-148" class="resource-target" aria-hidden="true"></span>

### K tile · K 维分块

- **定义：** K 维分块（K tile）是 GEMM reduction extent 的一个有限 slice，由同一个 output owner/block 与其他 slices 依次组合。
- **避免使用：** 新的 output ownership dimension、额外 C writer、observed hardware instruction tile。
- **相关资源：** [M03](/memory/shared-memory-tiling/)、[A08](/algorithms/tiled-gemm-correctness/)、[EX15](/examples/tiled-gemm/)和 [VIS12](/visuals/gemm-tiling-hierarchy/)。
- **版本说明：** Logical slice 不绑定 WMMA/MMA/Tensor Core；architecture-specific shape 留给 version-gated units。

<span id="term-149" class="resource-target" aria-hidden="true"></span>

### sorting · 排序

- **定义：** 排序（sorting）按声明的 key projection、direction、stability、equal-key 与 payload-movement contract 建立 output order。
- **避免使用：** 只把 items 分 bins、任意 atomic scatter、所有 selection/compaction、自动最快的 custom kernel。
- **相关资源：** [A09](/algorithms/sorting-selection-compaction/)。
- **版本说明：** Production API coordinate 固定 CCCL v3.4.2；CCCL 3.x 只支持 latest-patch Toolkit 12.x/13.x，不支持 11.8；availability 不等于 measured suitability。

<span id="term-150" class="resource-target" aria-hidden="true"></span>

### selection · 选择

- **定义：** 选择（selection）按 predicate 或 flags 产生满足条件的 values、indices 或 key/value payload，并声明 selected count 与 output ownership。
- **避免使用：** 必然 stable compaction、sorting、未声明 equivalence 的 unique。
- **相关资源：** [A09](/algorithms/sorting-selection-compaction/)。
- **版本说明：** CUB `DeviceSelect` v3.4.2 的 `Flagged`、`If`、`Unique` 是不同 production contracts；该 3.x coordinate 不覆盖 Toolkit 11.8。

<span id="term-151" class="resource-target" aria-hidden="true"></span>

### stream compaction · 流压缩

- **定义：** 流压缩（stream compaction）把 selected items 写入 contiguous output positions；original-order exclusive prefix rank 可提供 stability。
- **避免使用：** 任意 atomic append 都叫 stable、sorting、CUDA stream API operation。
- **相关资源：** [A03](/algorithms/inclusive-exclusive-scan/)和 [A09](/algorithms/sorting-selection-compaction/)。
- **版本说明：** Composition 是 algorithm contract；CUB/Thrust exact API 与 storage/policy/Toolkit compatibility 由 selected CCCL release 决定。

<span id="term-152" class="resource-target" aria-hidden="true"></span>

### APOD · 评估、并行化、优化、部署

- **定义：** 评估、并行化、优化、部署（Assess, Parallelize, Optimize, Deploy，APOD）是围绕 correctness-qualified recorded baseline 重复执行的 evidence cycle：评估真实 workload，提出可证伪 hypothesis，以一项受控变更进行并行化或优化，并只在 correctness、performance、regression 与 operational gates 通过后部署。
- **避免使用：** 一次性 tuning checklist、跳过 correctness 的 optimization、profiler ranking、自动 speedup guarantee。
- **相关资源：** [Q05](/correctness/timing-asynchronous-gpu-work/)和 [Q06](/correctness/apod-optimization-loop/)。
- **版本说明：** APOD 表述按 current CUDA C++ Best Practices Guide v13.3 与 archived v11.8.0 复核；每轮仍绑定自己的 baseline、hypothesis、controlled change 与 deploy gate，静态流程本身不证明 improvement。

<span id="term-157" class="resource-target" aria-hidden="true"></span>

### replay · 重放

- **定义：** 在 profiler 语境中，重放（replay）是为了跨一个或多个 collection passes 获取所需数据而重复 kernel、application 或 range 的采集机制；replay mode 决定重复边界和 state-validity contract。

<span id="term-158" class="resource-target" aria-hidden="true"></span>

### profiler report · 性能分析报告

- **定义：** 性能分析报告（profiler report）是 profiler 生成的 primary observation artifact，例如 `.nsys-rep` 或 `.ncu-rep`；只有与 exact producer version、command/method、workload、correctness verdict、Environment Manifest、logs、hash 和 interpretation contract 一起保管时才可审查。
- **避免使用：** 把 screenshot、stats table 或 export 当作完整 report、脱离 manifest 的结论、仅因文件存在就视为 Runtime-Verified、可由任意 tool version 无损解释的通用格式。
- **相关资源：** [Q07](/correctness/timeline-first-nsight-systems/)、[Q08](/correctness/kernel-first-nsight-compute/)、[Q09](/correctness/occupancy-stalls-throughput/)、[Q10](/correctness/roofline-arithmetic-intensity/)、[LAB06](/labs/build-overlapped-pipeline/)、[LAB08](/labs/profile-full-application-before-kernel/)和 [LAB09](/labs/build-original-roofline/)。
- **版本说明：** `.nsys-rep` 绑定实际 Nsight Systems version；`.ncu-rep` 绑定 actual 2026.2.1 或 selected Lane 2022.3.0.22/2025.2.1.3/2026.2.1.5 与 exact GPU。Filter、replay、source command、derivative、redaction、hash 和 reader-version 差异需记录；report existence 不支持未声明的结论。

<span id="term-159" class="resource-target" aria-hidden="true"></span>

### command-line interface (CLI) · 命令行接口

- **定义：** 命令行接口（command-line interface，CLI）是通过 executable 与 ordered argument vector 调用工具并返回 stdout、stderr 和 exit status 的文本接口；可复现 profiler command 还保留 executable path、expanded arguments、environment、working directory、version 与相关 help output。
- **避免使用：** Shell 本身、与 GUI workflow 自动等价、owner example command 的本机 observation、用 `nvcc --version` 代替 `nsys`/`ncu` version。
- **相关资源：** [Q07](/correctness/timeline-first-nsight-systems/)、[Q08](/correctness/kernel-first-nsight-compute/)、[LAB06](/labs/build-overlapped-pipeline/)和 [LAB08](/labs/profile-full-application-before-kernel/)。
- **版本说明：** `nsys` syntax 绑定 actual current 2026.4/2026.4.1 或 selected Lane 2022.4.2.1/2025.1.3.140/2026.1.3.425；`ncu` syntax 绑定 actual 2026.2.1 或 selected Lane 2022.3.0.22/2025.2.1.3/2026.2.1.5。先保存实际 `--version` 与 subcommand help，再解释 command；文档中的 symbolic shape 不是执行记录。

<span id="term-160" class="resource-target" aria-hidden="true"></span>

### theoretical occupancy · 理论占用率

- **定义：** 根据 exact kernel binary、launch configuration、register/shared-memory allocation rules 与 exact-device limits 推导的每 SM modeled active warps 相对 maximum active warps 的比值；它描述 residency capacity，不是运行观察。
- **避免使用：** 最大占用率、预测 utilization、达成占用率。
- **相关资源：** [F08](/foundations/launch-geometry/)、[Q09](/correctness/occupancy-stalls-throughput/)和 [LAB09](/labs/build-original-roofline/)。
- **版本说明：** CUDA 13.3 与 Nsight Compute 2026.2.1；compiler/resource record、allocation granularity、device limit 或 launch 改变后必须重算，不能把 model 值写成 observed percentage。

<span id="term-161" class="resource-target" aria-hidden="true"></span>

### achieved occupancy · 实际占用率

- **定义：** 在合格 execution report 的声明 sampling/aggregation scope 内，execution-derived active warps 相对同一 exact-device maximum active warps 的比值。
- **避免使用：** 测得的 utilization、理论占用率、持续驻留保证。
- **相关资源：** [Q09](/correctness/occupancy-stalls-throughput/)和 [LAB09](/labs/build-original-roofline/)。
- **版本说明：** Nsight Compute 2026.2.1；必须保留 exact metric definition、denominator、scope、GPU、filter、replay 与 report custody，不能从 theoretical occupancy 推导。

<span id="term-162" class="resource-target" aria-hidden="true"></span>

### warp stall reason · warp 停顿原因

- **定义：** Profiler 在已声明 sampling 与 normalization contract 下，对 warp 暂时不 eligible 或未发射原因进行的分类；它是 investigation lead，不是 whole-kernel cause。
- **避免使用：** 根因、瓶颈、修复方向。
- **相关资源：** [Q09](/correctness/occupancy-stalls-throughput/)和 [LAB09](/labs/build-original-roofline/)。
- **版本说明：** Nsight Compute 2026.2.1；taxonomy、unit、sampling、denominator、scheduler context 与 availability 绑定 exact GPU/report，最大类别不能单独证明 speedup opportunity。

<span id="term-163" class="resource-target" aria-hidden="true"></span>

### hardware ceiling · 硬件上限

- **定义：** 对一个具名 operation family 或 memory path，在已声明 device、unit、scope 与 provenance 下使用的性能上界；它可以是 theoretical、calibrated/measured 或 tool-reported，但不能静默混合。
- **避免使用：** 实际吞吐量、保证峰值、无来源的 roof。
- **相关资源：** [A14](/algorithms/algorithm-choice-arithmetic-intensity/)、[Q10](/correctness/roofline-arithmetic-intensity/)、[LAB09](/labs/build-original-roofline/)和 [VIS13](/visuals/roofline/)。
- **版本说明：** CUDA 13.3、Nsight Compute 2026.2.1 与 original Roofline model；operation convention、path、clock/power state、device、method 或 provenance 改变后，ceiling 也必须独立重建。

<span id="term-164" class="resource-target" aria-hidden="true"></span>

### ridge point · 屋脊点

- **定义：** Roofline 中 compatible compute ceiling 与 path-bandwidth ceiling 的交点，其 arithmetic intensity 为 `I_ridge=P_compute/B_path`，把斜向 bandwidth-side model region 与水平 compute-side model region 分开。
- **避免使用：** 瓶颈点、测得的拐点、自动优化阈值。
- **相关资源：** [Q10](/correctness/roofline-arithmetic-intensity/)、[LAB09](/labs/build-original-roofline/)和 [VIS13](/visuals/roofline/)。
- **版本说明：** Nsight Compute 2026.2.1 与 original Roofline model；两个 ceilings 必须共享 operation convention、path、unit、device/scope 与 provenance，ridge location 不是 observed bottleneck。

<span id="term-165" class="resource-target" aria-hidden="true"></span>

### Roofline model · Roofline 模型

- **定义：** 以 arithmetic intensity 为横轴、achievable work rate 为纵轴，用 `min(P_compute, I*B_path)` 表示一组声明 compute 与 memory-path ceilings 的上界模型。
- **避免使用：** Profiler verdict、瓶颈证明、自动 optimization selector。
- **相关资源：** [A14](/algorithms/algorithm-choice-arithmetic-intensity/)、[Q10](/correctness/roofline-arithmetic-intensity/)、[LAB09](/labs/build-original-roofline/)和 [VIS13](/visuals/roofline/)。
- **版本说明：** 2009 original paper 只负责 model 构造；CUDA 13.3 与 Nsight Compute 2026.2.1 facts 另行复核。VIS13 browser values 和 static chart 都不是 GPU evidence。

<span id="term-166" class="resource-target" aria-hidden="true"></span>

### softmax · Softmax 归一化

- **定义：** Softmax 把一组有限 logits `x_i` 映射为 `exp(x_i)/sum_j exp(x_j)`；在实数算术中结果非负且和为 1，实际计算还必须声明 row domain、shift、precision 与 non-finite policy。
- **避免使用：** 指数函数、任意归一化、自动稳定的 framework 操作。
- **相关资源：** [A10](/algorithms/numerically-stable-softmax/)和 [A11](/algorithms/attention-as-an-io-problem/)。
- **版本说明：** Milakov/Gimelshein 2018 与 Blanchard/Higham/Higham 2019 提供算法和 floating-point analysis；术语不声明 current backend behavior。

<span id="term-167" class="resource-target" aria-hidden="true"></span>

### numerically stable softmax · 数值稳定 softmax

- **定义：** 数值稳定 softmax（numerically stable softmax）先从 row logits 减去 maximum，再求指数和归一化，从而避免 large positive exponent overflow，同时保持数学 softmax。
- **避免使用：** 逐位精确 softmax、绝不 underflow、没有 floating-point error。
- **相关资源：** [A10](/algorithms/numerically-stable-softmax/)和 [A11](/algorithms/attention-as-an-io-problem/)。
- **版本说明：** Max-shift 不消除 underflow、rounding 或 reduction-order differences；CUDA Programming Guide v13.3 的 floating-point boundary 仍适用。

<span id="term-168" class="resource-target" aria-hidden="true"></span>

### online normalization · 在线归一化

- **定义：** 在线归一化（online normalization）在扫描 values 时共同维护 running maximum 和相对该 maximum 的 denominator，并在 maximum 变化时重标定旧 state。
- **避免使用：** One-read output、自动 fusion、完整 probabilities 的单遍保证。
- **相关资源：** [A10](/algorithms/numerically-stable-softmax/)、[A11](/algorithms/attention-as-an-io-problem/)和 [VIS18](/visuals/attention-memory-traffic/)。
- **版本说明：** Milakov/Gimelshein 2018 提供 recurrence；输出 pass、residency、tiling 和 traffic 仍取决于具体 schedule。

<span id="term-169" class="resource-target" aria-hidden="true"></span>

### scaled dot-product attention · 缩放点积注意力

- **定义：** 缩放点积注意力（scaled dot-product attention）计算 `S=QK^T/sqrt(d_k)`，沿 key dimension 对每个 query row 做 softmax，再以 probabilities 聚合 V 得到 O。
- **避免使用：** Attention backend、FlashAttention、自动选择的 fused kernel。
- **相关资源：** [A11](/algorithms/attention-as-an-io-problem/)和 [VIS18](/visuals/attention-memory-traffic/)。
- **版本说明：** Vaswani 等 2017 的 scale motivation 依赖独立、零均值、单位方差 components 假设；它不替代 stable softmax 或 current backend review。

<span id="term-170" class="resource-target" aria-hidden="true"></span>

### IO-aware tiling · IO 感知分块

- **定义：** IO 感知分块（IO-aware tiling）在明确 slow/fast-store boundary、tile order 与 residency assumptions 后重排计算和 state，使中间值在声明层级中复用并可逐项核算 movement。
- **避免使用：** 必然更快的 tiling、FlashAttention 的同义词、实际 DRAM traffic。
- **相关资源：** [A08](/algorithms/tiled-gemm-correctness/)、[A10](/algorithms/numerically-stable-softmax/)、[A11](/algorithms/attention-as-an-io-problem/)和 [VIS18](/visuals/attention-memory-traffic/)。
- **版本说明：** Dao 等 2022 支持 attention IO-aware algorithm history；static logical reduction 不构成 current backend、actual traffic 或 speedup evidence。

<span id="term-171" class="resource-target" aria-hidden="true"></span>

### coordinate format (COO) · 坐标格式

- **定义：** 坐标格式（coordinate format，COO）用独立 row-index、column-index 与 value arrays 表示每个 stored matrix entry；三个数组长度都是 `nnz`。
- **避免使用：** 无索引稀疏数组、自动合并重复项、任意顺序都等价的格式。
- **相关资源：** [A12](/algorithms/sparse-formats-spmv/)和 [A13](/algorithms/sparse-matrix-multiplication-preprocessing/)。
- **版本说明：** cuSPARSE v13.3 的 storage-format contract 把 COO 说明为 row-sorted 并允许行内 columns 有序或无序；本课程 fixture 使用 unique coordinates。

<span id="term-172" class="resource-target" aria-hidden="true"></span>

### compressed sparse row (CSR) · 压缩稀疏行

- **定义：** 压缩稀疏行（compressed sparse row，CSR）用长度 `rows+1` 的 row offsets 把每行映射到长度 `nnz` 的 column-index/value arrays；相邻相等 offsets 表示空行。
- **避免使用：** COO 的别名、每行固定长度、没有 index overhead 的格式。
- **相关资源：** [A12](/algorithms/sparse-formats-spmv/)和 [A13](/algorithms/sparse-matrix-multiplication-preprocessing/)。
- **版本说明：** cuSPARSE v13.3 支持零基或一基 descriptor contract；duplicate columns 的正确性不能默认成立。

<span id="term-173" class="resource-target" aria-hidden="true"></span>

### sparse matrix-vector multiplication (SpMV) · 稀疏矩阵-向量乘法

- **定义：** 稀疏矩阵-向量乘法（sparse matrix-vector multiplication，SpMV）按 stored coordinates 从 vector gather values，并将 products 归约到对应 output rows。
- **避免使用：** 无索引的 dense dot product、天然 coalesced operation、必然 memory-bound 或更快的 kernel。
- **相关资源：** [A12](/algorithms/sparse-formats-spmv/)和 [A13](/algorithms/sparse-matrix-multiplication-preprocessing/)。
- **版本说明：** cuSPARSE v13.3 的 format、algorithm、workspace、preprocessing 与 determinism 均是 exact combination 的 API facts；A12 没有执行它们。

<span id="term-174" class="resource-target" aria-hidden="true"></span>

### sparse matrix-matrix multiplication (SpMM) · 稀疏矩阵-矩阵乘法

- **定义：** 稀疏矩阵-矩阵乘法（sparse matrix-matrix multiplication，SpMM）在 A13 中指 sparse `M x K` A 乘 dense `K x N` B，并生成 dense `M x N` C。
- **避免使用：** Sparse-output SpGEMM、dense GEMM 的自动替代品、structured sparsity 的同义词。
- **相关资源：** [A08](/algorithms/tiled-gemm-correctness/)、[A12](/algorithms/sparse-formats-spmv/)和 [A13](/algorithms/sparse-matrix-multiplication-preprocessing/)。
- **版本说明：** cuSPARSE v13.3 的 supported formats/layouts/algorithms 绑定 exact operation；A13 只发布 high-level comparison，不发布 API code。

<span id="term-175" class="resource-target" aria-hidden="true"></span>

### preprocessing · 预处理

- **定义：** 预处理（preprocessing）是某些 sparse operation/algorithm 可选的准备阶段，可针对会复用的 sparsity pattern 在 caller workspace 中建立 acceleration data。
- **避免使用：** 必做编译阶段、永久缓存、一次准备对任意 matrix 或 algorithm 都加速。
- **相关资源：** [A12](/algorithms/sparse-formats-spmv/)和 [A13](/algorithms/sparse-matrix-multiplication-preprocessing/)。
- **版本说明：** cuSPARSE v13.3 SpMM 只为特定 CSR algorithms 声明 benefit；是否支持、何时失效和是否有收益必须按 exact version/combination 核对。

<span id="term-176" class="resource-target" aria-hidden="true"></span>

### external workspace · 外部工作区

- **定义：** 外部工作区（external workspace）是 caller 在 exact operation/algorithm 的 size query 返回非零时分配和管理的 device buffer，用于 temporary 或 preprocessing acceleration storage；返回零时无需该 buffer。
- **避免使用：** Sparse matrix payload、CUDA external-memory interoperability、可由 `nnz` 猜出的固定 buffer。
- **相关资源：** [A12](/algorithms/sparse-formats-spmv/)和 [A13](/algorithms/sparse-matrix-multiplication-preprocessing/)。
- **版本说明：** Workspace owner、size、lifetime 与 active preprocessing state 绑定 pinned cuSPARSE contract；A12/A13 没有分配或测量它。

<span id="term-177" class="resource-target" aria-hidden="true"></span>

### production library · 生产库

- **定义：** 生产库（production library）暴露 broad domain operation，由外部 owner 维护 implementation/release lifecycle；caller 仍拥有 integration、完整 operation semantics、validation 与 evidence。
- **避免使用：** 自动最快的代码、无需维护的依赖、任意 reusable function 的同义词。
- **相关资源：** [L01](/libraries/library-primitive-dsl-custom-kernel/)和 [PB-R4-001](/practice/#pb-r4-001)。
- **版本说明：** Library decision 要独立于 Toolkit label 记录 exact component；API presence/owner testing 不是本地 build、runtime 或 performance evidence。

<span id="term-178" class="resource-target" aria-hidden="true"></span>

### reusable primitive · 可复用原语

- **定义：** 可复用原语（reusable primitive）是 reduction、scan、selection、sorting 等专注且可组合的 operation；外围 storage、stream、lifetime 与 end-to-end composition 仍由 caller 负责。
- **避免使用：** 完整生产应用、无人拥有的 building block、custom code 的保证替代品。
- **相关资源：** [L01](/libraries/library-primitive-dsl-custom-kernel/)和 [L02](/libraries/thrust-algorithm-vocabulary/)。
- **版本说明：** L01/L02 独立固定 CCCL v3.4.2，只评估 Toolkit 12.9.2/13.3.1；CUDA 11.8 需要另一个 reviewed coordinate。

<span id="term-179" class="resource-target" aria-hidden="true"></span>

### domain-specific language (DSL) · 领域特定语言

- **定义：** 领域特定语言（domain-specific language，DSL）描述 constrained problem family，让 compiler/generator 选择或生成 implementation；应用团队仍拥有 specification、toolchain pin、generated-artifact acceptance、cache、fallback 与 upgrade policy。
- **避免使用：** General-purpose CUDA C++、自动正确的 generated code、没有 owner 的实现。
- **相关资源：** [L01](/libraries/library-primitive-dsl-custom-kernel/)和 [PB-R4-001](/practice/#pb-r4-001)。
- **版本说明：** Availability、accepted language、generated behavior 与 supported deployment rows 绑定 exact DSL/compiler release，并需要独立 evidence。

<span id="term-180" class="resource-target" aria-hidden="true"></span>

### custom kernel · 自定义内核

- **定义：** 自定义内核（custom kernel）是由应用团队拥有 source、correctness、portability、tuning、regression response、handoff 与 removal 的 CUDA kernel。
- **避免使用：** 默认晋升为生产实现的教学 kernel、自动更快的代码、一次性 implementation cost。
- **相关资源：** [L01](/libraries/library-primitive-dsl-custom-kernel/)和 [PB-R4-001](/practice/#pb-r4-001)。
- **版本说明：** 生产理由需要 unmet semantic/deployment contract，或在 target workload 上通过正确性验收的 material measured gap；只有 source existence 两者都不能提供。

<span id="term-181" class="resource-target" aria-hidden="true"></span>

### execution policy · 执行策略

- **定义：** 在 Thrust 中，执行策略（execution policy）选择 sequential、configured host 或 configured device system；CUDA policy 还可把 work 绑定到 stream。
- **避免使用：** Pointer validator、automatic memory migration、返回即代表 asynchronous work 完成的保证。
- **相关资源：** [M07](/memory/stream-ordering/)和 [L02](/libraries/thrust-algorithm-vocabulary/)。
- **版本说明：** CCCL v3.4.2 的 `par_nosync` 允许省略 optional synchronization，但不保证完全不发生同步；extent、accessibility、lifetime 与 completion 仍是 caller contracts。

<span id="term-182" class="resource-target" aria-hidden="true"></span>

### fancy iterator · 花式迭代器

- **定义：** 花式迭代器（fancy iterator）通过 iterator operations 表示 generated、transformed、zipped 或其他 virtual range，无需为每个 logical range 单独存储数组。
- **避免使用：** 保证 fused kernel、停在最短 zipped component 的 range、自动性能提升。
- **相关资源：** [L02](/libraries/thrust-algorithm-vocabulary/)和 [PB-R4-002](/practice/#pb-r4-002)。
- **版本说明：** CCCL v3.4.2 composition 必须显式声明 extent、system、value/reference 与 lifetime；在 owner 指明处优先 current `cuda::` counting/transform/zip forms，但并非所有 legacy Thrust fancy iterator 都 deprecated。

<span id="term-183" class="resource-target" aria-hidden="true"></span>

### temporary storage · 临时存储

- **定义：** 临时存储（temporary storage）是调用者为一项尚未完成的 collective operation 提供的 scratch。Device-wide CUB 传统 API 先查询 device buffer 字节数；warp/block CUB class 则使用与 exact specialization 匹配的 nested `TempStorage`。两种形式的 owner、独占期、stream 或 participant scope、completion 与 reuse edge 都必须显式声明。
- **避免使用：** Output 或 persistent state、跨 operation/device/type/problem size 通用的固定字节数、多个并发 group 可无同步共享的 shared buffer。
- **相关资源：** [L03](/libraries/cub-device-primitives/)、[L04](/libraries/cub-warp-block-primitives/)、[EX17](/examples/cub-device-reduction-scan/)和 [LAB11](/labs/compare-custom-reduction-with-cub/)。
- **版本说明：** L03 的传统两阶段合同覆盖 bundled CUB 1.15.1/2.8.2/3.3.4 与 selected 3.4.2；L04 的 nested `TempStorage` 合同固定 CCCL/CUB v3.4.2。查询、分配或复用事实必须来自 exact environment；本词条没有记录实际字节数或 execution。

<span id="term-184" class="resource-target" aria-hidden="true"></span>

### logical warp · 逻辑线程束

- **定义：** 逻辑线程束（logical warp）是同一 hardware warp 内由 compile-time `LogicalWarpThreads` 指定的一组连续 threads，它们按 logical lane rank 共同参与匹配的 CUB warp collective。
- **避免使用：** 任意 runtime-selected active mask、永远等于完整 32-lane hardware warp 的同义词、可以缺少 required participants 的分支内小组。
- **相关资源：** [F02](/foundations/execution-hierarchy/)、[M06](/memory/warp-divergence-reconvergence/)、[M12](/memory/cooperative-groups/)和 [L04](/libraries/cub-warp-block-primitives/)。
- **版本说明：** CCCL/CUB v3.4.2 接受 compile-time size 1 至 32；2 的幂可把一个 hardware warp 划分为多个 subwarps，非 2 的幂不做该 partition 且只有第一个 logical warp 执行。Exact participation 仍需按 pinned interface 与 launch 复核；这不是 hardware observation。
