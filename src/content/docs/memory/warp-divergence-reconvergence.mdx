分支发散（warp divergence）发生在同一 warp 的 lanes 进入不同 control-flow paths 时。重汇合（reconvergence）表示 lanes 再次有资格执行共同 source region，却不暴露 exact instruction schedule。线程束安全推理（warp-safe reasoning）因此要命名活动通道（active lanes）、活动掩码（active mask）与 intended 参与掩码（participation mask），并写明 synchronization edge，不能依赖 implicit lockstep。

## 学完本单元，你应该能

- 跟踪 divergent branch 中的 active lanes 与非活动通道（inactive lanes）。
- 区分 current active mask 与 intended participation mask。
- 解释 CC 7.0+ 的独立线程调度（Independent Thread Scheduling）改变了什么。
- 拒绝依靠隐式锁步（implicit lockstep）保证 correctness 的代码。
- 说明源代码级汇合点（source-level join）为何不是 synchronization，以及 exact hardware schedule 为何 unknown。

## 先修关系

先完成 [F02：建立执行层级心智模型](/foundations/execution-hierarchy/)和 [M05：同步作用域与内存可见性](/memory/synchronization-scopes/)。F02 提供 warp/lane identity；M05 提供 participant mask、memory visibility，以及 source proximity 不构成 synchronization edge 的规则。

本单元分析 SIMT C++ control flow，不公开或反推 instruction-by-instruction scheduler trace，也不需要 CUDA-capable system。

## Active mask 与 participation mask

Active mask 回答“哪些 lanes 正在执行当前 instruction？”Participation mask 回答“哪些 lanes 必须参与这个 collective protocol？”两者可能不同。某个 lane 在一条 path instruction 上 inactive，却仍可能属于 paths 汇合后执行的 collective。

`__activemask()` 只报告调用点的 active lanes，不能恢复 earlier divergence 已排除的 intended group。若 protocol 需要所有满足 predicate `p` 的 lanes，应在 required voters 均 active 的位置用 documented ballot 等方式形成 participation set，再把该 mask 带入后续 warp collectives。

对每个 mask-sensitive operation 证明：

```text
mask members = intended participants
every named lane reaches the operation under its contract
every consumed source lane is named and supplies a value
```

## Divergence：路径与 disabled lanes

Data-dependent branch 拆分 warp 时，每条 taken path 执行，而不在该 path 上的 lanes 被 disabled。Divergence 只发生在 warp 内；different warps 本来就独立执行。Source trace 可以为讲解画成 path A 后 path B，但该图不承诺 hardware 先 issue 哪条 path，也不承诺 instructions 如何 interleave。

Correctness question 不是“哪个 branch 获胜”，而是每个 lane 的 scalar semantics 是否正确，以及 cross-lane exchange 是否使用合法 participant set 和所需 synchronization。

## Reconvergence：共同执行资格，不是同一时钟点

Reconvergence 是 control-flow concept：走过不同 paths 的 lanes 后续可以对 common region eligible。它不表示每个 lane 在同一瞬间完成，也不会因为 source 中出现一个 closing brace 就建立 memory ordering。

Reconvergence diagram 可以展示 source region 对应的 masks，但不能证明 exact program-counter stack、issue order 或 cycle count。这些 implementation details 不属于 portable source contract。

## CC 7.0+ 的 Independent Thread Scheduling

Compute capability 低于 7.0 的 device 为一个 warp 使用 shared program counter 与 active mask。CC 7.0+ 的 Independent Thread Scheduling 维护 per-thread execution state，并允许 sub-warp granularity 的 divergence/reconvergence；schedule optimizer 决定怎样把 active threads 组合成 SIMT units。

兼容性规则很直接：依赖 implicit warp-synchronous behavior 的代码必须重新检查。CC 7.0+ 不是说所有 intra-warp communication 都错误，而是说 implicit lockstep 不能作为 correctness argument。应使用 documented synchronized warp operations 与 explicit masks。

## 不安全的 implicit lockstep

下面的论证不安全：

```text
lane i writes shared[i]
lane i immediately reads shared[i - 1]
there is no race because lanes are in one warp
```

“One warp” 只标识 execution group，不提供 exchange 所需 memory ordering edge。修复必须定义 participating lanes，在 shared-memory visibility 所需位置使用 documented warp synchronization，并 guard 不存在的 source lane。若 mask 与 source-lane contracts 均满足，也可以用 suitable shuffle collective 传递 register values。

## Source-level join 不是 synchronization

一个 `if` 的两个 arms 都到达 branch 后 statement 时，source 出现 join，但 `source-level join is not synchronization` 仍然成立：join 本身既不是 barrier，也不是 memory fence。若 path A 写的数据由 path B 的 lane 消费，程序仍需要 documented cross-lane protocol。

这也防止另一种错误：在两个 branch 内分别调用 `__activemask()`，之后却假装两个 branch-local masks 命名同一 group。应在 protocol 合法的 formation point 捕获 intended participation mask。

## 调度边界

Portable reasoning 可以陈述 lane predicates、modeled source regions 的 active masks、required participation masks，以及 documented synchronization relations；它必须把 path issue order、instruction interleaving、reconvergence-stack details 与 timing 留作 unspecified。简言之：`the exact hardware schedule is unknown`。

这不是对 program 一无所知，而是有意区分 correctness 所需 guarantees 与 GPU 保留的 implementation freedom。
