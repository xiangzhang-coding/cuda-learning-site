A09 不发布一个“教学 sort kernel”。它从已知 primitives 推导三个算法合同：[选择（selection，TERM-150）](/glossary/#term-150)决定保留哪些 items，[流压缩（stream compaction，TERM-151）](/glossary/#term-151)把保留项写成 contiguous output，[排序（sorting，TERM-149）](/glossary/#term-149)按 key 建立 order。理解 composition 后，production 选择从 CUB/Thrust contracts 开始。

## 学完本单元，你应该能

- 把 stable selection 写成 `flag -> exclusive scan -> scatter`。
- 从最后一个 scan position 与 flag 推导 compacted count。
- 用 histogram、exclusive scan、within-bin rank 与 scatter 描述 bounded-key stable ordering。
- 解释 atomic slot allocation 为什么可保证 unique destination，却不自动保证 stability 或低 contention。
- 在 CUB `DeviceRadixSort`、CUB `DeviceSelect`、Thrust algorithms 与 custom code 之间写 decision packet。
- 把 algorithm contract、library availability、correctness evidence 与 measured performance 分开。

## 先修关系

严格先修项只有 `A03, A04`。A03 提供 inclusive/exclusive scan、block totals 与 offset propagation；A04 提供 histogram bins、atomics、privatization 与 merge。A09 使用这些 vocabulary，不把 CCCL API 变成 prerequisite。

## 三个合同先分开

Selection 输出满足 predicate 的 values 或 indices。Compaction 还要求 output positions `0..count-1` 连续；若使用 original-order prefix rank，它是 stable compaction。Sorting 要声明 key projection、ascending/descending、stability、key/value movement、equal-key policy 与 output ownership。一个实现可能组合这些动作，但三类 acceptance criteria 不能混写。

## 从 scan 得到 compaction positions

对每个 input `i` 计算 `flag[i]` 为 0 或 1。对 flags 做 exclusive scan 得到 `position[i]`。若 `flag[i] == 1`，把 item scatter 到 `output[position[i]]`。最终 `count = position[n-1] + flag[n-1]`；空输入要有独立合同。

因为 exclusive prefix 只计数当前 item 之前的 selected items，selected positions 唯一、连续，并按 input order 增加。这里的核心 composition 是 **flag -> exclusive scan -> scatter**。Scan 解决 destination ownership，scatter 负责 movement；两者都不能省略。

## Selection 是 predicate 与 payload contract

Predicate 可以检查 value、key、stencil mask 或外部 flags。Payload 可以是 value、index 或 key/value pair。In-place/out-of-place、aliasing、output capacity、selected-count type 与 stream/order 都必须先声明。`unique` 又需要 equivalence 与相邻/全局语义，不能仅因为名字相近就等同于 arbitrary predicate selection。

## 从 histogram、scan 与 movement 理解 bounded-key sorting

对有限 key domain，一个 counting/radix pass 可分成四步：histogram 得到每个 bin 的 count；对 counts 做 exclusive scan 得到 bin starts；为每个 item 计算 within-bin rank；scatter key/payload 到 `bin_start + rank`。重复 digit passes 时，每一 pass 若要保持 prior-digit order，就必须有 stable rank/movement contract。

Histogram + scan 只给 bucket boundaries，不给同一 bucket 内每个 item 的唯一 stable rank。这个缺口可以由 per-item prefix、stable partition primitive 或另一个明确算法填补。把 atomic increment 当 rank 可以产生 unique slots，但 arrival order 不等于 input order，所以不能自动声称 stable sort。

## Atomics：正确 ownership 与 contention 是两件事

Atomic counter 可给 concurrent writers 分配不同 slots；这可以支持 unordered compaction。它没有保证 selected items 的 original order，也没有给出 timing。Hot counter、key distribution、privatization、merge 与 architecture 决定 contention behavior；source-level shared target 只建立 hypothesis。

## Production choice：先读 exact owner contract

CCCL v3.4.2 是本页选择的 immutable owner release。它的 tagged platform-support table 明确限定 CCCL 3.x 支持 CUDA Toolkit 12.x 与 13.x 的 latest patch releases，不支持本站的 Toolkit 11.8 lane。12.9.2/13.3.1 decision packet 可以评估 v3.4.2；11.8 path 必须使用该 Toolkit bundled 的旧版 CUB/Thrust，或另选并重新复核一个兼容的 CCCL 2.x coordinate，不能把 v3.4.2 直接投射到 11.8。

CUB `DeviceRadixSort` 提供 device-wide radix sort，CUB `DeviceSelect` 提供 `Flagged`、`If` 与 `Unique` production primitives；传统 device-wide form 需要查询/提供 temporary storage 并声明 stream。Thrust 提供更高层 `sort`、`stable_sort` 与 `copy_if` vocabulary，并通过 execution policy/iterator contract 选择 backend。

教育 composition 解释 flags、prefix ranks、bin offsets、movement、stability 与 ownership，但不是 production implementation。选择 production path 时至少比较 operation semantics、types/iterators、stability、temporary storage、stream/execution policy、maintenance、toolkit/CCCL version、correctness fixtures 和 measured workload。没有测量就不能宣布 custom、CUB 或 Thrust 更快。

## 离开前检查

1. Exclusive scan of flags 为什么同时给出 unique、contiguous 与 stable positions？
2. Compacted count 为什么是最后一个 exclusive position 加最后一个 flag？
3. Histogram 与 bin-start scan 之后，stable sorting 还缺哪个 per-item quantity？
4. Atomic increment 可以建立哪种 ownership，又不能建立哪种 order？
