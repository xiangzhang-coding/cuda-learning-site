扫描（scan）为每个位置生成一个前缀结果，而不是只生成一个最终归约值。本单元先定义包含式扫描（inclusive scan）、排除式扫描（exclusive scan）与单位元（identity），再把顺序依赖（sequential dependency）改写成带阶段（stage）和屏障（barrier）的并行树，最后通过块总和（block sum）、块偏移（block offset）与偏移传播（offset propagation）扩展到多 thread block。

## 学完本单元，你应该能

- 写出 inclusive scan 与 exclusive scan 的逐位置合同，并说明 identity 出现在哪里。
- 把一条串行 recurrence 转换成读取前一 stage 快照的 parallel tree。
- 证明 block scan 中每个 stage 的 shared-memory 可见性与 barrier participation。
- 用 block sums、block offsets 和 offset propagation 解释 device-wide scan。
- 区分教学用手写实现、CUB `DeviceScan` production baseline 与尚未取得的性能证据。

## Scan 合同

给定输入 `x[0..n-1]`、结合运算 `op` 和 identity `e`，scan 必须保留输入顺序。对非交换但结合的运算，`x[0] op x[1]` 不能交换成 `x[1] op x[0]`。空输入产生空输出；边界与 accumulator type 也必须由实现声明。

顺序定义可以写成：

```text
inclusive[0] = x[0]
inclusive[i] = inclusive[i - 1] op x[i]

exclusive[0] = e
exclusive[i] = exclusive[i - 1] op x[i - 1]
```

这两条 recurrence 是语义 oracle，不是并行执行计划。

## Inclusive、exclusive 与 identity

Inclusive scan 包含（includes）current input `x[i]`：位置 `i` 的结果覆盖 `x[0]` 到 `x[i]`。Exclusive scan 不包含（excludes）current input `x[i]`：位置 `i` 只覆盖更早的元素，因此第一个输出必须是 identity `e`。

对 addition，`e = 0`。若 `x = [3, 1, 4, 2]`，则：

```text
inclusive = [3, 4, 8, 10]
exclusive = [0, 3, 4, 8]
```

在同一 `op` 与 identity 合同下，`inclusive[i] = exclusive[i] op x[i]`。这个关系适合做 invariant 检查，但不能忽略溢出、浮点 operation order 或自定义运算的类型合同。

## 把顺序 dependency 转换成并行 stages

Sequential dependency 让位置 `i` 等待 `i - 1`。Parallel tree 将这条链转换为若干 stage：距离依次为 `1, 2, 4, ...`，每个 stage 只读取前一 stage 的稳定快照，并把更长前缀写到下一快照。距离达到或超过 logical block length 后，每个位置拥有自己的完整 block prefix。

1. **Stage 0：** 每个 lane 拥有一个 input value。
2. **Stage k：** 若 predecessor 存在，lane `i` 组合 `prior[i - 2^(k-1)]` 与 `prior[i]`。
3. **Barrier：** current snapshot 完成前，没有 lane 可以开始 next stage。

`__syncthreads()` 是 block barrier，不会把同一数组的无序 read/write 自动变成 snapshot。教学实现可以 ping-pong 两个 shared buffers；其他 in-place 方案必须单独证明它的读写顺序。每个 stage 的 barrier 必须由所有 participating threads 到达，edge lane 不能提前 return。

## Block scan

一个 block 先把合法 input 放入 shared state，把越界 slot 设为 identity，再执行 staged scan。Inclusive output 可直接来自最终前缀；exclusive output 可以右移 inclusive prefix 并把 lane 0 设为 identity，或由等价且已证明的 exclusive construction 产生。

每个 block 还输出一个 block sum，也就是该 block 合法元素按原顺序合并后的 total。提取位置取决于实现证明：canonical EX12 把越界 slots 写成 identity，再对全部 `blockDim.x` slots 完成 full-width inclusive scan，因此 partial block 的最后一个 physical lane 正好保存合法 slice total；没有这项 identity-padding/full-width proof 的实现必须改读 logical last valid element 或证明另一条等价路径。这个 block sum 是下一层 scan 的输入，不是当前 block 的全局 offset。

## Multi-block scan：sum、offset、propagation

Device-wide baseline 分三步：

1. 每个 block 生成 local scan outputs 和一个 block partial sum。
2. 对 block sums 按 block 顺序执行 scan，得到 block offsets；exclusive offset 的第一个值是 identity。
3. Offset propagation kernel 把所属 block 的 offset 加回（add）或用 `op` 合并到每个 local prefix。

例如 block totals 为 `[10, 7, 5]`，addition 的 exclusive block offsets 是 `[0, 10, 17]`。第三个 block 的每个 local prefix 都要加 17。Kernel launch boundary 让第一步的 sums 对第二步可见，也让 offsets 在 propagation 前完成；普通 block barrier 不能跨越整个 grid 完成这项工作。

这套分解还给出验证点：local recurrence 正确、block sum 等于对应 slice total、offset recurrence 正确、传播后全局 recurrence 仍成立。任何一步漏掉 partial block、identity 或原始顺序，最终结果都会偏离 scan 合同。

## Production baseline：CUB DeviceScan

CCCL v3.4.2 的 CUB `DeviceScan` 是 device-wide inclusive/exclusive scan 的 production baseline 和 comparison point。实际应用应先评估它的 API、temporary storage、stream、type 与 operation contract，而不是默认维护一份教学 kernel。
