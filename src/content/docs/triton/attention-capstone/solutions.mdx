## 状态不变量与合并手算

任意非空键前缀处理后，`m=max(s)`、`l=Σexp(s−m)`、`a=Σexp(s−m)V`。新最大值 m′ 使所有旧项乘 `exp(m−m′)`，因此对 l 和 a 施加相同修正可保持定义。加入新块后扩展前缀，通过归纳可知最终除以 l 得到稠密注意力。FP16 概率转换使实际浮点实现只是该实数恒等式的近似。

合成分数先为 `[0,0]`、再为 `[ln(2),ln(2)]`，标量值先为 `[1,3]`、再为 `[5,7]`。第一状态为 `(0,2,4)`，新最大值为 ln(2)，修正 1/2，合并状态 `(ln(2),3,14)`，输出 **14/3**。平均两个块均值会得到错误的 4。这是数学案例，不声称存储的 FP16 输入能产生精确这些分数。因果首行唯一权重为一，输出等于键零处 V。

## 正确账本与可视化解释

N=32、D=16、BM=16 时，两个查询块读取 Q、写 O 各一次（`4Nd=2048 B`），读取 K/V 两次（`4*2Nd=4096 B`），共 **6144 B**。声明的物化稳定调度为 `8Nd=4096 B` 加 `24N²=24576 B`，共 **28672 B**。VIS18 全部采用 FP32，不能把它的元素数直接整体乘二。这里因果掩码改变概率却不跳过键块，因此流量模型不减半。

## 验收与报告解答

把标量参考测试、CPU FP64 框架输出检查、显式编译产物、GPU 输出检查和性能分析分为独立报告部分。`--mode compile` 无驱动也可有效执行，但不能替代 `--mode verify`。验收采集器检查全部五种形状 × 三类输入 × 两种掩码。MATH 对照必须通过；FLASH 要么检查输出，要么保留 unavailable-or-failed 诊断。FLASH 数值不匹配是失败，不是后端不可用。

全部正确性案例通过后才能开始计时。实现的范围两边都计入输出分配，排除适配器验证。保留三轮交替顺序和计时后输出检查。对 IO 假设，检查单独过滤的内存计数器、精确名称/单位及重放策略。清单不完整或计数器权限失败时，正确回答是 **无法确定 IO 机制**。解答不包含任何实测获胜配置或加速比。仅完成主机/编译的提交可以完成那些阶段，设备验收仍待完成。

## 常见错误与修正

| 错误 | 修正与区分性检查 |
| --- | --- |
| 只重缩放 l，不处理 a | 两者都乘 α；使用最大值改变案例 |
| 无效 K 填零却保留有限分数 | 无效分数设为 −∞；使用 N=17、均匀 Q |
| 因果不等式方向反了 | 要求 key≤query；验证首行等于首个 V |
| 每个键块重置状态 | 整个循环保留 m/l/a；使用 N=65 |
| 混用自然指数与 exp2 缩放 | 全程统一底数，对照独立参考 |
| 接受梯度却返回无追踪张量 | 拒绝 `requires_grad`；反向需要独立设计和测试 |
| 不断放宽容差直到单例通过 | 先检查掩码、缩放、转换和累加，保留全部失败 |
| 把模型字节比值叫作实测加速比 | 采集匹配计时与独立计数器，否则说明缺什么证据 |

## 有效替代方案

采用块局部 m/l/a、两个显式缩放因子的合并在数学上有效。exp2 递推也可行，但分数缩放和所有修正必须统一底数。因果注意力跳过完全未来的键块可作为后续候选，前提是新增所有权/覆盖证明、编译检查和全部数值案例，并修改工作量/流量账本。不同 BM/BN 需要重新声明候选与资源/形状检查，不能声称基线已调优。增加 BF16、反向、任意掩码或框架编译器集成属于独立契约，不是本解答隐含扩展。
