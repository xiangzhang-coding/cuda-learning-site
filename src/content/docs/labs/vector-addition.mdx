LAB02 是一个实验（Lab）：你在网站之外的 CUDA-capable environment 中执行步骤，网站只提供合同、预期观察和验收条件。没有可用硬件时，可以完成准备与预测，但不能填写运行观察。

## 实验合同

| 坐标 | 要求 |
| --- | --- |
| 预计时间 | 45 分钟 |
| 难度 | 入门（introductory） |
| 先修 | O03、F01 |
| 受支持环境（Supported Environment） | 仅原生 Linux；WSL、Windows 和托管 notebook 不在本站支持边界内 |
| Toolkit Lane | 选择 CUDA 11.8.0/Ubuntu 22.04、12.9.2/Ubuntu 24.04 或 13.3.1/Ubuntu 24.04 的 C++17 Lane；其他环境不得冒用 Lane 名称 |
| GPU Capability Tier | 基础 GPU 能力层级（Baseline GPU Capability Tier）；compute capability 7.5 或更新 |
| GPU 数量 | 恰好使用 1 个可见 GPU |
| 工作负载 | 默认 1,048,576 个 `float`；可选 `1..134,217,728`；最大三个 device vector 为 1,610,612,736 bytes（1.5 GiB），低于 8 GB |
| 权限 | 能访问所选 CUDA device；执行 NVCC、host compiler、`make` 和 binary；在 EX02 `build/` 中创建和删除文件；不要求性能计数器权限 |
| 正确性 | 所有 CUDA 边界通过；独立 CPU reference 接受每个元素；进程零退出 |
| 编译证据 | canonical EX02 在声明的 C++17 Lane 中为 Compile-Checked |
| 运行证据 | Pending Hardware Verification；本页没有 Reference Environment 运行记录 |

## 先修检查

1. 能解释 [O03](/start/environment-manifest/) 的 Environment Manifest 字段，并准备记录真实值。
2. 能回答 [F01](/foundations/first-cuda-kernel/) 的五道 retrieval questions，尤其是 partial block 和容差规则。
3. 选定上表的一条 C++17 Toolkit Lane。若你的原生 Linux 环境不匹配任何 Lane，可以把它记录为自己的环境，但不能继承已提交的 Lane 编译证据。
4. 确认将只使用一个 GPU，且它的 compute capability 为 7.5 或更新。


## 先预测

对默认规模和 `1003` 两个规模分别写下：block size `256`、向上取整后的 block count、launch thread 总数、最后合法 index 和越界 thread 数。需要重新检查坐标时使用共享的 [VIS02 索引讲解](/visuals/indexing/)；需要定位 launch 到完成的边界时使用 [VIS01 kernel 路径](/visuals/kernel-journey/)。它们是浏览器模型，不是本次 Lab 的运行证据。完成 LAB 后只比较这些结构性预测，不补写你没有测量的时间。

## 构建与 host-only 检查

错误检查 helper 来自 canonical source：

<CanonicalCode exampleId="EX02" range="error-checking" />

在项目目录运行 C++17 合同：

```sh
make preprocess DIALECT=c++17 BUILD_DIR=build
make compile DIALECT=c++17 BUILD_DIR=build
make link DIALECT=c++17 BUILD_DIR=build
make inspect DIALECT=c++17 BUILD_DIR=build
make host-test DIALECT=c++17 BUILD_DIR=build
```

保留完整 stdout/stderr 和每个命令的退出状态。`make host-test` 只检查 CPU reference 与比较函数；它不会执行 CUDA binary。若任一步失败，记录 blocker 并停止，不把失败或跳过写成 Compile-Checked。

## 验证正确性

CPU reference 和接受规则来自同一 canonical project：

<CanonicalCode exampleId="EX02" range="cpu-reference" />

本次 Lab 只有在下列条件全部成立时完成：

1. 三次 `cudaMalloc`、两次 host-to-device copy、`cudaGetLastError`、`cudaDeviceSynchronize`、device-to-host copy 和三次 `cudaFree` 均未触发错误路径。
2. 默认规模和 `1003` 两次运行都以状态 0 退出。
3. 每个 GPU 元素由独立 CPU reference 比较；绝对差 `<= 1e-5` **或**相对差 `<= 1e-5 * max(abs(expected), abs(actual))` 即接受，两者都不接受才失败。
4. Manifest、精确命令、日期、原始日志和 criteria result 一起保存；没有这些坐标，单独一行 `PASS` 不够。
5. 不根据这两次正确性运行声明 latency、bandwidth、speedup、occupancy 或 profiler 结论。

## 预期观察，不是记录结果

- 一个合格运行**应当**被独立 CPU reference 按绝对或相对容差接受。
- `1003` 个元素**应当**产生最后一个 partial block；global index `1003..1023` 的 thread 应跳过数组访问。

这些句子是执行前标准。本站没有观察到你的环境、输出或 GPU 行为；请把自己的实际观察放入单独记录，不修改预期来迎合结果。
