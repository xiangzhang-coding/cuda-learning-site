## 实验合同

构建一个原创相邻能量算子，完成注册、求导、两条本地路径测试，再把同一提前构建的 wheel 安装到干净匹配环境。实验（Lab）预计 120 分钟，另加环境准备。网站不运行 CUDA。无 GPU 构建和 CPU 检查是有用进展，但完成实验需要下列 CUDA 检查和完整记录。当前状态为**待硬件验证（Pending Hardware Verification）**，不是预填成功报告。

## 准备并预测

准备声明的 Python、GCC、Toolkit。使用该解释器创建并激活新虚拟环境，在下载仓库根目录执行：

```sh
python -I scripts/pytorch-environment/check.py --install
```

它在 EX22 增加自己的发行包之前安装并检查既有精确应用闭包。保留该阶段退出码。在外部复制 EX22 的空白 `environment-manifest.json`，作为自己的环境清单（Environment Manifest）；不得把目标要求填进观察字段。

预测字面量输入 [1,-2,2,2.5] 的结果、g=[1,2,3] 时加权梯度、单元素输出/梯度，以及 n=258 的启动形状。答案应为 [9,16,0.25]、[6,-22,13,3]、空/一个零，以及两个 256 线程块中的 257 个输出。这些是代数预测，不是运行输出；执行前解释它们。

## 验证数值、元数据和梯度

<CanonicalCode exampleId="EX22" range="checks" />

```sh
python -I verify.py --device cuda
```

验证器拒绝不可用或不足的硬件，在非默认当前流执行并汇合完成。检查全部前向输出和保留输入、非均匀上游梯度、float64 gradcheck 与 gradgradcheck、opcheck、显式 meta 调用、fullgraph 动态前向/反向。大小 1、2、256、257、258、1003 覆盖空输出和块边界。接受偏移连续输入，拒绝空、超预算、跨步、二维、整数、half 输入。二进制分数支持前向精确容差，数值导数使用 eps=1e-6、atol=1e-5、rtol=1e-3。不匹配、非有限结果、启动或完成错误都使该阶段失败；保留首个诊断。

## 证明打包与导入行为

计算构建 wheel 和已安装扩展的 SHA-256。创建**第二个**匹配 CPython 虚拟环境，从仓库根安装同一应用哈希锁依赖，再用 `python -m pip install --no-deps /absolute/path/to/wheel.whl` 安装这个确切 wheel。替换成你的真实路径，不能原样粘贴占位路径。运行 `python -m pip check`，再通过第二个解释器用 `-I --device cpu` 执行同一验证脚本。隔离模式下，脚本自己的路径不会成为包导入路径。

记录解析到的 `cuda_learning_ops`、`_C` 路径，它们必须属于第二个环境的 site-packages。每次检查使用新进程。在一次性环境中临时移除仅已安装的 `_C` 文件；即使源码目录仍存在，新隔离公开导入也必须失败。重装原 wheel 恢复后要求导入成功。不得存在 editable 安装、源码回退、导入时编译。负向检查用于区分产物完整性与单进程已经缓存或加载的本地模块。

两条本地路径**应当**构建成一个可导入 wheel。CPU/CUDA **应当**满足数值、导数、元数据和编译执行合同。移除已安装扩展**应当**导致导入失败。预期不是观察。编译证据为空，运行是**待硬件验证（Pending Hardware Verification）**，已记录观察为空。CI 构建不会自动成为编译已检查（Compile-Checked）；任意成功 GPU 运行也不会未经基准环境审查便成为运行已验证（Runtime-Verified）。
