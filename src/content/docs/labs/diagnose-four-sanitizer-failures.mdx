LAB07 是一个实验（Lab）。你在网站之外对 EX16 的四组 defect/corrected executable 做隔离检查；每次只让一个 Compute Sanitizer tool 观察一个 scenario，网站不执行 CUDA 或发布 sanitizer transcript。

## 实验合同

| 坐标 | 要求 |
| --- | --- |
| 难度与时间 | 中级（intermediate），约 120 分钟 |
| 先修 | Q03、Q04 |
| 受支持环境 | 仅原生 Linux；恰好一张 compute capability 7.5 或更新的 CUDA GPU |
| Toolkit Lane | CUDA 11.8.0、12.9.2 或 13.3.1，C++17；使用该 Lane 提供的 `compute-sanitizer` |
| 工作负载 | 每个 executable 独立进程；每进程 problem memory 最多 128 bytes |
| 工具顺序 | memcheck 必须先运行，再依次运行 racecheck、initcheck、synccheck；每个 tool 只运行 matching pair |
| 权限 | 执行编译工具、八个 binary、shell 与 Compute Sanitizer；允许 tool launch/instrument learner-owned child；写分离日志与状态；不要求 profiler performance counter |
| 验收 | defect 出现预先声明的 targeted report class；corrected 通过 exact host reference 且没有该 targeted report |
| 证据 | compilation 为空；runtime 为 Pending Hardware Verification；recorded observations 为空 |

## 先修检查

1. 完成 [Q03](/correctness/memcheck-invalid-memory-access/)，能说明 memcheck 的 executed-path scope，以及 clean report 为什么不是不存在其他缺陷的证明。
2. 完成 [Q04](/correctness/racecheck-initcheck-synccheck/)，能分别界定 shared-memory hazard、uninitialized device global memory 与 synchronization primitive misuse。
3. 确认可以执行 **one scenario per process**（每个进程一个 scenario），并能分开保存 tool/application logs and statuses。

## 预先声明报告类别

在运行前冻结下面的 **predeclared report class**。类别是验收粒度，不是 exact diagnostic text、error count 或 address promise：

| Tool | Defect targeted class | Corrected acceptance |
| --- | --- | --- |
| memcheck | device global-memory out-of-bounds access | exact 32-element host reference；没有 targeted bounds report |
| racecheck | shared-memory read-after-write data access hazard | exact produced value；没有 targeted hazard report |
| initcheck | uninitialized device global-memory read | exact initialized-output host reference；没有 targeted uninitialized-read report |
| synccheck | divergent block synchronization primitive/barrier misuse | exact 16-element host reference；没有 targeted synchronization report |

不要承诺 diagnostic 的逐字文本、报告条数、线程/块坐标、PC、source line 或地址。Tool version、driver、schedule 和终止边界都可能影响呈现。

## 验证正确性

在解释任何 sanitizer report 前，先把四个 corrected executable 各自作为独立进程直接运行：

```sh
for scenario in \
  memcheck-corrected racecheck-corrected \
  initcheck-corrected synccheck-corrected
do
  ./build/"$scenario" \
    >"lab07-evidence/direct-${scenario}.stdout.log" \
    2>"lab07-evidence/direct-${scenario}.stderr.log"
  status=$?
  printf '%s\n' "$status" \
    >"lab07-evidence/direct-${scenario}.status"
done
```

四个 corrected process 都必须通过源码内独立 host reference 的 exact comparison、全部必要 CUDA boundary 与零 application status。一个 `PASS` 字样不能替代原始 stdout/stderr、status 和逐项 criteria。任何解读之前，正确性必须先满足；不通过时 corrected 还不能作为修复证据。

Defect process 不承诺零状态：故障可能让 completion 失败。原样记录 application status，不把 nonzero 自动当作 targeted report，也不把 zero 当作 clean tool run。

## 运行隔离的 tool/scenario matrix

Run memcheck first, before racecheck, initcheck, and synccheck。严格按下表顺序；每行都是新的 `compute-sanitizer` process，且只包含一个 matching scenario：

| Order | Tool | Scenario |
| ---: | --- | --- |
| 1 | memcheck | memcheck-defect |
| 2 | memcheck | memcheck-corrected |
| 3 | racecheck | racecheck-defect |
| 4 | racecheck | racecheck-corrected |
| 5 | initcheck | initcheck-defect |
| 6 | initcheck | initcheck-corrected |
| 7 | synccheck | synccheck-defect |
| 8 | synccheck | synccheck-corrected |

对每行填写变量并单独执行下面模板。`--log-file` 保存 tool output；child shell 把 application stdout/stderr 与 application status 分开；外层保存 tool status：

```sh
tool='<fill matching tool>'
scenario='<fill scenario>'
binary="./build/${scenario}"
prefix="lab07-evidence/${scenario}"

compute-sanitizer --target-processes all --tool "$tool" \
  --log-file "${prefix}.tool.log" -- \
  sh -c '
    binary=$1
    stdout_path=$2
    stderr_path=$3
    status_path=$4
    "$binary" >"$stdout_path" 2>"$stderr_path"
    application_status=$?
    printf "%s\n" "$application_status" >"$status_path"
    exit "$application_status"
  ' sh "$binary" "${prefix}.application.stdout.log" \
  "${prefix}.application.stderr.log" \
  "${prefix}.application.status"
tool_status=$?
printf '%s\n' "$tool_status" >"${prefix}.tool.status"
```

这套 wrapper 通过 `--target-processes all` 让 tool 跟踪唯一 child binary，同时保留 separate tool/application logs and statuses。先用一行 probe 确认当前版本确实按该 contract 分离 channel；否则记录 blocker。不要并行运行、合并多个 scenario、重用失败后的 process，或只保存终端截图。

## 解读 defect/corrected 记录

逐 pair 验收：defect log 必须包含预先声明类别中的 targeted report；matching corrected application 必须再次通过 exact host correctness，且 corrected tool log 没有该 targeted report。若 defect 没有 targeted class，记录未复现；若 corrected 仍有 targeted class，修复未通过。二者都不能靠退出状态单独决定，因为 tool 的 `--error-exitcode` policy 与 application status 是不同坐标。

“Corrected 没有 targeted report”只约束这个 tool、版本、build、input、device 与 executed path。它不证明没有其他错误，也不允许把 racecheck、initcheck 或 synccheck 当作 memcheck。保留所有额外 report class 与 blocker，不为得到 clean 表格而过滤输出。

本 Lab 不承诺 exact diagnostic text、error count、address、thread coordinate、source line、tool exit number 或 defect application exit number，也不记录 timing 或性能结果。

## 预期观察，不是记录结果

- memcheck defect **应当**落入预先声明的 global-memory bounds report class；corrected **应当**精确保留 32 个 intended writes，且没有该 targeted report。
- racecheck defect **应当**落入 shared-memory data access hazard class；corrected **应当**精确保留 produced value，且没有该 targeted report。
- initcheck defect **应当**落入 uninitialized device global-memory class；corrected **应当**精确保留 initialized increment result，且没有该 targeted report。
- synccheck defect **应当**落入 synchronization primitive misuse class；corrected **应当**精确保留 phase-copy outputs，且没有该 targeted report。

这些是预期观察，不是记录结果。本页没有预填或虚构任何运行输出或 sanitizer 输出；`recordedObservations` 仍为空。
