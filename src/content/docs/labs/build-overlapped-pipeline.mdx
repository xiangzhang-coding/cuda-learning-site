## 复核 canonical source

`chunk-contract` range 固定 4,099 个元素、1,024 个元素一块、2 条 chunk streams、无溢出的 byte/chunk 计算、确定性 input/reference 与 exact verifier：

<CanonicalCode exampleId="EX07" range="chunk-contract" />

`stream-pipeline` range 固定 serial path 与 chunked path 的 H2D、同一 transform kernel、D2H、stream placement、从 serial completion 发出的 wait edge，以及 terminal events：

<CanonicalCode exampleId="EX07" range="stream-pipeline" />

Chunk offsets/counts 是 `(0, 1024)`、`(1024, 1024)`、`(2048, 1024)`、`(3072, 1024)` 与 `(4096, 3)`。每个 chunk 按 index modulo 2 选择 slot/stream；同一 stream 的顺序保护 slot reuse。完整 source 在 imported ranges 之外用 `cudaMallocHost` 分配三个 16,396-byte host buffers，总计 49,188 bytes；serial input/output 与两组 chunk input/output slots 的 device allocation 总计最多 49,176 bytes。

这些 source facts 只说明 intended graph 与 correctness oracle。Timing-disabled events、`asyncEngineCount`、`concurrentKernels`、page locking、`cudaMemcpyAsync` 和 multiple streams 都不记录执行 interval，也不证明 overlap。

## 构建并保留记录

在同一个 Bash session 中创建不可复用的学习者自有目录，再执行 EX07 的 C++17 build contract：

```bash
mkdir -p lab06-evidence
session_id="$(date -u +%Y%m%dT%H%M%SZ)-$$"
session_dir="lab06-evidence/session-${session_id}"
if ! mkdir "$session_dir"; then
  printf 'session directory already exists: %s\n' "$session_dir" >&2
  exit 1
fi
make preprocess DIALECT=c++17 BUILD_DIR=build
make compile DIALECT=c++17 BUILD_DIR=build
make link DIALECT=c++17 BUILD_DIR=build
make inspect DIALECT=c++17 BUILD_DIR=build
make host-test DIALECT=c++17 BUILD_DIR=build
sha256sum build/ex07-streams-events-overlap \
  >"${session_dir}/binary.sha256"
```

每条 build command 分别保留 expanded command、原始 stdout/stderr 和 exit status。任一步非零就把 session 标为 blocker 并停止依赖步骤。Host test 验证 pure chunk/reference contract，但不执行 CUDA，不能观察 page locking、copy engine、timeline 或 overlap。本地 build 也不会填充空的 compilation evidence。

## 首先验证正确性

先运行未被 profiler instrument 的 frozen binary：

```bash
./build/ex07-streams-events-overlap \
  >"${session_dir}/correctness.stdout.log" \
  2>"${session_dir}/correctness.stderr.log"
correctness_status=$?
printf '%s\n' "$correctness_status" \
  >"${session_dir}/correctness.status"
```

只有 application status 为零，serial 与 chunked 两行都报告 `PASS`，全部 CUDA checks 成功，而且 source review 确认两个 verdict 都来自 independent host reference 对全部 4,099 个 output 的 exact comparison，才可继续。不要用 tolerance、subset、单独一个 `PASS` 或 host test 代替这项 gate。

这次 uninstrumented run 是 correctness preflight，不是 profiler result。它来自单独 process，也不能被描述为消除了后续 `nsys` process 的 initialization 或 tracing overhead。正确性失败时，停止并拒绝所有 timeline、timing、bottleneck 与 speedup 结论。

## 通过能力门槛

把 EX07 输出中的 `asyncEngineCount` 与 `concurrentKernels` 原样保留，并记录取得这些值的 binary hash、device 和 status。`asyncEngineCount` 参与 compatible asynchronous copy/compute gate；`concurrentKernels` 是另一项 capability，不能替代 copy/compute eligibility。两个值都只是“可能发生什么”，不是 timestamped observation。

继续采集前逐项确认：恰好一张 visible GPU、compute capability 至少 7.5、49,176-byte device allocation 与 49,188-byte page-locked host allocation 成功、stream/event/CUDA checks 成功，并且 selected device/path 报告 compatible asynchronous copy/compute capability。任何一项缺失时，保留已经通过的 correctness 与 blocker，但不要声称 overlap eligible，也不要为了通过门槛更换未声明的 GPU。

通过 gate 仍不保证 overlap。Short copies/kernels、direction、dependency、resource availability、runtime scheduling 与 profiler overhead 都可能让 exact trace 串行或无法判定。

## 冻结时间线计划

在第一次 capture 前写下唯一问题：**Does the frozen chunked path exhibit overlap, serialization, or an inconclusive short trace?** 不要预设答案，也不要把“更快”当作本实验问题。

1. 冻结 source commit、binary SHA-256、Lane、device、4,099-element input、5-chunk partition、2 streams、build flags、full-process scope 与 `--trace=cuda`。
2. Correctness preflight 明确排除在 profiler observation 之外。Capture 恰好运行一次未修改的完整 EX07 process；不要 loop、batch、sleep、添加 NVTX 或增大 workload。
3. Capture boundary 是 process start 到 checked completion/cleanup。Serial path 先完成，chunk streams 通过 event wait 后开始；解读必须区分这两个 phase。
4. Classification rule 预先固定：在完整且可关联的 chunked phase 中，copy 与 kernel 的 observed intervals 相交才是 `overlap`；完整轨迹显示相关 intervals 不相交才是 `serialization`；dropped/incomplete records、stream/phase 无法关联或 interval 太短而不能可靠判断时是 `inconclusive`。
5. Tool/application failure 不得被选择性覆盖。修复后使用新 session directory 重新开始，并把旧 report、logs、statuses 与 blocker 全部保留。

与 expected-only fixture 对齐的 symbolic CLI command 是：

```bash
nsys profile --trace=cuda --output=lab06-timeline ./build/ex07-streams-events-overlap
```

实际 command 的 output base 必须位于本次唯一 `session_dir`。本计划没有 repetition statistic、timing baseline 或 speedup computation；短 workload 没有 guaranteed overlap。

## 采集并保管原始 report

  ./build/ex07-streams-events-overlap \

printf '%s\n' "$stats_status" >"${session_dir}/stats.status"
if [ -f "$stats_db" ]; then

## 解读 exact trace

先检查 application status、profiler diagnostics、dropped/incomplete records、report hash 与 stream/phase correlation。然后在 chunked phase 把 H2D/D2H direction、kernel interval、stream identity、event wait/record 与 dependency edge 放在一张 ledger 中。Serial phase 是 correctness-preserving baseline path，不是与 chunked path 同时执行的 overlap candidate。

只在两个 observed intervals 的时间范围实际相交时记录 overlap，并写出 report hash、process/context、stream、operation direction/name 与 interval coordinates。只有 complete qualifying trace 清楚显示 relevant intervals 不相交时才记录 serialization。若 interval 过短、rows 缺失、correlation ambiguous 或 tracing quality 不足，就记录 inconclusive；不能把空白 timeline 强改成 serialization。

`.nsys-rep` 是 primary artifact。`nsys stats` 聚合后会丢失 ordering；SQLite export 是 version/schema-dependent derived representation。两者用于查找和交叉核对，不独立证明 overlap。CUPTI tracing 是 instrumented execution，并受 buffering、delivery、overhead 与 dropped-record boundaries 约束。

即使本次观察到 overlap，也不能仅凭一条 trace 断言 pinned memory、two streams 或 engine count 是 cause，更不能推出 throughput、bottleneck 或 speedup。若本次串行，也不能把结果推广到所有 compatible GPUs。要进入 kernel-specific investigation，先按 [LAB08](/labs/profile-full-application-before-kernel/) 与 [VIS14](/visuals/nsight-systems-versus-nsight-compute/) 的 gate 选择 exact kernel/question；不要在 LAB06 中追加 Nsight Compute collection。
