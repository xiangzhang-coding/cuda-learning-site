LAB08 是一个实验（Lab）。本双语发布对（Publication Pair）要求你在网站之外、仅在原生 Linux（Native Linux）上运行 canonical EX07 可运行示例（Runnable Example）：正确性（correctness）首先通过，随后用分开的 Nsight Systems 与 Nsight Compute 执行建立环境清单（Environment Manifest）和决策链。页面本身不运行 CUDA；它只声明预期观察与证据状态（Evidence Status），当前 runtime 仍是待硬件验证（Pending Hardware Verification）。

## 实验合同

| 坐标 | 要求 |
| --- | --- |
| 难度与时间 | 中级（intermediate），约 150 分钟 |
| 先修 | 严格为 Q07、Q08 |
| 受支持环境（Supported Environment） | 仅 Native Linux；恰好一张 compute capability 7.5 或更新的 CUDA GPU |
| 工具包通道（Toolkit Lane） | `cuda-11.8`、`cuda-12.9` 或 `cuda-13.3`；同一 Lane 的 `nsys`、`ncu` 与兼容 CUPTI |
| 固定工作负载 | EX07 的 4,099 个 `std::uint32_t` 元素、serial 路径、五个 chunk 与两个 chunk streams；最大 device memory 为 49,176 bytes |
| 权限 | device、compiler、binary、report/log directory 与 CUDA trace 访问；管理员预先批准的 non-admin performance-counter access；禁止 `sudo`、临时提权和策略绕过 |
| 执行顺序 | unprofiled exact correctness，分开的 Systems collection 与 instance selection，随后才是最小 Compute collection |
| 证据 | compilation 为空；runtime 为 Pending Hardware Verification；recorded observations 为空 |

Nsight Systems 回答 application-level 定位问题；Nsight Compute 只回答已经选定的一个 kernel-level 问题。两份报告来自不同 instrumented executions，不能写成同一次 launch 的联合测量。

## 先修检查

1. 完成 [Q07：先用 Nsight Systems 阅读 application timeline](/correctness/timeline-first-nsight-systems/)，能够用 `.nsys-rep`、process、context、stream、correlation 或 launch occurrence 选中一个 exact kernel instance。
2. 完成 [Q08：用 Nsight Compute 询问一个 selected-kernel question](/correctness/kernel-first-nsight-compute/)，能够在 collection 前固定 question、filter、section/metric、replay、permission 与 custody。
3. 确认恰好一张 GPU 对进程可见，管理员已经批准非管理员 performance counters，且你有 learner-owned evidence directory。没有授权时停止；本实验绝不把 `sudo ncu` 当作修复。
4. [EX07](/examples/streams-events-overlap/)提供 fixed workload；[LAB06](/labs/build-overlapped-pipeline/)与 [VIS14](/visuals/nsight-systems-versus-nsight-compute/)是相关资源，不增加先修项。

在 EX07 project directory 中执行 canonical C++17 build：

## 冻结 Systems collection plan

## 保留 Systems-to-Compute decision trail

| Edge | 必需记录 | Stop rule |
| --- | --- | --- |
| Systems report -> selection | `.nsys-rep` SHA-256、phase、process、context、stream、name、occurrence/correlation | 不能唯一定位就返回 Systems |
| Selection -> question | 一个 mechanism、一个 symptom、一个可改变的 decision | “profile slow kernel” 不合格 |
| Question -> query | actual `ncu` version/help、section list、metric query、definitions 与 units | unavailable 就记录 blocker |
| Query -> Compute report | exact filter、skip/count、一个 section 或 short metric list、permission、replay | 目标不唯一或 permission denied 就停止 |
| Reports -> interpretation | 两个 report hashes、对应规则、不同执行声明、remaining alternatives | 不允许 same-run equivalence |

Decision 可以是继续 controlled baseline/candidate experiment、拒绝当前 hypothesis、证据不足或返回 Nsight Systems。单份 `.ncu-rep` 中的高 percentage、stall share、throughput 或 duration 不能自动命名 bottleneck；本 Lab 也不从 selection workflow 推导 speedup。
