本实验（Lab）在**网站之外**对比教学用的 EX15 内核与 EX18 cuBLAS 基准实现。这里提供可执行的测量步骤，不发布跑分。编译证据为空；运行仍为**待硬件验证（Pending Hardware Verification）**；实际观察记录为空。

## 实验约定

工具链已安装时，预计用时 **60–90 分钟**：源码与环境检查约 15 分钟，正确性检查约 20 分钟，测量约 20 分钟，解释与整理约 15–30 分钟。受支持环境（Supported Environment）仅限原生 Linux（Native Linux）。选择一张计算能力（compute capability，CC）不低于 7.5 的 GPU，问题内存预算不超过 8 GB；不要求张量核心（Tensor Core）。

必做对比采用行主序（row-major）FP32 `C = alpha*A*B + beta*C`，只覆盖三组小矩阵，不代表生产环境的全部 GEMM 工作负载。最大用例的设备端 A/B/C 共需 `4*(33*31 + 31*35 + 33*35) = 13,052` 字节。这是根据源码计算的容量，不包括 CUDA 上下文及库管理的工作区（workspace）；后两项应单独记录，内存不足时停止。问题规模适合 8 GB 预算，不等于已经测得进程内存占用。

## 对齐完整的数值问题

形状顺序为 **M,K,N**：`A[M,K] * B[K,N] -> C[M,N]`。三者均连续、行主序存储，数学问题本身不包含转置操作。

| 用例 | M,K,N | alpha | beta | 检查目的 |
| --- | --- | --- | --- | --- |
| `2x3x2-hand` | `2,3,2` | `1` | `0` | 手算索引与操作数顺序 |
| `33x31x35-partial` | `33,31,35` | `0.75` | `0.25` | M/N/K 不完整分块与初始 C |
| `32x32x32-aligned` | `32,32,32` | `1` | `0` | 对齐对照组，不是推荐工作负载 |

使用 EX15 的生成器，不另换随机种子。手算用例的 A、B 展平后均为 `[1,2,3,4,5,6]`，初始 C 全零，数学结果为 `[22,28,49,64]`。这是**手算参考值，不是已记录的 GPU 输出**。另外两组使用 `A[i]=(int(i%7)-3)/8.0F`、`B[i]=(int(i%5)-2)/7.0F`，初始 `C[i]=(int(i%3)-1)/5.0F`。只有形状一致还不够：运行前要与 EX18 逐字节核对全部 A/B/初始 C，并核对标量。随后两个候选共享同一份设备 A/B，每次操作前都恢复相同的初始 C。

cuBLAS 按列主序（column-major）解释这些字节。适配函数不实际搬动数据，而是计算 `C^T = alpha*B^T*A^T + beta*C^T`：`cublasGemmEx` 使用 `(transa,transb)=(CUBLAS_OP_N,CUBLAS_OP_N)`、维度 `(N,M,K)`、第一操作数 `(B,lda=N)`、第二操作数 `(A,ldb=K)`，以及 `(C,ldc=N)`。A/B/C 类型保持 `CUDA_R_32F`，计算类型为 `CUBLAS_COMPUTE_32F_PEDANTIC`，句柄（handle）数学模式为 `CUBLAS_DEFAULT_MATH`，算法为 `CUBLAS_GEMM_DEFAULT`。alpha/beta 是驻留主机的 FP32 标量，使用 `CUBLAS_POINTER_MODE_HOST`。仅设置默认数学模式并不能固定计算精度，显式 pedantic 计算类型不可省略。

对**每份完整输出矩阵独立验证**：CPU 以 double 累加，逐元素要求 `abs(actual-reference) <= 1e-4 + 2e-5*abs(reference)`。输入、参考值或输出出现非有限值时均拒绝。两个候选相互一致不能替代参考计算；容差通过也不保证逐位相同或跨库版本可复现。预热期间也必须恢复初始 C。beta 非零时，把上次结果当作下一次 C 会悄悄改变问题。

## 逐次测量并验证

独立示例只打印正确性，不打印时间。不要用 `time` 测量这些进程，再与事件时间作比较。先按 EX15/EX18 页面说明运行规范可执行文件，然后运行辅助程序：

```bash
date -u +%FT%TZ > "$run_dir/start-utc.txt"
set +e
"$run_dir/lab12-gemm-comparison" > "$run_dir/samples.txt" 2> "$run_dir/errors.txt"
status=$?
set -e
printf '%s\n' "$status" > "$run_dir/exit-status.txt"
date -u +%FT%TZ > "$run_dir/end-utc.txt"
nvidia-smi > "$run_dir/gpu-after.txt"
sha256sum "$run_dir"/*.txt > "$run_dir/logs.sha256"
test "$status" -eq 0
```

每组用例都先分配 A/B/C，创建一个显式 `cudaStreamNonBlocking` 流，并在采样前将一个 cuBLAS 句柄绑定到它。程序运行**三轮不计入统计的预热对**，随后运行**十轮测量对**：测量轮次为奇数时先 EX15 后 EX18，偶数时先 EX18 后 EX15。每次操作都等待完成并验证，预热也不例外。每组用例的 A/B 只上传一次；每次候选执行前均重置 C。

| 边界 | 必须执行的顺序 |
| --- | --- |
| 计时外 | 在所选流中将初始 C 复制到已有设备分配，开始前检查 `cudaStreamSynchronize` |
| 事件区间 | 在该流记录 start；启动一次 EX15 GEMM 或调用一次 EX18 适配函数；检查立即返回的状态；在同一流记录 stop |
| 完成检查 | 检查 `cudaEventSynchronize(stop)`，再调用 `cudaEventElapsedTime`；事件必须启用计时 |
| 计时外 | 在同一流回传完整 C，检查完成状态，执行 double 参考比较，保留该候选的结果状态 |

程序逐条输出以**毫秒**为单位的原始样本，保留用例、候选、轮次和顺序。每个用例与候选分别汇总 count=10、最小值、中位数（排序后第 5 与第 6 个值的均值）及最大值。预热行没有时间值。任何 API、完成、清理或数值检查失败都会导致非零退出；保留失败记录，不使用不完整汇总。修正后开始新运行，不删慢样本，也不拼接不同运行。

这里测量的是**未挂分析器的 GPU 事件区间**，不是 CPU 调用延迟、进程墙钟时间、含传输的延迟，也不是把报告中各内核耗时相加。cuBLAS 可能启动多个内核；主机提交间隙和其他 GPU 工作会影响区间。官方 API 给出的事件分辨率约为 0.5 微秒，这些小矩阵未必足以分辨有意义的差距。实际测到零时保留原值，但不能除以零，更不能凭分辨率受限的数据选赢家。本程序不输出包含初始化的计时系列：句柄创建、分配、H2D/重置、D2H、验证与资源释放均被排除。以后若要测量这些成本，需为两个候选另建边界完全相同的主机时钟实验。

性能分析**不是**完成这份 60–90 分钟实验的必要条件。如果计时留下了机制问题，在**独立运行**中遵循 [Q13 的分析边界](/correctness/gemm-optimization-case-study/)及对应版本官方手册。查询实际 GPU 可用的指标，取得合法计数器访问权限，识别实际 cuBLAS launch，并保留原始报告与哈希。不要假设一次库调用等于一个内核，不编造 cuBLAS 内核名、占用率、流量指标或 Tensor Core 结果。分析器时间不能替代原始、未挂分析器的事件样本。计数器拒绝访问时记录分析阻塞，不填零，也不使用 `sudo` 或修改安全策略。

TF32、FP16、BF16、FP8、FP4、浮点仿真、Tensor Core 路径、cuBLASLt 启发式选择、工作区调优、融合及更大形状均属于**独立实验**，各自需要硬件/版本门槛、回退路径、数值约定和匹配基线。CC 7.5 的 FP32 门槛不自动授权这些路径。L07 是进一步控制库行为的学习入口，不是悄悄替换本实验 API 的理由。

## 验收标准与阻塞

1. 解释 `(N,M,K; B,N; A,K; C,N)` 操作数映射，保留全部三组用例，包括初始 C 和各自 alpha/beta。
2. 对两个候选保留预热期间及每次计时操作后的独立参考检查成功记录，拒绝非有限值，不改变容差。
3. 提交完整清单、源码/构建/库身份、每组用例三轮排除的预热对及十轮交替测量对、所有原始毫秒值、最小/中位/最大值、日志和实际退出状态。
4. 区分事件区间、端到端延迟和分析器指标，给出有条件的维护结论，并指出至少一个尚未排除的其他解释。
5. 硬件/系统不受支持、库来源混乱或未核实、分配/API/完成失败、输出非有限或不匹配、样本缺失、条件漂移、清单不完整时，停止比较并提交阻塞，不补写结果。计数器拒绝访问只阻塞可选分析。

自行编写测量程序时，仍须保持上述边界并复用规范代码，不能复制内核。链接的辅助程序是测量任务的完整解答；其 CPU-only 模式可在不使用 CUDA 的情况下，通过相同参考计算检查行主序输出文件：

```bash
c++ -std=c++17 -DLAB12_HOST_ONLY -x c++ \
  -I examples/ex15-tiled-gemm/include -I examples/ex18-cublas-gemm/include \

"$run_dir/lab12-host" --check-fixtures
"$run_dir/lab12-host" --check-output 33x31x35-partial < matrix.txt
```

这里的 `matrix.txt` 必须恰好包含该用例输出的 1,155 个行主序 FP32 值。这个模式只检查给定数值，不执行或模拟 GPU。
