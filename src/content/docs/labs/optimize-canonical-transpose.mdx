## 冻结 workload 与内存算术

Declared performance workload 是：

```yaml
element_type: float
rows: 4096
columns: 4096
element_count: 16777216
bytes_per_element: 4
bytes_per_matrix: 67108864
global_matrix_count: 2
global_matrix_bytes: 134217728
logical_tile: 32x32
maximum_physical_shared_layout: 32x33
maximum_shared_bytes_per_block: 4224
declared_problem_bound_bytes: 134221952
canonical_correctness_fixture_bound_bytes: 20608
```

精确算术为：

- 一个 matrix：`4096 x 4096 x 4 = 67,108,864` bytes；
- 两个 global matrices：`2 x 67,108,864 = 134,217,728` bytes；
- 最大 stage-local shared tile：每 block `32 x 33 x 4 = 4,224` bytes；
- 保守 declared bound：`134,217,728 + 4,224 = 134,221,952` bytes。

该 bound 覆盖 canonical application problem model，不包含 host allocations、driver/context state、code、allocator granularity、全部 concurrently resident blocks、profiler libraries 或 replay save/restore storage。采集前必须检查 actual free memory 和 profiler requirements。

EX14 tiny correctness fixture 的 bound 是 `2 x (64 x 32 x 4) + 4,224 = 20,608` bytes。这个 **20,608-byte bound 与 LAB10 的 134,221,952-byte performance bound 不同，必须分开**；不得相互替换，也不得把任一 bound 称为 observed allocation traffic。

## 声明 stages 与 hypotheses

Learner-owned runner 按固定顺序各 launch 一次以下 stages。相邻 stage 形成三次 passes，每次只改变一个变量（one variable at a time）：

```yaml
stages:
  - stage_id: baseline-direct
    changed_variable: none; frozen direct output-linear baseline
    hypothesis: exact-GPU evidence 可以刻画 strided input reads 与 contiguous output writes；不预判 timing order
  - stage_id: coalescing-direction
    changed_variable: only thread-to-coordinate direction
    hypothesis: exact-GPU global-access evidence 可以区分 input-linear ownership 与 baseline-direct；不预判 metric value 或 winner
  - stage_id: shared-memory-tiling
    changed_variable: only unpadded 32x32 shared staging plus one uniform block barrier
    hypothesis: exact-GPU evidence 可以支持或拒绝 coalesced global reads/writes model，同时 exact output 保持不变
  - stage_id: padded-bank-layout
    changed_variable: only physical shared row stride changes from 32 to 33
    hypothesis: exact-GPU shared-bank evidence 可以支持或拒绝 padding model；不预判 direction、magnitude 或 winner
```

Baseline 使用 output-linear ownership：相邻 threads 写相邻 output elements，并读取 transposed input coordinates。Coalescing-direction pass 只翻转 ownership，使相邻 threads 读取相邻 input elements 并写 transposed output coordinates。Tiling pass 保持 input-linear ownership，增加 shared staging 与 uniform barrier，让静态模型在两端都表达 contiguous global access。Bank-layout pass 只把 physical shared stride 从 `32` 改为 `33`；它不增加 logical column。

四阶段之间**保持不变的常量（held constants）**是 EX14 parent 与 CPU reference、finite non-NaN deterministic input/oracle values、`4096x4096` shape、out-of-place mapping、exact comparison、每个 process 内的一份 stable device output allocation/address、每次 launch 前 identical checked full-output quiet-NaN sentinel procedure、每 block 256 threads、32x32 logical tile、每 thread 四个 cooperative slots、edge guards、stage order、一张 selected GPU、C++17 Lane、compiler/link options、candidate binary、process environment、synchronization rule、profiler executable、selected section/metrics、filter、replay controls 与 ten-attempt policy。Sentinel fill 与 complete-output readback 保持在 selected kernel metrics 之外。必须保留 reviewed source diff，证明每个相邻 stage 只改声明变量。若其他变量改变，就创建新实验。

这些是 explicit hypotheses，不是结论。LAB10 **不预填 timing、metric、speedup、bottleneck 或 winner**。

run_recorded() {
  local output_relative="$1"
  shift
  local stdout_path="${run_dir}/${output_relative}"
  local record_base="$stdout_path"
  case "$record_base" in
    *.stdout.log) record_base="${record_base%.stdout.log}" ;;
    *.csv) record_base="${record_base%.csv}" ;;
  esac
  local stderr_path="${record_base}.stderr.log"
  local status_path="${record_base}.status"
  local command_path="${record_base}.command"
  local records_hash_path="${record_base}.records.sha256"
  local record_path actual_status
  test "$#" -gt 0 || return 2
  for record_path in "$stdout_path" "$stderr_path" "$status_path" "$command_path" "$records_hash_path"; do
    test ! -e "$record_path" || return 1
  done
  printf '%q ' "$@" >"$command_path" || return 1
  printf '\n' >>"$command_path" || return 1
  "$@" >"$stdout_path" 2>"$stderr_path"
  actual_status=$?
  printf '%s\n' "$actual_status" >"$status_path" || return 1
  sha256sum "$stdout_path" "$stderr_path" "$status_path" "$command_path" \
    >"$records_hash_path" || return 1
  return "$actual_status"
}

## 保留 replay、report 与 hash custody

对每个 `.ncu-rep` 中的每个 stage，保留 requested/actual replay mode、pass count、memory save/restore behavior、cache control、clock control、serialization、selected device/context/stream/kernel/launch 与 measurement perturbation boundary。Nsight Compute 可能插入 measurement libraries，并因 requested counters 无法在一个 pass 中同时采集而 replay kernel。Kernel replay 可能保存 accessible memory 并恢复 written memory；application replay 则重复 host activity。必须记录 actual tool behavior，不预设任一 mode。

Profiled execution 不能与 direct run 互换。Metric count、section choice、first-kernel configuration、save/restore volume、cache state、clock policy 与 serialization 都可能影响 overhead/context。Report value 只支持 documented scope 下、带 perturbation record 的结论。
