## 顺序与直接查找

当前顺序依次列出 LAB01-LAB09，随后是 [LAB10：优化 canonical transpose](/labs/optimize-canonical-transpose/)。LAB10 的严格先修只有 [Q11](/correctness/transpose-optimization-case-study/)；它从 immutable [EX14](/examples/tiled-transpose/)开始，只把 [VIS11](/visuals/tiled-transpose/)复用为 evidence-neutral browser arithmetic。它声明 `4096x4096` `float` workload、134,221,952-byte 保守上界、一次排除的 warm-up、显式同步，以及十次 retained attempts 的 median 与 min/max 方法。[Q12](/correctness/reduction-optimization-case-study/)已经发布，但 LAB11 的 CUB comparison 仍等待未发布的 L03，因此 LAB11 不在本索引中。规划 ID 是跨课程讨论和维护时使用的稳定标签，不是 URL 稳定性承诺。请使用卡片中的当前链接，并在进入实验前完成卡片列出的全部先修学习单元（Learning Unit）。

## 证据边界

卡片中的编译和运行状态直接复制自链接实验的受控证据字段，不会把网站构建、筛选或浏览器测试升级为 CUDA 证据。既有 LAB01-LAB09 状态不变。LAB10 的 compilation evidence 与 recorded observations 为空、runtime 为待硬件验证（Pending Hardware Verification），只发布 expected observations；没有 Reference Environment 或 `performanceObservations`。它的 expected-only fixture 不是采集所得 `.ncu-rep`，也没有 timing、metric、speedup、bottleneck 或 winner。Immutable EX14、VIS11、static/browser evidence、host-only test、学习者本机构建与工具文档都不能填充 LAB10 的证据字段。
