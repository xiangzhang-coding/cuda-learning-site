LAB05 是一个实验（Lab）。你在网站之外保持 EX06 的逻辑工作不变，只观察明确的 unpadded 与 padded shared-memory layout；网站不会运行 CUDA 或填入 profiler 结果。

## 实验合同

| 坐标 | 要求 |
| --- | --- |
| 难度与时间 | 中级（intermediate），约 90 分钟 |
| 先修 | M04、Q05 |
| 受支持环境 | 仅原生 Linux；恰好一张 compute capability 7.5 或更新的 CUDA GPU |
| Toolkit Lane | CUDA 11.8.0、12.9.2 或 13.3.1，C++17 |
| 工作负载 | 一个 32-thread block；32 x 32 input tile；两份 32-element output；global + 较大 shared layout 的保守上限 8,576 bytes |
| 工具 | 与 Lane 对应的 Nsight Compute CLI（`ncu`），以及当前 GPU 实际提供的 shared-memory bank-conflict 相关指标 |
| 权限 | 设备、binary 与 evidence directory 访问，以及管理员预先批准的 performance counter permission；本 Lab 不允许临时提权 |
| 验收顺序 | unpadded/padded 相同 logical outputs 的 exact CPU-reference correctness，随后才允许 profiling 与解读 |
| 证据 | compilation 为空；runtime 为 Pending Hardware Verification；recorded observations 为空 |

## 验证正确性

先在 profiler 外运行 canonical binary：

```sh
./build/ex06-shared-memory-tile-bank-padding \
  >lab05-evidence/correctness.stdout.log \
  2>lab05-evidence/correctness.stderr.log

```

Unpadded 与 padded 必须产生相同 logical outputs；两个 variant 的全部 32 个 lane output 都必须与独立 CPU reference 精确比较一致，CUDA boundary 成功，application status 为零。不能放宽 comparison 或只比较两份 GPU output 而跳过 reference。任何解读之前，正确性必须先满足；否则拒绝 timing、profiler 与“padding 有效”的运行结论。

## 冻结测量计划

第一次 profiler collection 前固定：

1. 同一 source commit、binary SHA-256、Lane、device、input、logical work、variant order、build flags、launch geometry、`ncu` options 和 metric list；唯一 layout 变量是 padding。
2. 额外直接运行完整 binary 一次作为 process-level warm-up，复核 exact outputs，并从统计中排除。它不等价于在每个新 profiler process 内完成 steady-state warm-up。
3. 对相同 binary 恰好执行 10 次独立 measured profiler invocation，并按 acquisition order 保留每次 unpadded/padded 尝试。
4. 预先声明每个 layout/metric 的汇总为该固定 10-attempt batch 的 median 与 min/max spread，并且只有 10 次尝试全部合格时才计算。只有 nonzero tool/application status、correctness failure、missing kernel 或 missing metric value 可标 invalid；原记录和原因仍须保留，数值很大或不利于结论不构成 invalid。任一次 invalid 时不发布 summary，而是记录 batch blocker；修复原因后必须在新 batch directory 中重做全部 10 次，禁止选择性补样本或覆盖旧记录。

这就是 equal work/build/launch freeze。改变固定项后必须重启整个 batch，不能挑选或拼接样本。

## 解读记录

Event timing 与 profiler measurement 不能互换。Timing-enabled event 由 `cudaEventRecord` 标记 device timeline，完成后 `cudaEventElapsedTime` 返回该 event interval；canonical EX06 没有 event instrumentation。Nsight Compute 会插入 measurement library，并可能 replay、serialize、控制 cache/clock 或多 pass 采集；它的 duration 或 counter 只属于这份 profiler contract。

LAB05 不修改 binary 来添加 event，也不混合 event、wall-clock 与 profiler sample。新 event 实验必须重新声明 build、warm-up、同步边界与 statistic。

只有固定 10 次尝试在相同 metric、unit、options 与 device 下全部合格时，才把每次路径附到 median 与 min/max spread；否则只报告 blocker，不给 summary。地址模型可以解释 bank mapping，但本 Lab 不预言 unpadded/padded 的 profiler ordering、duration、latency、throughput 或 speedup。若 required metric 缺失或结果不支持解释，结论就是 blocker 或不确定，而不是预测。

## 预期观察，不是记录结果

- Unpadded 与 padded **应当**产生相同 logical outputs，并分别对全部 32 个 lane 通过 CPU reference exact comparison。
- Gate 通过后，每个 layout **应当**能关联自己的 raw bank-conflict profiler measurement、report 与 status；不承诺方向或数值。
- Warm-up **应当**被排除，固定 10 次尝试都**应当**保留；只有整批合格时才报告预先声明的 median 与 min/max spread。

这些是预期观察，不是记录结果。本页没有预填任何 GPU 数值、运行输出或 profiler 结果，`recordedObservations` 为空。
