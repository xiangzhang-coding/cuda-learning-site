EX12 is a standalone, original Inclusive and Exclusive Scan Runnable Example. The same C++17 project scans 4,099 bounded `std::uint32_t` inputs and checks both outputs with independent CPU references, exact recurrences, and a last-total invariant. The page publishes no timing or performance result.

## Purpose

Complete [A03: Inclusive and Exclusive Scan](/en/algorithms/inclusive-exclusive-scan/) first. EX12 turns A03's block-local prefixes, block sums, cross-block offsets, and exclusive identity into one independently buildable project. It verifies algorithm structure and exact correctness; it is not a replacement for a production primitive.

## CPU reference

The deterministic input repeats 1 through 7. The public host contract accepts at most 4,099 values and rejects a value above 7 before writing any output. Every prefix is therefore at most 28,693 and is exactly representable in `std::uint32_t`.

The inclusive and exclusive CPU references each perform an independent serial accumulation. The exclusive reference neither reads nor derives from the inclusive output:

## Multi-block scan

The first stage launches 17 blocks of 256 threads. Each thread writes a valid input or the identity 0 into shared memory. All threads therefore reach every `__syncthreads()` unconditionally even though the final block has only three valid elements. Each block produces local inclusive prefixes and one block sum.

The second stage scans 17 block sums in one bounded 256-thread block. The third stage adds the preceding scanned block sum as the offset for each local prefix. The final kernel derives `exclusive[i] = inclusive[i] - input[i]`:

<CanonicalCode exampleId="EX12" range="multi-block-scan" />

Guards protect memory accesses, not barriers. No thread returns before a block-wide barrier, and invalid lanes in the partial block participate in the same stages with value 0.

## Exact invariants

The host test and CUDA binary require exact full-array matches. They also check `inclusive[0] = input[0]`, `inclusive[i] = inclusive[i-1] + input[i]`, `exclusive[0] = 0`, `exclusive[i] = exclusive[i-1] + input[i-1]`, and `inclusive[i] = exclusive[i] + input[i]`.

An independent total for the complete deterministic input is 16,390. The last-total invariant requires both `inclusive[last] == 16390` and `exclusive[last] + input[last] == 16390`. This includes the three elements after index 4,095 instead of validating only full blocks.

## Build contract

From the project directory, run:

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

The CUDA stages create `build/inclusive_exclusive_scan.ii`, `build/inclusive_exclusive_scan.o`, and `build/ex12-inclusive-exclusive-scan`. Inspection checks a native `sm_75` cubin and PTX generated from `compute_75`. Host-test needs only a host C++17 compiler and prints `host-reference: pass` after every exact check succeeds.

`scripts/compile-check.sh c++17 ex12 <result-dir>` runs clean, preprocess, compile, link, inspect, and host-test in order. It retains logs and inspection artifacts but never executes the CUDA binary.

## Expected observations, not runtime records

1. The inclusive and exclusive device arrays should each report `PASS` only when all 4,099 `uint32` outputs exactly match their independent CPU references.
2. Every adjacent inclusive and exclusive prefix should satisfy the exact recurrences, including the identity at exclusive index zero.
3. Both last-total identities should produce 16,390 for the deterministic input, including the guarded three-element final block.

These are acceptance criteria. None is a recorded GPU observation.
