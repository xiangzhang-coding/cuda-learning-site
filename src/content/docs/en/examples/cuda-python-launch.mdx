## Independent CPU reference

<CanonicalCode exampleId="EX21" range="cpu-reference" />

Inputs are `a[i]=(i % 37)*0.25` and `b[i]=-(i % 19)*0.5`. The CPU reference reads stored `ctypes.c_float` inputs and adds them as Python floats. These small binary fractions and sums are exactly representable in float32, so require finite exact equality for **every** output. This is a fixture-specific rule, not a general floating-point policy.

Independent literal checks include `i=0 -> 0`, `19 -> 4.75`, `37 -> -9`, `256 -> 4`, and `1002 -> -6.25`. They are derived expectations, not a GPU transcript. Host tests cover sizes 1, 255, 256, 257, 1003, invalid counts and lengths, non-finite values, corruption at different positions, and mismatch counts. A host-test pass validates CPU logic only.

## Python lifecycle

<CanonicalCode exampleId="EX21" range="python-lifecycle" />

The run path selects visible device 0, calls `dev.set_current()`, and creates an owned nonblocking stream. Three device and three pinned host Buffers have equal byte extents. Only pinned host handles become ctypes views; those views borrow and do not retain their Buffer owners. The two input uploads and a NaN output-sentinel upload precede the kernel, so a missed store cannot accidentally match recycled memory. D2H has an explicit pinned host destination.

`stream.sync()` must succeed before output inspection. Every result is checked for finiteness and equality, retaining first mismatch and total count. Normal cleanup stops view use, closes Buffers on the same stream, drains queued frees with another checked sync, then closes the stream. Failure cleanup preserves the first exception and reports secondary errors/warnings; stderr may contain native cleanup diagnostics. Kernel/ObjectCode have no public close, Device has no close, and the shared primary context is not reset or destroyed.

## Runtime compilation and linking

<CanonicalCode exampleId="EX21" range="runtime-compile" />

Program compiles C++17 source with a virtual `compute_...` target and relocatable device code to PTX. `Linker(ptx, options=LinkerOptions(arch="sm_..."))` explicitly links it to cubin. The CLI refuses driver-linker fallback. Inspection checks the PTX entry/target and ELF cubin, then uses the selected Toolkit's `cuobjdump --dump-sass` to check the kernel and real target. No artifact size or SASS instruction listing is claimed before execution.

The no-GPU build uses explicit arch 75. It does not call Device, `set_current()`, `get_kernel()`, `launch()`, or `cuInit`. **It still needs real `libcuda` userspace:** core 1.2.0's PTX compilation queries `cuDriverGetVersion()`. A Toolkit stub, fake driver, or skipped stage is not a substitute. No NVCC invocation is needed. Loading occurs later at `linked.get_kernel("ex21_vector_add")`, not during cubin reconstruction or an invented `ObjectCode.load()` step.

## Kernel and argument contract

<CanonicalCode exampleId="EX21" range="kernel" />

The three pointer arguments are core Buffers; the final unsigned 32-bit count is `ctypes.c_uint32(n)`. Raw Python int packing is not signature inference. A 256-thread block and ceiling grid cover the input, with the bound checked before all array accesses. `run` accepts integers from 1 through 1000000; zero never submits a zero grid. The default n=1003 gives four blocks and 21 inactive tail threads.

Caller device payload is `12*n` bytes, 12036 by default and 12 MB at the maximum, plus equal pinned host payload. CPU reference storage, context/library/compiler allocations and actual free memory are additional; the static count is not total memory usage or allocation-success evidence. These sizes stay inside the Baseline GPU Capability Tier's 8 GB problem boundary.

## Setup and GPU-free build

Provision the exact interpreter, selected Toolkit, real driver userspace library, and cuobjdump first. From a fresh standalone working copy, `CUDA_PATH` defaults to `/usr/local/cuda-13.3`; if set, `CUDA_HOME` must resolve to the same root. Setup creates `.venv`, refuses to overwrite an existing one, and installs the exact four-wheel closure using `--require-hashes --only-binary=:all:`. It installs neither native CUDA extras nor the system interpreter/driver.

```sh
bash scripts/setup.sh
.venv/bin/python ex21.py host-test
.venv/bin/python ex21.py check-environment
.venv/bin/python ex21.py build --arch 75
```

On a prepared copy, omit setup. The default native environment check validates packages/imports/native libraries and supported architecture queries without device initialization. The build then compiles, links, and inspects without a GPU. Missing real driver userspace or an unsupported target is a failure, not permission to bypass a check.

For a development machine without CUDA packages, the separate CPU-logic check can use a local Python 3.10+ interpreter from the same project directory:

```sh
python3 -I -S ex21.py host-test
```

This mode neither imports CUDA nor validates the selected profile. It tests original input/reference/validator logic with stdlib ctypes storage and independent literals, not simulated device buffers. The interpreter exception applies only to `host-test`; setup, environment, build and run retain the exact CPython 3.14.7 profile.

Build outputs default to `build/compile`: `report.json`, `ex21.ptx`, `ex21.cubin`, `nvrtc.log`, `link-info.log`, `link-error.log`, and `sass.txt`. Existing result files are rejected. For another attempt, choose a fresh `--output-dir`, such as `build/compile-second`; do not overwrite an earlier verdict. Retain actual exit status and stderr with JSON reports. No successful build is asserted on this page.

## Separately gated run

Only after satisfying the runtime profile:

```sh
.venv/bin/python ex21.py run --size 1003
```

Run uses the selected GPU's exact supported target, rebuilds through the same PTX/link/inspection path, then loads, launches, copies and verifies. Results default to fresh `build/run`. To inspect a boundary size without overwriting that report:

```sh
.venv/bin/python ex21.py run --size 257 --output-dir build/run-257
```

**Acceptance:** Every output is finite and exactly equals its independently checked CPU reference; all submitted work completes before inspection and release; cleanup failures are not hidden. Keep source/profile identities, actual device and native-library records, stage diagnostics, artifact hashes, full-output verdict, warnings and exit status. ## Diagnose without erasing failure

Reports distinguish profile, library discovery, compilation, linking, artifact inspection, allocation, lazy lookup, launch, copy, sync, correctness and cleanup. An attempted launch with failed completion is not successful execution. An empty `nvrtc.log` on compile failure may coexist with the compiler log attached to the exception. Retain the first exception and subsequent log/cleanup errors separately. Failed work must exit nonzero, never fall back to comparing stale host output.

In the actual JSON contract, `launchAttempted` records submission intent, and `gpuExecuted` becomes `null` before submission because completion is unknown if launch, copy or sync fails. It becomes `true` only after the checked stream sync; a later correctness or cleanup failure still leaves `result: "fail"`. None of these fields alone is a maintainer Runtime-Verified claim. Retain both stdout JSON and stderr diagnostics.

The program supplies no timer. First-use compilation/loading, allocations, copies and CPU checking cannot be silently excluded from an end-to-end performance claim. Nonblocking stream or pinned-memory use alone is not an overlap measurement.

## Expected observations

1. The GPU-free build should produce PTX for compute_75 and a nonempty nvJitLink cubin with the original kernel's sm_75 SASS, without initializing a device/context or launching work.
2. The default run should submit four blocks of 256 threads for 1003 values; 21 tail threads should take the bounds guard.
3. After checked stream completion, every output should be finite and exactly equal to its CPU reference. CPU reference values should also match the independent literals.
4. Owned buffers should close on their submission stream before draining frees and closing that stream; logs and the first failure should survive cleanup attempts.
