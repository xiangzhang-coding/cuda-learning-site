EX15 is an independent, original C++17 CUDA Runnable Example. It implements row-major FP32 `C = alpha*A*B + beta*C` and checks output against an independent double CPU reference with finite absolute-plus-relative tolerance. The website executes no CUDA, and this page publishes no timing, throughput, utilization, speedup, or production-library comparison.

## Purpose

Complete A08 first. EX15 turns the naive-to-tiled mental model into a partial-safe project with three fixtures, one-block-per-output-tile ownership, zero-filled K tails, two uniform barriers, a guarded store, and deterministic mismatch reporting.

## Get the canonical project

[View the pinned EX15 project](https://github.com/xiangzhang-coding/cuda-learning-site/tree/0000000000000000000000000000000000000000/examples/ex15-tiled-gemm), or [download the same revision](https://github.com/xiangzhang-coding/cuda-learning-site/archive/0000000000000000000000000000000000000000.zip). ## Matrix contract

`A[M,K]`, `B[K,N]`, and `C[M,N]` are row-major. Every output owner evaluates `C[row * N + col] = alpha * sum(A[row * K + p] * B[p * N + col]) + beta * C[row * N + col]`. Fixtures are a hand-checkable `2x3x2`, all-partial/nonzero-beta `33x31x35`, and aligned `32x32x32`.

## CPU reference

<CanonicalCode exampleId="EX15" range="cpu-reference" />

The reference accumulates in double after validating dimensions and counts, pointers, finite inputs, and finite scalars. The verifier uses `atol=1e-4` and `rtol=2e-5`, rejects non-finite candidate/reference values and negative tolerances, and reports the first mismatch.

## Tiled GEMM

<CanonicalCode exampleId="EX15" range="tiled-gemm" />

One `16x16` thread block owns one `16x16` output tile. Each K slice guards and zero-fills partial A/B loads into two `float[16][16]` arrays, executes a barrier, 16 products, and a second barrier. The kernel has no return before a barrier, and the final C store is separately guarded.

There is no architecture-specific variant. Ordinary FP32, shared memory, and block barriers satisfy the CC 7.5 baseline. The single path is the portable fallback in every lane; EX15 introduces no WMMA, Tensor Core, TF32, `cp.async`, or Toolkit-specific fork.

## Host-model boundary

`make host-test` compiles only the pure C++17 header and test. It checks the hand oracle, all three fixtures, a near-zero absolute term, magnitude-scaled relative term, out-of-tolerance mismatch, NaN/infinity, negative tolerances, and mismatch coordinates. Success prints `host-reference: pass` but establishes no CUDA compilation or execution.

## Build contract

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

`scripts/compile-check.sh c++17 ex15 <result-dir>` runs clean and those stages, retaining logs, a cubin list, and a PTX dump without ever executing the CUDA binary. The artifact plan is native `sm_75` plus `compute_75` PTX.

## Expected observations, not runtime records

1. Each declared fixture should satisfy the finite atol + rtol * abs(reference) comparison against the independent double CPU reference.
2. The 33x31x35 fixture should exercise partial M, N, and K tiles while every thread reaches both block barriers in every K-tile iteration.
3. The portable FP32 baseline should preserve the declared alpha and beta contract without implying an architecture-specific instruction or performance result.
