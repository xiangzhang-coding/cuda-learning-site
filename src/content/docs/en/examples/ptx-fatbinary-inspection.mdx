EX10 is a build-only, inspection-only Runnable Example. It turns NVCC's public compilation phases into an auditable artifact chain without making artifact execution an acceptance step. Complete [M15](/en/toolchain/nvcc-compilation-flow/) and [M16](/en/toolchain/ptx-cubin-fatbinary/) first. M17, M18, M19, and VIS09 expand the target, linking, inspection, and visual models represented here.

## Purpose

This project asks what each stable compilation phase leaves behind and what the next phase consumes. It does not ask how fast a kernel runs. One small kernel separately produces preprocessing output, standalone PTX, a standalone cubin, and a fatbin carrying `sm_75` and `compute_75` images:

A second path deliberately crosses two CUDA translation units. `src/caller.cu` only declares and calls the device function defined by `src/device_math.cu`, so the two `-dc` objects require an explicit device link:

## Artifact matrix

| Stage | Primary output | Inspection and record |
| --- | --- | --- |
| preprocess | `artifact_kernel.ii` | Require a non-empty file and add it to the SHA-256 ledger |
| standalone PTX | `artifact_kernel.ptx` | Check `.target sm_75` and hash the file |
| cubin | `artifact_kernel.cubin` | Emit SASS, CUDA ELF, and symbol listings with `cuobjdump`; hash the cubin |
| fatbin | `artifact_kernel.fatbin` | List PTX and ELF images from this same container, dump embedded PTX, confirm the `compute_75`/`sm_75` paths, and hash the fatbin |
| relocatable compile | `device_math.o`, `caller.o` | Apply `-dc` to each translation unit; hash both and record pre-link symbols |
| device link | `device_link.o` | Run explicit `--device-link`; hash it and record linked CUDA symbols |
| host link | `ex10-ptx-fatbinary-inspection` | Use `--no-device-link` to perform only the host link; hash and never execute it |
| inspect | Same-fatbinary PTX/ELF lists, linked-artifact ELF list, PTX/SASS/ELF dumps, symbol/link ledger | Static evidence from version-recorded `cuobjdump`, GNU `nm`, and SHA-256 |
| artifact test | `artifact-test-report.txt` | Check files, targets, symbols, hashes, and the no-execution boundary |

## Complete pipeline

The Makefile exposes nine separate targets. The final host link cannot silently repeat the device link:

<CanonicalCode exampleId="EX10" range="artifact-pipeline" />

In a supported native Linux environment, invoke them in order:

```sh
make preprocess DIALECT=c++17
make standalone-ptx DIALECT=c++17
make cubin DIALECT=c++17
make fatbin DIALECT=c++17
make relocatable-compile DIALECT=c++17
make device-link DIALECT=c++17
make host-link DIALECT=c++17
make inspect DIALECT=c++17
make artifact-test DIALECT=c++17
```

`artifact-test` only reads files and invokes inspection utilities. It neither starts the final host artifact nor launches a kernel.

## Toolkit Lanes and the C++23 probe

| Checked subject | Dialect | Container boundary |
| --- | --- | --- |

The CUDA 13.3.1, NVCC 13.3.73, GCC 14.2.0 C++23 probe from the same run passed, but it is strictly a `C++23-Dialect-Probe`. It does not add C++23 to the ordinary EX10 matrix or declare another compiler, platform, source, runtime behavior, or performance. A failed or skipped job, or merely finding an image, still grants no status.

Runtime evidence is permanently Runtime-Not-Applicable. EX10's acceptance criteria are compilation, hashing, and artifact inspection, not GPU behavior.

## No runtime and no performance boundary

- Workflow containers receive no `--gpus`; ordinary containers run non-root on `linux/amd64` with `--network none`.
- The final host artifact exists only as host-link and inspection input and is never executed.
- The C++23 probe only produces and inspects an object file; it executes no host or GPU code.
- The page records no latency, throughput, speedup, occupancy, or other performance number.
- Compile-Checked does not substitute for Runtime-Verified. Runtime is outside EX10's acceptance criteria.
