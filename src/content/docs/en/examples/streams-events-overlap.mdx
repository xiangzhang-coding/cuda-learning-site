EX07 is a standalone, original Streams, Events, and Overlap Runnable Example. It applies one deterministic transform through a serial stream structure and a bounded chunked stream/event structure. The only verdict is complete correctness; the project has no timer and draws no conclusion about concurrent execution.

## Purpose

Complete M07, M08, and M09 in that order. EX07 combines named-stream ordering, timing-disabled dependency events, page-locked host buffers, and asynchronous copies in one small project. Q05 is related because it explains what a real measurement would require, but EX07 intentionally does not perform that measurement.

The two GPU paths hold input values, transform, element count, output order, and exact verifier constant. Their submission structures differ. This comparison proves whether both structures preserve the same result, not whether operations intersected in time.

## Chunk contract

The workload contains 4,099 `std::uint32_t` elements and uses a maximum chunk extent of 1,024 elements:

| Chunk | Offset | Count | End-exclusive |
| ---: | ---: | ---: | ---: |
| 0 | 0 | 1,024 | 1,024 |
| 1 | 1,024 | 1,024 | 2,048 |
| 2 | 2,048 | 1,024 | 3,072 |
| 3 | 3,072 | 1,024 | 4,096 |
| 4 | 4,096 | 3 | 4,099 |

The pure header computes that partition without CUDA and validates byte arithmetic before any allocation or copy:

<CanonicalCode exampleId="EX07" range="chunk-contract" />

Rejected zero chunk sizes, invalid indices, overflowing products, and undersized destinations leave caller outputs unchanged. The same header defines deterministic input, `output[index] = input[index] * 3 + 7`, and exact comparison.

## Stream pipeline

The serial path enqueues one H2D copy, one kernel, and one D2H copy in a named nonblocking stream, then records a timing-disabled completion event. Each chunk stream first waits on that captured serial prefix. Every chunk then places its H2D, kernel, and D2H operations in one named nonblocking stream, preserving the data dependency by same-stream order:

<CanonicalCode exampleId="EX07" range="stream-pipeline" />

Chunks alternate between two fixed device slots. Reusing a slot is safe because prior operations in that same stream precede later operations. Each launch is followed immediately by `cudaGetLastError`; a completion event is recorded after each stream's final D2H and synchronized before host verification. Events use `cudaEventDisableTiming`, and the source never calls an elapsed-time API.

The host input and both returned outputs are allocated with `cudaMallocHost`. `asyncEngineCount` and `concurrentKernels` are printed as capability fields only. Page locking, multiple streams, asynchronous API names, and those capability values do not prove that a copy engine was used or that any intervals overlapped.

## Host reference boundary

`make host-test` uses only the C++17 header and host test. It covers the exact five-chunk partition, zero elements, the three-element final chunk, overflow and undersized rejection, the complete 4,099-element expected transform, first-mismatch reporting, and nonmutation after rejected calls.

Passing this test establishes only pure software arithmetic and oracle behavior. It cannot establish that a host allocation was page-locked, a CUDA source compiled, a copy engine handled a transfer, a stream executed, or device work overlapped.

## Build contract

From the project directory on Native Linux, run:

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

The CUDA stages create `build/streams_events_overlap.ii`, `build/streams_events_overlap.o`, and `build/ex07-streams-events-overlap`. Inspection checks a native `sm_75` cubin and PTX generated from `compute_75`. Host-test needs only a host C++17 compiler.

`scripts/compile-check.sh c++17 ex07 <result-dir>` performs those stages and retains logs plus inspection artifacts. It never executes the CUDA binary, so its output cannot become runtime or concurrency evidence.

## Compilation and runtime evidence

EX07's compilation array is empty, so **EX07 is not Compile-Checked**. Runtime remains **Pending Hardware Verification**, and recorded observations are empty. The Learning Site has not executed this binary in a Reference Environment.

The page publishes no duration, bandwidth, throughput, speedup, copy-engine trace, stream timeline, or overlap verdict. A future observation would require a complete Environment Manifest and a method capable of supporting the particular claim; passing correctness remains a prerequisite.

## Expected observations, not runtime records

1. The serial and chunked paths should each report `PASS` only when all 4,099 outputs exactly match the pure host reference.
2. The pure host contract should produce four 1,024-element chunks followed by one 3-element chunk, with no gap or intersecting logical ranges.
3. `asyncEngineCount` and `concurrentKernels` should appear only as capabilities and should not be interpreted as evidence that submitted work overlapped.

These are acceptance criteria. None is a recorded GPU observation.
