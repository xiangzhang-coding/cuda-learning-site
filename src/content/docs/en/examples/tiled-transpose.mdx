EX14 is a standalone, original C++17 CUDA Runnable Example. It transposes three row-major `float` matrices into separate outputs, then compares each CUDA result exactly with a pure C++17 CPU reference. The website does not execute CUDA. This page publishes no speedup, global-memory transaction count, bank-conflict observation, timing, or profiler result.

## Purpose

Complete A05 first. EX14 turns rectangular-transpose shape, row-major mapping, edge-guard, shared-tile, and barrier contracts into a project that can be built independently. It establishes correctness acceptance criteria only. Source layout is not evidence of GPU behavior or performance.

## Canonical project

[View EX14 at its pinned commit](https://github.com/xiangzhang-coding/cuda-learning-site/tree/6993495d0bf1f62901eee151b2bf138c78d3c22f/examples/ex14-tiled-transpose), or [download the source archive for the same revision](https://github.com/xiangzhang-coding/cuda-learning-site/archive/6993495d0bf1f62901eee151b2bf138c78d3c22f.zip). `project.json` declares two canonical ranges, three fixtures, a 32 x 32 logical tile, a 32 x 8 block, a 32 x 33 shared layout, a conservative 20,608-byte memory bound, three C++17 Toolkit Lanes, and an empty compilation axis. The project source and page prose are original; software files use Apache-2.0. No NVIDIA owner source, sample, figure, or result is copied.

## Matrix contract

The input shape is `rows x columns`, and the output shape must be `columns x rows`. Both use row-major flattening. Every valid `(row, col)` coordinate must satisfy:

```text
output[col * rows + row] = input[row * columns + col]
```

The deterministic fixtures are `5x7`, `33x35`, and `64x32`. The first two leave one or both axes in a partial tile; the third is a tile-aligned rectangular shape. Fixture values are positive integers represented exactly by `float`. Transpose performs no arithmetic, so CPU and CUDA outputs use exact float equality.

## Tiled transpose

The CUDA source declares a 32 x 32 logical tile, `BLOCK_ROWS=8`, and `__shared__ float tile[32][33]`:

<CanonicalCode exampleId="EX14" range="tiled-transpose" />

Each 32 x 8 block covers 32 local rows by looping the thread's y coordinate in increments of eight. The load guard checks both input row and column. Every thread then reaches the only `__syncthreads()` unconditionally. The store guard independently checks the transposed output extents. The kernel has no return before the barrier.

The 33rd shared column is physical storage padding only. It is not a logical matrix column, does not change output shape, and creates no output value. This project does not observe or quantify its bank behavior on a GPU.

## Host model boundary

`make host-test` compiles only `tests/host_reference_test.cpp` and the pure C++17 header. It checks all three output dimensions and every mapping, verifies exact equality and mismatch coordinates, and covers the non-writing rejection boundaries for an unknown fixture, zero or overflowing dimensions, null pointers, incorrect sizes, an incorrect output shape, and an in-place request. It prints `host-reference: pass` on success.

The host test includes no CUDA header or syntax and launches no kernel. It cannot establish CUDA compilation, device allocation or copies, shared-memory access, barrier participation, GPU edge guards, or GPU execution. Passing it grants no CUDA compilation or runtime Evidence Status.

## Build contract

From the project directory on Native Linux, run:

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

The first four stages require the selected CUDA Toolkit; host-test needs only a host C++17 compiler. CUDA stages create `build/tiled_transpose.ii`, `build/tiled_transpose.o`, and `build/ex14-tiled-transpose`. Inspection checks a native `sm_75` cubin and PTX generated from `compute_75`.

`scripts/compile-check.sh c++17 ex14 <result-dir>` performs clean, preprocess, compile, link, inspect, and host-test while retaining logs and inspection artifacts. It never executes the CUDA binary, so it supplies no GPU observation.

## Expected observations, not runtime records

1. For `5x7`, `33x35`, and `64x32`, the CUDA output should match the independent CPU transpose reference exactly at every element.
2. Each fixture's output shape should be input columns x input rows, and every valid coordinate should satisfy `output[col * rows + row] = input[row * columns + col]`.
3. The extra shared-memory padding column should affect storage extent only: it should add no logical matrix column, alter no output value, and produce no output outside guarded dimensions.

These are correctness, dimension, and padding-neutral acceptance criteria that the Learning Site has not observed. They contain no measured performance conclusion.
