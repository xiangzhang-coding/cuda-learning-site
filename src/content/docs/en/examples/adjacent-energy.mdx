## Contract

Prerequisites: [P08](/en/frameworks/first-custom-operator/) and [P09](/en/frameworks/operator-registration/). Compute `y[i]=(x[i+1]-x[i])^2` for contiguous rank-one strided CPU/CUDA float32 or float64 tensors with 1 through 1,000,000 elements. Return fresh contiguous n-1 output on the same device and dtype without mutation or alias. A contiguous offset view works; a stride-two view, empty input, half/integer dtype or batched shape is rejected. A singleton returns empty output. Ordinary nonfinite arithmetic is not masked. This is original instructional code, not an adapted tutorial operator or a performance benchmark.

## CUDA implementation

<CanonicalCode exampleId="EX22" range="cuda" />

Select the input device and its current stream. For n=258, 257 outputs require two blocks with 255 inactive threads. Skip launch for n=1. The launch check reports submission errors; correctness checking still requires successful completion. No private stream, device-wide synchronization or allocator ownership transfer occurs inside the operator.

## Fake and meta

<CanonicalCode exampleId="EX22" range="fake" />

Only metadata is read. A new n-1 tensor preserves dtype/device and the fresh contiguous output contract; symbolic constraints do not turn lengths into concrete Python integers.

## Autograd

<CanonicalCode exampleId="EX22" range="autograd" />

With q=2*diff(x)*g, left padding supplies each edge's positive right-end contribution, and right padding supplies the negative left-end contribution. This handles singleton input and permits higher derivatives through ordinary tensor operations.

## Independent reference

<CanonicalCode exampleId="EX22" range="reference" />

For input [1,-2,2,2.5], the hand-derived output is [9,16,0.25]. Nonuniform upstream g=[1,2,3] gives dx=[6,-22,13,3]. These are predictions. Binary-fraction generated inputs permit exact forward comparison; float64 finite differences use eps=1e-6, atol=1e-5, rtol=1e-3.

## Correctness and integration checks

<CanonicalCode exampleId="EX22" range="checks" />

The complete verifier adds explicit meta calls and a separately selected CPU or CUDA mode. CUDA mode refuses missing hardware and checks CC >= 8.0 and at least 8 GB. It runs on a non-default stream and joins completion. Opcheck checks registration; gradcheck checks the mathematical derivative; fullgraph dynamic compilation tests integration, not fusion or speedup. Input/output payload is below 16 MB at the maximum double-precision length; compiler/context/test storage is extra.

## Build, install and execute

Prepare a fresh CPython 3.12.14 venv using the exact command-scoped bootstrap settings in [LAB13 preparation](/en/labs/build-custom-operator/#prepare-and-predict). That command hides GPUs only for preparation, selects the native allocator and restricts loader paths to the interpreter library. Provision GCC and Toolkit separately. From the EX22 root:

```sh
bash scripts/check-wheel.sh
python -I verify.py --device cuda
```

The first command builds both paths, installs the wheel, checks dependencies, validates isolated installed imports and executes CPU integration checks without a GPU. The second requires one suitable CUDA device and a compatible driver, conservative baseline 570.124.06. Never call a missing CUDA device a passing skip. Keep complete stage exit codes and diagnostics; failed builds/imports are failures even if source execution works. [LAB13](/en/labs/build-custom-operator/) supplies the full packaging and Environment Manifest acceptance procedure.
