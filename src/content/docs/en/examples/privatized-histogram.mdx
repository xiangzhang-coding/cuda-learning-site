EX13 is a standalone, original C++17 CUDA Runnable Example. It computes a 16-bin histogram for the `uniform`, `skewed`, and `boundary` fixtures, then compares the global-bin and block-private CUDA paths exactly with the same CPU reference. The website does not execute CUDA. This page publishes no contention observation, timing, or performance result.

## Purpose

Complete A04 first. EX13 turns A04's atomic-update, block-privatization, barrier, and merge structure into a project that can be built independently, but it verifies correctness only. Source structure alone cannot establish contention behavior or support a performance conclusion.

## Canonical project

[View EX13 at its pinned commit](https://github.com/xiangzhang-coding/cuda-learning-site/tree/81d43aa7568514e37ef190da59c845b8072b7011/examples/ex13-privatized-histogram), or [download the source archive for the same revision](https://github.com/xiangzhang-coding/cuda-learning-site/archive/81d43aa7568514e37ef190da59c845b8072b7011.zip). The project directory is `examples/ex13-privatized-histogram/`.

`project.json` declares two canonical ranges, three fixed fixtures, 16 bins, 259 inputs, a 128-thread block, a conservative 1,228-byte memory bound, three Toolkit Lanes, and an empty compilation axis. The project source and page prose are original; software files use Apache-2.0.

## Fixture contract

`uniform` generates `index % 16`, so bins 0 through 2 contain 17 values each and the remaining bins contain 16 each. The literal expected counts for `skewed` are 17 in bin 0, 226 in bin 7, 16 in bin 8, and zero elsewhere. `boundary` uses only the two legal endpoint values, placing 130 values in bin 0 and 129 in bin 15.

With 259 inputs and a 128-thread block, the grid has two full blocks followed by a partial block with three active threads. Both kernels guard input updates with `index < value_count`; the guard never encloses a block barrier.

## CPU reference

The pure C++17 header generates all three fixtures, computes the reference in a temporary 16-bin array, rejects out-of-range bins, and supplies both per-bin exact comparison and the sum-of-bins invariant:

The reference updates the caller's output only when the input count is exactly 259, the pointers are valid, and every value lies in `[0, 15]`. Every valid fixture must satisfy `sum_of_bins(histogram) == 259`.

## Histogram kernels

The CUDA source defines and launches `global_histogram_kernel` and `privatized_histogram_kernel`:

<CanonicalCode exampleId="EX13" range="histogram-kernels" />

The first path applies `atomicAdd` to a separate global output. The second gives each block 16 shared-memory private bins, passes through unconditional zero, update, and merge barriers in that order, then atomically merges block-local counts into another global output. This structure states update placement and synchronization order. It is not a contention or performance observation.

## Host model boundary

`make host-test` compiles only `tests/host_reference_test.cpp` and the pure C++17 header. It compares the three CPU-reference results with hand-written literal histograms, checks every sum-of-bins invariant, rejects an unknown fixture and an out-of-range bin, and verifies deterministic mismatch location. It prints `host-reference: pass` on success.

The host test includes no CUDA header and launches no kernel. It cannot establish shared-memory, barrier, atomic-update, merge, or GPU-execution behavior. Passing it grants no CUDA compilation or runtime Evidence Status.

## Build contract

From the project directory on Native Linux, run:

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

The first four stages require the selected CUDA Toolkit; host-test needs only a host C++17 compiler. CUDA stages create `build/privatized_histogram.ii`, `build/privatized_histogram.o`, and `build/ex13-privatized-histogram`. Inspection checks a native `sm_75` cubin and PTX generated from `compute_75`.

`scripts/compile-check.sh c++17 ex13 <result-dir>` performs clean, preprocess, compile, link, inspect, and host-test while retaining logs and inspection artifacts. It never executes the CUDA binary, so it supplies no GPU observation.

## Compilation and runtime evidence

EX13's compilation array is empty, so **EX13 is not Compile-Checked**. Runtime is **Pending Hardware Verification**, and recorded observations are empty. A passing host test populates no CUDA evidence axis.

This page does not claim observed GPU output, atomic behavior, barrier behavior, contention, timing, throughput, speedup, or profiler results. A future runtime record must come from a declared Reference Environment, include a complete Environment Manifest, and preserve all three fixtures, both kernels, and every exact acceptance criterion.

## Expected observations, not runtime records

1. For `uniform`, `skewed`, and `boundary`, the global-bin kernel should match the independent 16-bin CPU reference exactly, bin by bin.
2. For the same three fixtures, the block-private shared-memory kernel should match the independent 16-bin CPU reference exactly, bin by bin.
3. For both CUDA paths and every fixture, the sum of all 16 output bins should equal the 259 input values.

These are correctness acceptance criteria that the Learning Site has not observed. They contain no contention or performance judgment.
