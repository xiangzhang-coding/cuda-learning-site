EX08 is a standalone, original Unified Memory Migration Runnable Example. One phased workload initializes a managed allocation on the host, transforms it on the device, completes the CUDA stream, and verifies every value on the host. Capability reports and a separate software model never substitute for a runtime observation of memory behavior.

## Purpose

Complete M10 first. M01 and M02 supply related address-space and global-memory context, while VIS08 is the related browser model. EX08 focuses on the boundary between a correct program structure and an unsupported inference about what the memory system did internally.

Correctness depends only on deterministic initialization, one declared transform, explicit completion, and exact full-array comparison. It does not depend on where a page resided, whether a fault happened, whether bytes moved, or whether an optional hint changed behavior.

## Access sequence and software proxy

The pure C++17 model accepts a sequence of `(page, access origin)` records. The declared fixture names 16 logical pages in this order:

| Phase | Access origin | Pages |
| --- | --- | --- |
| host initialization | host | 0 through 15 |
| device transform | device | 0 through 15 |
| host verification | host | 0 through 15 |

The first access to a page establishes its initial software-model origin. A later change of origin appends one transition to the ledger. Repeating the same origin appends nothing:

<CanonicalCode exampleId="EX08" range="access-sequence" />

For the declared sequence, the model derives 32 transitions. With the declared logical page size of 4,096 bytes, its cost proxy is 32 moved-page units and 131,072 moved-byte units. These are arithmetic outputs of the supplied sequence. The model does not query CUDA, the operating system, physical page sizes, hardware coherence, residency, faults, or movement.

The function validates every page and origin, the moved-byte multiplication, and output capacity before writing the ledger or summary. Invalid or undersized input therefore leaves caller output unchanged.

## Managed workload

The CUDA source calls `cudaMallocManaged`, performs deterministic host initialization, builds a separate expected array, and launches one in-place XOR kernel in a named nonblocking stream:

<CanonicalCode exampleId="EX08" range="managed-workload" />

The program queries `managedMemory` and `concurrentManagedAccess` from `cudaDeviceProp` and prints both as capabilities. If `concurrentManagedAccess` is nonzero, it submits preferred-device advice and prefetch requests before the kernel, followed by a host prefetch request in the same stream. Those calls are optional hints. A successful call reports only API acceptance, not a measured placement or transfer.

CUDA 11.8 uses integer destination arguments for `cudaMemAdvise` and `cudaMemPrefetchAsync`. CUDA 12.9 retains those interfaces while introducing location-based variants. CUDA 13.3 uses the location-based signatures under the current names. The source branches on `CUDART_VERSION` so the same C++17 build input uses the appropriate contract in each declared Lane.

The kernel launch receives an immediate `cudaGetLastError` check. `cudaStreamSynchronize` is the explicit completion and completion-error boundary. Only after it succeeds does the host read managed data and compare all 16,384 values. Stream destruction and `cudaFree` follow completion and verification.

## Host model boundary

`make host-test` is CUDA-free. It covers a sequence with no transition, repeated origins, alternating host/device origins, invalid page and origin values, moved-byte overflow, undersized ledgers, the exact 32-transition declared fixture, full expected output, first mismatch, and nonmutation after rejection.

Passing the host test establishes the software model and oracle only. It cannot establish managed-memory availability, optional-hint support, runtime residency, a fault, or migration.

## Build contract

From the project directory on Native Linux, run:

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

The CUDA stages create `build/unified_memory_migration.ii`, `build/unified_memory_migration.o`, and `build/ex08-unified-memory-migration`. Inspection checks a native `sm_75` cubin and PTX generated from `compute_75`. Host-test needs only a host C++17 compiler.

`scripts/compile-check.sh c++17 ex08 <result-dir>` performs those stages and retains logs plus inspection artifacts. It never executes the CUDA binary and therefore supplies no managed-memory runtime observation.

## Compatibility

| Coordinate | Declaration |
| --- | --- |
| Supported Environment | Native Linux only |
| Runtime gate | One CUDA GPU with compute capability 7.5 or newer and `managedMemory` available |
| Baseline GPU Capability Tier | One 65,536-byte managed allocation, far below 8 GB |
| Optional-hint gate | Submit advice and prefetch only when `concurrentManagedAccess` is nonzero |
| Compiler target | Native `sm_75` cubin plus PTX generated from `compute_75` |
| Language contract | The same original C++17 source with a cross-Lane API-signature branch |

The exact Lanes are CUDA 11.8.0 on Ubuntu 22.04 x86-64, CUDA 12.9.2 on Ubuntu 24.04 x86-64, and CUDA 13.3.1 on Ubuntu 24.04 x86-64. Digest-pinned images are build targets, not evidence records.

## Compilation and runtime evidence

EX08's compilation array is empty, so **EX08 is not Compile-Checked**. Runtime is **Pending Hardware Verification**, and recorded observations are empty. The Learning Site has not run the workload in a Reference Environment.

No statement on this page says that a page fault or migration occurred. Capability values, source-level phases, accepted advice, accepted prefetch, and the software proxy are not equivalent to an observed runtime mechanism. A future claim needs a suitable observation method and complete Environment Manifest in addition to correctness.

## Expected observations, not runtime records

1. The workload should report `PASS` only after explicit completion and exact comparison of all 16,384 values.
2. `managedMemory` and `concurrentManagedAccess` should be capability fields; advice and prefetch should remain optional guarded requests rather than movement observations.
3. The software fixture should derive 32 transitions, 32 moved-page units, and 131,072 moved-byte units as a cost proxy independent of runtime behavior.

These statements are acceptance criteria and model outputs, not recorded migration evidence.
