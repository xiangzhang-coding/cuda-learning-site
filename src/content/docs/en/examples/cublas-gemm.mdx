EX18 is an original standalone C++17 cuBLAS GEMM Runnable Example. It checks correctness, not speed. CUDA runs only in an external environment, never in this Learning Site.

## Purpose

Complete [L06: cuBLAS GEMM](/en/libraries/cublas-gemm/) first. EX18 makes layout, leading dimensions, precision, handle state, and stream completion explicit in one buildable project. [L07: cuBLASLt Matmul](/en/libraries/cublaslt-matmul/), [EX15: Tiled GEMM](/en/examples/tiled-gemm/), and [LAB12: Compare GEMM with cuBLAS](/en/labs/compare-gemm-with-cublas/) are related resources, not additional prerequisites.

## Independent CPU Reference

<CanonicalCode exampleId="EX18" range="cpu-reference" />

The header preserves this site's original EX15 input generator and oracle logic without an EX15 dependency. A and B are stored as `float`, then converted to `double` for multiplication and serial accumulation. Initial C and alpha/beta are included in that independent calculation. No cuBLAS result is used to construct expected output.

| Fixture, in M,K,N order | alpha | beta | What it checks |
| --- | --- | --- | --- |
| `2,3,2` | 1 | 0 | A and B each contain 1 through 6, C starts at zero; literal row-major result `22,28,49,64` |
| `33,31,35` | 0.75 | 0.25 | Non-square extents and an observable initial-C contribution |
| `32,32,32` | 1 | 0 | The same aligned fixture used by EX15 |

For the latter two fixtures, A repeats `(i%7-3)/8`, B repeats `(i%5-2)/7`, and C repeats `(i%3-1)/5`, using signed subtraction and float division. Every output must be finite and satisfy `abs(gpu-cpu) <= 1e-4 + 2e-5 * abs(cpu)`. Passing requires checking the full matrix, not a sample or checksum. A failure reports the first mismatching row and column. Tolerance is fixed before execution; it does not imply bitwise equality or cross-GPU reproducibility.

## Row-Major GEMM Mapping

<CanonicalCode exampleId="EX18" range="gemm-call" />

The input contract is row-major `C[M,N] = alpha*A[M,K]*B[K,N] + beta*C[M,N]`. The same bytes are column-major transposes, so compute `C^T = alpha*B^T*A^T + beta*C^T`. Pass B first and A second, swap M and N, and use `(lda,ldb,ldc)=(N,K,N)`. Both operations are `CUBLAS_OP_N`: the transpose is already represented by the memory interpretation, not by an extra transpose flag or a data-conversion kernel.

All three matrix data types are `CUDA_R_32F`. `CUBLAS_COMPUTE_32F_PEDANTIC` explicitly selects single-precision arithmetic; `CUBLAS_DEFAULT_MATH` alone is not the precision contract. The program requests neither FAST_TF32 nor lower-precision/emulated computation and uses `CUBLAS_GEMM_DEFAULT` rather than an architecture-specific algorithm. This correctness baseline is not a promise about the fastest library configuration.

## Stream And Resource Lifetime

<CanonicalCode exampleId="EX18" range="stream-lifecycle" />

One handle and one `cudaStreamNonBlocking` stream are reused across all three cases. `cublasSetPointerMode(..., CUBLAS_POINTER_MODE_HOST)` gives host alpha/beta addresses their intended meaning. `cublasSetStream` runs before work and resets the library workspace to its default pool. EX18 installs no user workspace; do not treat it as a zero-workspace operation.

Each case restores initial C, enqueues A/B/C H2D copies, GEMM, and the C D2H copy on that same stream, then checks `cudaStreamSynchronize` before validation or buffer reuse. Submission success is not completion. Host vectors are pageable, so `cudaMemcpyAsync` does not establish transfer overlap.

RAII cleanup synchronizes again before releasing the handle, device buffers, and stream, including after partial allocation or submission failure. Every release is attempted without short-circuiting; a cleanup failure makes the process fail. Host storage is constructed before the owner and outlives cleanup. The three normal completion boundaries and final cleanup boundary are not timings.

## Build And Run

The CPU test needs no CUDA headers or GPU:

```sh
make host-test DIALECT=c++17
```

It checks literal GEMM results, alpha/beta, double accumulation under cancellation, all fixture values, tolerance boundaries, final-element corruption, nonfinite output, and invalid extents/counts. `host-reference: pass` establishes only the host contract.

In the matching 11.8.0 development image, run the CUDA stages explicitly:

```sh
make preprocess DIALECT=c++17 EXPECTED_CUBLAS_VERSION=11.11.3.6
make compile DIALECT=c++17 EXPECTED_CUBLAS_VERSION=11.11.3.6
make link DIALECT=c++17 EXPECTED_CUBLAS_VERSION=11.11.3.6
make inspect DIALECT=c++17 EXPECTED_CUBLAS_VERSION=11.11.3.6
```

Alternatively, the wrapper runs clean, all four stages, and host-test, but never the CUDA binary:

```sh
bash scripts/compile-check.sh c++17 cuda-11-8-bundled-cublas-11-11-3-6 artifacts/ex18-11-8
```

Use the corresponding profile ID in each other lane. Link explicitly uses `-lcublas`. Inspection retains `readelf -d` and `ldd` reports, requires a cuBLAS shared-library dependency and resolution, and rejects missing libraries. Because EX18 defines no device kernel, inspection does not require an EX18-owned cubin or PTX. The compiler architecture flags do not establish the library's internal dispatch.

Only after satisfying the runtime gate:

```sh
./build/ex18-cublas-gemm
```

The executable selects visible device 0 and reports header/loaded cuBLAS coordinates, device and driver/runtime versions, precision policy, and three correctness verdicts. This is a description of the reporting contract, not retained execution output.

## Expected Observations

1. All three EX15-compatible fixtures should pass the finite full-output check against the independent double oracle, including the literal hand result and nonzero beta case.
2. The row-major mapping should use swapped operands/dimensions, explicit FP32 pedantic computation, host scalars, and completion before CPU validation.
