## Purpose

Complete [L12](/en/libraries/cufft-plans-layouts-startup/) first. EX19 is a standalone original C++17 correctness project: two FP32 complex batches, a strided out-of-place C2C plan, and explicit resource ownership. It executes CUDA only in an external environment, never in this Learning Site. It contains no timer.

[Inspect the fixed source tree](https://github.com/xiangzhang-coding/cuda-learning-site/tree/a090417a1f3d7cc873afa3c9452d8afe005e2bbc/examples/ex19-cufft-batched-transform) or [download the same revision](https://github.com/xiangzhang-coding/cuda-learning-site/archive/a090417a1f3d7cc873afa3c9452d8afe005e2bbc.zip). ## Independent CPU Reference

<CanonicalCode exampleId="EX19" range="cpu-reference" />

The oracle operates on logical batch-major `std::complex<double>` samples, independently of cuFFT's physical address mapping. Forward uses the negative exponent, inverse the positive exponent; neither direction normalizes. These four literal spectra are mathematical expectations, not recorded GPU output:

| Fixture / batch | Input | Forward spectrum |
| --- | --- | --- |
| `signed-impulse` / 0 | `1+i, 2-i, -1+2i, 3` | `5+2i, 1, -5+4i, 3-2i` |
| `signed-impulse` / 1 | `0, 2-i, 0, 0` | `2-i, -1-2i, -2+i, 1+2i` |
| `opposite-tones` / 0 | `1, i, -1, -i` | `0, 4, 0, 0` |
| `opposite-tones` / 1 | `2, -2i, -2, 2i` | `0, 0, 0, 8` |

Every logical complex output must have finite components and satisfy `abs(gpu-cpu) <= 1e-4 + 2e-5*abs(cpu)`, using complex magnitude. The tolerance belongs to these small fixtures, not arbitrary FFT sizes. Both forward and unscaled inverse are checked; the completed inverse is then divided by 4 on the host and compared with the original input. A round trip is additional validation, not the only oracle. Padding is not transform output.

## Plan And Physical Layout

<CanonicalCode exampleId="EX19" range="plan-layout" />

Rank is 1, N is 4, batch count is 2. Non-null embeddings `{4}` enable the advanced stride contract. Every number below counts complex elements, not bytes:

| Side | Stride | Batch distance | Allocation | Logical offsets by batch |
| --- | --- | --- | --- | --- |
| Input | 2 | 11 | 22 | `0,2,4,6; 11,13,15,17` |
| Output | 3 | 16 | 32 | `0,3,6,9; 16,19,22,25` |

Nonlogical input slots contain `123-321i` to expose accidental contiguous reads. Output starts as NaNs before each execution so an unwritten logical value fails validation. No claim is made about preservation of unused padding. Automatic workspace allocation is disabled before planning; the final size is queried, budget-checked, allocated, and attached. A zero-byte requirement skips allocation and attaches null. Library internal resources are additional.

## Stream And Resource Lifetime

<CanonicalCode exampleId="EX19" range="stream-lifecycle" />

One non-default `cudaStreamNonBlocking` stream, one plan, and one caller-owned workspace serve four sequential executions: forward/inverse for each of two fixtures. H2D initialization, FFT and D2H share the stream; checked completion precedes CPU inspection or reuse. Pageable host vectors do not establish transfer overlap.

The same plan still expects input stride 2/distance 11 during inverse. The program extracts the completed forward GPU spectrum and **host-repacks it into that input layout**, rather than swapping device pointers. It then checks the unnormalized inverse and host scale `1/4`. It never remakes the finalized plan. Host transfer buffers outlive cleanup, including exceptions. Cleanup drains partial submissions, destroys only acquired resources, attempts every release, and makes release errors fail the process.

## Build And Run

From the standalone directory, the host test requires no CUDA headers or GPU:

```sh
make host-test DIALECT=c++17
```

It checks literal spectra and an independent inverse, signs, batch-distinct inputs, layout offsets, normalization, every-output corruption, nonfinite values, invalid extents/directions, and inclusive tolerance boundaries. Success establishes the host contract only.

In the matching 11.8.0 development image, build and inspect without executing CUDA:

```sh
make preprocess compile link inspect DIALECT=c++17 EXPECTED_CUFFT_VERSION=10.9.0.58
bash scripts/compile-check.sh c++17 cuda-11-8-bundled-cufft-10-9-0-58 artifacts/ex19-11-8
```

The wrapper additionally cleans and runs the host test. Choose the corresponding profile in each other lane, not three profiles in one installation. It propagates failed stages and never executes the CUDA binary. Link uses `-lcufft`; `readelf -d` must show a cuFFT dependency and `ldd` must resolve it with no missing libraries. EX19 defines no device kernel, so it does not require an EX19-owned cubin/PTX. Compiler target flags do not certify cuFFT's internal dispatch or plan-time JIT.

Only after meeting the runtime gate:

```sh
./build/ex19-cufft-batched-transform
```

The program selects visible device 0. Expected reporting includes version granularity, GPU/API levels, planned/attached workspace bytes, and four correctness verdicts checking eight complex outputs each. This describes future output, not a retained run.

## Compatibility

All three profiles use C++17 and the manifest's digest-pinned x86-64 development images: Ubuntu 22.04 for 11.8.0; Ubuntu 24.04 for 12.9.2 and 13.3.1. Native Linux is the only Supported Environment. Runtime requires a selected CC 7.5+ GPU. Use a suitably Toolkit-matched or newer driver; a lower family minor-compatibility floor alone does not guarantee PTX JIT support.

Input/output buffers total `(22+32)*8=432` bytes. Fixed buffers plus queried workspace are checked against 8,000,000,000 bytes; internal library resources and free-memory requirements are additional and allocation failures remain fatal. This is a problem-memory budget, not a measured footprint or a promise of zero scratch.

R2C/C2R, in-place transforms, low precision, callbacks, multi-GPU, graphs, timing and patient-JIT/LTO opt-in are excluded. The real-side LTO callback known issue in 13.3 Update 1 therefore does not describe this C2C-without-callbacks path. That exclusion is not a general release all-clear. [L12](/en/libraries/cufft-plans-layouts-startup/) teaches the broader gates without claiming they were executed here.

## Expected Observations

1. Both fixtures should pass finite full-output complex-magnitude tolerance against the double DFT and literal spectra with distinct batches and nontrivial input/output layouts.
2. The same plan and caller workspace should execute both directions on both inputs sequentially; repacking before inverse should preserve layout and explicit host scaling by 1/4 should recover the original input.
