Shared-memory tiling has one thread block cooperate through a load phase, a thread-block barrier, and a use/reuse phase. This site's portable C++17 baseline is the synchronous `load -> __syncthreads() -> use/reuse` sequence. When a loop will overwrite the same tile on its next iteration, a second `__syncthreads()` is required before that overwrite.

## What you should be able to do

- Derive from M01 ownership that each block has a distinct shared tile.
- Write the portable C++17 synchronous load, first barrier, use/reuse, and second barrier phases.
- Ensure all participating threads reach every block barrier rather than letting bounds-invalid threads return early.
- Have an invalid load write an operation-appropriate neutral value while only valid output threads commit results.
- Prove with a happens-before phase ledger that the next iteration cannot overwrite a tile while another thread still reads it.

## Tile contract: one block, one shared instance

Let `tile` be a block's shared array and `t = threadIdx.x`. Threads in that block cooperate through `tile[t]`; another block sees its own instance. Current iteration defines the tile's logical contents. It is neither a cross-block global communication channel nor storage that survives block execution.

For every `base` iteration, maintain four phases:

```text wrap
L: every participating thread writes its assigned tile slot
B1: every participating thread reaches the first __syncthreads()
U: threads read/reuse the complete tile and conditionally write valid output
B2: every participating thread finishes tile reads before the next overwrite
```

The simple portable proof requires `L -> B1 -> U -> B2 -> next L`.

## Load: define every slot

A one-dimensional teaching baseline is:

<pre tabindex="0" aria-label="Portable shared-tile phase pseudocode">
  <code>{`for (int base = 0; base < n; base += blockDim.x) {
  const int input_index = base + threadIdx.x;
  tile[threadIdx.x] = input_index < n ? input[input_index] : neutral;
  __syncthreads();

  if (output_index < n) {
    // Read/reuse only the tile slots required by the algorithm.
    accumulate_from(tile);
  }

  __syncthreads();
}`}</code>
</pre>

This is a teaching skeleton, not a complete algorithm. A real kernel defines `output_index`, which tile slots each output reads, why `neutral` is an identity for the operation, and why the whole block has an identical loop extent.

## First barrier: publish a complete tile

The minimum first-`__syncthreads()` contract is that all participating threads in the block reach the barrier, after which the use phase reads cooperative writes. Do not place it in a per-thread bounds branch that only some threads take, and do not let some threads return before it.

```text
if (input_index >= n) return;  // wrong before a block-wide barrier
tile[threadIdx.x] = input[input_index];
__syncthreads();
```

That early return makes some edge-block threads absent from the barrier. The repair does not delete bounds. It writes neutral for an invalid load and lets that thread reach the barrier with its peers.

## Use/reuse: guard output without skipping participation

An out-of-bounds input thread remains a barrier participant and defines its load slot with neutral. Output bounds are a separate contract: an invalid output thread may skip arithmetic or result storage, but it must still follow control flow to any later block barrier.

Neutral depends on the operation. Sum can use identity 0, product can use 1, and max needs a lower identity valid for the declared domain. If no suitable neutral exists, redesign validity handling rather than inserting 0 and declaring correctness.

Reuse must also be concrete: list which valid outputs read each loaded value. Copying a value into shared memory does not prove fewer global transactions and does not prove a speed improvement.

## Second barrier: finish old reads before overwrite

When a loop reuses one shared array, some threads can finish the use phase and begin the next load while peers still read the old tile. The first barrier protects “read after this iteration's loads complete.” It does not protect “overwrite only after every read completes.” The second `__syncthreads()` is therefore required before the next iteration overwrites the tile.

This second barrier is simply a buffer-reuse boundary. A kernel with no next overwrite, or storage governed by another proven ownership contract, can differ. M03's frozen loop baseline explicitly reuses the same tile, so B2 is required.

## Bounds: an invalid load is not a nonparticipant

For an edge tile, establish separate predicates:

```text
load_valid   = input_index is inside the logical input
output_valid = output_index is inside the logical output
```

`load_valid` selects input value or neutral. `output_valid` selects whether to commit output. Neither allows one thread to bypass a block-wide barrier. Loop trip count and barrier positions must be uniform for participating block threads.

## Evidence boundary

A phase trace, pseudocode, and host-side oracle can review contracts but cannot execute GPU `__syncthreads()` behavior. Without a qualifying compile record, compilation remains empty; without a Reference Environment run, runtime remains empty. This page claims no transaction reduction, bandwidth increase, or kernel speedup from tiling.

Future measurement first verifies identical logical results for untiled and tiled variants, then records the exact kernel, tile shape, Environment Manifest, metrics, and timing boundary. M03's barrier proof is a correctness prerequisite, not a performance result.

## Retrieval check

1. Why does the same `__shared__` declaration create distinct tile instances for different blocks?
2. Why should a bounds-invalid loader write neutral rather than return before the first barrier?
3. What minimum phase contract does the first `__syncthreads()` establish between load and use?
4. Why does a loop need a second `__syncthreads()` before the next load overwrites the same tile?
5. Why may an output-invalid thread skip its store but still have to reach a later block barrier?
