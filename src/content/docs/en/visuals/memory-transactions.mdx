## Learning purpose

VIS04 is a Visual Explainer for the address-grouping prerequisite behind [M02](/en/memory/coalescing-transactions/) and [EX05](/en/examples/coalesced-strided-access/). It answers one bounded question: which naturally aligned 32-byte segments contain the bytes requested by the selected active lanes?

## Input contract

The model accepts a contiguous or strided pattern, an element width of `1`, `2`, `4`, or `8` bytes, an integer element stride, a byte offset, and `1` through `32` active lanes. It models one global-memory instruction from one warp; active lanes are consecutive from lane zero, and all addresses are relative to a fixture base `B = 0` aligned to 32 bytes. Contiguous mode fixes the stride at one element. Strided mode uses the entered positive stride.

Browser caps keep the generated table bounded: stride is at most `64` elements and offset is at most `4096` bytes. These are interface limits, not CUDA device limits. A malformed, fractional, signed, exponential, or out-of-range value produces no partial grouping.

## Segment model

For lane `L`, element width `E`, stride `S`, and starting offset `O`, the requested inclusive byte range is:

```text
start(L) = O + L * S * E
end(L)   = start(L) + E - 1
```

Every requested byte belongs to the naturally aligned segment beginning at `floor(address / 32) * 32`. If one element crosses a boundary, that lane appears in both segment groups. The lane table therefore retains the byte range and every segment start rather than assigning one element to only its first segment.

The fixture explicitly applies the CUDA rule for compute capability 6.0 and newer. The Learning Site’s Baseline GPU Capability Tier begins at compute capability 7.5, so the fixture lies inside the site’s declared Stable Curriculum scope.

## Byte accounting

The aligned default (`32` lanes, `4` bytes, stride `1`, offset `0`) requests bytes `0` through `127` and occupies segment starts `0`, `32`, `64`, and `96`. Offset `4` extends the final request through byte `131`, so five segment groups are present. Stride `2` addresses every other 4-byte word and occupies eight segment groups.

“Requested bytes” is the sum of lane element widths. “Segment coverage bytes” is the number of represented segment groups multiplied by `32`. Their difference is displayed only as address coverage accounting. It is not cache traffic, an observed hardware transaction count, bandwidth, efficiency, or speedup.

## Static fallback

The four ledgers after the workbench are generated by the same pure TypeScript model. They preserve the required default, offset, stride, and boundary-crossing cases with JavaScript disabled and in print. Controls and the interactive table remain hidden until successful enhancement.

## Evidence boundary

The browser evaluates integer address equations only. It compiles no CUDA, launches no GPU work, queries no cache, and reads no profiler. Consequently, selections and static ledgers grant no **Compile-Checked**, **Community-Observed**, or **Runtime-Verified** status, and all publication evidence axes remain empty.
