## Learning purpose

VIS03 is the standalone Visual Explainer related to M06. It separates a lane-level predicate from the teaching trace used to inspect **warp divergence**, and it keeps control-flow reconvergence separate from synchronization.

<WarpDivergenceExplorer locale="en" />

## Predicate masks

The model always starts with one participating mask containing lanes `0` through `31`. A selected predicate partitions that set:

```text
trueMask  = { lane in participatingMask | predicate(lane) is true }
falseMask = { lane in participatingMask | predicate(lane) is false }

trueMask intersection falseMask = empty
trueMask union falseMask = participatingMask
```

Five reviewed presets make the partition deterministic: uniform true, uniform false, lower half (`0` through `15`), alternating even lanes, and one fixed non-contiguous set. Uniform presets have one empty path. The empty path is represented as **skipped**, not as an invisible or failed stage.

## Path trace

The five teaching stages are `before-branch`, `predicate-evaluated`, `true-path`, `false-path`, and `logical-join`. VIS03 deliberately displays the true path before the false path so Step has one stable outcome. That ordering is **not hardware scheduling** and must not be used to predict which path a warp scheduler issues first.

At the logical join, the participating lanes have a common control-flow successor in this model. A logical join is **not memory synchronization**: it is not `__syncwarp()`, a block barrier, a memory fence, or proof that memory communication is safe.

## Independent Thread Scheduling boundary

On devices with compute capability below 7.0, a warp used a shared program counter plus an active mask. On **CC 7.0+**, Independent Thread Scheduling maintains execution state per thread and allows sub-warp divergence and reconvergence. Code that assumes lanes permanently execute every instruction in implicit lockstep can therefore be incorrect. Required coordination must use an appropriate explicit primitive, such as `__syncwarp()` for the intended participating mask when that primitive fits the communication contract.

The lane table is a predicate and control-flow model. It does not expose an instruction trace, a scheduler trace, latency, or the exact lane grouping chosen by hardware.

## Static fallback

The permanent fallback contains two complete 32-row tables. The lower-half table shows both non-empty paths; the uniform-true table labels the false path as skipped. Text such as `ACTIVE`, `INACTIVE`, and `Skipped` carries the state, so color is never the only distinction. These tables remain available without JavaScript and in print.

## Evidence boundary

VIS03 compiles and executes no CUDA, reads no GPU, and records no timing. Its deterministic masks confer no **Compile-Checked**, **Community-Observed**, or **Runtime-Verified** status. Compilation, runtime, expected-observation, and recorded-observation metadata remain empty.
