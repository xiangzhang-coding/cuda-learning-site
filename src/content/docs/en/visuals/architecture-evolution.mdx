## Purpose and prerequisites

Exact ordered prerequisites: [H01](/en/architecture/turing-warp-safety/), [H02](/en/architecture/ampere-pipelines-tensor-cores/). Compare a portable explicit-synchronization baseline with documented feature additions. Turing inherited independent thread scheduling from Volta. Ampere adds hardware copy and split-barrier paths, but native FP64 Tensor Cores are not shared by all 8.x rows. Read a capability contract, not a product ranking.

## Controls

Select an **exact compute capability** and a **required feature**. Filters intersect; choosing CC 8.6 and native FP64 Tensor Cores produces an explained empty result, not automatic fallback to 8.0. Reset returns both filters to all reviewed states and focuses the CC select. Native select/button keyboard behavior applies; results are announced politely. There is no animation, autoplay, timer, randomness, persistence or GPU query. Reload starts with all four states. An unknown filter is rejected and the previous selection is retained.

## Model contract

Order is fixed: Turing 7.5, Ampere 8.0, 8.6, 8.7. Every published row has a target, shared-memory limit and all seven feature decisions. Future architectures have no options, rows or placeholders. Feature availability is the reviewed hardware contract, not the set of all instructions accepted by an API or compiler. FP64 here means **native Tensor Core inputs**, not ordinary double arithmetic. FP16/BF16/TF32/FP64 still require H02's precise WMMA types, shapes, layout, participation and caller-approved precision.

The 64/163/99/163 KiB values are per-block maxima; more than 48 KiB requires dynamic shared memory and opt-in. They are not measured occupancy or device memory capacity. The portable site scope is CC 7.5+ with a problem fitting within 8 GB; the Modern Single-GPU Capability Tier requires CC 8.0+ and at least 8 GB. An 8.7 row does not select or verify a platform environment. Consult H02 before proposing execution.
