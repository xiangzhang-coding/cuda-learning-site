## Purpose and prerequisites

Exact ordered prerequisites: [H01](/en/architecture/turing-warp-safety/), [H02](/en/architecture/ampere-pipelines-tensor-cores/), [H03](/en/architecture/ada-working-sets/), [H04](/en/architecture/hopper-clusters-tma/). Compare a portable explicit-synchronization baseline with documented additions. Turing inherited independent thread scheduling from Volta; Ampere adds hardware copy and split-barrier paths. Ada adds implementation-specific cache capacity, while Hopper introduces clusters, DSM and TMA. Read each capability contract, not a product ranking.

## Controls

Select an **exact compute capability** and a **required feature**. Filters intersect; CC 8.6 with native FP64 Tensor Cores, or CC 8.9 with TMA, produces an explained empty result without silently changing CC. Reset returns both filters to all reviewed states and focuses the CC select. Native select/button keyboard behavior applies; results are announced politely. There is no animation, autoplay, timer, randomness, persistence or GPU query. Reload starts with all six states. An unknown filter is rejected and the previous selection is retained.

## Model contract

Order is fixed: Turing 7.5, Ampere 8.0, 8.6, 8.7, Ada 8.9, Hopper 9.0. Every row has a target, shared-memory limit and all eleven feature decisions. Future architectures have no options, rows or placeholders. FP64 means **native Tensor Core inputs**, not ordinary double arithmetic: among these rows, 8.0 and 9.0 qualify. FP16/BF16/TF32/FP64 still require H02's precise WMMA types, shapes, layout, participation and caller-approved precision. Hardware availability does not establish selected instructions.

The 64/163/99/163/99/227 KiB values are per-block maxima; more than 48 KiB requires dynamic shared memory and opt-in. They are not measured occupancy or device memory capacity. The portable site scope is CC 7.5+ with a problem fitting within 8 GB; the Modern Single-GPU Capability Tier requires CC 8.0+ and at least 8 GB. An 8.7 row does not select or verify a platform environment.

L2-policy eligibility starts at 8.0; actual cache capacity is queried per device, not inferred from CC. MIG/MPS and window/set-aside constraints remain gates. Cluster/DSM/TMA filters select only 9.0 among these rows. A cluster must pass actual dimension/resource queries; DSM needs initialization and exit synchronization. Single-block TMA needs no cluster, but does need H04's descriptor/alignment, transaction wait, proxy visibility and direction-specific store completion. H03/H04 specify exact memory, targets, profiler permission and ordinary-copy/global-scratch fallbacks.
