## Learning purpose

VIS08 helps a CUDA learner keep two statements separate: a teaching model can **declare** where each managed-memory page resides after a fixed access sequence, while a runtime claim needs observations from a stated environment. The visual is related to M10 and EX08 and requires the M01, M02, and M10 concepts listed in metadata.

## Controls

Choose one of three reviewed scenarios with the native select. Each scenario controls a reviewed access-origin and page sequence as one bounded unit; the visual intentionally does not accept an arbitrary sequence that could imply a broader residency predictor. **Step access** applies exactly one fixed CPU or GPU access. **Reset sequence** restores the selected scenario's initial declarations and returns keyboard focus to the scenario select. There is no autoplay, scrubber, editable page size, or persisted state. Reloading starts again with `gpu-linear-sweep` at step zero.

The model rejects an unknown scenario, malformed action, invalid step index, or step beyond the end without changing the previous state. The live status region names each accepted step or rejection. Native select and button behavior supplies keyboard operation without a custom key map.

## Declared model

The model explicitly chooses the **software-coherent** branch for a bounded lesson. At each model step, every teaching page has exactly one declared location, CPU or GPU. When an access origin differs from that declaration, the model changes the declaration to the access origin and increments a **modeled residency transition** count. A matching-origin access leaves the declaration unchanged.

The declared page size is `65,536 B` (`64 KiB`). It is a teaching symbol, not a detected operating-system page, GPU page, transfer granularity, or promise that one runtime action moves exactly that amount. The symbolic byte expression is only:

```text
modeled transition count x declared page size
```

The fixed scenarios intentionally exclude hardware-coherent direct access, remote mappings, prefetch, memory advice, access-counter policy, oversubscription, multi-GPU placement, concurrent CPU/GPU access, and eviction. Those mechanisms can change real placement and access behavior, so this deliberately narrow rule must not be generalized into a platform-independent residency predictor.

## Transition ledger

The signature page-residency rail preserves deterministic page ID order. The transition ledger records access ID, CPU or GPU origin, read or write operation, residency before and after, whether the declaration changed, cumulative transition count, and cumulative symbolic bytes. All IDs, scenarios, access sequences, and tie-free ordering are fixed in source; the model uses no clock, randomness, storage, or device query.

The rail and ledger answer only, "What does this declared model produce for this reviewed input?" They do not answer whether a CUDA run generated a fault, moved data, selected a transfer granularity, or incurred an elapsed duration.

## Static fallback

The server renders all three scenarios, not only the initially selected one. Each static card includes its initial-condition description, final residency rail, full four-row before/after ledger, transition total, and symbolic-byte expression. The same complete fallback remains visible without JavaScript, at a 390-pixel viewport, in forced colors, with reduced motion, and in print. Text labels carry CPU/GPU and changed/unchanged states without relying on color.

Controls and the interactive workbench are hidden in source HTML. They become visible only after the light-DOM custom element finds every required native control and successfully derives the initial frame. If enhancement does not complete, the full static representation remains the lesson.

## Evidence boundary

VIS08 compiles and executes no CUDA. It obtains no Environment Manifest, profiler output, page-fault record, transfer record, residency query, byte count, or elapsed-time result. Its modeled transition count and symbolic bytes are not measured migration evidence and grant no **Compile-Checked**, **Community-Observed**, or **Runtime-Verified** Evidence Status. Compilation, runtime, expected-observation, and recorded-observation metadata are all empty.
