## Purpose

After A08, use VIS12 to narrow `A[M,K] × B[K,N] -> C[M,N]` from the complete matrix through a logical tile, CUDA thread-block owner, modeled warp subtile, and source-level scalar operation slot. The related Runnable Example is EX15.

## Controls

Three native selects choose matrix shape `128x128x32` or `256x128x64`, tile shape `64x64x16` or `128x64x16`, and one of five hierarchy levels. Reset restores the first matrix, first tile, and matrix level, then returns focus to the matrix select. Status uses a polite live region.

Controls and the live workbench carry `hidden` in source HTML. The custom element reveals them only after finding every required part and deriving the initial model. The page has no autoplay, timer, randomness, storage, range input, canvas, or SVG.

## GEMM shapes

Shape notation is `M x N x K`. Matrix means the complete `A[M,K]`, `B[K,N]`, and `C[M,N]` contract. Tile means a `TM x TN` output footprint and `TK` reduction slice. The output grid is `ceil(M/TM) x ceil(N/TN)`. One thread block owns one output tile and loops through `ceil(K/TK)` slices, so block count is not multiplied by K-slice count.

Both tile shapes use a modeled `32x32x16` warp subtile. `64x64x16` displays four warps per block, while `128x64x16` displays eight. This is a bounded teaching partition, not a launch recommendation or observed schedule.

## Five hierarchy levels

1. **Matrix:** the complete problem and three logical matrices.
2. **Tile:** an output partition and K-slice loop.
3. **Thread block:** the CUDA owner in this teaching mapping; its shape matches the tile but its semantics differ.
4. **Warp:** a modeled subtile within the thread-block footprint, without an issue-order prediction.
5. **Instruction:** a `1x1x1` source-level scalar multiply-accumulate slot, not a claim about compiler-emitted FMA, MMA, WMMA, or SASS.

The hierarchy explains ownership and nesting, not occupancy, register allocation, Tensor Core eligibility, pipelines, latency, throughput, or speedup. Architecture-specific instruction hierarchies belong to the later version-gated L09 unit.

## Static fallback

Outside the interactive area, the server permanently renders all four matrix/tile selections, each with five purpose-built hierarchy panels, for 20 panels total. Every panel states shape, owner, relationship, and boundary. All panels remain with JavaScript disabled, at a 390-pixel viewport, under reduced motion, in forced colors, and in print. Selected state uses `aria-current`, text, and a thick border rather than color alone.
