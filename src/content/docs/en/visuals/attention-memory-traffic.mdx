## Purpose

After [A11](/en/algorithms/attention-as-an-io-problem/), use VIS18 to see the logical IO of score, normalization, and value aggregation together. The upper track materializes full `S` and `P`. The lower track retains a query tile while sweeping key/value tiles and keeps the temporary score tile, online row statistics, and weighted accumulator in fast storage.

## Fixed fixture and boundary

The two self-attention shapes are `N=8,d=4` and `N=16,d=8`; the score tiles are `Br×Bc=4×4` and `8×8`. Storage is FP32, so every counted element is 4 bytes, and Q, K, and V already exist. The model excludes projections, mask, bias, dropout, backward, allocation, host-device transfer, cache lines, transaction overfetch, and spills.

The boundary is a stipulated logical element transfer between slow and fast stores. It is not a GPU DRAM counter. `ceil(N/Br)` is the query-tile count and `ceil(N/Bc)` is the key/value-tile count. Every reviewed combination divides evenly so that learners can first audit the core ledger.

## Three stages

1. **Score:** the materialized path reads Q/K and writes the full `S=QK^T/sqrt(d)`; the tiled path forms only a `Br×Bc` temporary score tile.
2. **Normalize:** the materialized path reads S three times for stable softmax and writes P; the tiled path merges online `(m,l)` state without moving S/P across this boundary.
3. **Value:** the materialized path reads P/V and writes O; the tiled path rereads V per query tile, retains accumulator `a`, and finally writes `O=a/l`.

An exact tiled recurrence actually interleaves normalization and value aggregation. The stage selector is a conceptual ledger, not a claim about three separate kernels or any backend dispatch. Exact means equivalent to dense attention over real arithmetic, not floating-point bitwise identity.

## IO ledger

For self-attention shape `N,d` and `Tr=ceil(N/Br)`, full S/P materialization plus stable three-pass normalization counts `4Nd + 6N^2` elements. The query-outer tiled schedule counts `2Nd + 2TrNd`: Q and O cross once, K and V cross `Tr` times, and full S/P is never materialized.

The default `N=8,d=4,Br=Bc=4` yields `512 elements = 2048 B` for the materialized path, `192 elements = 768 B` for the tiled path, and a `1280 B` static-analysis difference. The normalize card's `0 B` means no slow-store transfer is counted for that stage; it does not mean zero exponent, max, sum, or rescale work.

A larger query tile reduces K/V replay in this simplified ledger, but the model has no fast-store capacity, register pressure, occupancy, parallelism, or spill term. It therefore cannot declare `8×8` faster or better.
