## Learning purpose

VIS01 is a Visual Explainer. It uses a **deterministic teaching trace** to connect a kernel launch, thread blocks in a grid, warps on an SM, global-memory transactions, and a synchronization boundary. Determinism makes controls repeatable and predictions checkable; it does not mean a real GPU follows a fixed schedule.

## How to read the model

The trace begins when the host enqueues a launch in a stream and ends when a declared synchronization or dependency boundary can observe all grid work as complete. Each step adds one conceptual fact. Scrubbing backward reconstructs that state instead of retaining highlights from later steps.

Playback never starts automatically. Opening, reloading, and resetting the page all return to the first step. Visual state is not written to `localStorage`, cookies, or a remote service.

## Controls and no-motion access

- **Play** advances in one fixed order and stops at completion; its interval is only interface pacing.
- **Pause** preserves the current step; **Step** advances once and remains paused.
- The range input supports arrow-key stepping; **Reset** clears playback state and returns to launch.
- Under `prefers-reduced-motion`, there is no positional animation. Step, scrub, and the complete static sequence retain every fact.

## Real scheduling boundaries

Every thread in one thread block executes on one SM, but independent blocks have no guaranteed dispatch or completion order; they may run in parallel or in series. Threads in a block are partitioned into 32-thread warps using x-fastest local linear IDs. The visual follows one illustrative block and one ready warp without excluding other legal schedules.

The memory stage is deliberately narrow: 32 lanes read aligned consecutive 4-byte words spanning 128 B, so four 32 B global-memory transactions satisfy the requests. Change the width, alignment, address distribution, cache behavior, or architecture conditions and the transaction count may change.

## Static stage sequence

The numbered list inside the component is the purpose-built static fallback. With JavaScript disabled, controls do not appear, but all eight stages, every boundary note, and the evidence statement remain in the initial HTML. Print shows that complete sequence rather than a state-less screenshot of an animation.

## Evidence boundary

This page neither compiles CUDA nor runs a kernel on a GPU. Browser state, playback intervals, completion labels, and screenshots grant no **Compile-Checked**, **Community-Observed**, or **Runtime-Verified** status. Runtime evidence must follow the [O02 Evidence Status contract](/en/start/evidence-status/).
