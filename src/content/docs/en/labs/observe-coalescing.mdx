## Freeze the measurement plan

Write this contract before the first profiler collection:

1. Freeze source commit, binary SHA-256, Lane, device, scenario order, logical work, build flags, launch geometry, `ncu` options, and metric list. Preserve only the canonical `offset`/`stride` differences.
2. Directly run the complete binary once more as a process-level warm-up. Check correctness but exclude that run from every statistic. It cannot remove all startup or replay effects in a new profiler process, so do not call it a steady-state event warm-up.
3. Make exactly 10 independent, complete measured profiler invocations of the same unchanged binary. Retain every attempt in acquisition order and do not delete samples merely because they look unusual.
4. Predeclare the summary for each scenario/metric as the median and min/max spread of that fixed 10-attempt batch, calculated only when all 10 attempts qualify. Only a nonzero tool/application status, correctness failure, missing target kernel, or missing metric value makes an attempt invalid; retain that record and reason. A large or inconvenient value is not invalid. If any attempt is invalid, publish no summary and record a batch blocker; after correcting the cause, restart all 10 attempts in a new batch directory instead of selectively replacing or overwriting samples.

These rules freeze equal work/build/launch. If any frozen dimension changes, discard the batch and restart rather than joining samples from different contracts.

## Collect repeated profiles

Fill one fixed comma-separated list with complete metric names returned by this GPU's query. Do not copy another architecture's names:

```sh
metric_csv='<fill exact queried metric names>'
batch_id="$(date -u +%Y%m%dT%H%M%SZ)-$$"

```

## Interpret the records

CUDA event timing and a profiler measurement are different records. Timing-enabled events mark a device-timeline interval through `cudaEventRecord`; after completion, `cudaEventElapsedTime` reports that interval's elapsed time. Canonical EX05 contains no event instrumentation. `ncu` inserts measurement libraries and may serialize or replay kernels, control cache or clocks, and make multiple passes. It reports selected metrics under that collection contract, not an interchangeable event sample.

LAB04 therefore adds no event-instrumented binary and does not combine profiler duration, host wall-clock, and event time. A separate event experiment must redeclare source/build, warm-up, completion boundary, and statistic instead of borrowing this Lab's frozen-binary record.

State only what each metric's owner definition supports. If all 10 attempts qualify under the same metric, unit, options, and device, report the median and min/max spread with paths to every attempt; otherwise report the blocker and no summary. This Lab predicts no metric ordering, latency, bandwidth, throughput, or speedup among contiguous, misaligned, and strided. Preserve equal, noisy, or model-disagreeing results and investigate rather than rewriting expectations.

## Expected observations, not recorded results

- Contiguous, misaligned, and strided should first pass exact CPU-reference comparison for all 256 outputs.
- After version, metric-query, and permission gates pass, each scenario should map to its own raw profiler record and exit status; this promises no direction or magnitude.
- The warm-up should be excluded and all 10 attempts retained; the predeclared median plus min/max spread should be reported only when the complete fixed batch qualifies.

These are expected observations, not recorded results. There is no prefilled numeric GPU result, runtime output, or profiler result on this page; `recordedObservations` remains empty.
