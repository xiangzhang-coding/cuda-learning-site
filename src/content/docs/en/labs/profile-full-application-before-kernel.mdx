LAB08 is a Lab performed outside the website on Native Linux. Correctness comes first for the canonical EX07 Runnable Example; separate Nsight Systems and Nsight Compute executions then establish an Environment Manifest and a reviewable decision trail. The page runs no CUDA, declares expectations rather than results, and retains Pending Hardware Verification as its runtime Evidence Status.

## Lab contract

| Coordinate | Requirement |
| --- | --- |
| Difficulty and time | Intermediate, about 150 minutes |
| Prerequisites | Exactly Q07 and Q08 |
| Supported Environment | Native Linux only; exactly one CUDA GPU with compute capability 7.5 or newer |
| Toolkit Lane | `cuda-11.8`, `cuda-12.9`, or `cuda-13.3`, with Lane-matched `nsys`, `ncu`, and compatible CUPTI |
| Frozen workload | EX07's 4,099 `std::uint32_t` elements, serial path, five chunks, and two chunk streams; maximum device memory is 49,176 bytes |
| Permissions | Device, compiler, binary, report/log-directory, and CUDA-trace access; administrator-approved non-admin performance-counter access; no `sudo`, temporary elevation, or policy bypass |
| Execution order | Unprofiled exact correctness, a separate Systems collection and instance selection, then a minimal Compute collection |
| Evidence | Compilation is empty; runtime is Pending Hardware Verification; recorded observations are empty |

Nsight Systems answers the application-level localization question. Nsight Compute answers only one already-selected kernel-level question. Their reports come from different instrumented executions and must never be represented as joint measurement of one launch.

## Prerequisite check

1. Complete [Q07: Read the Application Timeline First with Nsight Systems](/en/correctness/timeline-first-nsight-systems/) and be able to select one exact kernel instance through `.nsys-rep`, process, context, stream, correlation, or launch-occurrence coordinates.
2. Complete [Q08: Ask One Selected-Kernel Question with Nsight Compute](/en/correctness/kernel-first-nsight-compute/) and freeze the question, filter, section or metric, replay, permission, and custody before collection.
3. Confirm that exactly one GPU is visible, an administrator has approved non-admin performance-counter access, and a learner-owned evidence directory is writable. Stop without authorization; this Lab never treats `sudo ncu` as a repair.
4. [EX07](/en/examples/streams-events-overlap/) supplies the fixed workload. [LAB06](/en/labs/build-overlapped-pipeline/) and [VIS14](/en/visuals/nsight-systems-versus-nsight-compute/) are related resources, not additional prerequisites.

## Verify correctness first

Before either profiler, run the uninstrumented binary directly:

```sh
./build/ex07-streams-events-overlap \
  >lab08-evidence/correctness.stdout.log \
  2>lab08-evidence/correctness.stderr.log
status=$?
printf '%s\n' "$status" >lab08-evidence/correctness.status
```

Continue only if the serial and chunked paths each exactly match the independent host reference for all 4,099 outputs, every CUDA boundary succeeds, and process status is zero. A tolerance, sampled elements, or the printed word `PASS` alone cannot replace the source-defined exact verifier. Correctness is a precondition before profiling or interpretation; failure produces no Systems-to-Compute conclusion.

## Freeze the Systems collection plan

Write the plan before the first `nsys profile` command:

1. Ask only where CUDA APIs, copies, streams, events, and `transform_kernel` instances appear in the fixed EX07 control path. Assume no overlap, duration, or bottleneck.
2. In this Lab, representative means that the exact pinned binary completes its serial and chunked paths, 4,099-element workload, and normal completion. It does not mean production scale or general performance.
3. Freeze source commit, binary hash, device, Lane, environment, trace domains, sampling policy, capture boundary, concurrent-load policy, output base, and exact command. The Systems run must pass application correctness again.
4. Plan one primary `.nsys-rep` from which to select one exact `transform_kernel` instance. If a rerun is necessary, create a new run directory rather than overwriting the old report.

The deliverable here is selection evidence, not a timing summary. A timeline may locate an instance, but LAB08 requires no overlap, latency, or speedup statement from it.
