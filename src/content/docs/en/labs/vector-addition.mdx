## Prerequisite check

1. Explain the Environment Manifest fields from [O03](/en/start/environment-manifest/) and prepare to record real values.
2. Answer all five [F01](/en/foundations/first-cuda-kernel/) retrieval questions, especially partial blocks and tolerance semantics.
3. Select one C++17 Toolkit Lane from the table. If your native Linux environment matches none, record it as your own environment but do not inherit committed Lane evidence.
4. Confirm that only one GPU will be used and its compute capability is 7.5 or newer.

[View or download the complete EX02 project at its pinned commit](https://github.com/xiangzhang-coding/cuda-learning-site/tree/d69f7131acff7f8b1dfcd780b494426b5948735b/examples/ex02-vector-addition). One reviewable acquisition path is:

```sh
git clone https://github.com/xiangzhang-coding/cuda-learning-site.git
cd cuda-learning-site
```

Before building, create your manifest with at least GPU identity, compute capability and query method, GPU count, driver, Toolkit, NVCC, host compiler, OS/architecture, project commit, element count, device-memory bound, permissions, exact commands, correctness method and criteria, and observation date. Do not treat the command forms below as observed values:

```sh

nvcc --version

```

## Predict first

For the default size and size `1003`, record block size `256`, ceiling-divided block count, total launched threads, final valid index, and out-of-bounds thread count. Use the shared [VIS02 Indexing Explainer](/en/visuals/indexing/) to revisit coordinates and [VIS01 Kernel Journey](/en/visuals/kernel-journey/) to locate launch-to-completion boundaries. ## Build and run the host-only check

The error-checking helper comes from canonical source:

Run the C++17 contract from the project directory:

```sh
make preprocess DIALECT=c++17 BUILD_DIR=build
make compile DIALECT=c++17 BUILD_DIR=build
make link DIALECT=c++17 BUILD_DIR=build
make inspect DIALECT=c++17 BUILD_DIR=build
make host-test DIALECT=c++17 BUILD_DIR=build
```

Retain complete stdout/stderr and each command's exit status. `make host-test` checks only the CPU reference and comparison function; it executes no CUDA binary. If any step fails, record the blocker and stop. Never relabel failure or a skipped step as Compile-Checked.

## Verify correctness

The CPU reference and acceptance rule come from the same canonical project:

<CanonicalCode exampleId="EX02" range="cpu-reference" />

The Lab is complete only when all criteria hold:

1. Three `cudaMalloc` calls, two host-to-device copies, `cudaGetLastError`, `cudaDeviceSynchronize`, the device-to-host copy, and all three `cudaFree` calls avoid the error path.
2. Both default-size and `1003` runs exit with status zero.
3. The independent CPU reference checks every GPU element. Accept when absolute difference is `<= 1e-5` **or** relative difference is `<= 1e-5 * max(abs(expected), abs(actual))`; fail only when neither accepts.
4. Save the manifest, exact commands, date, raw logs, and criterion result together. A bare `PASS` line without these coordinates is insufficient.
5. Infer no latency, bandwidth, speedup, occupancy, or profiler conclusion from these two correctness runs.

## Expected observations, not recorded results

- A qualifying run **should** be accepted by the independent CPU reference under the absolute-or-relative tolerance rule.
- A size of `1003` **should** create a final partial block whose global indices `1003..1023` skip array access.

These sentences are pre-run criteria. The site observed neither your environment, output, nor GPU behavior. Put actual observations in a separate record and never rewrite an expectation to fit a result.
