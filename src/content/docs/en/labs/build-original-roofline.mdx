LAB09 is a Lab performed outside the website on Native Linux. It turns a correctness-qualified canonical EX02 run into an original, reviewable roofline artifact. This page provides a measurement contract, not results: compilation evidence is empty, runtime remains Pending Hardware Verification, and recorded observations are empty.

## Lab contract

| Coordinate | Frozen requirement |
| --- | --- |
| Difficulty and time | Advanced, about 180 minutes |
| Strict prerequisite | Exactly Q10 |
| Related, not prerequisite | Q09, A14, [EX02](/en/examples/vector-addition/), and VIS13 |
| Supported Environment | Native Linux only; exactly one CUDA GPU with compute capability 7.5 or newer |
| Toolkit Lane | C++17 in `cuda-11.8`, `cuda-12.9`, or `cuda-13.3`, with matching Nsight Compute and CUPTI |
| Frozen workload | Exactly 16,777,216 `float` elements and one canonical `vector_add` launch |
| Application allocation | Three 67,108,864-byte device vectors, exactly 201,326,592 bytes total |
| Permissions | Administrator-approved non-admin performance-counter access; no `sudo`, elevation, setuid workaround, container escape, or policy bypass |
| Acquisition | One excluded direct-process warm-up, then exactly 10 independent retained profiler attempts |
| Evidence | Compilation empty; runtime Pending Hardware Verification; recorded observations empty |

Q09, A14, EX02, and VIS13 are related resources only. They do not add prerequisite edges. A measured chart is not accepted merely because a profiler UI can draw one: this Lab requires its own ceiling provenance, retained samples, CSV, table, chart, and hashes.

## Prerequisite check

1. Complete Q10 and be able to align an operation convention, byte domain, duration scope, ceilings, ridge point, and roof before interpreting a point.
2. Confirm exactly one selected device is visible and is CC 7.5 or newer. Record the query, not only a product name.
3. Select one C++17 Toolkit Lane and its matching Nsight Compute/CUPTI installation. A nearby version must be recorded as a different environment, not silently assigned a Lane label.
4. Obtain an administrator-approved record granting this non-admin account access to performance counters. Without it, stop. LAB09 never authorizes `sudo ncu` or another bypass.
5. Reserve a learner-owned evidence directory that can preserve reports, raw logs, statuses, hashes, manifests, CSV, table, chart, and sanitization records without overwriting.

## Freeze the workload and byte models

The immutable model coordinates are:

```yaml
element_type: float
element_count: 16777216
bytes_per_element: 4
device_vector_count: 3
bytes_per_device_vector: 67108864
maximum_device_allocation_bytes: 201326592
algorithmic_fp32_additions: 16777216
algorithmic_requested_bytes: 201326592
algorithmic_intensity_operations_per_byte: 1/12 (~0.083333)
```

For each valid element, canonical `vector_add` requests two 4-byte reads and one 4-byte write at the declared source-level device-memory boundary. Therefore:

- counted work is `16,777,216 x 1 = 16,777,216` FP32 additions;
- requested traffic is `16,777,216 x (4 + 4 + 4) = 201,326,592` bytes; and
- requested-byte arithmetic intensity is `16,777,216 / 201,326,592 = 1/12`, approximately `0.083333` operations/byte.

This is an **algorithmic requested-byte model**. It is not a measurement of DRAM sectors, L2 traffic, L1/TEX traffic, cache hits, write allocation, compression, ECC effects, or any profiler-attributed physical traffic. The equal totals for three allocations and source-level read/read/write requests are arithmetic coincidences of this workload, not evidence that allocation bytes equal transferred bytes. Profiler-owned replay storage is also outside the canonical application's 201,326,592-byte allocation and must be recorded separately if exposed.
