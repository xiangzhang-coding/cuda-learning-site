## Evidence boundary

Compilation and runtime labels are copied directly from the linked Lab's controlled evidence fields. A site build, filter action, or browser test cannot upgrade CUDA evidence. LAB01 has an empty compilation axis with no Compile-Checked claim, and its runtime axis is Pending Hardware Verification. LAB02 retains its existing status. LAB03 and its EX04 Runnable Example both have empty compilation evidence and Pending Hardware Verification runtime. LAB04, LAB05, and LAB07 likewise have empty compilation evidence, Pending Hardware Verification runtime, empty recorded observations, and expected observations only. LAB06 and LAB08 also retain empty compilation evidence, Pending Hardware Verification runtime, empty recorded observations, and expected observations only. Both require learner-owned report custody and existing non-admin profiling access: LAB06 authorizes no `sudo` or other privilege escalation; LAB08 additionally requires administrator-approved non-admin performance-counter access and forbids elevation or security-policy bypass. The Learning Site publishes no collected profiler report. LAB06's expected-only fixture is not an `.nsys-rep` or profiler output; LAB08's expected-only report plan is neither an `.nsys-rep` nor an `.ncu-rep` and contains no counter, timeline, timing, or runtime observation. Any actual Systems and Compute reports for LAB08 come from separate instrumented executions and cannot represent one physical launch. LAB04/LAB05 publish no profiler result or timing, and LAB07 publishes no sanitizer report. A report file, host-only test, learner-local build, expected observation, or tool manual changes none of these statuses.
