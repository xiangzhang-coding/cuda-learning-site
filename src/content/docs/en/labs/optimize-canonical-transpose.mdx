The declared performance workload is:

```yaml

```

The arithmetic is exact:

- one matrix: `4096 x 4096 x 4 = 67,108,864` bytes;
- two global matrices: `2 x 67,108,864 = 134,217,728` bytes;
- the largest stage-local shared tile: `32 x 33 x 4 = 4,224` bytes per block; and
- the conservative declared bound: `134,217,728 + 4,224 = 134,221,952` bytes.

This bound covers the canonical application problem model, not host allocations, driver/context state, code, allocator granularity, all concurrently resident blocks, profiler libraries, or replay save/restore storage. Check actual free memory and profiler requirements before collection.

EX14's tiny correctness-fixture bound is `2 x (64 x 32 x 4) + 4,224 = 20,608` bytes. That **20,608-byte bound remains distinct** from LAB10's `134,221,952-byte` performance-workload bound; never replace one with the other or claim that either is observed allocation traffic.

## Declare stages and hypotheses

The learner-owned runner launches these stages once in this fixed order. Adjacent stages form three passes, and each pass changes one variable at a time:

```yaml
stages:
  - stage_id: baseline-direct
    changed_variable: none; frozen direct output-linear baseline
    hypothesis: exact-GPU evidence may characterize strided input reads and contiguous output writes; no timing order is predicted
  - stage_id: coalescing-direction
    changed_variable: thread-to-coordinate direction only
    hypothesis: exact-GPU global-access evidence may distinguish input-linear ownership from baseline-direct; no metric value or winner is predicted
  - stage_id: shared-memory-tiling
    changed_variable: unpadded 32x32 shared staging plus one uniform block barrier only
    hypothesis: exact-GPU evidence may support or reject the model of coalesced global reads and writes while exact output remains fixed
  - stage_id: padded-bank-layout
    changed_variable: physical shared row stride changes from 32 to 33 only
    hypothesis: exact-GPU shared-bank evidence may support or reject the padding model; no direction, magnitude, or winner is predicted
```

The baseline uses output-linear ownership: adjacent threads write adjacent output elements and read transposed input coordinates. The coalescing-direction pass flips only that ownership so adjacent threads read adjacent input elements and write transposed output coordinates. The tiling pass keeps input-linear ownership and adds shared staging plus a uniform barrier so the static model can present contiguous global access on both sides. The bank-layout pass changes only physical shared stride `32` to `33`; it adds no logical column.

**Held constants** across all four stages are the EX14 parent and CPU reference, finite non-NaN deterministic input and oracle values, `4096x4096` shape, out-of-place mapping, exact comparison, one stable device output allocation and address per process, the identical checked full-output quiet-NaN sentinel procedure before every launch, 256 threads per block, 32x32 logical tile, four cooperative slots per thread, edge guards, stage order, one selected GPU, C++17 Lane, compiler and link options, candidate binary, process environment, synchronization rule, profiler executable, selected section or metrics, filter, replay controls, and ten-attempt acquisition policy. The sentinel fill and complete-output readback stay outside selected kernel metrics. Preserve a reviewed source diff proving only the declared variable changed between adjacent stages. If another variable changes, create a new experiment.

These are explicit hypotheses, not conclusions. LAB10 contains **no timing, metric, speedup, bottleneck, or winner**.

run_recorded() {
  local output_relative="$1"
  shift
  local stdout_path="${run_dir}/${output_relative}"
  local record_base="$stdout_path"
  case "$record_base" in
    *.stdout.log) record_base="${record_base%.stdout.log}" ;;
    *.csv) record_base="${record_base%.csv}" ;;
  esac
  local stderr_path="${record_base}.stderr.log"
  local status_path="${record_base}.status"
  local command_path="${record_base}.command"
  local records_hash_path="${record_base}.records.sha256"
  local record_path actual_status
  test "$#" -gt 0 || return 2
  for record_path in "$stdout_path" "$stderr_path" "$status_path" "$command_path" "$records_hash_path"; do
    test ! -e "$record_path" || return 1
  done
  printf '%q ' "$@" >"$command_path" || return 1
  printf '\n' >>"$command_path" || return 1
  "$@" >"$stdout_path" 2>"$stderr_path"
  actual_status=$?
  printf '%s\n' "$actual_status" >"$status_path" || return 1
  sha256sum "$stdout_path" "$stderr_path" "$status_path" "$command_path" \
    >"$records_hash_path" || return 1
  return "$actual_status"
}
