LAB05 is a Lab. Outside the website, you hold EX06's logical work constant and observe only its explicit unpadded and padded shared-memory layouts. The site runs no CUDA and fills no profiler result.

## Lab contract

| Coordinate | Requirement |
| --- | --- |
| Difficulty and time | Intermediate, about 90 minutes |
| Prerequisites | M04 and Q05 |
| Supported Environment | Native Linux only; exactly one CUDA GPU with compute capability 7.5 or newer |
| Toolkit Lane | CUDA 11.8.0, 12.9.2, or 13.3.1 under C++17 |
| Workload | One 32-thread block, one 32 x 32 input tile, two 32-element outputs, and a conservative global-plus-larger-shared-layout bound of 8,576 bytes |
| Tool | The Lane-matched Nsight Compute CLI (`ncu`) and a shared-memory bank-conflict metric actually exposed by this GPU |
| Permissions | Device, binary, and evidence-directory access plus administrator-approved performance counter permission; no temporary privilege elevation |
| Acceptance order | Exact CPU-reference correctness and the same logical outputs for unpadded/padded, then profiling and interpretation |
| Evidence | Compilation is empty; runtime is Pending Hardware Verification; recorded observations are empty |

## Prerequisite check

1. Complete [M04](/en/memory/bank-conflicts-layouts/), use word index modulo bank count to analyze a bank conflict, and distinguish an address model from a profiler observation.
2. Complete [Q05](/en/correctness/timing-asynchronous-gpu-work/) and define warm-up exclusion, repeated samples, a completion boundary, and a predeclared statistic.
3. Confirm that exactly one GPU participates and that you can preserve raw stdout/stderr, each command's exit status, profiler reports, and a complete Environment Manifest.

## Freeze the measurement plan

Before the first profiler collection:

1. Freeze the same source commit, binary SHA-256, Lane, device, input, logical work, variant order, build flags, launch geometry, `ncu` options, and metric list. Padding is the only layout variable.
2. Directly run the complete binary once more as a process-level warm-up, recheck exact outputs, and exclude it from all statistics. It is not equivalent to steady-state warm-up inside each new profiler process.
3. Make exactly 10 independent measured profiler invocations of the same binary and retain every unpadded/padded attempt in acquisition order.
4. Predeclare the summary for each layout/metric as the median and min/max spread of that fixed 10-attempt batch, calculated only when all 10 attempts qualify. Only a nonzero tool/application status, correctness failure, missing kernel, or missing metric value marks an attempt invalid; preserve the record and reason. A large or inconvenient value is not invalid. If any attempt is invalid, publish no summary and record a batch blocker; after correcting the cause, restart all 10 attempts in a new batch directory instead of selectively replacing or overwriting samples.

This is the equal work/build/launch freeze. Restart the complete batch after changing a frozen dimension; never select or join samples across contracts.

## Interpret the records

Event timing and a profiler measurement are not interchangeable. A timing-enabled event marks the device timeline through `cudaEventRecord`, and `cudaEventElapsedTime` returns the completed event interval. Canonical EX06 has no event instrumentation. Nsight Compute inserts measurement libraries and may replay or serialize work, control cache or clocks, and collect in multiple passes; its duration or counter belongs only to that profiler contract.

LAB05 does not modify the binary to add events and does not mix event, wall-clock, and profiler samples. A new event experiment must redeclare build, warm-up, synchronization boundary, and statistic.

If all 10 attempts qualify under the same metric, unit, options, and device, attach every path to the median and min/max spread; otherwise report the blocker and no summary. The address model can explain bank mapping, but this Lab predicts no profiler ordering, duration, latency, throughput, or speedup between unpadded and padded. A missing required metric or result that cannot support interpretation remains a blocker or uncertainty, not a prediction.

## Expected observations, not recorded results

- Unpadded and padded should produce the same logical outputs and each exactly match the CPU reference for all 32 lanes.
- After the gates pass, each layout should map to its raw bank-conflict profiler measurement, report, and status; no direction or value is promised.
- The warm-up should be excluded and all 10 attempts retained; the predeclared median plus min/max spread should be reported only when the complete fixed batch qualifies.

These are expected observations, not recorded results. There is no prefilled numeric GPU result, runtime output, or profiler result on this page, and `recordedObservations` is empty.
