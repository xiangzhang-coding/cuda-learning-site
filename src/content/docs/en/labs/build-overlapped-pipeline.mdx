## Review canonical source

The `chunk-contract` range freezes 4,099 elements, 1,024 elements per chunk, 2 chunk streams, overflow-safe byte and chunk calculations, deterministic input and reference functions, and an exact verifier:

<CanonicalCode exampleId="EX07" range="chunk-contract" />

The `stream-pipeline` range freezes the H2D, same transform kernel, D2H, stream placement, wait edge from serial completion, and terminal events for the serial and chunked paths:

<CanonicalCode exampleId="EX07" range="stream-pipeline" />

Chunk offset and count pairs are `(0, 1024)`, `(1024, 1024)`, `(2048, 1024)`, `(3072, 1024)`, and `(4096, 3)`. Each chunk selects a slot and stream by index modulo 2; order in each stream protects slot reuse. Outside the imported ranges, the complete source allocates three 16,396-byte host buffers with `cudaMallocHost`, totaling 49,188 bytes. Serial input/output allocations plus two sets of chunk input/output slots use at most 49,176 device bytes.

These source facts establish only the intended graph and correctness oracle. Timing-disabled events, `asyncEngineCount`, `concurrentKernels`, page locking, `cudaMemcpyAsync`, and multiple streams record no execution interval and prove no overlap.

  2>"${session_dir}/export.stderr.log"

## Interpret the exact trace

Check application status, profiler diagnostics, dropped or incomplete records, the report hash, and stream/phase correlation first. In the chunked phase, place H2D and D2H direction, kernel intervals, stream identity, event waits and records, and dependency edges in one ledger. The serial phase is a correctness-preserving baseline path, not an overlap candidate executing alongside the chunked path.

Record overlap only when two observed intervals actually intersect, and include the report hash, process/context, streams, operation directions or names, and interval coordinates. Record serialization only when a complete qualifying trace clearly shows that relevant intervals do not intersect. If intervals are too short, rows are missing, correlation is ambiguous, or tracing quality is insufficient, record inconclusive. Blank timeline space cannot be forced into a serialization result.

The `.nsys-rep` is the primary artifact. `nsys stats` can aggregate away ordering, and the SQLite export is a version- and schema-dependent representation. They support lookup and cross-checking but do not independently prove overlap. CUPTI tracing is an instrumented execution bounded by buffering, delivery, overhead, and dropped records.

Even observed overlap in this run does not prove that pinned memory, two streams, or engine count caused it, and it supports no throughput, bottleneck, or speedup inference. A serialized run cannot be generalized to every compatible GPU. For kernel-specific investigation, use the gates in [LAB08](/en/labs/profile-full-application-before-kernel/) and [VIS14](/en/visuals/nsight-systems-versus-nsight-compute/) to select one exact kernel and question.
