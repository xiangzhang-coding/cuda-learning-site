This Glossary records the canonical vocabulary used by CUDA Learning Site. Each entry pairs the English term used in source material and tools with the preferred Chinese term used here.

## How to use it

“Avoid” identifies wording that would blur a teaching contract or resource type. It is not a ban on ordinary language. Each entry also names related Learning Units and any version boundary.

## Published term index

<ResourceIndex group="glossary" locale="en" />

`TERM-*` is a stable planning ID, not a rule that generates a permanent URL. Card links point to the current term locations. Filtering does not hide the static definitions below or retain learner progress.

## Published entries

<span id="term-001" class="resource-target" aria-hidden="true"></span>

### Learning Site · 学习站

- **Definition:** The complete public learning resource, including the Stable Curriculum, Runnable Examples, Labs, and Exercises.
- **Avoid:** Blog, documentation site.
- **Related unit:** O01.
- **Version note:** Not tied to a Toolkit version.

<span id="term-002" class="resource-target" aria-hidden="true"></span>

### Stable Curriculum · 稳定课程

- **Definition:** The prerequisite-bearing curriculum built on non-preview interfaces and durable concepts. Stability describes the teaching dependency contract, not a hardware-observation claim for every hands-on activity.
- **Avoid:** Main curriculum, latest-feature catalog.
- **Related unit:** O01.
- **Version note:** Maintained continuously rather than copied per Toolkit.

<span id="term-003" class="resource-target" aria-hidden="true"></span>

### Learning Unit · 学习单元

- **Definition:** A sequenced part of the curriculum that motivates one topic, develops its mental model and relevant historical context, and ends by checking understanding through practice.
- **Avoid:** Article, post.
- **Related unit:** O01.
- **Version note:** The resource type is version-independent.

<span id="term-004" class="resource-target" aria-hidden="true"></span>

### Publication Pair · 双语发布对

- **Definition:** The Chinese and English counterparts of one public page, sharing facts, structure, code, visuals, metadata, and source dates.
- **Avoid:** Translation fallback, optional translation.
- **Related unit:** O01.
- **Version note:** Applies to every release.

<span id="term-005" class="resource-target" aria-hidden="true"></span>

### Runnable Example · 可运行示例

- **Definition:** A standalone source project demonstrating one focused idea and serving as the canonical executable source for Learning Units.
- **Avoid:** Snippet, pseudocode, Lab.
- **Related units:** O01 and F01.
- **Version note:** Each project declares its own compatibility.

<span id="term-006" class="resource-target" aria-hidden="true"></span>

### Lab · 实验

- **Definition:** A guided activity that learners run in an external CUDA-capable environment, with expected observations and acceptance criteria.
- **Avoid:** Demo, browser playground.
- **Related units:** O01 and LAB02.
- **Version note:** Each Lab declares its environment requirements.

<span id="term-007" class="resource-target" aria-hidden="true"></span>

### Exercise · 练习

- **Definition:** A learner-completed task that states its goal, constraints, and acceptance criteria rather than only presenting an answer.
- **Avoid:** Example, Lab.
- **Related unit:** O01.
- **Version note:** The resource type is version-independent.

<span id="term-008" class="resource-target" aria-hidden="true"></span>

### Practice Bank · 练习题库

- **Definition:** A curated collection of original problems across the curriculum, with every entry linked to the Learning Units that teach its prerequisites.
- **Avoid:** FAQ, copied question dump.
- **Related unit:** O01.
- **Version note:** Individual entries declare version boundaries when needed.

<span id="term-009" class="resource-target" aria-hidden="true"></span>

### Visual Explainer · 可视化讲解

- **Definition:** An interactive or animated representation that exposes spatial, temporal, or architectural behavior. It may model CUDA concepts in the browser but never executes CUDA.
- **Avoid:** Decoration, CUDA demo.
- **Related resources:** O01, [VIS01](/en/visuals/kernel-journey/), [VIS02](/en/visuals/indexing/), [VIS04](/en/visuals/memory-transactions/), [VIS05](/en/visuals/shared-memory-banks/), [VIS06](/en/visuals/memory-hierarchy-lifetime/), [VIS19](/en/foundations/asynchronous-errors/#vis19), [VIS20](/en/foundations/compute-capability/#vis20), [VIS21](/en/foundations/runtime-driver-api/#vis21), and [VIS22](/en/foundations/launch-geometry/#vis22).
- **Version note:** Conceptual models must be separated from hardware-specific behavior.

<span id="term-010" class="resource-target" aria-hidden="true"></span>

### Glossary · 术语表

- **Definition:** A learner-facing bilingual index of canonical terms used throughout the curriculum.
- **Avoid:** Dictionary, keyword list.
- **Related unit:** O01.
- **Version note:** Entries are reviewed with the curriculum but do not imply interface compatibility.

<span id="term-011" class="resource-target" aria-hidden="true"></span>

### Evidence Status · 证据状态

- **Definition:** A controlled label describing the reviewable evidence available for a Lab or Runnable Example. Compilation and runtime are independent axes.
- **Avoid:** Unqualified “verified” or “supported.”
- **Related unit:** O02.
- **Version note:** A status is scoped to a subject, environment, criteria, and date; publishing a web page grants none.

<span id="term-012" class="resource-target" aria-hidden="true"></span>

### Compile-Checked · 编译已检查

- **Definition:** The required source actually built in a declared Toolkit Lane with dialect, target, command, and build environment recorded. It neither requires nor implies GPU execution.
- **Avoid:** Runtime-Verified, tested on GPU.
- **Related units:** O02, O03.
- **Version note:** Every claim binds to an exact Toolkit Lane.

<span id="term-013" class="resource-target" aria-hidden="true"></span>

### Community-Observed · 社区已观察

- **Definition:** A contributor reported a runtime observation with a complete Environment Manifest, logs or artifacts, criteria, and date. It is not maintainer reproduction.
- **Avoid:** Runtime-Verified, anecdotal support.
- **Related units:** O02, O03.
- **Version note:** May coexist with Pending Hardware Verification.

<span id="term-014" class="resource-target" aria-hidden="true"></span>

### Runtime-Verified · 运行已验证

- **Definition:** The subject executed in a declared, maintainer-controlled Reference Environment and met its stated correctness and observation criteria.
- **Avoid:** Compile-Checked, expected to work.
- **Related units:** O02, O03.
- **Version note:** The conclusion covers only recorded GPU, driver, Toolkit, components, workload, and method coordinates.

<span id="term-015" class="resource-target" aria-hidden="true"></span>

### Pending Hardware Verification · 待硬件验证

- **Definition:** Acceptance requires GPU behavior, but the required qualifying runtime evidence does not yet exist.
- **Avoid:** Runtime-Verified, should run.
- **Related unit:** O02.
- **Version note:** A successful build or community observation does not remove it automatically.

<span id="term-016" class="resource-target" aria-hidden="true"></span>

### Runtime-Not-Applicable · 无需运行验证

- **Definition:** A runtime-axis status for acceptance criteria that require compilation or artifact inspection and no GPU behavior.
- **Avoid:** Compile-only, skipped runtime.
- **Related unit:** O02.
- **Version note:** It must not hide runtime correctness or performance requirements.

<span id="term-017" class="resource-target" aria-hidden="true"></span>

### Environment Manifest · 环境清单

- **Definition:** Separate GPU, compute-capability, count, driver, Toolkit, component, compiler, operating-system, workload, and method coordinates needed to interpret a build, run, or measurement.
- **Avoid:** Version string, machine description.
- **Related unit:** O03.
- **Version note:** New evidence records new coordinates and an observation date.

<span id="term-018" class="resource-target" aria-hidden="true"></span>

### Supported Environment · 受支持环境

- **Definition:** An environment family for which the site accepts setup guidance, troubleshooting boundaries, and validation responsibility. Native Linux is the only one.
- **Avoid:** Any platform that may happen to work.
- **Related unit:** O03.
- **Version note:** Upstream product support does not expand site responsibility automatically.

<span id="term-019" class="resource-target" aria-hidden="true"></span>

### Reference Environment · 基准环境

- **Definition:** A declared, maintainer-controlled configuration inside the Supported Environment with a complete manifest and successful controlled baseline run.
- **Avoid:** Recommended environment, community setup.
- **Related unit:** O03.
- **Version note:** No Reference Environment is currently declared.

<span id="term-020" class="resource-target" aria-hidden="true"></span>

### Toolkit Lane · 工具包通道

- **Definition:** A pinned Toolkit and host environment with declared C++ dialects, used as a compile-evidence target.
- **Avoid:** Site version, documentation version.
- **Related unit:** O03.
- **Version note:** A Lane is not a curriculum copy or Reference Environment; only a successful build can add Compile-Checked.

<span id="term-021" class="resource-target" aria-hidden="true"></span>

### GPU Capability Tier · GPU 能力层级

- **Definition:** A curriculum support tier defined by compute capability, memory, GPU count, features, and permissions.
- **Avoid:** GPU class, memory tier.
- **Related unit:** O03.
- **Version note:** Product names and extra memory cannot select a tier alone.

<span id="term-022" class="resource-target" aria-hidden="true"></span>

### Baseline GPU Capability Tier · 基础 GPU 能力层级

- **Definition:** The tier for Stable Curriculum fundamentals, requiring compute capability 7.5 or newer and problem sizes that fit within 8 GB.
- **Avoid:** 8 GB GPU tier, Turing tier.
- **Related unit:** O03.
- **Version note:** 8 GB is a workload boundary, not a separate hardware class.

<span id="term-023" class="resource-target" aria-hidden="true"></span>

### Modern Single-GPU Capability Tier · 现代单 GPU 能力层级

- **Definition:** The tier for the complete single-GPU route, requiring compute capability 8.0 or newer and at least 8 GB. Additional activities state extra gates.
- **Avoid:** Complete tier, Ampere tier.
- **Related unit:** O03.
- **Version note:** It does not automatically cover multi-GPU or architecture-specific activities.

<span id="term-024" class="resource-target" aria-hidden="true"></span>

### CUDA Toolkit · CUDA 工具包

- **Definition:** NVIDIA's bundle of compilers, libraries, tools, and runtime development components, recorded separately from the installed driver and individual component versions.
- **Avoid:** CUDA driver version, the whole CUDA environment.
- **Related unit:** O03.
- **Version note:** Toolkit Lanes use exact `X.Y.Z` coordinates.

<span id="term-025" class="resource-target" aria-hidden="true"></span>

### compute capability · 计算能力

- **Definition:** A major.minor capability coordinate describing a set of GPU architectural features and technical limits.
- **Avoid:** GPU generation, Toolkit version.
- **Related resources:** [O03](/en/start/environment-manifest/) and [F06](/en/foundations/compute-capability/).
- **Version note:** Model mappings, features, limits, and compiler targets require current NVIDIA documentation.

<span id="term-026" class="resource-target" aria-hidden="true"></span>

### kernel · 核函数

- **Definition:** A function launched by the host and executed by many threads on a CUDA device. In CUDA C++, a `__global__` kernel is launched with an execution configuration.
- **Avoid:** Ordinary CPU function, browser animation.
- **Related resources:** [F01](/en/foundations/first-cuda-kernel/), [F02](/en/foundations/execution-hierarchy/), [F03](/en/foundations/multidimensional-indexing/), [F04](/en/foundations/host-device-lifecycle/), [EX03](/en/examples/multidimensional-indexing/), and [LAB02](/en/labs/vector-addition/).
- **Version note:** F01 uses the foundational execution model in CUDA Programming Guide v13.3.

<span id="term-027" class="resource-target" aria-hidden="true"></span>

### execution configuration · 执行配置

- **Definition:** The kernel-launch configuration that declares grid and thread-block shapes; a one-dimensional case commonly supplies block count and threads per block.
- **Avoid:** Data extent, GPU configuration.
- **Related resources:** [F01](/en/foundations/first-cuda-kernel/), [F02](/en/foundations/execution-hierarchy/), [F03](/en/foundations/multidimensional-indexing/), [VIS02](/en/visuals/indexing/), and [EX03](/en/examples/multidimensional-indexing/).
- **Version note:** The configuration creates execution threads but does not define logical data extent automatically.

<span id="term-028" class="resource-target" aria-hidden="true"></span>

### grid · 网格

- **Definition:** The complete collection of thread blocks created by one kernel launch, with one-, two-, or three-dimensional shape.
- **Avoid:** Data array, fixed scheduling order.
- **Related resources:** [F01](/en/foundations/first-cuda-kernel/), [F02](/en/foundations/execution-hierarchy/), [F03](/en/foundations/multidimensional-indexing/), [VIS01](/en/visuals/kernel-journey/), [VIS02](/en/visuals/indexing/), and [EX03](/en/examples/multidimensional-indexing/).
- **Version note:** Grid coordinates do not guarantee block dispatch or completion order.

<span id="term-029" class="resource-target" aria-hidden="true"></span>

### thread block · 线程块

- **Definition:** A group of threads in a grid scheduled together on one SM. `blockIdx` identifies a block, while `blockDim` describes its shape.
- **Avoid:** CPU thread pool, warp.
- **Related resources:** [F01](/en/foundations/first-cuda-kernel/), [F02](/en/foundations/execution-hierarchy/), [F03](/en/foundations/multidimensional-indexing/), [VIS01](/en/visuals/kernel-journey/), [VIS02](/en/visuals/indexing/), and [EX03](/en/examples/multidimensional-indexing/).
- **Version note:** F01 uses only one-dimensional blocks; VIS02 covers multidimensional relationships.

<span id="term-030" class="resource-target" aria-hidden="true"></span>

### thread · 线程

- **Definition:** One logical execution instance of a kernel. It derives an owned data position from `threadIdx` and block/grid coordinates.
- **Avoid:** Element, warp, operating-system thread.
- **Related resources:** [F01](/en/foundations/first-cuda-kernel/), [F02](/en/foundations/execution-hierarchy/), [F03](/en/foundations/multidimensional-indexing/), [VIS02](/en/visuals/indexing/), and [EX03](/en/examples/multidimensional-indexing/).
- **Version note:** A launched thread may lie beyond logical data extent, so a bounds check remains necessary.

<span id="term-031" class="resource-target" aria-hidden="true"></span>

### host and device · 主机与设备

- **Definition:** Host code runs on the CPU side and manages allocation, copies, launch, and synchronization. Device code executes on a CUDA GPU, with explicit memory and completion boundaries between them.
- **Avoid:** Treating a host test as a GPU run, treating device memory as host memory.
- **Related resources:** [F01](/en/foundations/first-cuda-kernel/), [F04](/en/foundations/host-device-lifecycle/), [EX03](/en/examples/multidimensional-indexing/), and [LAB02](/en/labs/vector-addition/).
- **Version note:** LAB02 uses the declared CUDA Runtime API 11.8.0, 12.9.2, or 13.3.1 Lane.

<span id="term-032" class="resource-target" aria-hidden="true"></span>

### bounds check · 边界判断

- **Definition:** A comparison between a thread's derived index and logical extent before array access, causing out-of-bounds threads in the final partial block to skip access.
- **Avoid:** Preventing thread launch, shrinking the grid.
- **Related resources:** [F01](/en/foundations/first-cuda-kernel/), [F03](/en/foundations/multidimensional-indexing/), [VIS02](/en/visuals/indexing/), [EX03](/en/examples/multidimensional-indexing/), and [LAB02](/en/labs/vector-addition/).
- **Version note:** EX02's one-dimensional condition is `index < element_count`.

<span id="term-033" class="resource-target" aria-hidden="true"></span>

### CPU reference · CPU 参考实现

- **Definition:** An implementation independent of the CUDA kernel that calculates expected results on the CPU for element-wise correctness comparison.
- **Avoid:** GPU runtime evidence, performance baseline unless separately defined by a measurement contract.
- **Related units:** F01 and LAB02.
- **Version note:** EX02's host-only test runs no GPU and grants no Runtime-Verified status.

<span id="term-034" class="resource-target" aria-hidden="true"></span>

### tolerance · 容差

- **Definition:** A predefined floating-point acceptance rule. EX02 accepts an element when either absolute `1e-5` or relative `1e-5` succeeds.
- **Avoid:** Requiring both criteria, treating any decimal output as correct.
- **Related units:** F01 and LAB02.
- **Version note:** The values belong to the EX02 correctness contract; changing them creates a new evidence scope.

<span id="term-035" class="resource-target" aria-hidden="true"></span>

### RAII · 资源获取即初始化

- **Definition:** A C++ lifetime-management technique that binds resource ownership to an object's lifetime, acquires the resource during initialization, and releases it through the owner's destructor. O04 treats raw pointers as non-owning views as guidance, not as a rule of the C++ language.
- **Avoid:** Garbage collection, treating every raw pointer as an owner.
- **Related unit:** O04.
- **Version note:** O04 uses the C++17 baseline; an interface may still document ownership transfer explicitly.

<span id="term-036" class="resource-target" aria-hidden="true"></span>

### undefined behavior · 未定义行为

- **Definition:** An operation for which the C++ specification imposes no required behavior.
- **Avoid:** Guaranteed crash, unspecified behavior, implementation-defined behavior.
- **Related unit:** O04.
- **Version note:** O04 uses the C++17 language baseline; compiler diagnostics and sanitizer results neither redefine undefined behavior nor prove its absence.

<span id="term-037" class="resource-target" aria-hidden="true"></span>

### translation unit · 翻译单元

- **Definition:** The source material produced after preprocessing one source file, including expanded includes and macros, that a compiler translates as one unit.
- **Avoid:** The unpreprocessed source file, the whole program, a linked executable.
- **Related unit:** O04.
- **Version note:** O04 describes the boundary with C++17 and NVCC 13.3; Toolkit-internal steps may change, but a translation unit exists after preprocessing.

<span id="term-038" class="resource-target" aria-hidden="true"></span>

### reproducible command record · 可复现命令记录

- **Definition:** A reviewable capture of one command stage containing the literal command and argument boundaries; working directory, allowlisted environment, and tool context; separate stdout and stderr streams; exit status; collection date and UTC start and finish times; and hashes of retained inputs and artifacts.
- **Avoid:** Paraphrased command, screenshot-only log, merged output without exit status.
- **Related unit:** O05.
- **Version note:** Tool and operating-system versions belong to the execution context; changing the command, context, or hashed bytes creates a different record.

<span id="term-039" class="resource-target" aria-hidden="true"></span>

### latency · 延迟

- **Definition:** Elapsed time from a declared start boundary to a declared finish boundary for one named event, reported with units. It measures one event, not completed work per interval.
- **Avoid:** Throughput, rate, a timing value without an event and boundaries.
- **Related unit:** O06.
- **Version note:** Comparable latency measurements align the event, synchronization boundary, timer and version, workload, and units.

<span id="term-040" class="resource-target" aria-hidden="true"></span>

### throughput · 吞吐量

- **Definition:** The amount of named work completed per declared time interval, reported with units such as items/s or operations/s. It is a rate, not one event's elapsed time.
- **Avoid:** One operation's latency, a rate without work and time boundaries, an unconditional peak value.
- **Related units:** O06 and O07.
- **Version note:** Concurrency or batching can raise throughput while per-item latency stays unchanged; comparisons must align workload, interval, and units.

<span id="term-041" class="resource-target" aria-hidden="true"></span>

### bandwidth · 带宽

- **Definition:** A data-transfer rate over a named path and direction, with a byte-count convention, time interval, and units such as GB/s or GiB/s.
- **Avoid:** Pathless throughput claim, omitted units, treating GB/s and GiB/s as interchangeable.
- **Related unit:** O06.
- **Version note:** Theoretical, effective, and actual bandwidth are comparable only when path, direction, time, and unit conventions align.

<span id="term-042" class="resource-target" aria-hidden="true"></span>

### concurrency · 并发

- **Definition:** Two or more named operations overlap in time within a declared scope; this alone does not mean different hardware units execute them at the same instant.
- **Avoid:** Treating stream count, asynchronous submission, residency, or occupancy as proof of observed overlap.
- **Related unit:** O06.
- **Version note:** Source and APIs can show only that overlap is possible; actual concurrency needs a timeline or equivalent observation from the exact execution and a scope such as kernels, copy/compute, or CPU/GPU work.

<span id="term-043" class="resource-target" aria-hidden="true"></span>

### arithmetic intensity · 算术强度

- **Definition:** For a named workload, a declared count of arithmetic work divided by data traffic across a declared memory boundary, in operations/byte.
- **Avoid:** Operation count alone, FLOP/s, a ratio without a traffic boundary.
- **Related unit:** O06.
- **Version note:** Changing the operation-count rule, read/write traffic convention, memory level, or workload scope changes the intensity.

<span id="term-044" class="resource-target" aria-hidden="true"></span>

### occupancy · 占用率

- **Definition:** Commonly, the ratio of active warps per SM to the hardware maximum active warps, not GPU utilization or a performance guarantee.
- **Avoid:** GPU utilization, proof of concurrent execution, performance score or guarantee.
- **Related unit:** O06.
- **Version note:** Architecture, block size, registers, and shared-memory limits jointly constrain occupancy; higher occupancy guarantees neither higher throughput nor shorter runtime.

<span id="term-045" class="resource-target" aria-hidden="true"></span>

### programmable shader stage · 可编程着色器阶段

- **Definition:** A selected stage in a graphics pipeline where an application supplies instructions while invocation, inputs, outputs, resource limits, and surrounding stages retain graphics semantics.
- **Avoid:** General-purpose kernel, unrestricted processor interface, CUDA kernel.
- **Related unit:** O07.
- **Version note:** Available stages, profiles, and capabilities vary by graphics API and period; the term remains bound to a graphics pipeline.

<span id="term-046" class="resource-target" aria-hidden="true"></span>

### GPGPU · 通用 GPU 计算

- **Definition:** The broad practice of using GPUs for nongraphics computation, historically often by mapping data and work through textures, shader stages, and render targets, and later also through general-purpose compute interfaces. It is a historical category, not a synonym for CUDA.
- **Avoid:** A synonym for CUDA, programmable shader stage, a label for all GPU work.
- **Related unit:** O07.
- **Version note:** GPGPU spans periods, APIs, and hardware; CUDA is one general-purpose platform and model within that history, not an equivalent term.

<span id="term-047" class="resource-target" aria-hidden="true"></span>

### compatibility assessment · 兼容性评估

- **Definition:** A source-dated comparison of exact environment coordinates with selected current owner documentation that yields only one of three triage outcomes: `documented-path`, `not-documented`, or `indeterminate`. No outcome grants compilation or runtime evidence.
- **Avoid:** Supported verdict, Evidence Status, runtime validation, Reference Environment declaration.
- **Related unit:** O08.
- **Version note:** An outcome is scoped to the recorded coordinates, sources, and date, and none grants compilation or runtime evidence; `documented-path` only permits validation to continue.

<span id="term-048" class="resource-target" aria-hidden="true"></span>

### Reference Environment candidate · 基准环境候选配置

- **Definition:** One exact native-Linux GPU and software configuration being reviewed against manifest, tier, compatibility, maintainer control, and a separately designated baseline. Candidate status does not declare a Reference Environment.
- **Avoid:** Declared Reference Environment, recommended setup, validated machine.
- **Related units:** O08 and LAB01.
- **Version note:** Candidate status is not a declaration; only a separate maintainer declaration after every gate passes can establish a Reference Environment.

<span id="term-049" class="resource-target" aria-hidden="true"></span>

### streaming multiprocessor (SM) · 流式多处理器

- **Definition:** A hardware execution resource in a CUDA GPU that receives thread blocks and schedules their warps. The blocks and warps resident on one SM are limited by architectural resources such as registers and shared memory.
- **Avoid:** The whole GPU, CUDA core, thread block.
- **Related resources:** [F02](/en/foundations/execution-hierarchy/) and [VIS01](/en/visuals/kernel-journey/).
- **Version note:** Execution-hierarchy and scheduling language follows CUDA Programming Guide v13.3. SM counts and per-SM limits are architecture-specific and cannot be inferred from launch geometry.

<span id="term-050" class="resource-target" aria-hidden="true"></span>

### warp · 线程束

- **Definition:** A group of 32 threads with consecutive block-local linear IDs from one thread block, scheduled by an SM under the SIMT model. Each thread occupies one lane.
- **Avoid:** Thread block, CPU SIMD vector, completion-order guarantee.
- **Related resources:** [F02](/en/foundations/execution-hierarchy/), [VIS01](/en/visuals/kernel-journey/), and [VIS02](/en/visuals/indexing/).
- **Version note:** The 32-thread grouping and execution model follow CUDA Programming Guide v13.3. Specific scheduling order still cannot be inferred from a warp number.

<span id="term-051" class="resource-target" aria-hidden="true"></span>

### lane · 通道

- **Definition:** The `0..31` position occupied by a block thread within its warp. For block-local linear thread ID `t`, the lane is `t % 32`; it is neither a data index nor an execution order.
- **Avoid:** CUDA core, global data index, synonym for `threadIdx.x`.
- **Related resources:** [F02](/en/foundations/execution-hierarchy/) and [VIS02](/en/visuals/indexing/).
- **Version note:** The position and modulo rule follow the 32-thread warp model in CUDA Programming Guide v13.3.

<span id="term-052" class="resource-target" aria-hidden="true"></span>

### dim3 · 三分量 launch 配置类型

- **Definition:** A CUDA C++ type with `x`, `y`, and `z` components used to express grid or thread-block dimensions. Components omitted during construction default to `1`.
- **Avoid:** Logical extent, data layout, complete kernel launch.
- **Related resources:** [F03](/en/foundations/multidimensional-indexing/) and [EX03](/en/examples/multidimensional-indexing/).
- **Version note:** The type and component defaults follow CUDA Programming Guide v13.3 and CUDA Runtime API 13.3.1. EX03 selects CUDA 11.8.0, 12.9.2, and 13.3.1 Toolkit Lanes; selection alone is not Compile-Checked.

<span id="term-053" class="resource-target" aria-hidden="true"></span>

### logical extent · 逻辑范围

- **Definition:** The valid coordinate range declared by an application for a problem or data along each active axis. Threads check it per axis before access, while the launch may create more threads.
- **Avoid:** `gridDim`, allocation byte count, launch geometry.
- **Related resources:** [F03](/en/foundations/multidimensional-indexing/), [VIS02](/en/visuals/indexing/), and [EX03](/en/examples/multidimensional-indexing/).
- **Version note:** Coordinates and the launch model follow CUDA Programming Guide v13.3. EX03 shares the same extent contract across its selected CUDA 11.8.0, 12.9.2, and 13.3.1 Toolkit Lanes.

<span id="term-054" class="resource-target" aria-hidden="true"></span>

### row-major layout · 行主序布局

- **Definition:** An application-declared data layout that maps consecutive columns in a row to consecutive linear positions. F03 and EX03 use the x-fastest formula `((z * height) + y) * width + x`. CUDA launch geometry produces coordinates but does not declare this layout.
- **Avoid:** CUDA default layout, grid/block shape, synonym for column-major layout.
- **Related resources:** [F03](/en/foundations/multidimensional-indexing/), [VIS02](/en/visuals/indexing/), and [EX03](/en/examples/multidimensional-indexing/).
- **Version note:** The CUDA coordinate model follows CUDA Programming Guide v13.3. The layout formula is an application contract held constant across EX03's selected CUDA 11.8.0, 12.9.2, and 13.3.1 Toolkit Lanes.

<span id="term-055" class="resource-target" aria-hidden="true"></span>

### resource lifecycle · 资源生命周期

- **Definition:** The acquisition, initialization, use, synchronization or transfer, and release of resources organized by ownership and last-use boundaries. An explicit CUDA program tracks host storage separately from device allocations.
- **Avoid:** Kernel execution alone, synonym for RAII, API list without ownership and release responsibility.
- **Related resources:** [F04](/en/foundations/host-device-lifecycle/), [O04](/en/start/cpp17-for-cuda/), and [EX03](/en/examples/multidimensional-indexing/).
- **Version note:** F04's CUDA call boundaries follow CUDA Runtime API 13.3.1. EX03 declares the same explicit lifecycle in its selected CUDA 11.8.0, 12.9.2, and 13.3.1 Toolkit Lanes; Lane selection grants neither compilation nor runtime evidence.

<span id="term-056" class="resource-target" aria-hidden="true"></span>

### asynchronous error · 异步错误

- **Definition:** A failure produced by previously submitted device work that may become host-visible only at a later API observation or completion boundary because submission can return before execution finishes.
- **Avoid:** Saying every CUDA error is asynchronous, or that the API call reporting the failure necessarily caused it.
- **Related resources:** [F05](/en/foundations/asynchronous-errors/), [F07](/en/foundations/runtime-driver-api/), [EX04](/en/examples/error-handling-lifecycle/), and [LAB03](/en/labs/break-and-repair-indexing/).
- **Version note:** Error and synchronization boundaries were reviewed across Runtime API 11.8.0, the 12.9.2 archive whose pages label themselves 12.9.1, and 13.3.1; exact reporting statuses may vary.

<span id="term-057" class="resource-target" aria-hidden="true"></span>

### last-error state · 末次错误状态

- **Definition:** Runtime-library state associated with a host thread that records the last Runtime error: `cudaPeekAtLastError` reads it without resetting, while `cudaGetLastError` reads it and resets it to `cudaSuccess`.
- **Avoid:** Per-kernel error queue, direct return value, completion check.
- **Related resources:** [F05](/en/foundations/asynchronous-errors/), [EX04](/en/examples/error-handling-lifecycle/), and [LAB03](/en/labs/break-and-repair-indexing/).
- **Version note:** The getter-reset, peek-non-reset, and previous-asynchronous-launch caveats are shared by the selected 11.8.0, 12.9.2 archive/page-label 12.9.1, and 13.3.1 Runtime documentation.

<span id="term-058" class="resource-target" aria-hidden="true"></span>

### CUDA Runtime API · CUDA 运行时 API

- **Definition:** NVIDIA's higher-level `cuda*` host API and CUDA C++ launch surface, which commonly manage primary-context initialization and modules implicitly while leaving allocation, arguments, status checks, completion, correctness, and release responsibilities with the application.
- **Avoid:** Ownership-free CUDA, a separate GPU execution system, a one-to-one alias for the Driver API.
- **Related resources:** [F04](/en/foundations/host-device-lifecycle/), [F05](/en/foundations/asynchronous-errors/), [F07](/en/foundations/runtime-driver-api/), [EX04](/en/examples/error-handling-lifecycle/), and [LAB03](/en/labs/break-and-repair-indexing/).
- **Version note:** Implicit-state and interoperability details must be read at the selected 11.8.0, 12.9.2 archive/page-label 12.9.1, or 13.3.1 coordinate; newer execution-context interfaces must not be projected backward.

<span id="term-059" class="resource-target" aria-hidden="true"></span>

### CUDA Driver API · CUDA 驱动 API

- **Definition:** NVIDIA's lower-level `cu*` host API, exposing explicit initialization and device, context, module, function, memory, launch, and synchronization handles or operations to application control.
- **Avoid:** A different device stack, automatically faster Runtime replacement, an API that removes asynchronous errors.
- **Related unit:** [F07](/en/foundations/runtime-driver-api/).
- **Version note:** Handle ownership, current-context rules, interoperability, and teardown are versioned across Driver API 11.8.0, the 12.9.2 archive whose page labels itself 12.9.1, and 13.3.1.

<span id="term-060" class="resource-target" aria-hidden="true"></span>

### virtual architecture target · 虚拟架构目标

- **Definition:** An NVCC `compute_XY`, `compute_XYa`, or `compute_XYf` target that selects the GPU feature assumptions used while preprocessing and compiling device source into PTX.
- **Avoid:** Installed GPU, real architecture target, Toolkit version, runtime compatibility verdict.
- **Related unit:** [F06](/en/foundations/compute-capability/).
- **Version note:** Accepted names and suffixes depend on the exact compiler; F06 reviews selected rows from NVCC 11.8.0, the 12.9.2 archive, and the current NVCC page under Toolkit 13.3.1.

<span id="term-061" class="resource-target" aria-hidden="true"></span>

### real architecture target · 实际架构目标

- **Definition:** An NVCC `sm_XY`, `sm_XYa`, or `sm_XYf` code target naming the GPU architecture for assembled binary code; it must implement every feature assumption of its paired virtual target.
- **Avoid:** Proof of the installed GPU, product model, virtual target, performance prediction.
- **Related unit:** [F06](/en/foundations/compute-capability/).
- **Version note:** Compiler acceptance is versioned, and an accepted pair proves only a compile-plan fact until a qualifying build records the actual artifact.

<span id="term-062" class="resource-target" aria-hidden="true"></span>

### architecture-specific feature set · 架构特定功能集

- **Definition:** The complete set of specialized features for one exact compute capability that are not guaranteed on later architectures; an `a` target enables this set and restricts code to that exact capability.
- **Avoid:** Baseline feature set, family-wide compatibility, “newer GPUs support it automatically.”
- **Related unit:** [F06](/en/foundations/compute-capability/).
- **Version note:** The current CUDA Programming Guide v13.3 defines architecture-specific feature sets beginning with compute capability 9.0; exact targets still require support from the selected NVCC.

<span id="term-063" class="resource-target" aria-hidden="true"></span>

### family-specific feature set · 系列特定功能集

- **Definition:** The subset of architecture-specific features shared by the explicitly listed members of one compute-architecture family; an `f` target enables that subset and restricts code to those family members.
- **Avoid:** Baseline set, exact-architecture `a` set, compatibility with every numerically later capability.
- **Related unit:** [F06](/en/foundations/compute-capability/).
- **Version note:** The current CUDA Programming Guide v13.3 defines family-specific sets beginning with compute capability 10.0; family membership and accepted compiler targets require current owner tables.

<span id="term-064" class="resource-target" aria-hidden="true"></span>

### launch geometry · 启动几何

- **Definition:** The grid and thread-block dimensions supplied for one kernel launch, determining created blocks, threads per block, coordinate coverage, and fringe threads while remaining separate from the application's logical extent and data layout.
- **Avoid:** Logical extent, block shape alone, proof of launch legality, performance configuration.
- **Related resources:** [F02](/en/foundations/execution-hierarchy/), [F03](/en/foundations/multidimensional-indexing/), [F08](/en/foundations/launch-geometry/), and [LAB03](/en/labs/break-and-repair-indexing/).
- **Version note:** F08 reviews CUDA Programming Guide v13.3 and Runtime API 13.3.1 device/function limits; an actual launch must use properties from its selected environment and kernel.

<span id="term-065" class="resource-target" aria-hidden="true"></span>

### block shape · 线程块形状

- **Definition:** The one-, two-, or three-dimensional `blockDim` tuple chosen for a launch; each axis and their checked product must satisfy device limits, and the product plus resource use must satisfy limits for the specific kernel.
- **Avoid:** Threads-per-block scalar alone, logical data tile, occupancy target, fastest configuration.
- **Related resources:** [F08](/en/foundations/launch-geometry/) and [LAB03](/en/labs/break-and-repair-indexing/).
- **Version note:** Equal thread counts can have different coverage and fringe, while device and function limits can change by environment, target, and kernel; only controlled measurement can compare speed.

<span id="term-066" class="resource-target" aria-hidden="true"></span>

### address space · 地址空间

- **Definition:** A program-visible storage and naming domain that constrains which execution agents may address an object, whether they share one instance, and how long that instance remains valid. It does not by itself identify a cache, physical chip, or access time.
- **Avoid:** Cache level, physical-memory tier, speed class.
- **Related resources:** [M01](/en/memory/address-spaces/) and [VIS06](/en/visuals/memory-hierarchy-lifetime/).
- **Version note:** M01 reviews the current Programming Guide v13.3 together with 11.8.0 and 12.9.1 owner documentation for the selected Toolkit Lanes.

<span id="term-067" class="resource-target" aria-hidden="true"></span>

### global memory · 全局内存

- **Definition:** A device address space whose objects can be addressed by kernel threads holding valid device pointers and can outlive one block or kernel launch. Explicit Runtime allocations are acquired and released by host control flow after every device user has completed.
- **Avoid:** Device DRAM as an exact synonym, all device memory, always-uncached memory.
- **Related resources:** [M01](/en/memory/address-spaces/), [M02](/en/memory/coalescing-transactions/), [VIS04](/en/visuals/memory-transactions/), and [EX05](/en/examples/coalesced-strided-access/).
- **Version note:** Ownership, accessibility, and access-shaping semantics are reviewed at selected 11.8.0, 12.9.1, and current v13.3/v13.3.1 coordinates; cache paths remain architecture- and instruction-dependent.

<span id="term-068" class="resource-target" aria-hidden="true"></span>

### constant memory · 常量内存

- **Definition:** Module/context-lifetime device storage declared with `__constant__`, read-only to kernels, grid-visible on one device, and initialized or updated by host symbol operations. The symbol is not an allocation released with `cudaFree`.
- **Avoid:** Constant cache, immutable for the whole application, ordinary global allocation.
- **Related resources:** [M01](/en/memory/address-spaces/) and [VIS06](/en/visuals/memory-hierarchy-lifetime/).
- **Version note:** Declaration, symbol-copy, accessibility, and lifetime details are reviewed in current Programming Guide v13.3 and Runtime API v13.3.1 plus the selected 11.8.0 and 12.9.1 owner documents.

<span id="term-069" class="resource-target" aria-hidden="true"></span>

### shared memory · 共享内存

- **Definition:** Programmer-managed on-device storage instantiated per thread block, shared by threads in that block, and retired automatically when the block's execution ends. Static declarations and dynamic launch allocation establish capacity; neither creates a host-freed global allocation.
- **Avoid:** L1 cache alias, cross-block shared object, automatically coherent global cache.
- **Related resources:** [M01](/en/memory/address-spaces/), [M03](/en/memory/shared-memory-tiling/), [M04](/en/memory/bank-conflicts-layouts/), [VIS05](/en/visuals/shared-memory-banks/), and [EX06](/en/examples/shared-memory-tile-bank-padding/).
- **Version note:** M01/M03/M04 use selected 11.8.0, 12.9.1, and current v13.3 owner documentation; capacity and shared/L1 configuration must be queried for the selected architecture.

<span id="term-070" class="resource-target" aria-hidden="true"></span>

### local memory · 本地内存

- **Definition:** A thread-private CUDA address space used for compiler-managed automatic objects and spills. Its logical scope belongs to one thread even though its backing storage is physically in device memory and may use caches.
- **Avoid:** On-chip local storage, host stack memory, block-private shared memory.
- **Related resources:** [M01](/en/memory/address-spaces/) and [VIS06](/en/visuals/memory-hierarchy-lifetime/).
- **Version note:** Local placement and cache behavior depend on the selected compiler, target, architecture, and access pattern; M01 cross-checks the semantic boundary at 11.8.0, 12.9.1, and current v13.3.

<span id="term-071" class="resource-target" aria-hidden="true"></span>

### register · 寄存器

- **Definition:** A finite per-thread hardware resource assigned by the compiler to values for one thread invocation. Source spelling does not guarantee register placement, and pressure can move a value into thread-private local memory without changing its owner.
- **Avoid:** Source variable that must stay in a register, cache entry, cross-thread storage.
- **Related resources:** [M01](/en/memory/address-spaces/) and [VIS06](/en/visuals/memory-hierarchy-lifetime/).
- **Version note:** Register limits, allocation, and spills vary by compute capability, compiler, target, and kernel; they require the selected environment and compilation artifacts.

<span id="term-072" class="resource-target" aria-hidden="true"></span>

### memory transaction · 内存事务

- **Definition:** A hardware memory-system transfer that services requested bytes at a particular architecture and instruction boundary. M02 predicts the aligned 32-byte segments needed to cover one active warp's global requests; that static set is not an observed transaction log.
- **Avoid:** Source-level load, requested word, segment count relabeled as measured traffic.
- **Related resources:** [M02](/en/memory/coalescing-transactions/), [VIS04](/en/visuals/memory-transactions/), and [EX05](/en/examples/coalesced-strided-access/).
- **Version note:** M02's model applies to CC 6.0+ and this site's CC 7.5+ tier; access size, cache state, and architecture still bound actual issued transactions.

<span id="term-073" class="resource-target" aria-hidden="true"></span>

### coalescing · 合并访问

- **Definition:** The memory system's grouping of active warp lanes' global-memory requests into transactions according to requested addresses, access sizes, and the selected compute-capability rules. Contiguous indexing can support coalescing but does not itself prove a transaction count or speed.
- **Avoid:** Contiguous source order alone, cache hit, automatic speedup.
- **Related resources:** [M02](/en/memory/coalescing-transactions/), [VIS04](/en/visuals/memory-transactions/), and [EX05](/en/examples/coalesced-strided-access/).
- **Version note:** Coalescing rules change across architecture generations; M02 explicitly uses the CC 6.0+ naturally aligned 32-byte segment fixture reviewed against current and selected archive owner guides.

<span id="term-074" class="resource-target" aria-hidden="true"></span>

### shared-memory bank · 共享内存存储体

- **Definition:** One independently serviceable partition in shared memory selected from a word address by an architecture-specific mapping. In M04's fixture, successive 32-bit words map successively across 32 banks.
- **Avoid:** Warp lane, cache line, one private bank per thread.
- **Related resources:** [M04](/en/memory/bank-conflicts-layouts/), [VIS05](/en/visuals/shared-memory-banks/), and [EX06](/en/examples/shared-memory-tile-bank-padding/).
- **Version note:** M04 uses a selected CC 7.5+ fixture with 32 banks and 32-bit words; bank width and mapping must be rechecked before extending the model to another architecture or access size.

<span id="term-075" class="resource-target" aria-hidden="true"></span>

### bank conflict · 存储体冲突

- **Definition:** In the selected shared-memory model, one warp instruction's request for multiple distinct words in the same bank, requiring those distinct-word accesses to be serviced separately. A same-address read broadcast is classified separately and is not a conflict.
- **Avoid:** Any repeated bank number, data race, global-memory coalescing failure.
- **Related resources:** [M04](/en/memory/bank-conflicts-layouts/), [VIS05](/en/visuals/shared-memory-banks/), and [EX06](/en/examples/shared-memory-tile-bank-padding/).
- **Version note:** Conflict degree is meaningful only with a declared bank mapping, word size, active-lane set, and read/write pattern; it is not a speedup ratio.

<span id="term-076" class="resource-target" aria-hidden="true"></span>

### tiling · 分块

- **Definition:** Partitioning a problem into bounded working subsets that threads cooperatively stage, synchronize around, and reuse. M03's shared-memory form separates load, first barrier, use/reuse, and a second barrier before shared storage is overwritten.
- **Avoid:** Automatic caching, bounds-free copy, guaranteed optimization.
- **Related resources:** [M03](/en/memory/shared-memory-tiling/), [M04](/en/memory/bank-conflicts-layouts/), and [EX06](/en/examples/shared-memory-tile-bank-padding/).
- **Version note:** M03 teaches the portable C++17 synchronous baseline for the selected Lanes; future asynchronous tiling interfaces are version-gated and are not projected backward.
