[Scaled dot-product attention (TERM-169)](/en/glossary/#term-169) can be written as a three-matrix-stage contract or executed as an exact tiled recurrence that never materializes full intermediate matrices. A11 uses [IO-aware tiling (TERM-170)](/en/glossary/#term-170) to explain the distinction: no mystical backend label, only an account of which values are reused, reread, or written back.

## Attention contract

For one dense, unmasked, single-head forward problem, freeze:

- `Q` has shape `n_q x d_k`.
- `K` has shape `n_k x d_k`.
- `V` has shape `n_k x d_v`.
- Output `O` has shape `n_q x d_v`.

The three stages are:

`S = QK^T / sqrt(d_k)`

`P = softmax_row(S)`

`O = PV`

This subset excludes Q/K/V projection, mask, bias, dropout, backward, and multi-head packing. Adding any one of them extends shape, semantics, and the traffic ledger; the numbers below cannot be reused silently.

## Score stage: scaling and stabilization solve different problems

Each `S[i,j]` is the length-`d_k` dot product between query row `Q[i,:]` and key row `K[j,:]`, divided by `sqrt(d_k)`. The Transformer paper's motivation has an explicit assumption: if query and key components are independent, mean-zero, unit-variance variables, the unscaled dot product has variance `d_k`, and scaling makes the modeled variance one.

This is neither universal normalization of arbitrary real data nor a substitute for softmax max shifting. Scaling controls modeled dot-product magnitude; max shifting avoids exponential overflow. They serve different purposes.

## Normalization stage: one independent reduction per query row

`softmax_row` normalizes along the key dimension. Every query row owns its own maximum `m_i` and denominator `l_i`; separate dense-score rows do not share one global denominator. Finite-input row probabilities are nonnegative and sum to one in real arithmetic. Floating-point acceptance still needs a predeclared tolerance and non-finite policy.

If full S is materialized first, stable three-pass normalization reads every S element for max, sum, and output, then writes P. A10's online state can remove one S read, but “online” alone does not remove full S/P materialization. Schedule and residency decide IO.

## Value stage: probability-weighted V

Each output row is `O[i,:] = sum_j P[i,j] V[j,:]`. The reduction runs across key rows, and output depth is `d_v`, not `d_k`. If P is materialized, this stage reads P and V and writes O. If tile-local weights and a weighted accumulator remain in fast storage, the key/value sweep can accumulate directly without writing full P.

## Traffic for materialized S/P

Declare FP32 storage, precomputed Q/K/V, separate O, and logical slow/fast-store element transfers as the boundary. Exclude cache lines, transaction overfetch, projections, masks, dropout, backward, allocation, and host-device movement.

The stable three-pass materialized schedule counts:

`E_mat = (n_q+n_k)d_k + (n_q+n_k)d_v + 6n_qn_k`

The `6n_qn_k` term is one S write, three S reads, one P write, and one P read. For self-attention with `n_q=n_k=N,d_k=d_v=d`:

`E_mat = 4Nd + 6N^2`

This ledger is neither a compulsory lower bound nor actual DRAM transactions. It belongs only to the stated materialized schedule and boundary.

## Exact tiling: merge row state instead of materializing S/P

Take a query tile of `Br` rows. Retain its Q values, per-row running maximum `m`, denominator `l`, and value accumulator `a` in fast storage while sweeping `Bc`-row K/V tiles. For one query row and current tile, first compute:

`m_t = max_{j in tile} s_j`

`l_t = sum_{j in tile} exp(s_j-m_t)`

`a_t = sum_{j in tile} exp(s_j-m_t)v_j`

Merge this with state for prior keys:

`m' = max(m, m_t)`

`l' = exp(m - m')l + exp(m_t - m')l_t`

`a' = exp(m - m')a + exp(m_t - m')a_t`

Initialize `m=-infinity,l=0,a=0`; after all key tiles, emit `o=a/l`. The invariants are `l=sum_processed exp(s_j-m)` and `a=sum_processed exp(s_j-m)v_j`. Every dense score still contributes, but full S/P need not cross the declared slow/fast boundary.

“Exact” means equivalent to the dense contract in real arithmetic, not bitwise identity across floating-point reduction orders. Tile size, accumulation type, operation order, and tolerance remain correctness contracts.

## Worked IO fixture

VIS18 freezes unmasked self-attention with `N=8,d=4`, FP32, and `Br=Bc=4`. The query-tile count is `T_r=ceil(N/Br)=2`; the key-tile count is also two. Four temporary score tiles contain 16 elements each.

The query-outer schedule retains each Q tile and sweeps all K/V tiles:

`E_tile = Nd + T_r*Nd + T_r*Nd + Nd = 2Nd + 2T_rNd`

The first and final terms are the Q read and O write; the middle terms reread K and V for every query tile. The stable materialized schedule counts `512 elements = 2048 B`; substitution in the tiled formula gives `192 elements = 768 B`; the static-analysis difference is `1280 B`.

This is not a FlashAttention traffic number. The paper's concrete pseudocode, loop order, state residency, and IO theorem have their own boundaries. VIS18 selects a query-outer schedule only to make the four ledger terms directly auditable. Do not attribute `768 B` to an existing implementation or infer timing or speedup from fewer logical requests.
