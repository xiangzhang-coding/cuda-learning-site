## State invariant and a worked merge

After any nonempty key prefix, `m=max(s)`, `l=Σexp(s−m)`, `a=Σexp(s−m)V`. A new maximum m′ multiplies every old term by `exp(m−m′)`, so applying the same correction to l and a preserves their definitions. Adding the new tile then extends the prefix; induction gives dense attention after division by l. FP16 probability conversion makes this an approximate floating-point implementation of the real-arithmetic identity.

For synthetic scores `[0,0]` then `[ln(2),ln(2)]` with scalar values `[1,3]` then `[5,7]`, the first state is `(0,2,4)`. The new maximum is ln(2), correction 1/2, merged state `(ln(2),3,14)`, output **14/3**. Averaging tile means gives 4 and is wrong. This is a mathematical fixture, not a claim that stored FP16 inputs generate these exact scores. For a causal first row, the only weight is one and output equals V at key zero.

## Correct ledger and visual interpretation

For N=32,D=16, BM=16, two query tiles read Q and write O once (`4Nd=2048 B`), and read K/V twice (`4*2Nd=4096 B`), total **6144 B**. The declared materialized stable schedule uses `8Nd=4096 B` plus `24N²=24576 B`, total **28672 B**. VIS18 is FP32 throughout, so its element counts must not be multiplied by two wholesale. Causal masking here changes probabilities but does not skip key tiles, so it does not halve this traffic model.

## Acceptance and reporting solution

Keep scalar-reference tests, CPU FP64 framework-output checks, explicit compiler artifacts, GPU output checks and profiling as separate report sections. `--mode compile` is valid without a driver; it cannot replace `--mode verify`. The acceptance collector checks all five shapes × three input families × two mask modes. The MATH reference must pass; FLASH is either output-checked or accompanied by preserved unavailable-or-failed diagnostics. A FLASH numerical mismatch is a failure, not an unavailable backend.

Only after all correctness cases pass may timing begin. The implemented scope includes output allocation on both sides and excludes adapter validation. Preserve three alternating rounds and post-timing output checks. For the IO hypothesis, inspect independently filtered memory counters with exact names/units and replay policy. If the manifest is incomplete or counter access fails, the correct answer is **inconclusive for the IO mechanism**. No measured winning configuration or speedup is part of this solution. ## Common errors and corrections

| Error | Correction and discriminating check |
| --- | --- |
| Rescale l but not a | Apply α to both; use the changing-maximum fixture |
| Zero invalid K but leave scores finite | Set invalid scores to −∞; use N=17 and uniform Q |
| Reverse causal inequality | Require key≤query; verify first row equals first V |
| Reset state per key tile | Retain m/l/a across the whole loop; use N=65 |
| Mix natural exp and exp2 scaling | Use one convention consistently; compare against the independent oracle |
| Permit gradients but return an untracked tensor | Reject `requires_grad`; backward needs its own design and tests |
| Loosen tolerance until one case passes | Inspect masks, scale, conversion and accumulation first; retain all failures |
| Call a model byte ratio a measured speedup | Collect matched timing and independent counters; otherwise state the missing evidence |

## Valid alternatives

A merge using tile-local m/l/a and two explicit scale factors is mathematically valid. An exp2 recurrence is valid if score scaling and every correction use the same base. Skipping wholly future key tiles for causal attention can be a later candidate after a new ownership/coverage proof, compiler checks and every numerical case; its work/traffic ledger must change. Different BM/BN values require a newly declared candidate and resource/shape checks, not a claim that the baseline was tuned. Adding BF16, backward, arbitrary masks or framework compiler integration is a separate contract, not an implied extension of this solution.
