EX05 是一个独立、原创的合并与跨步访问可运行示例（Runnable Example）。一份 C++17 CUDA kernel 和一个场景循环共同覆盖连续、偏移一个元素和步长为二的 gather。网站不会执行 CUDA；项目只报告正确性，不报告性能。

## 用途

先完成 M02。EX05 把其中的全局内存访问模型变成受控的可执行对比，VIS04 是相关的纯浏览器可视化讲解（Visual Explainer）。host test 和 VIS04 都不会执行 kernel，也不会授予 CUDA 证据状态（Evidence Status）。

实验保持元素类型、逻辑数量、launch geometry、输入值、输出布局和验证方式不变，只改变 `offset` 与 `stride`。这种控制变量让 source-index sequence 明确可查，同时不会把尚未测量的 transaction count 或运行时间差写成结果。

[在固定提交中查看完整 EX05 项目](https://github.com/xiangzhang-coding/cuda-learning-site/tree/09aa5ea16bf9a997b2711e4e96f15ec63623f3ee/examples/ex05-coalesced-strided-access)，或[下载同一提交的源码归档](https://github.com/xiangzhang-coding/cuda-learning-site/archive/09aa5ea16bf9a997b2711e4e96f15ec63623f3ee.zip)。解压后进入 `examples/ex05-coalesced-strided-access/`。

## 场景合同

三个场景都固定 `logicalCount=256`，并执行 `output[logicalIndex] = input[offset + logicalIndex * stride]`。

| 场景 | Offset | Stride | 第一个 warp 的 source indices | 所需 input elements |
| --- | ---: | ---: | --- | ---: |
| `contiguous` | 0 | 1 | 0 到 31 | 256 |
| `misaligned` | 1 | 1 | 1 到 32 | 257 |
| `strided` | 0 | 2 | 0, 2, 4, ..., 62 | 511 |

这里的 “misaligned” 指访问序列相对 base 偏移一个四字节元素，并不表示 C++ `std::uint32_t` load 违反类型对齐。表格描述的是确定性索引，不是实测 memory transaction。

## Host reference 边界

`include/coalesced_strided_access_reference.hpp` 是纯 C++17。它定义有序场景表，在计算 required input size 前检查乘法与加法，拒绝 undersized allocation 且不改写调用方的 source-index destination，生成每个 reference output，并执行 exact comparison。

`make host-test` 检查 256、257、511 三个 required count；包括 lane 31 和 logical index 255 在内的代表性 source index；越界、undersized、zero-stride 和 overflow 情况；以及三个完整 output array。它不包含 CUDA header 或 device annotation。通过 host test 不能证明 device code 已编译或运行。

## 构建合同

在原生 Linux 的项目目录中运行：

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

前四步需要所选 CUDA Toolkit，host-test 只需要 host C++17 compiler。CUDA stages 生成 `build/coalesced_strided_access.ii`、`build/coalesced_strided_access.o` 和 `build/ex05-coalesced-strided-access`。Inspect 检查 native `sm_75` cubin 与从 `compute_75` 生成的 PTX。

`scripts/compile-check.sh c++17 ex05 <result-dir>` 执行这些步骤并保留经过扫描的日志与 inspection artifacts。它绝不运行 `build/ex05-coalesced-strided-access`，因此成功的 build gate 不会产生 GPU observation。

## 预期观察，不是运行记录

1. 三个场景都应只在 256 个输出全部精确匹配纯 host reference 时报告 `PASS`。
2. 每个 warp 中，contiguous source index 应为 `logicalIndex`，misaligned 场景应以相同 unit stride 使用 `logicalIndex + 1`。
3. 每个 warp 中，strided 场景应使用 `2 * logicalIndex`，每隔一个元素取值并保持在 511 个 input 内。

这些是声明的正确性与地址序列预期，不包含性能排序，Learning Site 尚未观察它们。
