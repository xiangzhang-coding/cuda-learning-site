EX12 是独立、原创的 Inclusive 与 Exclusive Scan 可运行示例（Runnable Example）。同一份 C++17 项目扫描 4,099 个有界 `std::uint32_t` input，并用独立 CPU reference、精确 recurrence 和 last-total invariant 检查两个 output。页面不发布 timing 或 performance result。

## 用途

先完成 [A03：Inclusive 与 Exclusive Scan](/algorithms/inclusive-exclusive-scan/)。EX12 把 A03 的 block-local prefix、block sum、跨 block offset 与 exclusive identity 落到一个可独立构建的项目中。它用于验证算法结构和精确正确性，不替代生产 primitive。

## 获取 canonical project

[在固定提交中查看 EX12 项目](https://github.com/xiangzhang-coding/cuda-learning-site/tree/81d43aa7568514e37ef190da59c845b8072b7011/examples/ex12-inclusive-exclusive-scan)，或[下载同一 source revision 的源码归档](https://github.com/xiangzhang-coding/cuda-learning-site/archive/81d43aa7568514e37ef190da59c845b8072b7011.zip)。解压后进入 `examples/ex12-inclusive-exclusive-scan/`。

`project.json` 声明两个 build input、两个 canonical range、三条精确 Toolkit Lane、49,324-byte memory bound 和空 evidence record。实现、测试与页面文字均为原创；软件文件使用 Apache-2.0，本页使用 CC-BY-4.0。

## CPU reference

Deterministic input 重复 1 到 7。Public host contract 最多接受 4,099 个 value，并在写 output 前拒绝大于 7 的 value。因此任一 prefix 不超过 28,693，可以在 `std::uint32_t` 中精确表示。

Inclusive 与 exclusive CPU reference 各自执行独立 serial accumulation；exclusive reference 不读取也不派生自 inclusive output：

## Multi-block scan

第一阶段启动 17 个 256-thread block。每个 thread 把有效 input 或 identity 0 写进 shared memory；即使最后一个 block 只有三个有效 element，所有 thread 仍无条件到达每个 `__syncthreads()`。每个 block 产生 local inclusive prefix 与一个 block sum。

第二阶段用一个有界 256-thread block 扫描 17 个 block sum。第三阶段把前一个 block 的 scanned sum 作为 offset 加到当前 block 的 local prefix。最后一个 kernel 使用 `exclusive[i] = inclusive[i] - input[i]` 派生 exclusive output：

<CanonicalCode exampleId="EX12" range="multi-block-scan" />

Guard 只保护 memory access，不保护 barrier。没有 thread 在 block-wide barrier 前 return；partial block 的无效 lane 以 0 参与相同 stage。

## 精确 invariant

Host test 和 CUDA binary 都要求完整数组 exact match。除此之外，它们还检查：`inclusive[0] = input[0]`、`inclusive[i] = inclusive[i-1] + input[i]`、`exclusive[0] = 0`、`exclusive[i] = exclusive[i-1] + input[i-1]`，以及 `inclusive[i] = exclusive[i] + input[i]`。

完整 deterministic input 的独立 total 是 16,390。Last-total invariant 同时要求 `inclusive[last] == 16390` 与 `exclusive[last] + input[last] == 16390`。这覆盖 4,096 之后的三个 element，避免只验证完整 block。

## 构建合同

在项目目录中运行：

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

CUDA stages 生成 `build/inclusive_exclusive_scan.ii`、`build/inclusive_exclusive_scan.o` 与 `build/ex12-inclusive-exclusive-scan`。Inspection 检查 native `sm_75` cubin 与从 `compute_75` 生成的 PTX。Host-test 只需 host C++17 compiler，并在全部 exact check 通过后打印 `host-reference: pass`。

`scripts/compile-check.sh c++17 ex12 <result-dir>` 按顺序执行 clean、preprocess、compile、link、inspect 与 host-test，保留 log 和 inspection artifact，但不执行 CUDA binary。

## 编译与运行证据

EX12 的 compilation array 为空，因此 **EX12 不是 Compile-Checked**。Runtime 仍为 **Pending Hardware Verification**，recorded observations 为空。Learning Site 尚未在 Reference Environment 中运行该 CUDA binary。

页面没有 measured timing、bandwidth、throughput 或 speedup。Host test 只能建立 CPU reference 与 invariant 行为，不能建立 CUDA compilation 或 GPU execution evidence。

## 预期观察，不是运行记录

1. Inclusive 与 exclusive device array 都应只在全部 4,099 个 `uint32` output 精确匹配各自独立 CPU reference 时报告 `PASS`。
2. 每个相邻 inclusive 与 exclusive prefix 都应满足精确 recurrence，并保留 exclusive index 0 的 identity。
3. Deterministic input 的两条 last-total identity 都应得到 16,390，并覆盖 guarded three-element final block。

这些是验收条件，不是已记录的 GPU observation。
