EX11 是独立、原创的多阶段归约（Multi-Stage Reduction）可运行示例（Runnable Example）。项目以 C++17 实现，把 4,099 个确定性 `float` 归约为一个值，并以高精度 `double` CPU reference、明确的 reduction order 和 tolerance 合同判断正确性。项目没有 timer，也不发布性能结论。

## 用途

先完成 [A02 多阶段归约](/algorithms/multi-stage-reduction/)与 [Q02 浮点顺序和可复现性](/correctness/floating-point-order-reproducibility/)。A02 给出 reduction tree、inactive lane、barrier 与 kernel boundary；Q02 解释浮点加法顺序为什么会影响末位，以及 tolerance 为什么不等于 bitwise reproducibility。

EX11 把这两个合同放进一个最小 standalone project：shared-memory kernel 每次生成 block partial sum，host 重复 launch，直到只剩一个值。唯一 verdict 是 GPU sum 是否通过 CPU reference comparator。

## 获取 canonical project

[在固定提交中查看完整 EX11 项目](https://github.com/xiangzhang-coding/cuda-learning-site/tree/81d43aa7568514e37ef190da59c845b8072b7011/examples/ex11-multi-stage-reduction)，或[下载同一 source revision 的源码归档](https://github.com/xiangzhang-coding/cuda-learning-site/archive/81d43aa7568514e37ef190da59c845b8072b7011.zip)。Canonical implementation 位于 `examples/ex11-multi-stage-reduction/`。

`project.json` 声明两个 build input、两个 canonical range、三条精确 Toolkit Lane、memory bound 与空 evidence record。软件文件使用 Apache-2.0；本教学页面使用 CC-BY-4.0。

## CPU reference 与 tolerance

纯 C++17 header 定义 4,099-element workload、256-thread block、每个 block 最多 512 个 input、确定性 `float` 生成器，以及按 input order 在 `double` 中累加的 CPU reference：

<CanonicalCode exampleId="EX11" range="cpu-reference" />

GPU tree order 与串行 CPU order 不同，因此 comparator 不要求 bitwise equality。它检查 `absolute_error <= absolute_tolerance + relative_tolerance * abs(cpu_reference)`。Absolute term 保护接近零的 reference；relative term 让允许误差随 reference magnitude 缩放。这个规则是预先声明的 acceptance contract，不是运行后根据结果调整的阈值。

同一 range 还定义 stage-size helper。对非终止 stage，output count 必须大于零并严格小于 input count。

## 多阶段 shared-memory reduction

每个 thread 先把 contribution 设为零，再分别 guard 两个 global load。Bounds-invalid lane 仍写 shared slot，并与其他 thread 一起无条件到达每个 `__syncthreads()`：

<CanonicalCode exampleId="EX11" range="multi-stage-reduction" />

树的每一步只有 lower lanes 执行加法，但 barrier 不放在条件分支中。一次 kernel 只能在 block 内归约；下一次 launch 的 kernel boundary 才把前一 stage 的 global partial sums 交给下一 stage。

| Stage | Input count | Output count | 最后一个 block 的有效 input |
| ---: | ---: | ---: | ---: |
| 0 | 4,099 | 9 | 3 |
| 1 | 9 | 1 | 9 |

因此第一 stage 的前八个 block 各覆盖 512 个值，最后 partial block 只加载 index 4,096 至 4,098。Host loop 重复 stage，直到 count 为 1，然后只复制最终 `float`。

## Host reference 边界

`make host-test` 不包含 CUDA header。它独立重建 deterministic input，检查 stage sizes `4,099 -> 9 -> 1`、完整且不重叠的 block coverage、三元素 partial-block invariant、`double` reference 对更宽 accumulation 的一致性，以及 abs+rel comparator 的 near-zero、scale-aware 和 rejection cases。

Host test 还用同样的 staged float order 构造纯 CPU model。通过只能建立 arithmetic、stage-shape 与 oracle behavior；它不能证明 CUDA source 已编译、GPU barrier 已执行或 device result 已满足 comparator。

## 构建合同

在原生 Linux 的项目目录中运行：

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

CUDA stages 生成 `build/multi_stage_reduction.ii`、`build/multi_stage_reduction.o` 与 `build/ex11-multi-stage-reduction`。Inspection 检查 native `sm_75` cubin 和从 `compute_75` 生成的 PTX。Host-test 只需要 host C++17 compiler，并以 `host-reference: pass` 结束。

`scripts/compile-check.sh c++17 ex11 <result-dir>` 执行 clean、preprocess、compile、link、inspect 与 host-test，保留 logs 和 inspection artifacts，但绝不运行 GPU binary。

## 预期观察，不是运行记录

1. GPU result 应只在 abs+rel comparator 接受它相对于 `double` CPU reference 的误差时报告 `PASS`。
2. 4,099-element workload 应按 `4,099 -> 9 -> 1` 的 stage sizes 收敛，第一 stage 的最后一个 block 恰有三个有效 input。
3. Bounds-invalid load 应贡献零，同时 block 中每个 thread 仍应在下一步前到达每个 block-wide barrier。

这些是验收条件，不是已记录的 GPU observation。
