EX13 是一个独立、原创的 C++17 CUDA 可运行示例（Runnable Example）。它为 `uniform`、`skewed` 和 `boundary` 三个 fixture 计算 16-bin histogram，并让 global-bin 和 block-private 两条 CUDA 路径与同一份 CPU reference 做 exact comparison。网站不执行 CUDA；本页没有 contention observation、timing 或 performance 结果。

## 用途

先完成 A04。EX13 把 A04 的 atomic update、block privatization、barrier 和 merge 结构落实为一个可独立构建的项目，但这里只验证 correctness。源码结构本身不能证明 contention 行为，也不能推出任何性能结论。

## 获取 canonical project

[查看 EX13 的临时 source 坐标](https://github.com/xiangzhang-coding/cuda-learning-site/tree/0000000000000000000000000000000000000000/examples/ex13-privatized-histogram)，或[查看同一临时坐标的源码归档](https://github.com/xiangzhang-coding/cuda-learning-site/archive/0000000000000000000000000000000000000000.zip)。这两个 URL 中的四十个零是待后续替换的 sourceCommit 占位坐标。项目目录是 `examples/ex13-privatized-histogram/`。

`project.json` 声明两段 canonical range、三个固定 fixture、16 个 bin、259 个输入、128-thread block、1,228-byte 保守内存上界、三条 Toolkit Lane 和空 compilation axis。项目源码与页面文字均为原创；软件文件使用 Apache-2.0。

## Fixture 合同

`uniform` 按 `index % 16` 生成输入，因此 bin 0 到 2 各有 17 个值，其余 bin 各有 16 个。`skewed` 的 literal expected counts 是 bin 0 为 17、bin 7 为 226、bin 8 为 16，其余为零。`boundary` 只使用两个合法边界值：bin 0 为 130，bin 15 为 129。

259 个输入配合 128-thread block 形成两个完整 block 和一个只有三个 active thread 的 partial block。两条 kernel 都用 `index < value_count` 保护输入更新；这个 guard 不包围任何 block barrier。

## Histogram kernels

第一条路径对独立的 global output bins 使用 `atomicAdd`。第二条路径为每个 block 声明 16 个 shared-memory private bins，依次经过 unconditional zero、update 和 merge barrier，再把 block-local counts 原子合并到另一份 global output。这个结构说明更新位置和同步顺序，不构成 contention 或 performance observation。

## Host model 边界

`make host-test` 只编译 `tests/host_reference_test.cpp` 和 pure C++17 header。它把三个 CPU reference 结果分别与手写 literal histogram 精确比较，检查每个 sum-of-bins invariant，拒绝未知 fixture 与越界 bin，并验证 deterministic mismatch location。成功时打印 `host-reference: pass`。

Host test 不包含 CUDA header，不 launch kernel，也不能验证 shared memory、barrier、atomic update、merge 或 GPU execution。通过它不会产生 CUDA compilation 或 runtime Evidence Status。

## 构建合同

在原生 Linux 的项目目录中运行：

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

前四步需要所选 CUDA Toolkit；host-test 只需要 host C++17 compiler。CUDA stages 生成 `build/privatized_histogram.ii`、`build/privatized_histogram.o` 和 `build/ex13-privatized-histogram`。Inspect 检查 native `sm_75` cubin 与从 `compute_75` 生成的 PTX。

`scripts/compile-check.sh c++17 ex13 <result-dir>` 执行 clean、preprocess、compile、link、inspect 和 host-test，并保留日志与 inspection artifacts。它绝不执行 CUDA binary，因此不会产生 GPU observation。

## 预期观察，不是运行记录

1. 对 `uniform`、`skewed` 和 `boundary`，global-bin kernel 应逐 bin 精确匹配独立的 16-bin CPU reference。
2. 对同样三个 fixture，block-private shared-memory kernel 应逐 bin 精确匹配独立的 16-bin CPU reference。
3. 对两条 CUDA 路径和每个 fixture，16 个 output bin 的总和都应等于 259 个输入。

这些是尚未由 Learning Site 观察的 correctness acceptance criteria，不包含 contention 或 performance 判断。
