EX14 是一个独立、原创的 C++17 CUDA 可运行示例（Runnable Example）。它把三个 row-major `float` 矩阵转置到独立 output，并让 CUDA 结果与纯 C++17 CPU reference 逐元素精确比较。网站不执行 CUDA；本页没有 speedup、global-memory transaction count、bank-conflict observation、timing 或 profiler 结果。

## 用途

先完成 A05。EX14 把矩形 transpose 的 shape、row-major mapping、edge guard、shared tile 与 barrier 合同落实为一个可独立构建的项目。它只建立 correctness acceptance criteria；源码布局本身不是 GPU behavior 或 performance evidence。

## 获取 canonical project

[在初始 canonical coordinate 中查看 EX14](https://github.com/xiangzhang-coding/cuda-learning-site/tree/0000000000000000000000000000000000000000/examples/ex14-tiled-transpose)，或[下载同一初始 source revision 的源码归档](https://github.com/xiangzhang-coding/cuda-learning-site/archive/0000000000000000000000000000000000000000.zip)。项目目录是 `examples/ex14-tiled-transpose/`。这里的 40-zero coordinate 仅用于第一次提交前的开发状态，之后由 caller 固定到 immutable publication commit。

`project.json` 声明两个 canonical range、三个 fixture、32 x 32 logical tile、32 x 8 block、32 x 33 shared layout、20,608-byte 保守内存上界、三条 C++17 Toolkit Lane，以及空 compilation axis。项目源码与页面文字均为原创；软件文件使用 Apache-2.0。没有复制 NVIDIA owner source、sample、figure 或 result。

## Matrix 合同

输入 shape 是 `rows x columns`，output shape 必须是 `columns x rows`。两者都使用 row-major flattening；每个合法 `(row, col)` 坐标必须满足：

```text
output[col * rows + row] = input[row * columns + col]
```

三个 deterministic fixture 是 `5x7`、`33x35` 和 `64x32`。前两个让一个或两个轴落在 partial tile，第三个是 tile-aligned 的矩形 shape。Fixture values 是可由 `float` 精确表示的正整数；transpose 不执行数值运算，因此 CPU 与 CUDA output 使用 exact float equality。

## Tiled transpose

CUDA source 声明 32 x 32 logical tile、`BLOCK_ROWS=8` 和 `__shared__ float tile[32][33]`：

<CanonicalCode exampleId="EX14" range="tiled-transpose" />

每个 32 x 8 block 让 thread 在 y 轴按 8 循环，合作覆盖 32 行。Load guard 同时检查 input row 与 column；所有 thread 随后无条件通过唯一一个 `__syncthreads()`；store guard 再按 transpose 后的 output extents 独立检查。Kernel 在 barrier 前没有 `return`。

第 33 个 shared column 只是 physical storage padding，不属于 logical matrix，不改变 output shape，也不会生成 output value。本项目没有观察或量化它在 GPU 上的 bank behavior。

## Host model 边界

`make host-test` 只编译 `tests/host_reference_test.cpp` 和 pure C++17 header。它检查三个 fixture 的 output dimensions 和每一个 mapping，验证 exact equality 与 mismatch coordinates，并覆盖 unknown fixture、zero/overflow dimensions、null pointer、错误 size、错误 output shape 和 in-place rejection 的非局部写入边界。成功时打印 `host-reference: pass`。

Host test 不包含 CUDA header 或 syntax，不 launch kernel，也不能验证 CUDA compilation、device allocation/copy、shared-memory access、barrier participation、GPU edge guards 或 GPU execution。通过它不会产生 CUDA compilation 或 runtime Evidence Status。

## 构建合同

在原生 Linux 的项目目录中运行：

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

前四步需要所选 CUDA Toolkit；host-test 只需要 host C++17 compiler。CUDA stages 生成 `build/tiled_transpose.ii`、`build/tiled_transpose.o` 和 `build/ex14-tiled-transpose`。Inspect 检查 native `sm_75` cubin 与从 `compute_75` 生成的 PTX。

`scripts/compile-check.sh c++17 ex14 <result-dir>` 执行 clean、preprocess、compile、link、inspect 和 host-test，并保留 logs 与 inspection artifacts。它绝不执行 CUDA binary，因此不会产生 GPU observation。

## 预期观察，不是运行记录

1. 对 `5x7`、`33x35` 和 `64x32`，CUDA output 应逐元素精确匹配独立 CPU transpose reference。
2. 每个 fixture 的 output shape 应是 input columns x input rows，并且每个合法坐标满足 `output[col * rows + row] = input[row * columns + col]`。
3. Extra shared-memory padding column 应只影响 storage extent：它不增加 logical matrix column、不改变 output value，也不在 guarded dimensions 之外生成 output。

这些是尚未由 Learning Site 观察的 correctness、dimension 与 padding-neutral acceptance criteria，不包含 measured performance 结论。
