EX02 是一个独立、原创的向量加法可运行示例（Runnable Example）。它把网格索引、边界判断、显式内存生命周期、CUDA 错误检查和 CPU 正确性参考放在一个小项目里。它不是实验（Lab），也不在网页中执行 CUDA。

## 这个项目解决什么

学习者只需要面对一份 canonical C++17 实现。CUDA 11.8.0、12.9.2 和 13.3.1 的工具包通道（Toolkit Lane）检查都指向同一个源码树；12.9.2 和 13.3.1 还用 C++20 重新编译同一份源码，而不是维护另一份实现。

项目先规定正确性，再谈任何测量。当前没有合格 GPU 运行，因此没有记录运行输出或性能数字。

## 获取 canonical project

[在 GitHub 查看或下载通过编译检查的完整 EX02 项目](https://github.com/xiangzhang-coding/cuda-learning-site/tree/1cdca8b411135c6023d1241a25b2ff8aea820d65/examples/ex02-vector-addition)。`project.json` 是机器可读契约；`README.md` 给出独立构建步骤；`src/`、`include/` 和 `tests/` 是唯一实现来源。两个语言页面都只从下面声明的 marker range 读取代码。

## 正确性边界

CPU 参考和容差没有 CUDA 依赖，可以在普通 C++ 编译器下单独测试：

<CanonicalCode exampleId="EX02" range="cpu-reference" />

- 绝对容差：`1e-5`。
- 相对容差：`1e-5`。
- 每个元素只要满足绝对容差或相对容差之一就通过；两者都不满足才失败。
- 默认规模：`1,048,576` 个 `float` 元素。
- 可选规模：`1..134,217,728`；三份 device vector 在最大规模约占 1.5 GiB，低于 8 GB 课程边界。
- `make host-test` 只运行 CPU reference 和 tolerance 验收；它不能证明 GPU kernel 正确。

真正的 GPU 运行还必须经过 `cudaMalloc`、两次 host-to-device copy、launch error、`cudaDeviceSynchronize`、device-to-host copy、CPU 比较和三次 `cudaFree`。任何失败都会返回非零状态。

## 构建契约

在支持的原生 Linux 环境中，从项目目录执行：

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

前四步依次产生 `build/vector_add.ii`、`build/vector_add.o` 和 `build/ex02-vector-addition`，然后用 `cuobjdump` 确认 native `sm_75` cubin 和来自 `compute_75` 的 forward-compatible PTX。项目没有 relocatable device code，所以不增加虚假的独立 device-link 阶段。

CPU-only CI **绝不运行** `build/ex02-vector-addition`。学习者之后在满足条件的外部环境中运行它，也必须先记录完整环境清单（Environment Manifest）；构建通过不能替代 GPU 正确性。

## 兼容性

| 坐标 | 声明 |
| --- | --- |
| 受支持环境（Supported Environment） | 仅原生 Linux |
| 基础 GPU 能力层级（Baseline GPU Capability Tier） | compute capability 7.5 或更新；问题规模适配 8 GB |
| 编译目标 | `sm_75` cubin + `compute_75` PTX |
| 共享实现 | 显式 C++17；12.9.2/13.3.1 也检查同一源码的 C++20 编译 |
| C++23 | 13.3.1 image 中的 GCC 13.3 不支持 NVCC C++23 配置；独立 probe 记录 `unsupported`，不给 EX02 授予 C++23 编译声明 |

没有使用 `--allow-unsupported-compiler`。镜像 tag 和 digest 只是输入；实际 OS、host compiler、NVCC 和 pulled image identity 必须由每次结果记录。

## 预期观察，不是运行记录

以下内容是未来合格运行需要核对的**预期**，不是本页观察到的输出：

1. CUDA 结果应按“绝对容差或相对容差满足其一”的规则匹配独立 CPU reference。
2. 改变元素数量时，grid 大小应随之变化；最后一个不完整 block 仍由 `index < element_count` 保护。

当前已记录运行观察为空，没有 Reference Environment，也没有性能结论。
