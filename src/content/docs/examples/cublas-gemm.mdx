EX18 是原创、独立的 C++17 cuBLAS GEMM 可运行示例（Runnable Example），只检查正确性，不比较速度。CUDA 仅在外部环境运行，学习站（Learning Site）不会执行 CUDA。

## 用途

先完成 [L06：cuBLAS GEMM](/libraries/cublas-gemm/)。EX18 把布局、主维度（leading dimension）、精度、句柄（handle）状态和流（stream）的完成边界放进同一个可独立构建的项目。[L07：cuBLASLt Matmul](/libraries/cublaslt-matmul/)、[EX15：分块 GEMM](/examples/tiled-gemm/) 和 [LAB12：对比 GEMM 与 cuBLAS](/labs/compare-gemm-with-cublas/) 是相关资源，不增加先修要求。

## 规范项目

[查看固定的 EX18 源码目录](https://github.com/xiangzhang-coding/cuda-learning-site/tree/fb94c6c1fe972afeac9b5b30db995595c4dc5021/examples/ex18-cublas-gemm)，或[下载同一源码版本](https://github.com/xiangzhang-coding/cuda-learning-site/archive/fb94c6c1fe972afeac9b5b30db995595c4dc5021.zip)。解压后进入 `examples/ex18-cublas-gemm/`。项目包含清单、README、Makefile、纯主机参考头文件、CUDA 源码、主机测试、编译检查脚本和证据目录说明。

项目代码是原创 Apache-2.0 作品，本页文字使用 CC-BY-4.0。cuBLAS 是按其自身条款安装的外部依赖；项目不重新分发 NVIDIA 示例、库实现或 SDK 头文件。双语发布对（Publication Pair）导入同样的三个规范源码范围，不另存一份 C++ 代码。

## 独立 CPU 参考

<CanonicalCode exampleId="EX18" range="cpu-reference" />

头文件保留本站原创 EX15 输入生成器和参考计算逻辑，但不依赖 EX15 项目。A、B 先存为 `float`，计算时转成 `double` 做乘法和串行累加；初始 C 与 alpha/beta 也参与独立参考计算。预期输出不是用 cuBLAS 结果构造的。

| 测试输入，按 M,K,N 排列 | alpha | beta | 检查目的 |
| --- | --- | --- | --- |
| `2,3,2` | 1 | 0 | A、B 都按顺序存放 1 到 6，C 初始为零；手算行主序（row-major）结果为 `22,28,49,64` |
| `33,31,35` | 0.75 | 0.25 | 非方形尺寸，以及可观察的初始 C 贡献 |
| `32,32,32` | 1 | 0 | 与 EX15 相同的对齐测试输入 |

后两组的 A 重复 `(i%7-3)/8`，B 重复 `(i%5-2)/7`，C 重复 `(i%3-1)/5`，采用有符号减法和 float 除法。每个输出都必须有限，并满足 `abs(gpu-cpu) <= 1e-4 + 2e-5 * abs(cpu)`。通过条件覆盖完整矩阵，不能用抽样或校验和代替；失败时报告首个不匹配的行列。容差在运行前固定，不意味着逐位相等或跨 GPU 可复现。

## 行主序 GEMM 映射

<CanonicalCode exampleId="EX18" range="gemm-call" />

输入合同是行主序 `C[M,N] = alpha*A[M,K]*B[K,N] + beta*C[M,N]`。相同字节可以解释为列主序（column-major）的转置矩阵，因此计算 `C^T = alpha*B^T*A^T + beta*C^T`。先传 B、再传 A，交换 M 与 N，并取 `(lda,ldb,ldc)=(N,K,N)`。两个操作参数都是 `CUBLAS_OP_N`：转置已由内存解释表达，不需要再加转置标志或数据转换内核。

三个矩阵的数据类型（data type）都是 `CUDA_R_32F`。计算类型（compute type）`CUBLAS_COMPUTE_32F_PEDANTIC` 显式选择单精度算术；单独设置 `CUBLAS_DEFAULT_MATH` 并不能构成精度合同。程序不请求 FAST_TF32、低精度转换或模拟计算模式，并使用 `CUBLAS_GEMM_DEFAULT`，而不是特定架构算法。这是正确性基线，不保证是最快的库配置。

## 流与资源生命周期

<CanonicalCode exampleId="EX18" range="stream-lifecycle" />

三个测试共用一个句柄和一个 `cudaStreamNonBlocking` 流。`cublasSetPointerMode(..., CUBLAS_POINTER_MODE_HOST)` 明确 alpha/beta 是主机地址。`cublasSetStream` 在提交工作前调用，并将工作区（workspace）重置到库的默认池。EX18 没有安装用户工作区，不能据此称为零工作区操作。

每组先恢复初始 C，在同一流依次提交 A/B/C 的 H2D 拷贝、GEMM、C 的 D2H 拷贝，再检查 `cudaStreamSynchronize`，之后才验证结果或复用缓冲区。提交成功不等于执行完成。主机向量使用可分页内存，`cudaMemcpyAsync` 这个名称本身不能证明传输重叠。

资源获取即初始化（RAII）清理在释放句柄、设备缓冲区和流之前再次同步，也覆盖部分分配或提交失败的路径。各项释放不会因先前错误而短路，清理失败会让进程返回失败。主机存储先于资源所有者构造，存活到清理结束之后。正常路径的三次完成检查和最终清理边界都不是计时结果。

## 独立版本配置

| 配置 ID | Toolkit | cuBLAS | 头文件 MAJOR,MINOR,PATCH,BUILD |
| --- | --- | --- | --- |
| `cuda-11-8-bundled-cublas-11-11-3-6` | 11.8.0 | 11.11.3.6 | 11,11,3,6 |
| `cuda-12-9-bundled-cublas-12-9-2-10` | 12.9.2 | 12.9.2.10 | 12,9,2,10 |
| `cuda-13-3-bundled-cublas-13-6-0-2` | 13.3.1 | 13.6.0.2 | 13,6,0,2 |

每个组件坐标都独立取自 NVIDIA 对应的精确再分发清单，不由 Toolkit 版本推算。`EXPECTED_CUBLAS_VERSION` 转成四个 `EX18_EXPECTED_CUBLAS_*` 定义，预处理阶段检查所选头文件的 `CUBLAS_VER_MAJOR`、`CUBLAS_VER_MINOR`、`CUBLAS_VER_PATCH` 与 `CUBLAS_VER_BUILD`。

GEMM 之前，经状态检查的 `cublasGetProperty` 查询报告实际加载库的 `MAJOR_VERSION`、`MINOR_VERSION` 和 `PATCH_LEVEL`，并要求它们与头文件三元组一致。程序还单独打印 `cublasGetVersion` 的原始值及头文件的四段版本。这些 API 不暴露实际加载库的 build 号。完整二进制身份需要环境清单（Environment Manifest）中的库解析路径、包身份和文件哈希，不能把头文件 build 号拼到加载库三元组后就称为观察结果。

## 构建与运行

CPU 测试不需要 CUDA 头文件或 GPU：

```sh
make host-test DIALECT=c++17
```

它检查手算 GEMM 结果、alpha/beta、相消输入下的 double 累加、所有生成输入值、容差边界、末元素损坏、非有限输出以及无效尺寸/计数。`host-reference: pass` 只证明主机合同。

在匹配的 11.8.0 开发镜像中显式执行 CUDA 构建阶段：

```sh
make preprocess DIALECT=c++17 EXPECTED_CUBLAS_VERSION=11.11.3.6
make compile DIALECT=c++17 EXPECTED_CUBLAS_VERSION=11.11.3.6
make link DIALECT=c++17 EXPECTED_CUBLAS_VERSION=11.11.3.6
make inspect DIALECT=c++17 EXPECTED_CUBLAS_VERSION=11.11.3.6
```

也可以让脚本执行 clean、四个构建阶段和 host-test；脚本绝不执行 CUDA 二进制：

```sh
bash scripts/compile-check.sh c++17 cuda-11-8-bundled-cublas-11-11-3-6 artifacts/ex18-11-8
```

其他通道使用各自配置 ID。链接显式包含 `-lcublas`。产物检查保留 `readelf -d` 与 `ldd` 报告，要求存在并解析 cuBLAS 共享库依赖，且拒绝缺失库。EX18 没有定义设备内核，因此不要求找到属于 EX18 的 cubin 或 PTX。编译架构参数也不能证明库内部采用哪条分派路径。

只有满足运行门槛后才执行：

```sh
./build/ex18-cublas-gemm
```

程序选择可见设备 0，报告头文件/加载库的 cuBLAS 坐标、设备及驱动/runtime 版本、精度策略与三个正确性判定。这是在说明输出合同，并非保留的实际运行输出。

## 预期观察

1. 三组 EX15 兼容输入都应通过独立 double 参考的完整有限值容差检查，包括手算结果与非零 beta 情况。
2. 行主序映射应交换操作数与尺寸，显式采用 FP32 严格计算、主机标量，并在 CPU 验证前确认完成。
3. 四个头文件版本宏应匹配选定组件配置；GEMM 之前报告的加载库 major/minor/patch 应匹配这些头文件。

这三项是清单中的验收方向，不是已观察到的构建或运行结果。
