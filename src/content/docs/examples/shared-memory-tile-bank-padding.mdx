EX06 是一个独立、原创的共享内存 tile bank-padding 可运行示例（Runnable Example）。同一份模板化 C++17 CUDA 实现实例化明确的 unpadded `float[32][32]` 和 padded `float[32][33]` 共享布局。网站不会执行 CUDA，也不会发布实测 bank-conflict 或性能结果。

## 用途

先完成 M03，再完成 M04；这个顺序属于 prerequisite contract。EX06 把 shared-memory layout 与 bank-address arithmetic 变成可执行项目，VIS05 是相关的纯浏览器可视化讲解（Visual Explainer）。host model 和 VIS05 都不提供 GPU observation 或 CUDA Evidence Status。

对比保持 input tile、单 warp launch、cooperative load order、barrier、read column、output values 与 verifier 不变，唯一布局变量是 padding。这样可以隔离 address map，同时保持数学输出不变。

## 布局合同

一个 block 只包含一个 32-thread warp。确定性 input 是 row-major 32 x 32 float tile。加载时，lane `l` 先写 row 0、column `l`，再写 row 1、column `l`，并持续给 linear input index 加 32。因此每次循环迭代都由整个 warp 协作加载完整的一行。

全部 1,024 个值写入后，`__syncthreads()` 建立 block-wide barrier。随后每个 lane 读取 `tile[lane][5]` 并写一个连续 output。两种布局必须产生完全相同的 32 个值，因为 padding 只改变 storage pitch，不改变逻辑 row 或 column。

Unpadded pitch 是 32 words，padded pitch 是 33。显式类型避免 runtime pitch 掩盖每个 kernel specialization 实际持有的 shared-memory object。

## Tiled kernels

两个 kernel variant 来自同一份模板实现：

<CanonicalCode exampleId="EX06" range="tiled-kernels" />

Launch 使用同一 input、固定 column 5 与两个独立的 32-element output 实例化 `Padding=0` 和 `Padding=1`。Barrier 位于所有 lane 完成 cooperative store 之后、任何 lane 开始转置式 column access 之前。

在声明的 32-bank、four-byte-word model 下，unpadded 中 lane `l` 的 access word 是 `l * 32 + 5`，因此所有 lane 都选择 bank 5，但指向不同 word。Padded word 是 `l * 33 + 5`，bank 为 `(l + 5) % 32`，每个 lane 对应一个不同 bank。这些是 host-model prediction，不是 profiler observation。

## Host model 边界

`include/shared_memory_tile_bank_padding_reference.hpp` 是纯 C++17。它验证 row-major input index、padding 为零和一时的 physical shared-word index、bank number、确定性 float value，以及两种布局生成的完整 output。

`make host-test` 检查已知 tile position 与拒绝的 coordinate，证明 unpadded lane words 互不相同但共享 bank 5，证明 padded mapping 恰好访问每个 bank 一次，并精确比较两个 output array。值都以 `.25` 结尾，在这里可由 binary `float` 精确表示，因此测试不需要 tolerance。它不编译或运行 CUDA。

## 构建合同

在原生 Linux 的项目目录中运行：

```sh
make preprocess DIALECT=c++17
make compile DIALECT=c++17
make link DIALECT=c++17
make inspect DIALECT=c++17
make host-test DIALECT=c++17
```

前四步需要所选 CUDA Toolkit，host-test 只需要 host C++17 compiler。CUDA stages 生成 `build/shared_memory_tile_bank_padding.ii`、`build/shared_memory_tile_bank_padding.o` 和 `build/ex06-shared-memory-tile-bank-padding`。Inspect 检查 native `sm_75` cubin 与从 `compute_75` 生成的 PTX。

`scripts/compile-check.sh c++17 ex06 <result-dir>` 执行这些步骤，扫描生成的日志与 inspection artifacts，并且绝不运行 CUDA binary。因此 compile workflow 不提供 shared-memory runtime observation。

## 预期观察，不是运行记录

1. Unpadded 与 padded variant 都应只在 32 个 output 全部精确匹配纯 host tile reference 时报告 `PASS`。
2. 对并发 `tile[lane][5]` read，32 x 32 host model 预测 bank 5 中存在 32 个 distinct word。
3. 对同样的逻辑 read，32 x 33 host model 预测每个 lane 对应不同 bank，同时保持相同 value。

第二与第三项是 address-model prediction，不是实测 conflict counter，也不承诺性能排序。
