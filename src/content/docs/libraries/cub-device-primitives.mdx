CUB 的 device-wide [集体原语（collective，TERM-107）](/glossary/#term-107)把 [A02 的归约（reduction，TERM-127）](/glossary/#term-127)和 [A03 的扫描（scan，TERM-130）](/glossary/#term-130)交给库实现，但调用者仍拥有 [临时存储（temporary storage，TERM-183）](/glossary/#term-183)、流顺序、对象生命周期、重叠关系与[确定性（determinism，TERM-138）](/glossary/#term-138)合同。本单元只教授 `DeviceReduce::Sum`、`DeviceScan::InclusiveSum` 与 `DeviceScan::ExclusiveSum` 这一小组入口。

## 学习成果

- 根据“一个 aggregate”与“每个位置一个 prefix”选择正确的 device-wide primitive。
- 准确说明三种操作的输出、允许的原地形式与禁止的部分重叠。
- 执行传统 API 的查询、分配、执行两阶段协议，并让临时存储活到 GPU 工作完成。
- 在显式 stream 上建立 producer、consumer、host observation 与释放边。
- 区分 bundled CUB 1.15.1/2.8.2/3.3.4、独立选择的 v3.4.2，以及 reduction 与 scan 不同的浮点确定性合同。

## 范围、调用层级与 canonical headers

`cub::DeviceReduce` 和 `cub::DeviceScan` 是 host 侧调用的 device-scope 类；它们提交 device work，并把结果写入 device-accessible output。Focused canonical headers 分别是 `<cub/device/device_reduce.cuh>` 与 `<cub/device/device_scan.cuh>`。聚合头 `<cub/cub.cuh>` 也会公开这些名称，但 review packet 应记录实际依赖的窄头文件。

这里不覆盖通用 `Reduce`/`Scan`、segmented forms、by-key forms、selection 或 sorting。选择 production primitive 并不证明其 backend、kernel 数量、traffic 或速度。

## `DeviceReduce::Sum`：N 个输入，一个 aggregate

对 `N` 个输入 `x[0] ... x[N-1]`，`DeviceReduce::Sum` 使用加法和零初值，向 `d_out` 写一个 aggregate。数学合同是对全部 `N` 项求和；并行实现可以重新结合操作数，因此这不是固定的 serial left fold。Tagged interface 不支持非交换的自定义 `+` 语义。

输入范围 `[d_in, d_in + N)` 不得与 `d_out` 重叠。Reduction 没有 scan 那种 exact in-place 例外；把 output 放进 input range 会违反前置条件。`d_out` 只有在提交到 stream 的工作完成后才可由 host 或无依赖的其他 stream 观察。

## `DeviceScan::InclusiveSum` 与 `ExclusiveSum`：每个位置一个 prefix

对相同输入，`InclusiveSum` 的逻辑输出满足 `y[i] = x[0] + ... + x[i]`：当前位置参与自己的 prefix。`ExclusiveSum` 使用该输入类型的零初始化值作为初值，满足 `y[0] = 0`，且 `i > 0` 时 `y[i] = 0 + x[0] + ... + x[i-1]`：当前位置不参与自己的 prefix。这个零值必须确实适合作为应用类型的加法单位元。

两种 scan 都允许 `d_in == d_out` 的 exact in-place 形式。除此之外，完整 input/output ranges 不得以任何方式重叠。逻辑公式固定每个 prefix 包含哪些元素，不固定 parallel parenthesization；custom sum type 仍需满足 associative operation contract，tagged scan interface 允许非交换的 scan order。

| 所需结果 | 选择边界 | 输出有效范围 |
| --- | --- | --- |
| 全部 `N` 项的一个和 | Device reduction | 一个 output aggregate |
| 包含当前项的 `N` 个 prefixes | Inclusive device scan | `N` 个 outputs |
| 从零开始、不含当前项的 `N` 个 prefixes | Exclusive device scan | `N` 个 outputs |

## 传统 API 的两阶段临时存储协议

三种传统入口都把 `void* d_temp_storage` 与 `size_t& temp_storage_bytes` 放在最前面。严格协议是：

- **查询阶段：** 用 `d_temp_storage == nullptr` 调用同一 overload。API 把所需字节数写入 `temp_storage_bytes`，不启动 kernel、不访问用户 input/output storage，也不执行算法。
- **分配阶段：** 在当前 device 上分配至少该字节数的 device-accessible storage。Tagged developer guide 要求即使某项配置不需要 scratch，传统 overload 仍提供至少一字节 allocation。
- **执行阶段：** 在同一当前 device 上，以相同 API、template instantiation、参数类型和问题配置传入 allocation，再检查返回的 `cudaError_t`。

查询结果不是跨 API、跨 `NumItemsT`、跨 device 或跨配置的常量。改变当前 device、operation、iterator/type instantiation 或 problem size 后应重新查询。把 scratch 当作该未完成 operation 的独占可写资源；不要让它与 input/output allocation 重叠，也不要并发交给另一项 work。

## 显式 streams、completion 与 lifetime

传统 overload 的最后一个可选参数是 `cudaStream_t`，默认 stream 为 `0`。可维护的 composition 应把同一个显式 stream 传给执行调用，并在 ledger 中记录它。Device-level 调用返回 `cudaError_t`，但不会因此同步 host 与 device；成功返回表示 submission 没有报告该错误，不表示 output 已可在 host 使用。

同一 stream 的先后调用可按 stream order 复用同一 scratch，无需插入 host synchronization。不同 streams 不能同时复用它：先用 event dependency 或 stream completion 建立前一使用结束的边。Input、output 与 temporary allocation 都必须存活到最后一个使用者完成；host read、无依赖 cross-stream consumer、重新分配或释放都必须位于相应 completion edge 之后。后续同步点还可能报告异步错误。

## Reduction 与 scan 的确定性合同随版本而变

已检查的传统 owner headers 不支持一条不分版本的“reduction 对 scan”规则。对于浮点加法等 pseudo-associative operations：

- Bundled CUB 1.15.1、2.8.2、3.3.4 与 selected 3.4.2 的 `DeviceReduce::Sum` 都记录 **same-GPU run-to-run determinism**。该合同不承诺等于 serial left fold，也不承诺不同 compute capability 的 GPU 给出同一 bit pattern；架构相关 tile sizing 构成已记录的 cross-compute-capability caveat。
- CUB 1.15.1 的 `DeviceScan::InclusiveSum` 与 `ExclusiveSum` 也记录 same-GPU run-to-run determinism，并带有相同的 cross-compute-capability caveat。Bundled CUB 2.8.2、3.3.4 与 selected 3.4.2 则记录 pseudo-associative scan results 可能在不同运行之间变化。不能把 1.15.1 scan guarantee 继承到后续 rows，也不能拒绝其 inspected header 已明确给出的保证。

这些是 version/operation-specific owner contracts，不是已观察的 EX17 behavior。对于整数加法，正确的零 identity 与已证明的 no-overflow bound 让每个 prefix 不受 parenthesization 影响而保持 exact。EX17 因而继续要求完整 `uint32_t` scan arrays 精确匹配，但本页没有记录 device output 或 determinism observation。

## v3.4.2 的 environment overload 边界

CCCL 3.4.0 的 immutable release 记录“完成”CUB device-wide single-call environment overload rollout；传统两阶段 API 没有 deprecated。v3.4.2 同时提供 environment forms，可从 environment 取得 stream、memory resource 与受支持的 execution requirements。Exact v3.4.2 `DeviceScan` source 把这里的 `InclusiveSum`/`ExclusiveSum` environment overload 标为 **added in 3.4.0，first appears in CUDA Toolkit 13.4**；`DeviceReduce::Sum` environment form 在 v3.4.2 也可用。

“First Toolkit 13.4”是 owner 的 availability annotation，不是本站新增 Toolkit Lane 或 runtime claim。已发布的 [EX17](/examples/cub-device-reduction-scan/)为覆盖上表三个 bundles 并保持调用结构可比较，使用传统两阶段 API；它不以 v3.4.2 environment form 作为矩阵前置条件。

## 限定的 known-issue ledger

Open documentation issue [#5966](https://github.com/NVIDIA/cccl/issues/5966)用 `DeviceReduce::Min` 展示：相同数值的 item count 以 `size_t` 或 `int` 实例化时，查询出的 temporary-storage bytes 可以不同。它不证明本单元的 Sum/Scan 存在 correctness defect，也不覆盖所有版本；它只强化 tagged v3.4.2 guide 已明确的规则：query 与 execute 必须使用同一 template arguments 和 current device。

其他 issue 没有进入本单元：不同 pointer/input configurations 的比较不能直接反驳同一合同的 run-to-run guarantee，已在 v3.4.2 前关闭并修复的问题也不是当前缺陷。这是一份限定 ledger，不是 CCCL issue dump。
