CUB 的 warp/block [集体原语（collective，TERM-107）](/glossary/#term-107)要求一组明确参与者共同调用同一 operation。[逻辑线程束（logical warp，TERM-184）](/glossary/#term-184)不是“当前恰好 active 的任意 lanes”，而是同一 hardware warp 内 compile-time 大小的连续线程组。`WarpReduce`/`BlockReduce`实现[归约（reduction，TERM-127）](/glossary/#term-127)，`WarpScan`/`BlockScan`实现[扫描（scan，TERM-130）](/glossary/#term-130)；四者都把 participant、output validity 与 [临时存储（temporary storage，TERM-183）](/glossary/#term-183)合同留给调用者。

## 学习成果

- 根据需要协调的 group scope 与 output shape，在四个 focused collectives 间选择。
- 精确声明 logical-warp participant count、block template shape、row-major rank 与 blocked arrangement。
- 为每个同时活动的 group 提供匹配 specialization 的 `TempStorage`，并在 reuse/repurpose 前加入 caller barrier。
- 处理 `valid_items`/`num_valid` 与 output-validity boundaries，不让 inactive data 进入 operation。
- 选择 v3.4.2 algorithm variant 时描述语义与[确定性（determinism，TERM-138）](/glossary/#term-138)，不从名字生成 performance claim。

## Participant contract 先于 primitive name

| Primitive scope | Compile-time shape | 必须共同调用的 participants | 结果合同 |
| --- | --- | --- | --- |
| Warp | `T, LogicalWarpThreads`，其中 `1 <= n <= 32` | 同一 hardware warp 中 `n` 个连续 threads；entrant count 必须是 `n` 的倍数 | 由 logical lane rank 定义 |
| Block | `T, BlockDimX, Algorithm, BlockDimY, BlockDimZ` | launch 中与 template shape 完全匹配的整个 CUDA thread block | 由 row-major linear thread rank 定义 |

Collective call 必须由该 group 的所有 required participants 以一致参数到达。只让“有数据”的 threads 调用不是 partial-tile protocol；它可能让内部 communication 或 barrier 缺少参与者。[M06](/memory/warp-divergence-reconvergence/)解释 converged participation，[M12](/memory/cooperative-groups/)提供另一套 explicit-group vocabulary，但不会自动改变 CUB class 的 participant contract。

v3.4.2 对 logical-warp shape 还有一条容易漏掉的边界：当 `LogicalWarpThreads` 是 2 的幂时，一个 hardware warp 可按该大小划分 subwarps；当它不是 2 的幂时，tagged developer guide 明确说不做 partitioning，只有第一个 logical warp 执行。不能把 32 lanes 简单切成多个 7-lane 或 9-lane sibling groups。Exercise 使用 8，因而不触发这条边界。

## Warp primitives：一个 logical warp 的 reduction 或 prefixes

`WarpReduce<T, LogicalWarpThreads>`让每个 logical lane 提供一个 item（部分 overload 可提供 fixed-size range），并只在每个 logical warp 的 **lane 0** 返回有效 aggregate；其他 lanes 的 return value undefined。若一个 block 同时运行多个 logical warps，每组必须有自己的 `TempStorage` slot，不能让仍在执行的 groups alias 同一 slot。

`WarpScan<T, LogicalWarpThreads>`为每个 participating lane 产生 inclusive 或 exclusive prefix。普通 output 对对应 lane 有效；带 `warp_aggregate` 的 overload 把全部 inputs 的 aggregate 提供给每个 participating lane。`ExclusiveSum`提供 zero initial value，所以 logical lane 0 的 output 是零；不带 initial value 的 generic `ExclusiveScan` 则明确让 lane 0 output undefined。不能把 reduce 的 leader-only output rule误套到 scan，也不能反过来读取每个 lane 的 reduce return value。

## Block primitives：整个 launch block 的 reduction 或 prefixes

`BlockReduce` 与 `BlockScan` 的 template shape 不是建议值。Runtime launch 必须与 `BlockDimX * BlockDimY * BlockDimZ` 及各维形状匹配，整个 block 共同调用。两类 class 都有匹配 specialization 的 nested `TempStorage`；v3.4.2 也提供 internally allocated private shared-storage constructor，但 explicit storage 使 ownership 与 reuse phase 更容易审查。

`BlockReduce`的 public `Sum`/`Reduce` return value只在 row-major **thread 0** 有定义，其他 threads 不得消费，即使某个 internal algorithm 恰好让更多 lanes 看见值。`BlockScan`则为每个 thread 的 item(s)产生 prefix outputs；带 `block_aggregate` 的 overload 把 aggregate 提供给所有 threads。Reduction 与 scan 的 output cardinality 始终不同。

## Row-major blocked arrangement

多维 block 的 linear rank 是 `threadIdx.x + BlockDimX * (threadIdx.y + BlockDimY * threadIdx.z)`；X 变化最快。Single-item overload 按该 row-major rank 排序 participants。

当每个 thread 持有 `ItemsPerThread` 个 items 时，array overload 假设 **blocked arrangement**：linear thread `i` 拥有 global logical sequence 中从 `i * ItemsPerThread` 开始的连续区间。也就是说，先按 thread rank 排列，再按该 thread 的 local item index 排列。把 striped load 直接当成 blocked input 会改变 reduction/scan 的 logical order；应先转换 arrangement，或选择匹配数据布局的 load path。

## `TempStorage` 与 caller synchronization

`TempStorage` 是 opaque nested type，其 layout 取决于 class specialization、algorithm、data type 和 group shape。Caller 为每个同时活动且可能互相干扰的 group 提供独占 slot。可以在不同 collectives 之间用 union/alias 复用 shared memory，但 phase boundary 必须明确。

Collective 内部可能使用 shuffle、shared memory 和 embedded barriers；这些内部步骤只实现当前 call，**不能替代 caller 为 storage reuse 或 following use 所需的同步**：

- Warp collective 返回后，若要复用/repurpose 该 warp `TempStorage`，先让准确的 participating lanes 执行 `__syncwarp(mask)`；uniform full-warp case 才可无歧义使用默认 full-warp form。
- Block collective 返回后，若要复用/repurpose block `TempStorage`，整个 block 先执行 `__syncthreads()`。
- 若 leader 把 reduction result 发布到 shared memory 供 peers 消费，还要为这条 producer/consumer edge放置匹配 scope 的 synchronization；内部 barrier 不证明 publication 已完成。

Barrier 的 participant mask/phase 必须与 group ledger 一致。过宽 mask 中缺少到达者与过窄 mask 漏掉 consumer 都不是安全协议。

## Partial-valid contracts

`WarpReduce` 的 `valid_items` overload只归约 logical warp 中前 `valid_items` 个 lanes；calling warp 的所有 threads 必须对该值达成一致，否则结果 undefined。参与 collective 与贡献有效 input 是两个不同集合：无效 lane 仍按 group contract 调用，但其 input 不进入 reduction；结果仍只在 logical lane 0 有效。

v3.4.2 `WarpScan` 的 partial forms 同样只把前 `valid_items` 个 lane inputs 传给 scan operator。Invalid outputs 保持 unmodified；请求 aggregate 时，零个 valid inputs 会让 aggregate undefined。所有 participating lanes 仍需遵守同一个 group call 与 storage phase。

`BlockReduce(input, op, num_valid)`或 `Sum(input, num_valid)`只让 row-major rank 位于前 `num_valid` 的 threads贡献 item，但整个 block仍调用 collective，结果只在 thread 0 有效。Focused `BlockScan` surface 没有对应的 dynamic valid-count parameter；tail tile 必须由 caller 用正确 identity/padding 与 output guard 构造 full logical tile，或选择另一个有明确 partial contract 的 abstraction。对 generic operation，没有已证明的 identity 就不能随意 padding。

## v3.4.2 algorithm variants

`BlockReduceAlgorithm`公开 `BLOCK_REDUCE_RAKING_COMMUTATIVE_ONLY`、`BLOCK_REDUCE_RAKING`、默认 `BLOCK_REDUCE_WARP_REDUCTIONS` 与 `BLOCK_REDUCE_WARP_REDUCTIONS_NONDETERMINISTIC`。第一个只接受交换 reduction；tagged source 把后三个列为可接受交换与非交换 operation。最后一种用 atomic operations 合并 warp aggregates，所以同一 kernel 的不同 invocation 不保证相同 reduction order。无论 variant，public return contract 仍只授权 thread 0。

`BlockScanAlgorithm`公开默认 `BLOCK_SCAN_RAKING`、`BLOCK_SCAN_RAKING_MEMOIZE` 与 `BLOCK_SCAN_WARP_SCANS`。在 v3.4.2 source 中，如果 block thread count 不是 architecture warp size 的倍数，请求 `BLOCK_SCAN_WARP_SCANS`会映射到 safe `BLOCK_SCAN_RAKING` implementation。Warp classes 还会按 logical-warp shape 选择内部 specialization。这些 names 描述 available implementation families 与约束，不证明某一 variant 在目标 workload 上更快、使用多少 instructions、产生何种 occupancy 或赢得 benchmark。改变 reduction order 时，还必须重新应用数值验收与 determinism requirement。
