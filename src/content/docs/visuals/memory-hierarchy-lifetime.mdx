## 学习目的

VIS06 是与 [M01](/memory/address-spaces/) 相关的可视化讲解（Visual Explainer）。它不用容易误导的“从快到慢 memory pyramid”，而是按 owner/acquisition、accessible scope、lifetime、release/end condition 和 physical/address-space caveat 组织 catalog。

## 六项 catalog

Catalog 恰好包含六项：

| 记录 | Owner 与 acquisition | Accessible scope | Lifetime 与 end |
| --- | --- | --- | --- |
| Host | Host application 通过语言或选定 Runtime host-memory API 取得 | Host；device 访问需要另行声明机制 | Allocation/object lifetime；匹配的 host release 或 process end |
| Global | 通过 CUDA allocation path 持有 device allocation | 持有合法 pointer 的 grid thread；host 通过 API 管理或复制 | 跨 launch，直到 release、reset 或 context/application end |
| Constant | 由 module/context 持有、通过 symbol API 初始化 | Grid thread 只读；host API 可以定位 symbol | Module/context lifetime，直到 unload、reset 或 context end |
| Shared | 每个 block 的 static declaration 或 launch-sized storage | Owning block 中的 thread | Owning block 在 kernel execution 期间；block 完成时结束 |
| Local | Compiler-managed per-thread private storage | Owning thread | Owning thread/kernel execution；没有 host `cudaFree` |
| Register | Compiler-assigned per-thread storage | Owning thread | Owning thread/kernel execution；由 compiler 管理结束 |

组件内更完整的静态 table 为每项保留 release 与 physical/address-space caveat。

## 筛选

Scope filter 提供 host、grid、block、thread。Operation/lifecycle filter 区分显式 allocation/release、module/context end、owning-block end 与 owning-thread end。两者默认都是“全部”；reset 会恢复确定性的六项状态。

两个 filter 取交集：选择 thread scope 与 owning-thread end 会显示 local 和 register；选择 host scope 与 owning-thread end 会显示明确的 empty state。纯模型对未知 filter ID fail closed。筛选永远不会从永久静态 catalog 删除记录。

## Address-space 与 physical 边界

Global、constant、shared、local 是 device address-space 概念；register 是 compiler-managed on-SM storage。Host memory 用于揭示 ownership 与 transfer boundary，但它不是另一个 kernel device address space。

L1、L2 是 cache，不是拥有独立 source-level allocation lifetime 的额外 address space。Shared memory 可以与 L1 共享 SM physical resource，同时仍是由程序管理的 shared address space。相反，**local** 表示逻辑上只属于一个 thread，并不表示物理上 on-chip。CUDA local memory 位于 device memory，register pressure 可能把 thread value spill 到这里。

因此 physical-layer diagram 不是 latency 排名。它不声明选定 variable 的 cache hit、placement、occupancy effect 或 performance result。

## 静态回退

静态回退同时包含三层 grouping 与完整六行 table。二者都由同一 catalog 在 server 端生成，禁用 JavaScript 和打印时仍保留。增强 table 只是 filtered view，不是这些事实的唯一副本。

## 证据边界

浏览器 catalog 不编译 CUDA、不执行 kernel，也不探测 allocation、register assignment、cache 或 physical placement。Filter 不会授予 **Compile-Checked**、**Community-Observed** 或 **Runtime-Verified**。全部 publication evidence axis 均为空。
