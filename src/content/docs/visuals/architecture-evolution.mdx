## 目的与先修

精确有序先修：[H01](/architecture/turing-warp-safety/)、[H02](/architecture/ampere-pipelines-tensor-cores/)、[H03](/architecture/ada-working-sets/)、[H04](/architecture/hopper-clusters-tma/)。比较显式同步可移植基线与文档记录的新增功能。Turing 从 Volta 继承独立线程调度（Independent Thread Scheduling）；Ampere 增加硬件拷贝与分离屏障路径。Ada 扩大了具体实现的缓存容量，Hopper 引入线程块集群（Thread Block Cluster）、分布式共享内存（Distributed Shared Memory，DSM）和张量内存加速器（Tensor Memory Accelerator，TMA）。请按计算能力（Compute Capability，CC）契约理解，不按产品排名理解。

## 控件

选择**精确计算能力**与**所需功能**，两个条件取交集：CC 8.6 加原生 FP64 Tensor Core，或 CC 8.9 加 TMA，均给出有解释的空结果，不会悄悄改变 CC。重置恢复全部已核对状态，并把焦点移回 CC 选择框。使用原生选择框／按钮键盘行为，结果通过礼貌实时区域播报。没有动画、自动播放、定时器、随机数、持久化或 GPU 查询。刷新后显示全部六种状态。未知筛选值会被拒绝并保留此前选择。

## 模型契约

顺序固定：Turing 7.5，Ampere 8.0、8.6、8.7，Ada 8.9，Hopper 9.0。每行具有目标、共享内存上限和全部十一项功能结论。后续架构没有选项、行或占位符。FP64 指**原生 Tensor Core 输入**，不是普通 double 算术；在这些行中 8.0 与 9.0 合格。FP16/BF16/TF32/FP64 仍需满足 H02 的精确 WMMA 类型、形状、布局、参与和调用方精度许可。硬件可用性不能证明所选指令。

64/163/99/163/99/227 KiB 是每块上限，超过 48 KiB 需动态共享内存及显式启用；不是实测占用率或设备显存容量。本站可移植范围是 CC 7.5+ 且问题适合 8 GB 内存预算；现代单 GPU 能力层级（Modern Single-GPU Capability Tier）要求 CC 8.0+ 且至少 8 GB。8.7 行不选择或验证平台环境。

L2 策略资格始于 8.0；实际缓存容量按设备查询，不由 CC 推断。MIG／MPS、窗口／预留区限制仍是门槛。集群／DSM／TMA 筛选在这些行中只选择 9.0。集群需通过实际维度／资源查询，DSM 需初始化及退出同步。单块 TMA 不需要集群，但需满足 H04 的描述符／对齐、事务等待、代理可见性及按方向区分的存储完成。H03／H04 指明精确内存、目标、分析器权限和普通拷贝／全局暂存回退。
