## 目的与先修

精确有序先修：[H01](/architecture/turing-warp-safety/)、[H02](/architecture/ampere-pipelines-tensor-cores/)。比较显式同步可移植基线与文档记录的新增功能。Turing 从 Volta 继承独立线程调度（Independent Thread Scheduling）。Ampere 增加硬件拷贝与分离屏障路径，但并非全部 8.x 行都有原生 FP64 Tensor Core。请按计算能力（Compute Capability，CC）契约理解，不按产品排名理解。

## 控件

选择**精确计算能力**与**所需功能**。两个筛选条件取交集：CC 8.6 加原生 FP64 Tensor Core 会给出有解释的空结果，不会自动回退为 8.0。重置恢复全部已核对状态，并把焦点移回 CC 选择框。使用原生选择框／按钮的键盘行为，结果通过礼貌实时区域播报。没有动画、自动播放、定时器、随机数、持久化或 GPU 查询。刷新后显示全部四种状态。未知筛选值会被拒绝并保留此前选择。

## 模型契约

顺序固定：Turing 7.5，Ampere 8.0、8.6、8.7。每个已发布状态都具有目标、共享内存上限和全部七项功能结论。后续架构没有选项、行或占位符。功能可用性表示已核对的硬件契约，不等于 API 或编译器接受的全部指令集合。这里 FP64 指**原生 Tensor Core 输入**，不是普通 double 算术。FP16/BF16/TF32/FP64 仍需满足 H02 的精确 WMMA 类型、形状、布局、参与和调用方精度许可。

64/163/99/163 KiB 是每块上限，超过 48 KiB 需要动态共享内存并显式启用；不是实测占用率或设备显存容量。本站可移植范围是 CC 7.5+ 且问题适合 8 GB 内存预算；现代单 GPU 能力层级（Modern Single-GPU Capability Tier）要求 CC 8.0+ 且至少 8 GB。8.7 行不选择或验证平台环境，拟议执行前请参考 H02。
