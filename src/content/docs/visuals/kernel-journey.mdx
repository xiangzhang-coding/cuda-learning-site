## 学习目的

VIS01 是一份可视化讲解（Visual Explainer）。它用一条**确定性的教学轨迹**把 kernel launch、grid 中的 thread block、SM 上的 warp、global-memory transaction 和同步边界连起来。确定性只服务于重复操作和预测，不代表真实 GPU 采用固定调度顺序。

<KernelJourney locale="zh-CN" />

## 模型如何读取

轨迹从 host 把 launch 放入 stream 开始，到声明的同步或依赖边界可以观察全部 grid 工作完成为止。每一步只增加一个概念事实；向后拖动会重建对应状态，不保留后续步骤的高亮。

浏览器不自动开始播放。页面初次打开、刷新和重置都会回到第一个步骤，也不会把可视化状态写入 `localStorage`、cookie 或远端服务。

## 控件与无动态访问

- **播放**按固定顺序推进，完成后停止；间隔只是界面节奏。
- **暂停**保留当前步骤；**单步**推进一次并保持暂停。
- 范围输入可用方向键逐步定位；**重置**清除播放状态并回到 launch。
- `prefers-reduced-motion` 下没有位移动画。所有事实仍可通过单步、拖动和完整静态序列获取。

## 真实调度边界

一个 thread block 的全部 thread 在一个 SM 上执行，但不同 block 没有保证的分派或完成顺序；它们可以并行，也可以串行。Block 内 thread 以 x 最快的局部线性 ID 划分为 32-thread warp。图中只跟踪一个示意 block 和一个 ready warp，不声称其他合法调度不存在。

内存阶段使用一个严格限定的例子：一个 warp 的 32 个 lane 读取对齐、连续的 4-byte word，总共覆盖 128 B，因此由四个 32 B global-memory transaction 满足。宽度、对齐、地址分布、cache 行为或架构条件变化时，事务数量也可能变化。

## 静态阶段序列

组件中的编号列表就是 purpose-built static fallback。禁用 JavaScript 时控件不会出现，但八个阶段、每个阶段的边界说明和证据声明仍在初始 HTML 中；打印时也只保留这份完整序列，而不是打印一个失去状态的动画截图。

## 证据边界

这个页面没有编译 CUDA，也没有在 GPU 上运行 kernel。浏览器的当前状态、播放间隔、完成标签和截图都不会授予 **Compile-Checked**、**Community-Observed** 或 **Runtime-Verified**。真实运行证据必须遵守 [O02 的证据状态合同](/start/evidence-status/)。
