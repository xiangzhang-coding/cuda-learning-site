## 学习目的

完成 A08 后，用 VIS12 把 `A[M,K] × B[K,N] -> C[M,N]` 从完整 matrix 逐层缩小到 logical tile、CUDA thread block owner、modeled warp subtile 与 source-level scalar operation slot。Related Runnable Example 是 EX15。

## 控件

三个原生 select 选择 matrix shape `128x128x32`/`256x128x64`、tile shape `64x64x16`/`128x64x16`和五个 hierarchy levels。重置恢复第一个 matrix、tile 与 matrix level，并把焦点返回 matrix select。Status 使用 polite live region。

Controls 与 live workbench 在 source HTML 中带 `hidden`；custom element 只有找到完整 parts 且初始 model 推导成功后才显示。页面没有 autoplay、timer、randomness、storage、range input、canvas 或 SVG。

## GEMM shapes

Shape notation 固定为 `M x N x K`。Matrix 表示完整 `A[M,K]`、`B[K,N]`、`C[M,N]` contract。Tile 表示 `TM x TN` output footprint 与 `TK` reduction slice。Output tile grid 是 `ceil(M/TM) x ceil(N/TN)`；一个 thread block 拥有一个 output tile，并自己循环 `ceil(K/TK)` slices，因此 block count 不乘 K-slice count。

两个 tile shapes 都使用 modeled `32x32x16` warp subtile。`64x64x16` 显示 4 warps/block，`128x64x16` 显示 8 warps/block。这是 bounded teaching partition，不是 launch recommendation 或 observed scheduling。

## 五层 hierarchy

1. **Matrix**：完整问题与三张 logical matrices。
2. **Tile**：output partition 与 K-slice loop。
3. **Thread block**：本教学 mapping 中的 CUDA owner；shape 与 tile 相同但语义不同。
4. **Warp**：thread-block footprint 内的 modeled subtile，不预测 issue order。
5. **Instruction**：`1x1x1` source-level scalar multiply-accumulate slot；不声称 compiler emitted FMA、MMA、WMMA 或 SASS。

因此 hierarchy 解释 ownership 与 nesting，不解释 occupancy、register allocation、Tensor Core eligibility、pipeline、latency、throughput 或 speedup。Architecture-specific instruction hierarchy 留给后续 version-gated L09。

## 静态回退

交互区之外永久 server-render 四种 matrix/tile selections，每种都有五个 purpose-built hierarchy panels，共 20 panels。每个 panel 明确写 shape、owner、relationship 与 boundary。禁用 JavaScript、390-pixel viewport、reduced motion、forced colors 与 print 时，全部 panels 保留；selected state 还使用 `aria-current`、文字与粗边框，而不只依赖颜色。
