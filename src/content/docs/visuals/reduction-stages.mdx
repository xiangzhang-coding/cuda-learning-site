## 学习目的

完成先修 [A02](/algorithms/multi-stage-reduction/) 后，用 VIS10 检查 reduction tree 中每轮留下哪些部分和。非活动通道（inactive lane）表示该 ledger 位置在当前轮不产生更新，不表示浏览器观察到某条 GPU instruction。这个 **deterministic** Visual Explainer 让学习者切换 **algorithm variant**，逐个检查 **reduction stage** 和每个 **inactive lane**。相关实践是 [EX11](/examples/multi-stage-reduction/)，数值顺序边界见 [Q02](/correctness/floating-point-order-reproducibility/)。

## 控件

第一个原生 select 在 `adjacent-pairs` 与 `stride-halving` 之间选择。第二个原生 select 只接受 `5`、`6` 或 `8` 个输入元素；固定输入前缀来自 `[3, 1, 4, 1, 5, 9, 2, 6]`。**下一阶段**每次前进一轮，**重置**保留当前选择并回到输入阶段。更换任一 select 都会清除 traversal state。

按钮使用原生 Enter 与 Space 行为。最后一步禁用仍持有焦点的 Step button 时，焦点移到 Reset；Reset 后焦点返回 algorithm-variant select。状态区使用 polite live announcement。页面没有 autoplay、timer、randomness、storage 或 persisted state。

## Stage 模型

四个 frame 分别是输入、第一次合并、第二次合并与最终和。`adjacent-pairs` 每轮把相邻部分和写入组内最低编号 lane；如果尾部没有伙伴，该值继续进入下一轮。`stride-halving` 依次合并距离为 `4`、`2`、`1` 的位置。两条路径对同一整数前缀得到相同最终和，但中间活动位置不同。

这两个 schedule 是本站原创、有界的整数依赖图，不是 NVIDIA algorithm、kernel source、warp schedule 或性能建议的复刻。它们帮助读取 tree shape；真实实现仍要独立处理 block scope、阶段间同步、任意长度、多 block partial sums 和数值操作顺序。

## Inactive lane

每个 stage 总是渲染 lane `0` 到 `7`。活动 lane 显示当前整数部分和；inactive lane 显示**中性值 0**。这里的零只是 visual ledger 的显式 neutral placeholder，不是额外输入、padding load、thread return value 或已执行加法。后续 stage 只读取模型标为 active 的 predecessor。

因此不能从 inactive 数量推断 branch efficiency、occupancy、instruction count、latency、bandwidth 或 speedup。Browser layout 也不表示一个 warp 的实际时间顺序。

## 静态回退

交互区之外永久保留六种 selection：两种 variant 分别配合 `5`、`6` 与 `8` 个元素。每种 selection 包含四个 stage，每个 stage 包含八个显式 lane，共 24 个 stage ledger 和 192 个 lane cell。禁用 JavaScript、390-pixel viewport、reduced motion、forced colors 与 print 都保留完整内容；inactive 状态同时使用文字和 dashed border，不只依赖颜色。

原始 HTML 中 controls 与 live workbench 使用 `hidden`。Light-DOM custom element 只有找到完整的原生控件、状态区、四个 stage marker 和八个 live lane，并成功推导初始 frame 后才显示它们。静态回退不依赖 enhancement。

## 证据边界

VIS10 不编译或运行 CUDA、不加载 kernel、不查询 GPU、不读取 profiler，也不生成 timing 或 performance observation。整数加法和 stage transition 是 declared browser-model output，不是 build、runtime、correctness 或 performance evidence。

因此 compilation、runtime、expected-observation 与 recorded-observation metadata 均为空。页面不会授予 **Compile-Checked**、**Community-Observed** 或 **Runtime-Verified** Evidence Status。
